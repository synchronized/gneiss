# Gneiss 项目目标与边界

## 项目定位

Gneiss 是基于 Granit 构建的轻量级 C++20 游戏运行时。项目通过 Scene Tree（场景树）提供直观的
对象组织方式，通过 ECS 提供数据驱动的运行时处理，并通过 Service + RID 隔离渲染、资源和平台
能力。

Gneiss 的首要目标不是覆盖完整商业引擎功能，而是形成边界清晰、可测试、可逐步扩展的游戏运行时
核心。每个阶段都应交付可以运行和验证的端到端路径。

## 目标用户

- 希望使用现代 C++ 构建小型或中型游戏的开发者。
- 需要在 Granit 渲染能力之上组织场景、实体和游戏循环的项目。
- 重视显式生命周期、可测试性和模块边界的引擎或工具开发者。

## 核心目标

### 可验证的运行时闭环

应用能够完成初始化、运行、处理事件、更新场景、提交渲染和确定性退出。新增能力应接入真实运行
路径，而不是只提供孤立的抽象或接口。

### Scene Tree 与 ECS 协作

Scene Tree 负责层级、命名和开发者友好的对象组织；ECS 负责高频数据处理和系统调度。场景节点通过
实体 ID 与 ECS 关联，两者不维护含义重叠的组件状态。

### Service 与 RID 隔离

渲染、资源、网络、音频和物理等能力由独立 Service 提供。ECS 组件只保存数据或 RID，不持有后端
对象。Service 负责资源生命周期、句柄校验和后端调用。

### 稳定的公共边界

公共 `.h` 使用 C11 可表达的 ABI，公共 `.hpp` 提供轻量 C++20 包装。错误、所有权、线程安全和
父资源失效规则必须显式定义，第三方库类型不得泄漏到普通公共接口。

### 渐进式依赖

第三方库只在真实任务需要时引入。每项依赖都应说明用途、锁定版本、许可证、替代方案以及对构建、
ABI 和长期维护的影响。

## 与 Granit 的边界

Granit 是 Gneiss 的底层渲染与平台能力提供者，不是需要在 Gneiss 中重新实现的模块。

| 领域 | Granit 职责 | Gneiss 职责 |
| --- | --- | --- |
| GPU 与渲染 | Renderer、资源、命令、Render Pipeline | Render Service、场景提取、渲染对象生命周期 |
| Window 与 Input | 平台窗口、事件和输入能力 | 应用事件分发、输入映射和游戏行为 |
| 资源句柄 | Granit 内部 GPU 资源句柄 | 面向引擎资源的 RID 与跨服务校验 |
| 场景与 ECS | 不负责 | World、Entity、Component、System、Scene Tree |
| 游戏循环 | 不负责 | Application 生命周期、时间步进和系统调度 |
| 资产 | 只消费渲染输入 | 加载、缓存、依赖、转换和热重载边界 |

Gneiss 不直接复制 Granit API，也不把 Granit 原生对象存入业务组件。确需互操作的高级接口必须单独
设计和标记，不能污染普通用户路径。

## 初始模块

```text
Application
├─ Platform Service ── Granit Window / Input
├─ World
│  ├─ Scene Tree
│  └─ ECS
├─ Render Service ──── Granit
└─ Resource Service
```

- **Application**：服务装配、主循环、事件、时间和退出顺序。
- **World**：实体、组件、系统以及运行时状态的所有权边界。
- **Scene Tree**：层级关系、节点生命周期和实体 ID 映射。
- **Render Service**：从 World 提取渲染数据并通过 Granit 提交。
- **Resource Service**：RID、资源缓存和加载状态；首版只覆盖闭环所需的最小能力。
- **Platform Service**：适配 Granit 的窗口和输入能力，不重新实现平台后端。

模块名称描述职责边界，不代表首版必须拆分为多个动态库。

## 当前非目标

以下能力不进入 `0.1.0` 的核心验收范围：

- 完整编辑器和正式 UI 框架。
- 网络、音频、物理和脚本运行时。
- 通用异步任务系统。
- 完整资产数据库、资源热重载和场景序列化格式。
- 复杂渲染特性、通用 Render Graph 或自研渲染后端。
- 为尚未出现的使用场景提前设计插件市场或兼容层。

这些能力可以进入后续路线图，但必须由真实用户路径和独立 Plan 驱动。

## 成功标准

Gneiss 达成长期目标时，应具备以下特征：

- 最小项目能够通过少量代码创建应用、场景和可渲染实体。
- Scene Tree、ECS、Service 和后端之间的依赖方向可以通过测试和公共接口验证。
- 资源和对象拥有确定的创建、销毁及失效语义。
- 新服务可以在不修改核心数据模型的前提下接入。
- Windows 和 Linux 的开发、测试及发布路径可重复执行。

# Gneiss 开发路线图

## 说明

本路线图记录项目阶段、任务编号、优先级和状态摘要，不承诺发布日期。任务的设计、实施步骤与验收
细节由对应 Plan 维护；长期架构取舍由 ADR 记录。

优先级定义：

- **P0 核心路径**：形成当前阶段端到端闭环所必需。
- **P1 完整性**：提升正确性、可用性或可维护性。
- **P2 扩展能力**：在核心闭环稳定后按真实需求进入。

状态使用“待开始、设计中、实现中、已完成、暂缓”。

## 0.4.0：扩展服务

物理、音频、网络和脚本不预先规定实施顺序。每项能力应先出现至少一个真实使用场景，再建立独立
Plan 和 ADR，确定后端选择、线程模型、数据所有权及 Service 边界。

## 1.0.0：稳定运行时

进入 `1.0.0` 前至少需要：

- 代表性游戏样例验证核心 API 易用性。
- 公共 C ABI、C++ 包装和 CMake package 的兼容策略。
- Windows/Linux 共享与静态构建、安装 Consumer 和发布验证。
- 性能、内存、资源生命周期和故障诊断基线。
- 明确哪些模块属于稳定核心，哪些仍为实验性组件。

## 路线图调整规则

- 新任务先确认属于哪个阶段，以及是否阻塞当前端到端闭环。
- 改变优先级或阶段目标时更新本路线图；实现细节只写入对应 Plan。
- 跨模块长期决策写入 ADR，稳定后的当前行为回写 Concept、Guide 或 Reference。
- 没有真实使用场景、验收方法或维护责任的能力不提前进入实现阶段。

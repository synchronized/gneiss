# 0.49.0：大场景加载响应性与生命周期稳定性

2026-10-07 发布，[源码 Release：v0.49.0](https://github.com/synchronized/gneiss/releases/tag/v0.49.0)。
本版不附预编译程序或第三方场景资产。

## 目标与交付

- 资产准备与来源复验分步推进，复用现有任务调度器；Windows 使用可轮询范围读取和有界 Mesh 预读。
- 未发布场景候选取消后停止后续上传；唯一取消终态与真实清理完成分离，旧场景继续保留，清理期间禁止重试。
- Runtime 通过事件补报清理账本，Editor 校验请求身份，避免迟到结果重新激活已取消场景。
- POSIX I/O 工作线程局部屏蔽 SIGPIPE，增加受控断连回归和灯廊启动阶段诊断。
- 保持 2 GiB 候选上限、完整输入、公共 C/C++ SDK 与 Granit 依赖。

## 验收摘要

固定 Sponza 首载 12/12、完整实景生命周期 18/18 通过。两种执行模式均覆盖三次切换、
五阶段取消、失败重试、窗口操作和关闭；节点、资源数和图像一致。
完整 cooperative 首载最大主循环间隔由基线约 67.4 秒降至 187.8 ms。
测量设备、候选差异和具体门槛见 [M-312](../records/M-312-loading-stability-baseline.md)
与 [M-313～M-316](../records/M-313-316-loading-stability-validation.md)。

本地共享 190/190、静态 187/187、隔离安装消费者各 4/4，远端 Windows 4/4、Linux 8/8 通过。
实际 Vulkan 校验层下像素回归、Runtime 双模式完整场景加载及上传取消通过，无校验错误。
详细发布证据见 [M-317](../records/M-317-0.49.0-release-validation.md)。

## 已知限制

性能数字限定于记录中的 Windows 硬件和完整输入，未控制系统文件缓存；主循环间隔不等于 GPU 呈现帧率。
未测量独立 GPU 显存，逻辑资源账本不能替代驱动观测。清理完成不意味着旧场景、缓存或旧帧持有的共享资源全部释放。
完整场景生命周期由原生 Application 宿主验证，Editor/Runtime IPC 使用集成夹具，另有实际 Runtime 完整场景加载；
不宣称完整场景 Editor 手工验收、完整引擎 Web 或跨屏 DPI 验收。
启动历史抖动未复现，保留诊断，不宣称根因已消除；不可分割的系统调用仍不具备抢占保证。

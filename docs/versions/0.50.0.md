# 0.50.0：异步资产 I/O 与编辑器加载响应性

2026-10-14 发布，[源码 Release：v0.50.0](https://github.com/synchronized/gneiss/releases/tag/v0.50.0)。
沿用源码发布方式，不附预编译程序或第三方场景资产。

## 发布决定

用户明确要求直接发布，并将未完成内容记录留待后续。此决定接受下列已知限制与验收缺口，
不表示原性能门槛全部通过，不修改阈值或删除失败样本。

## 目标与交付

- 主循环进展通知与有限等待，减少重复轮询；协作模式读取/哈希采用有界批次。
- 线程池 Application 接入 libuv 异步路径解析、打开、区间读取和关闭，保持预算、来源校验与取消生命周期。
- Editor 启动与显式打开场景使用异步加载，增加阶段进度、取消和失败重试；成功后重绑文档及相机。
- 修复渲染纹理仍持有文件来源时过早停止 I/O 执行器导致的退出等待。
- 普通交互帧最多保留一份等待快照，减少旧相机状态排队；增加持续冒烟与显示/GPU 统计。
- 默认关闭的 Tracy、循环 CSV、输入响应探针及 Windows 系统采集辅助工具。
- 修复固定 ImGuizmo 提交的浅克隆获取问题，为 Linux 图形诊断增加超时与日志归档。
- C ABI 和 Granit 版本保持；C++ Scene 包装补充原始实例 RAII 接管入口。

## 验收摘要

候选 8944164 的 Windows 完整矩阵 4/4 通过，Linux 宿主共享 195/195、静态 192/192
及 Vulkan 像素校验通过；随后仅更新文档。更早 e8506f3 的 Linux 核心四项、Web 和
Sanitizer 通过，不将其描述为对最终候选重新执行。远端链接与具体边界见
[M-321](../records/M-321-0.50.0-release-validation.md)。

本地 Editor 完整 Sponza 加载及正常退出通过；对应功能、资源与生命周期回归见
[M-323](../records/M-323-editor-async-scene-loading.md)。性能验收有失败，见下节。

## 已知限制与后续工作

| 遗留项 | 发布时状态与后续方向 |
| --- | --- |
| 主循环与输入长间隔 | 历史输入超标保留；最新响应夹具通过但主循环最大 143.43 ms 超过 100 ms，主要落在窗口泵墙钟区间，根因未定 |
| 协作模式大场景 | 失败恢复、清理与重试功能通过，最大回调间隔 257.55 ms 超过 250 ms；后续需关联同轮任务、事件和等待 |
| 生命周期完整复验 | 最新协作矩阵因失败停止，窗口操作、关闭未运行；完整最新矩阵仍待补齐 |
| 资产 I/O 迁移 | 显式同步/协作回退仍存在，旧平台读取实现未全部删除；符号链接隔离专项验收及低内存失败注入尚未完成 |
| Editor 持续渲染 | Sponza 静止相机单轮约 15.7 FPS，尚未达到流畅交互；LOD、流送和渲染成本归因留待后续 |
| Editor 异步范围 | 作者事务回滚、文件监视结构重载仍同步；首个进度界面前的工程恢复与图形初始化仍可能阻塞 |
| 其他验收边界 | 完整场景真实鼠标回放、物理跨屏 DPI、独立 GPU 显存测量未完成；无跨设备硬实时保证 |

后续任务应保留原失败证据和冻结门槛，先建立可复现归因再修改实现；不将架构调整视为
卡顿已经修复。后续排期以[路线图](../roadmap.md)和对应计划为准。

# 0.47.0：原生 C++ SDK 与公共头收口

2026-10-06 发布，[源码 Release：v0.47.0](https://github.com/synchronized/gneiss/releases/tag/v0.47.0)。
本版不附预编译程序或第三方大场景资产。

## 目标与交付

- 普通 Engine C++ SDK 改用独立描述、枚举、强类型 ID、默认值及 noexcept 回调，不再要求 C 业务宏或布局字段。
- Application / Reflection 的稳定回调存储随拥有者及释放载体转移；Render、Scene 与 Reflection 明确转换数组和借用文本寿命。
- Game Module 使用编译期回调表生成 C ABI 桥接，工程模板只有真正的动态库查询入口保留 C 签名。
- 删除 26 个旧转发头，统一为 `gneiss/engine/` 规范路径；根总入口保留。严格原生映射清单与旧路径负向安装检查纳入 CTest。
- 修复显式标准头缺失、MSVC 空回调实例化/夹具告警，以及 CMake 3.25 检查脚本兼容性；未降低警告或检查等级。

## 验收摘要

最终候选本地 Windows Clang 共享完整 CTest 189/189、静态 186/186；安装消费者各 3/3。
两种 SDK 各 28 个公共头，独立 C11/C++20 头编译及 26 个旧路径负向检查通过。
102 个公共 C 导出、61 个同版本私有 C++ 导出与 0.46 一致，C 声明及结构布局保持。

最终候选手动矩阵 Windows 4/4、Linux 8/8 全部通过。Linux 核心四组各 101/101，
图形共享 187/187、静态 184/184，另含 Sanitizer 和无线程浏览器调度。
完整证据及失败/修复过程见 [M-306 验收记录](../records/M-306-native-cpp-sdk-validation.md)。

## 迁移与已知限制

这是有意的 C++ 源码不兼容版本：旧头路径、C 描述及回调签名需要迁移，消费者须重新编译，
并使用干净 SDK 安装前缀。详见[从 0.46 迁移到 0.47](../guides/migrating-0.46-to-0.47.md)。
C++ 二进制 ABI 不作稳定承诺；原生数组转换有临时分配成本，借用文本及 user_data 仍须遵守寿命契约。

本版不升级 Granit、不开发插件、不开放 Editor API，也没有重新测量第三方大场景或新增性能结论。
本地首轮灯廊第二次启动在并行构建时超过原 5 秒期限，停止并行构建后连续及完整复验通过，未宣称根因修复。
0.46 留下的 Linux IPC SIGPIPE 风险仍保留；本版最终矩阵该项通过，不等同于根因已解决。

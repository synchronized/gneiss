# 0.44.0：大场景纹理驻留与加载预算

2026-10-01 发布，[标签与源码 Release：v0.44.0](https://github.com/synchronized/gneiss/releases/tag/v0.44.0)。
本版为源码发布，不附二进制或第三方大场景资产。

## 目标与交付

针对完整 Cook 4K Sponza 的 CPU 候选容量和纹理负载驻留，接入设备能力驱动的单变体准备、
来源复验、上传负载租约、共享资源预算和 Editor/Runtime 反馈。保留 2 GiB CPU 候选上限，
不通过降低分辨率、裁剪资产或跳过贴图规避限制。

- 后台按设备能力只读取和准备选中的 BC7/RGBA8 纹理变体。
- 上传完成后释放可由原来源摘要重建的 CPU 负载；旧帧、失败、取消和重试保留正确所有权。
- 统计候选逻辑容量、CPU 数据、纹理负载、Application 共享资源和上传暂存，预算不足提供字节诊断。
- Editor 与 Runtime 共用场景加载路径，取消、失败和重试保持旧场景，支持阶段快照反馈。
- 兼容原始 PNG、RGBA8 回退和旧同步加载路径。

## 验收摘要

- 本地 Windows Clang Debug 全量 CTest：164/164 通过。
- 远端 Linux 手动矩阵：8/8 通过，包含 GCC/Clang、静态/共享、Runtime、sanitizer 和 task-web。
- 远端 Windows 手动矩阵：4/4 通过，包含 MSVC 静态/共享和安装后 C/C++ consumer。
- 完整 Cook Sponza Windows thread 样本成功加载；候选/CPU 数据约 1.788 GiB，低于 2 GiB，
  上传峰值约 64 MiB，激活约 0.2～1.7 ms。
- 完整场景三次切换、各阶段取消、失败重试、resize/最小化恢复和关闭自动化验证通过。
- 相关手动 Actions：[Linux run 36739328581](https://github.com/synchronized/gneiss/actions/runs/36739328581)、
  [Windows run 36739324044](https://github.com/synchronized/gneiss/actions/runs/36739324044)。

## 已知限制

- cooperative 模式的完整大场景任务仍可能造成秒级主线程长帧；任务不可抢占。
- 取消结果已验证旧场景保留和请求快速响应，但没有独立公共字段直接证明终态预算归零。
- 测量报告的是逻辑资源、服务 CPU 数据和进程峰值，不是驱动实际独立 GPU 显存。
- Sponza 当前材质管线不完整映射 glTF 法线、金属度/粗糙度、灯光、TEXCOORD_1、顶点色和 BLEND 语义。

# 0.51：降低资源加载语义并删除版本与事务协议

## 状态、范围与权威来源

2026-10-23：用户确认先降低普通资源加载承担的语义，再删除整套运行时资产版本与事务协议。
本轮批准范围已完成并通过本地功能与 Release 性能验收。架构决策见
[ADR-072](../decisions/ADR-072-progressive-render-assets.md)。本页取代此前逐个兼容旧协议的
实施顺序，承接[资产管理替换计划](PLAN-051-asset-manager-replacement.md) R4。

已提交基线：CAORS 已移除；已有异步纹理上传、稳定 RID 预留、默认资源和帧快照保活。
普通路径已接入上传后逐项生效、结果回执及每资源更新序号，详见
[实施记录](../records/2026-10-23-progressive-asset-results.md)。CPU 准备仍有批次限制，
场景与编辑器已切换稳定引用，固定版本索引、采用事务和依赖版本链已删除，见
[协议删除记录](../records/2026-10-23-asset-version-protocol-removal.md)。
普通请求已独立准备各请求项，上传失败后继续后续项，逐项结果已贯通 IPC 和编辑器。
场景在结构就绪后激活并接管视觉队列；依赖独立请求，上传改为单项任务数据。
资产候选 RID、批量发布 API、CPU 材质版本索引与租约包装已删除；同步入口逐项更新。
`material_document` 仅保留描述，摘要和字节数归加载证据；缓存拒绝跨挂载来源混用。
最终功能回归 201/201 通过，Release 固定大场景 12/12 通过；代价、测量限制和未验证平台见
[单项加载与内容缓存收尾](../records/2026-10-23-single-resource-loading.md)。

范围：Mesh、Texture、Material 加载与重载，以及 Scene/Prefab 和编辑器的资源接入。
不重写解码器、反射、ECS、RID 表或 Granit；不新增资源历史数据库、通用流送框架。
不删除编辑命令自身的有效性检查与场景结构构建保护，不默认改变公共 C ABI。

## 已确认的新契约

| 情况 | 目标行为 | 主动放弃的保证 |
| --- | --- | --- |
| 资源引用 | 引用同一逻辑资源，跟随最新成功内容；更新不改变 RID | 引用自动固定确切文件内容 |
| 首次加载 | 请求返回有效引用；Mesh 未就绪跳过，材质/纹理使用默认资源 | 取得引用即表示可以绘制 |
| 更新中/失败 | 有当前内容就继续使用；首次失败保持缺省，记录错误，显式重试 | 每次失败自动逐帧重试 |
| 多资源请求 | 逐项成功、逐项生效；回执含每项结果和汇总，不让汇总失败掩盖已成功项 | 跨资源全部成功或全部回滚 |
| 取消 | 停止未完成工作，等在途操作安全结束；已生效内容保留 | 取消恢复请求前全部内容 |
| 场景激活 | 结构合法、实例化和必要逻辑初始化完成即可激活；视觉资源后续就绪 | 全部视觉资产必须来自同一时刻并同时就绪 |
| 编辑撤销 | 恢复作者参数、结构和资源引用，资源仍使用当前成功内容 | 自动恢复外部文件的历史字节 |
| 编辑取消 | 不提交作者修改；已完成的共享资源加载可留在缓存 | 撤销加载对共享缓存的一切影响 |

临时新内容与旧内容可以同时存活，但没有供业务查找、选择、采用的历史版本身份。
格式版本号、RID generation、每资源更新序号、内容摘要不是本次删除对象。

## 最小结构与所有权

| 职责 | 唯一负责位置 | 禁止重复的状态 |
| --- | --- | --- |
| 来源身份、共享查找、使用者引用、读取解码调度 | 资产管理器及已有加载实现 | URI 缓存与固定版本选择表同时决定当前资源 |
| 逻辑 RID、当前渲染内容、上传、安全切换、GPU 退休 | 渲染资源服务与后端 | 资产管理器再拥有一套 GPU 资源 |
| 实例、实体、资源强引用及场景切换 | 场景运行时现有所有者 | ECS 组件持有第三方对象或加载服务 |
| 作者数据、未保存修改、撤销记录 | 编辑文档和命令历史 | 用运行时缓存充当文件历史 |

稳定身份包含来源域、规范化 URI、类型和影响内容兼容性的配置；同路径换挂载或设备失效
不能误复用不兼容内容。设备重建由渲染侧作废后端状态，不向业务暴露“选择设备版本”协议。
具体复用现有类型，首个闭环时确定字段，不先增加第二个 manager。

每个资源只需当前内容（可空）、当前更新任务（可空）、最新请求序号和最近错误。
任务只持有读取结果、上传数据和所属资源的有效性凭据，不分配候选资产 RID。
当前内容是否存在与更新任务阶段独立，更新期间不会把可绘制资源变为不可用。

使用者持有强引用，ECS 只存 RID；场景实例持有相应资源引用。首版沿用显式清理点回收缓存，
不提前增加 LRU/TTL 系统。最后使用者释放后停止不必要工作，在途任务与帧保留必要数据；
RID 被销毁或任务序号过期时，结果只清理，不恢复资源。无关资源更新不应使整个批次失败。

材质持有纹理身份引用。纹理完成后由渲染侧更新绑定，不重读材质文件或替换场景引用。
未改变的依赖只请求/复用，不能因加载一个材质而强制重载全部共享纹理。
必要的依赖完成标记属于渲染状态，不再建立依赖版本链和整批闭包采用。

## 协议与消费者删除清单

| 删除对象 | 当前消费者/位置 | 替代方式与退出条件 |
| --- | --- | --- |
| publication_mode、fixed_version | texture_load_service、scene_load_service、scene_session、application::prepare_edit_assets | 单一资源请求契约；所有入口不再选择发布模式 |
| asset_candidate、stage_asset、publish_assets 等对外候选协议 | render_asset_loader 与上传协调 | 临时加载输出由任务内部持有，成功后资源服务更新目标；不另造同义候选层 |
| publish_versions、version_publication、固定版本索引 | resource_cache、render_asset_loader | 按逻辑身份共享当前资源；不再支持版本查询 |
| prepared_adoption、prepare_adoption、adopt_versions、version_selection、selection_key、observe/acquire_selected | 场景 ready/take_candidate、普通重载、编辑资产接入 | 删除默认选择表与采用预约；直接绑定稳定资源引用 |
| previous_assets 与重载引用替换事务 | scene_session::request_assets/poll_assets | 更新资源内容，已有使用者无须整体重绑；真正的作者引用编辑仍保留 |
| prepare_edit_assets/accept_edit_assets 的固定版本职责 | application、内部宿主适配、editor_asset_edit、editor_prefab_edit | 请求资源与提交作者命令分开；命令成功不再提交缓存选择 |
| 回执 versions、prepared_asset.version/texture_versions 与传递版本编码 | texture_load_completion、asset_preparation、asset_identity | 逐项结果、稳定身份和任务序号；删除运行期版本链 |
| 批次全部复验后才保留的 CPU 文档批次流程 | cpu_document_batch/retain_verified、材质描述租约 | 评估保留按内容共享解析结果的最小缓存，移除整批采用前提；不新建第二份共享数据 |
| 全场景来源快照与整批复验 | 已移除 | 见[移除来源复验计划](PLAN-051-remove-source-revalidation.md)；保留格式与负载完整性校验 |
| 普通批次回滚、全局缓存 revision 冲突拒绝 | texture_load_service | 每资源最新请求胜出，未采用上传数据安全清理，已成功资源不撤回 |

删除 asset_version_key 前搜索全部用途；离线产物复用若需要摘要，仅保留明确的内容缓存键，
不能把运行时版本发布协议改名后保留下来。material_document 的摘要和字节数统一归加载证据，
迁移其校验消费者后再删除重复字段。

应保留：上传完成确认、旧帧数据保活、GPU 安全退休、RID 校验、每资源迟到检查、错误报告。
应保留：场景切换前临时构建 World，以及作者命令在提交前检查目标是否仍有效。
这些都不需要通用资源版本事务。Prefab 结构变更失败时仍应保留合法场景，视觉资源失败不回滚结构。

## 实施顺序与验收门槛

当前进度：R0～R4 在本机批准范围内完成。Runtime/编辑器资源入口不再使用版本采用；
普通重载不重绑 ECS 或自动重读材质。结构早激活、依赖迟到、逐项结果和旧内容保活已验证。
删除缓存版本/选择/候选协议及对应旧测试，记录中的平台限制不等于已经完成跨平台发布。

同一特性分支完成整项任务；各阶段形成可评审本地提交，不为每个阶段建立另一套长期接口。

| 阶段 | 连贯交付 | 退出条件 |
| --- | --- | --- |
| R0 契约与基线 | 本计划、ADR、消费者清单；审查未提交改动；记录现有帧间隔和内存基线 | 清楚区分待删语义与安全约束；不把旧协议测试当新目标 |
| R1 最小资源闭环 | 两个纹理、一个材质、一个网格；稳定引用、逐项结果、更新序号和失败保旧 | 一项成功另一项失败/取消时已成功项可见；旧回执不覆盖新请求；依赖迟到可正确显示 |
| R2 Runtime 与场景切换 | 同步入口、异步入口、普通重载统一；场景预留引用，活动场景接管在途任务 | 视觉加载未完成即可激活；结构失败仍保旧场景；切换/关闭没有悬空回调和泄漏 |
| R3 编辑器与 Prefab 切换 | 作者参数/引用/结构命令独立提交；撤销不锁定外部文件内容 | 撤销/重做、删除目标、取消编辑、外部文件变化均按新契约；无版本采用调用者 |
| R4 删除旧协议并收尾 | 删除缓存版本/选择表、候选 API、旧状态及仅验证它们的测试；统一文档 | 生产调用和构建无旧协议；下述完整验收通过；无长期双模式或空壳兼容层 |

R1 中小范围验证新契约，随后按消费者组集中替换；不再以“保留旧语义再删一个包装器”为推进单位。
R2/R3 是阻止旧协议重新出现的必要工作，不能把它们无限延期后宣布资源系统完成。

## 测试迁移与最终验收

删除仅约束固定版本共存、默认选择表、整批回滚、候选私有 RID 的测试。
将旧行为测试改写为新契约，不以关闭测试或降低检查等级处理错误。

必须验证：

- 首次未就绪默认行为、成功后同 RID 可见、更新失败保旧。
- 批次部分成功的逐项结果；随后失败/取消不撤回已经可用资源。
- A/B 更新乱序、无关资源并发、销毁后迟到、跨服务与类型错误、设备失效。
- 不兼容来源/配置不合并；同身份复用；材质依赖迟到刷新且不重复重载依赖。
- 场景结构失败、早激活、激活后资源失败、切换和关闭期间在途任务释放。
- 编辑撤销/重做恢复参数和引用；外部文件变化后仍遵循当前内容语义。
- 旧帧继续使用旧内容、最后引用释放、在途上传安全清理、最终 CPU/GPU 回收。
- 协作与线程池模式；用可控回执验证时序，不依赖随机睡眠。
- 真实 GPU 像素验证默认到真实内容、部分更新和失败保旧；测量帧间隔与峰值内存并对比基线。

按构建指南运行相关构建和测试，最终运行完整本地回归、格式与静态检查。
若公共 ABI/导出/安装受影响，补共享/静态和 C/C++ consumer 验证；不改 Granit 仓库。
最终搜索旧协议符号，检查源码、测试、示例和当前行为文档；历史 Record 保留原貌。

## 实施时需要核实的边界

1. 游戏模块必需依赖清单：视觉资源默认不阻塞，实际初始化所需逻辑资源仍检查。
2. 既有 IPC/回执是否能表达部分成功；若不足，同步迁移内部协议与 UI，不能把失败汇总误报为全部未改。
3. 历史命令是否持有具体渲染内容而非作者值/引用；逐个替换，文件历史不在本次实现。
4. CPU 文档共享缓存哪些部分有实际收益；内容去重与运行时历史索引分别处理。

这些核实用于确定代码改动范围，不恢复已放弃的通用原子发布和确切内容撤销保证。

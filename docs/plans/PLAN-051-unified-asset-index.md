# PLAN-051：统一资产资源索引

## 状态

资源索引与资源表加载入口已收敛。Windows Clang Debug 全目标编译、格式和架构边界静态检查通过；
测试目标已编译，未执行测试、大场景或 CI。决策见 [ADR-078](../decisions/ADR-078-unified-asset-index.md)。

## 目标与非目标

asset_manager 唯一持有当前资源表，Prefab 和 Render Loader 借用；
通用 CPU 资源结果接入同表，调度表不再保存 current 数据。
资源表统一以 load 执行复用、加载和成功登记，各类型入口保留解析及服务检查。
不引入 GPU 调度器、资源基类或候选事务。

## 实施顺序

1. resource_cache 使用来源域、规范 URI 与 C++ 类型组成的键。
2. 合并 Application 渲染缓存、Prefab 缓存及通用 CPU 成功结果存储。
3. CPU 输出引用保活缓存条目，未领取请求和旧描述引用不因回收失效。
4. Application 和场景收尾通过管理器统一回收；维持服务晚于缓存销毁。
5. 补充同 URI 不同类型/来源、缓存复用、回收和迟到完成的测试并编译。
6. 合并资源表 acquire/reload，Prefab 普通加载与重载共用实现，渲染预留仅查表一次。
7. CPU 同步解析进入统一加载回调；异步结果仍在所属线程通过同一入口登记。
8. 补充异常恢复、空输出与同键递归覆盖，只编译，不执行。

## 验收与风险

只有一份生产资源索引；调度表只有请求顺序和在途观察状态。
同来源同类型同 URI 复用，来源或类型不同独立；失败与迟到任务不得覆盖当前成功资源。
全目标编译和静态检查通过；按用户要求不执行测试、大场景或 CI。
渲染资源最后释放仍限所属线程，管理器必须先于渲染服务销毁。
加载入口收敛指共享资源表的复用和登记规则；CPU 异步调度、Prefab 诊断和 GPU 就绪检查
仍由各自入口负责，不将这些不同职责强制合并成一个 Loader。

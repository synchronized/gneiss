# VER-030：0.30.0 Runtime API 收敛与游戏工程模板

## 状态

- 状态：实现中
- 目标版本：0.30.0
- 优先级：P0
- 路线图阶段：1.0 候选契约与外部工程闭环

## 背景与目标

0.10.0 已完成首轮稳定性预览，但此后新增了 Runtime 宿主、Game Module、结构化日志、Prefab、
Editor–Runtime IPC、热重载和独立渲染线程。0.30.0 对这些增量重新审计，并把未来 1.0 的公共运行时
边界落实为机器可检查的契约。

本版本同时提供一个可复制的最小游戏工程模板。模板只依赖安装后的 Gneiss SDK，通过独立工程构建
Game Module，并由安装后的 `gneiss_runtime` 启动，以验证公开能力足以支撑真实下游工程。

## 非目标

- 不在 0.30.0 正式冻结 1.x ABI；Stable 仍是 1.0 候选级别。
- 不把 Editor、IPC、作者工具或 Granit 原生接口加入 Stable 公共面。
- 不增加物理、音频、脚本、正式游戏 GUI 或新的渲染效果。
- 不重复 0.10.0 已完成的全量基础审计和性能基线。
- 不为未发布的 0.x 接口维护无真实消费者的迁移层。

## 已确认决策

- `abi/api-stability.txt` 是逐符号分类的唯一机器可读来源；ABI 基线只记录符号存在性。
- 0.10.0 之后新增的 Game Module 与日志接口保持 Experimental，直到模板和跨版本验证证明其契约
  足够稳定；Editor–Runtime IPC 继续是内部能力。
- 工程模板位于 `templates/game`，不依赖源码树、私有头或示例资产；示例继续用于展示具体功能。
- 模板作为安装组件交付，并由隔离安装 Consumer 在 Shared/Static 可用边界内验证。
- 本版本不因 Granit 出现新版本而主动升级；只有模板或契约验收暴露上游通用缺口时才提出 PR 建议。

## 实施顺序

### M-193：0.10.0 后公共面增量审计

审计新增及改变的公共头、导出符号、C++ 包装、CMake target 和安装内容；修正文档中的过期版本状态，
记录 Stable 候选、Experimental 和 Internal 边界。

状态：已完成。审计发现并补齐 10 个未进入清单的 Experimental 导出，分类结论见
[M-193：0.10.0 后公共面增量审计](../records/M-193-public-api-delta-audit.md)。

### M-194：API 稳定性门禁加固

让自动检查验证 ABI 基线和稳定性清单的排序、唯一性、全集一致性，并核对公共 C 声明的导出与
Experimental 标记。扩展冻结头 Consumer，覆盖新增 Stable 候选所依赖的关键布局和调用路径。

状态：已完成。门禁现会核对排序、唯一性、公共声明全集及 `GNEISS_EXPERIMENTAL` 标记，不再允许
两份文本在同时遗漏声明时误通过。当前没有新增 Stable 候选，因此冻结头 Consumer 无需扩大接口面。

### M-195：最小游戏工程模板

提供可复制的工程描述、Game Module、最小场景和独立 CMake preset；模板代码只包含安装后的公共
头，并展示初始化、逐帧更新、结构化日志与确定退出。

状态：已完成。模板位于 `templates/game`，边界与内容见
[M-195：最小游戏工程模板](../records/M-195-game-project-template.md)。

### M-196：安装后模板闭环

将模板安装到 SDK，复制到源码树外的临时目录，以安装后的 Gneiss 配置、构建并运行。验证缺少 SDK、
模块加载失败和错误工程路径均给出可操作诊断。

状态：已完成。隔离安装、复制、配置、构建和 Runtime smoke 已纳入现有安装验收，结果见
[M-196：安装后游戏模板验收](../records/M-196-installed-game-template-validation.md)。

### M-197：外部消费与兼容文档收敛

更新兼容策略、构建指南、文档索引、安装内容和模板使用说明；明确 Runtime 库、宿主、Game Module
与 Editor 的边界。

状态：已完成。安装 package 暴露模板位置，兼容、构建与 Game Module 文档已收敛；结果见
[M-197：外部 SDK 消费与兼容文档收敛](../records/M-197-external-sdk-contract.md)。

### M-198：0.30.0 版本验收

提升版本号并完成 Windows/Linux、Shared/Static、C/C++ Consumer、安装后模板、Granit Runtime 与
Sanitizer 验证；更新 Changelog 和验收记录后完成发布工作流。

## 测试与验收

- ABI 基线、稳定性清单和公共 C 声明之间不存在遗漏、重复或分类漂移。
- 公共 `.h` 由 C11 独立包含，`.hpp` 由 C++20 独立包含。
- 冻结头 Consumer 能链接当前 Shared Library 并覆盖成功、失败和销毁路径。
- 模板复制到源码树外后只依赖安装 SDK，可构建 Game Module 并由 Runtime 完成 smoke 运行。
- 模板与安装包不引用源码树、构建树或 Granit 私有路径。
- Windows/Linux、Shared/Static、安装消费和 Sanitizer 矩阵通过。

## 风险与未决问题

- Game Module ABI 已被真实工程使用，但热重载和脚本模块尚未验证，因此本版本默认维持 Experimental。
- Static SDK 无法以同一方式跨动态库加载 Game Module；模板必须明确 Shared Runtime 是当前模块闭环。
- 自动从二进制提取跨平台导出符号会受工具链影响；声明级检查与平台二进制检查应各自承担明确职责。
- 若增量审计发现 Stable 候选存在错误所有权或不可扩展布局，应在 0.x 直接修正并记录，不为尚未发布
  的接口增加永久兼容负担。

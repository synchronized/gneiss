# DEV-043：PBR 材质管线开发计划

## 状态与依赖

2026-09-30 已完成确认范围并发布 [0.43.0](../versions/0.43.0.md)。以下保留实施与验收方案。范围以 [VER-043](VER-043-0.43.0-pbr-pipeline.md) 为准；
上游问题统一维护在 [UPSTREAM-043](UPSTREAM-043-granit-pbr.md)，多纹理所有权与格式决策见
[ADR-051](../decisions/ADR-051-pbr-material-dependencies.md)。

## 已确认约束

- Gneiss 拥有材质语义、导入 IR、运行资产与 RID；Granit 提供可复用的 GPU、标准 PBR 和渲染管线契约。
- 复用当前任务调度、资产事务、渲染线程与场景候选隔离，不增加第二套缓存或任务池。
- 新作者格式显式版本化，旧格式保持其已发布行为；缓存键纳入语义、处理器及依赖版本。
- 扩展公共描述时保留旧布局和错误语义，必要时新增版本化入口；第三方类型不进入公共 ABI。
- 格式、所有权及跨层契约在 M-280 建立 ADR 后实施。以下是设计要求，不表示接口已存在。

## 实施顺序

1. **M-279：先升级，再冻结对照基线。** 查询最新正式 Granit，记录 SHA 与差异；检查版本缓存升级、
   显式覆盖、Package 最低版本、AssetTools 与安装消费者。先运行现有 PBR、窗口 resize、回读、
   异步上传、退出和 Lantern 回归，再固定未改材质的 Sponza 图像。新增通用契约缺口立即写上游清单。
2. **M-280：贯通数据模型。** 设计 Material/Mesh 新版本与运行映射，明确每槽纹理、参数、UV、采样器、
   Alpha 模式和双面状态。列出 C API、C++ RAII、Loader、Cook、IPC 镜像和测试的影响。
   固定多纹理租约所有权、默认资源、缓存身份、候选失败和旧帧回收规则。
3. **M-281：导入及 Cook。** 扩展 glTF IR 与诊断，导入五类纹理及因子；MR 使用 G=roughness/B=metallic、
   AO 使用 R，base color/emissive 以 sRGB 解码，其他纹理按线性数据处理，因子按规范使用。
   保留有效 tangent.w，缺失切线时选择与 glTF 烘焙约定兼容的生成实现，评估依赖许可证；
   镜像 UV 必要时拆顶点，退化 UV 给出确定性诊断。PNG 保留，JPEG 等核心输入检查后补齐或显式报告。
4. **M-282：多依赖到 GPU。** 扩展依赖发现、去重、包内 URI 重写、构建裁剪、异步准备、事务预算和回执。
   同图片跨 sRGB/linear 用途采用明确变体身份，不能按源路径误合并；颜色 Mip 在线性光域过滤，
   法线 Mip 按向量语义生成并验证长度，数据纹理不作伽马转换。逐槽接入标准 Material，去掉固定切线。
   材质更新涉及任一贴图时保持整批发布，不能让旧材质引用半更新依赖。
5. **M-283：补齐材质状态。** 先做不透明五贴图闭环，再做 UV 选择、采样器、顶点色、MASK、双面、BLEND。
   核对采样寻址/过滤、Alpha 单次组合、双面法线、每 View 透明排序和深度状态；不能用改混合开关替代完整路径。
   上游阻塞时先完成 Gneiss 数据/诊断与无依赖测试；用户更新上游后继续接入并复验。
6. **M-284：真实场景与回归。** 对照固定 0.42 原始资产身份，更新转换报告，保留旧基线而不覆盖。
   明确哪些材质已恢复、哪些仍有损失；先日常配置，再完整配置。报告新增纹理数量与解码/GPU 内存估算，
   独立显存无法采集时标为未测，不能把进程 RSS 当显存。超预算明确失败，不丢贴图换取通过。
7. **M-285：收尾。** 当前行为进入 Reference/Guide，实测进入 Record，版本页只在发布后建立。
   按本版完整发布授权执行，同一候选完整平台矩阵不重复运行。

## 测试与验收

| 层级 | 必须覆盖 |
| --- | --- |
| 格式与 ABI | 新旧版本、可选默认值、无效 URI/枚举/NaN/范围、属性数量、C11/C++20 头文件及安装消费者 |
| 导入与构建 | 每槽独立图/共用图、ORM 打包、同图不同颜色空间、缺切线/镜像 UV/退化 UV、确定性缓存及失效 |
| GPU 材质 | 五贴图分别开关与组合、因子、默认纹理、切线手性、非均匀/负缩放、法线方向、粗糙度与金属度梯度 |
| 材质状态 | UV0/UV1 差异、wrap/filter、顶点色、MASK cutoff、双面正反面、BLEND 层次与不透明遮挡 |
| 生命周期 | 多贴图任一项失败、准备/上传取消、迟到回执、重试、热更新、旧帧持有、连续切换及退出无泄漏 |
| 显示与宿主 | 固定环境光/直接光/曝光，阴影与法线组合，resize/最小化恢复、Editor 反馈、打包后独立 Runtime |

图像测试使用原创小夹具：中性白/平法线、独立通道色块、金属与介质球、镜像 UV 网格、镂空卡片、
双面片及重叠透明物体。固定相机、灯光、环境、曝光和输出色彩空间；用解析预期或可信参考建立
局部像素/区域误差阈值，保留参考图、实际图和差异图，不能用当前错误输出自举为黄金图。
同设备确定性回归与跨设备容差分开，记录驱动、后端和阈值依据；差异不能只用全图平均值掩盖。

Sponza 日常/完整配置在 Debug/Release 下各至少三次线程池加载采样，协作模式验证语义并独立报告停顿。
至少覆盖完整配置连续三次切换、取消后重试、窗口操作与退出。记录 CPU 准备、上传、首个正确帧、
事件间隔 P50/P95/最大值、激活与回收、资源数及峰值内存；与 0.42 同机器/配置比较。
性能阈值在新增贴图实测前沿用 [0.42 预算与门禁](VER-042-0.42.0-async-scene-loading.md)，
M-280 如需调整应记录原因和新阈值，不能事后降低标准迁就结果。

本地按变更运行相关格式、静态检查及测试；发布要求 Windows/Linux 共享/静态、C/C++ 消费者、
Sanitizer、原有最小 Web 调度回归。最小 Web 通过不等同完整 PBR 浏览器验收；大型资产未运行必须显式标注。

## 完成定义

P0 全链路通过；P1 逐项有实现与验收证据或明确的上游阻塞和范围处理。没有无声贴图丢失、错误默认替代、
未回收候选或旧资产兼容性回退。上游需求必须有状态和 Gneiss 接入结果，不能只留一句“待上游”。
版本发布说明只列通过的能力；未解决透明/UV 等限制保持可见。

## 大场景验收边界更新（2026-09-29）

完整 4K 配置超出既定候选预算，处理方式以 [VER-043 的预算确认](VER-043-0.43.0-pbr-pipeline.md#m-284-预算边界确认2026-09-29) 为准。
日常配置继续执行三次采样、三次切换、各阶段取消、窗口与退出；完整配置验证明确失败和资源回收。
这不构成完整 4K 加载成功的验收，不能把该部分标为通过。

# 0.51：内部结果类型统一

## 目标与范围

用户确认 src 内部操作结果统一使用 engine::core::result，参考 Granit 的薄结果对象。
C API、外部回调和线协议边界保留明确转换，公共 C ABI 不变。
非目标：新增错误码语义、动态错误消息、异常传播、result<T> 或兼容隐式转换。
决策见[ADR-074](../decisions/ADR-074-native-result.md)。

## 实施顺序

1. 定义内部类型、静态文本和 ABI 转换；迁移核心日志、诊断值及其边界消费者。
2. 迁移核心 RID/反射、资源准备和资产请求的状态与返回值，删除内部过渡转换。
3. 迁移 World、Scene、Render、Runtime 的接口、异步完成值与诊断字段。
4. 迁移 Editor、宿主和工具层；保留必要的公共值/回调/IPC 边界适配。
5. 扫描普通内部实现中的 gneiss_result、GNEISS_ERROR_* 和公共 gneiss::result，
   排除 ABI 定义及适配边界后应无残留。

## 验证

按用户要求当前仅编译和必要源码检查，不运行行为测试、大场景或 CI。
编译期覆盖默认失败、值类型布局、禁止隐式转换、全部已知码对应和未知码往返。
静态文本、C/C++ consumer、回调及异步失败传播的行为验证延后统一执行。

## 当前状态

全量实现已完成：Core、Platform、Resource、World、Scene、Render、Runtime、Editor、
宿主和工具的内部操作结果统一使用 engine::core::result；异步完成值、诊断和回调同时迁移。
删除普通内部调用链的旧结果包装与整数往返。URI 校验直接调用原生接口。

边界处理：

- C API 保持既有签名和数值，在出口使用 to_c_result，在 C 回调入口使用 from_c_result。
- 游戏模块仍遵循 C ABI；宿主显式导入其结果。IPC/日志线格式继续存储整数码，编解码显式转换。
- 反射内部回调返回原生结果；C 回调在绑定处适配，并保留重复绑定的身份比较。
- 公共值布局辅助转换仍可返回公共结果，只在调用点显式适配；Granit/平台错误按原规则映射。
- 公共头未改动。测试调用点同步适配，公共 C/C++ 结果契约测试继续保留。

新增源码边界检查：普通 src 实现不得声明公共结果类型或使用 C 结果码宏；
ABI 实现与测试夹具作为显式边界豁免。内部结果头通过受限 CMake 接口共享。

验证状态：Windows Clang Debug 全目标编译通过（Engine、Editor、Runtime、工具及测试目标，
包括 C11/C++20 独立头编译目标）。源码分层检查与 git diff --check 通过；
编译期结果契约覆盖默认失败、禁止隐式转换、已知码对应和未知码往返。
按用户要求不运行行为测试、大场景、远端 CI 或跨平台/安装矩阵。
这些运行行为及共享/静态安装消费者的验证，留到架构统一验收阶段；不能以编译通过替代。

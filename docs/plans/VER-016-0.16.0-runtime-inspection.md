# VER-016：0.16.0 Runtime 调试与状态检查

## 状态

- 状态：设计中
- 目标版本：0.16.0
- 优先级：P0
- 路线图阶段：Runtime 调试与状态检查

## 背景与目标

0.15.0 已让 Editor 能可靠启动、暂停、恢复和停止独立 Runtime，并接收状态与结构化日志。下一步需要
让开发者在 Play 期间查看 Runtime 的真实场景树、组件属性和基础运行指标，而不是用作者场景或按钮
状态推断游戏进程内部情况。

版本完成后，Lantern Gallery 运行期间应在 Editor 中提供独立的 Runtime 检查视图：节点创建、删除和
属性变化能够按序同步；暂停后游戏状态保持稳定；断线或重新 Play 后不会混入旧会话数据。

## 非目标

- 不允许 Editor 修改 Runtime 属性，不实现运行态改值、撤销或保存回作者场景。
- 不实现游戏模块热重载、脚本断点、调用栈、变量求值或远程设备调试。
- 不同步 Mesh、Texture 等大块资产内容，也不暴露 Granit、libuv 或 ECS 原生类型。
- 不建立公共 Network Service，不将私有检查协议承诺为 Stable ABI。
- 不重构当前 ImGui 工作区，也不在本版本启动自研 GUI。

## 已确认决策

- 采用 [ADR-029](../decisions/ADR-029-runtime-inspection-model.md) 的 Runtime 主线程采样和 Editor 只读
  镜像模型。
- 复用 0.15.0 的会话鉴权、IPC Transport、分帧和专用 I/O 线程，不创建第二套通信链路。
- 运行态对象标识只在单次会话内有效，并携带 generation；持久化 UUID 只作为可选关联信息。
- 首次同步使用完整快照，稳定运行使用有序增量；序号缺口通过重新请求快照恢复。
- 属性沿用稳定 Type ID、Field ID 与类型安全值表示，只公开已登记且允许检查的字段。
- 控制消息优先于检查、统计和日志流量，所有队列、负载与单帧处理量保持有界。

## 实施顺序

### M-102：Runtime 会话与对象标识

定义检查能力协商、对象 ID、generation、会话归属和消息序号。覆盖零值、对象销毁后失效、旧会话
拒绝、重复消息及乱序消息。

状态：已完成。协议次版本已提升为 1，并建立 `runtime_inspection_v1` 能力名、会话内对象 ID、
generation、检查消息标记和严格顺序跟踪器。真实会话暂不宣告该能力，待快照收发闭环完成后启用。
实现与验证结果见
[M-102 Runtime 检查会话与对象标识实施记录](../records/M-102-runtime-inspection-identity.md)。

### M-103：场景快照与增量生成

在 Runtime 主线程安全点生成场景树完整快照，并将节点创建、删除、重命名、父子关系和组件集合变化
折叠为有界增量批次。I/O 线程不得访问 Scene Tree 或 ECS。

状态：已完成。Runtime 侧已建立有界快照生成器、场景实例查询适配和确定性增量差异；对象槽位复用
会递增 generation，无变化采样不消耗序号。实现与验证结果见
[M-103 Runtime 场景快照与增量生成实施记录](../records/M-103-runtime-scene-snapshot.md)。

### M-104：Editor Runtime 镜像与层级视图

建立每会话独立的只读镜像，处理完整替换、增量应用、序号缺口和会话退出。层级面板明确区分作者
场景与 Runtime 场景，停止后保留或清理行为保持确定性。

### M-105：组件与属性检查

通过既有 Type Registry、Type ID 和 Field ID 提取允许检查的属性值。Editor Inspector 只读显示常用
标量、字符串、向量、四元数、枚举和资源引用摘要，并明确不支持类型。

### M-106：基础运行统计

提供帧时间、固定更新次数、场景节点数、实体数和 IPC 队列水位的低频快照。统计用于诊断，不在本
版本建立完整 Profiler 或持久化遥测系统。

### M-107：流控、恢复与故障处理

限制快照大小、增量批次、发送频率和每帧应用预算。验证队列满、序号缺口、慢 Editor、断线重连、
Runtime 崩溃和连续 Play；控制通道在检查流量过载时仍可用。

### M-108：示例与跨平台验收

让 Lantern Gallery 产生可观察的节点或属性变化，自动验证完整快照、增量、暂停稳定、恢复继续、停止
关闭和新会话隔离。覆盖 Windows/Linux、Shared/Static 适用边界和 Sanitizer。

## 测试与验收

- 协议测试覆盖完整快照、增量、未知字段、负载上限、重复、乱序和序号缺口。
- 生命周期测试覆盖对象删除与 generation 失效、旧会话拒绝、Runtime 退出和重复 Play。
- 线程测试证明 Scene Tree、ECS 和属性注册表仅由 Runtime 主线程读取。
- 过载测试证明检查队列满时 Pause、Resume、Stop、心跳和错误消息仍可及时处理。
- Lantern Gallery 自动测试证明观察到的变化来自真实 Runtime 游戏逻辑，暂停期间保持稳定。
- 最终执行 Windows 本地矩阵和 Linux 手动 Actions，并形成 0.16.0 验收记录。

## 风险与未决问题

- 需要在 M-103 前测量代表性场景快照大小，据此确定负载、频率和每帧预算。
- 组件增删事件可由显式变更日志或快照差异生成；先用最小原型比较侵入性和确定性。
- Runtime 层级视图是复用现有层级面板还是作为独立面板，需要在 M-104 根据交互原型确定。
- 资源引用首版只显示 URI、RID 或状态摘要中的哪一部分，需要遵守 RID 非持久化和后端隔离约束。

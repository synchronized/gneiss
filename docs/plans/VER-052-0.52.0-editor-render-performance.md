# VER-052：0.52.0 大型场景视口性能

## 状态

2026-10-15，后续候选，尚未开始实现。原 0.51 性能计划迁移至此，优先实施 0.51 架构整理。
本次仅保存范围与开发顺序，不代表获得 0.52 的远端发布授权。
实施步骤见 [DEV-052](DEV-052-editor-render-performance.md)。

## 背景与目标

用户反馈 Release Editor 加载 Sponza 后，移动和旋转视角仍明显卡顿，加载期间反而较轻。
已有静止相机对照显示，减少交互帧排队后仍存在持续渲染性能问题；原始数据、设备、
排队和 GPU 统计的口径与限制统一见 [M-324](../records/M-324-editor-render-latency.md)。
它尚未包含相机输入回放，也没有证明场景规模是唯一原因。

本版目标是建立真实 Editor 的持续交互基准，解释 CPU、GPU、呈现与排队成本，
针对已证实瓶颈交付可量化的优化。不能只完成测量便称为性能优化版本完成。

## 范围与已确认决策

- 优先测量，再决定实现项；区分主循环间隔、显示帧间隔、GPU 时间和输入响应。
- 对比静止与固定相机路线、小场景与完整 Sponza；保留完整资产、相机、窗口及质量配置。
- 拆分资源准备、命令录制与提交、交换链获取、呈现等待，补齐绘制量和资源占用证据。
- 分别降低视口分辨率、关闭阴影、减少绘制对象作诊断对照；不同时改多个变量，
  不把诊断画质或缩减场景的结果冒充默认画质优化。
- 审计现有 Gneiss/Granit 剔除、阴影和资源复用能力，再选择最小修复；不先假定能力缺失。
- Editor 与 Runtime 共用渲染服务和资源机制；编辑器质量策略与作者场景数据分开。
- 涉及长期分层、资源契约或新质量策略时先补 ADR。第三方类型不进入普通公共接口。

## 候选优化，待测量选择

| 候选 | 进入实现的依据 |
| --- | --- |
| 阴影距离、分辨率、投影物体剔除 | 阴影阶段为显著成本，且对照能证明收益 |
| 视锥或遮挡剔除、批处理 | 不可见绘制或绘制提交量占主要开销，现有路径存在可验证缺口 |
| 几何 LOD / HLOD | 几何或绘制次数受限；需明确离线生成、屏幕误差、切换及资源生命周期 |
| Editor 预览质量、视口分辨率 | 像素或带宽压力显著；必须显式标注质量差异并可恢复完整质量 |
| 纹理 mip 流送、场景分级加载 | 内存/显存压力或资源驻留变化与卡顿有证据关联 |

分级加载主要管理加载工作与驻留资源；若最终仍绘制全部高精度内容，不能自动改善稳定帧率。
逐 mip 上传不等同于按视角动态驻留和淘汰。以上条目是候选，不承诺本版全部实现。

## 非目标与版本边界

不预先建设完整开放世界分区、通用流送框架、插件系统或新的调度器；不默认升级 Granit。
0.50 已接受遗留项发布，历史门槛及失败证据继续保留，详见
[0.50 归档](../versions/0.50.0.md)。本候选不自动承接全部遗留项，启动时明确范围。0.52 不承诺所有设备达到 60 FPS。
不创建已发布版本归档，不把计划写成当前功能。

## 验收与交付

测量、门槛冻结与回归方法以 DEV-052 为准。实施前必须在固定设备和场景上冻结本版
优化目标、质量约束及允许的回归范围；没有足够基线时不编造 FPS 承诺。
最终须交付可复现基准、已解释的主要瓶颈、针对性实现、视觉与生命周期回归，以及
相同质量下的前后对照。若交付可选低质量模式，另列其效果与画质代价。

## 上游协作与风险

需要 Granit 通用能力时，先在开发计划登记问题证据、最小接口、线程与生命周期行为、
测试要求和 Gneiss 接入路径，再形成具体上游需求文档交给用户提交。未另行授权不操作上游。
场景格式、RID、编辑器协议与项目专用 Shader 留在 Gneiss。

当前未知项包括移动视角的额外成本、GPU 时间与显示间隔的差额、显存压力、
现有剔除覆盖以及插桩开销。集成显卡的系统内存与显存口径需分别说明，不能只凭
进程工作集或适配器枚举值判断 GPU 内存瓶颈。

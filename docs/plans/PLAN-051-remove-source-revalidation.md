# 0.51：移除普通加载的来源版本跟踪与复验

## 目标与已确认决策

删除来源版本文件系统及验证专用读取协议，降低普通加载的一致性要求。
决策见 [ADR-075](../decisions/ADR-075-remove-source-revalidation.md)。
不删除格式校验、缓存内容摘要、范围读取、异步 I/O、取消或 GPU 资源安全回收。

## 实施顺序

1. VFS 合并同步打开，异步入口改为 begin_open_read，删除 read_source 的验证回执。
2. 资产准备直接使用 VFS，缓存摘要取自本次读取，完成解析后直接输出。
3. 场景删除复验任务和 verifying 阶段；独立 Scene/Prefab、Action Map 同步加载不再复读。
4. 删除来源账本实现、专用测试和构建清单，更新剩余测试、IPC、进度显示及诊断字段。
5. 更新当前接口文档，编译后做本地提交。

## 验收

- src/tests/构建清单不存在旧来源包装、验证专用打开或验证回执。
- 资产的首次读取摘要仍能命中 CPU 内容缓存；读取后的修改不触发二次读取。
- Scene/Prefab 同一路径不为结束校验再次读取；Action Map 每次同步加载只读取一次。
- 格式损坏、短读、缺失、大小上限和取消仍保留失败处理。
- Windows Clang Debug 全目标编译、格式和分层检查；按用户要求不执行测试、大场景或 CI。

## 当前状态

实现与既有测试契约调整完成。Windows Clang Debug 全目标编译通过，
格式、源码边界、脚本语法及 git diff --check 通过。没有执行测试、大场景或 CI。
行为与跨平台验证留待架构统一验收。

来源包装专用的身份转交接口也已删除，资源身份直接来自 VFS 挂载。
普通加载不再保证跨文件版本一致；格式与纹理负载内容校验继续保留。

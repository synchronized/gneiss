# DEV-044：纹理驻留与大场景加载开发计划

## 状态与依赖

2026-09-30 已开始 M-286，[容量与所有权初审](../records/M-286-texture-memory-audit.md) 已记录；
运行峰值与预算冻结尚未完成。范围以 [VER-044](VER-044-0.44.0-texture-residency.md) 为准，
所有权和分层以 [ADR-052](../decisions/ADR-052-texture-residency-and-budgets.md) 为准。
下列内容是实施要求，不代表接口已经存在。

## M-286：测量与契约审计

1. 固定资产哈希、Cook 参数、设备、构建类型和视角，分开测量原始 PNG、Cook BC7 与 RGBA8 回退。
   每条可完成路径至少三次采样；预算失败同样记录阶段、峰值和清理结果，不混合统计成功与失败样本。
2. 审计 `render_asset_loader.cpp`、`render_resource_service.h`、`texture_binary.*`、
   `granit_render_service.cpp`、`texture_load_service.*` 与 `scene_load_service.*`。
   为文件缓冲、解码结果、变体负载、帧快照、GPU 上传暂存列出所有者、复制点与释放时机。
3. 同步采集进程 RSS、服务实际分配字节、预算预留、峰值重叠和阶段耗时；GPU 逻辑资源估算与
   驱动实际驻留分别标注，无法获得实际值时明确未测量。共享负载使用稳定身份去重。
4. 审计 VFS 的区间读取、包内文件、完整性验证及取消能力；审计 Granit 变体选择线程要求与上传完成语义。
   不假定已有区间 API 或 GPU 完成回执；确认缺口后再决定最小扩展或提出上游需求。
5. 在实现前补充本计划的预算表与画质阈值：活动资源、候选、暂存、进程峰值目标、法线与颜色误差、
   Alpha 边界判定。保存基线到实际测量 Record，不能以估计值代替结果。

## M-287：变体选择与读取

已完成首个基础闭环：VFS `open_read`、独立所有权的 `read_source` 与原生文件区间读取；
调用者提供缓冲，来源支持并发调用和打开时长度边界。验证及未接入范围见
[M-287 读取来源记录](../records/M-287-read-source-foundation.md)。
纹理头/Manifest 读取器与 Payload 相对区间读取也已实现，验收见同一记录的容器读取器章节。
版本追踪已支持打开读取来源及 64 KiB 分块复验；异步纹理准备已接入设备能力快照、
工作线程变体选择及独立负载读取，验收与限制见
[M-287 单变体准备记录](../records/M-287-selected-variant-preparation.md)。
当前发布包是目录包，复用原生 VFS；ZIP 为分发封装，不新增运行时 ZIP 后端。
未绑定能力快照的同步加载仍走整文件兼容路径；源版本校验仍分块读取全文件。

- 后端在合法线程产生不含第三方类型的不可变能力/选择描述，工作线程只处理 Gneiss 数据。
  绑定设备代次，设备重建或能力变化使旧选择失效；避免工作线程调用 renderer。
- 先读取并验证封装头与 Manifest，再定位所选负载；校验溢出、重叠、截断、层数、Mip、颜色空间及格式。
  若完整性规则要求校验全文件，采用有界分块校验，不保留所有变体，也不绕过哈希检查。
- 保留旧封装和 PNG 行为，RGBA8 回退可用；缓存身份包含内容版本、纹理语义、选择配置和格式/Mip。
  不能仅按路径复用来自其他设备配置的准备结果。
- CPU 单元测试注入 BC7/非 BC7 能力，覆盖选择失败、损坏数据、短读、取消与旧设备代次。
  真实 GPU 只上传该设备支持的格式；模拟能力测试不冒充真实设备验证。

## M-288：驻留与重建

锁定 Granit 的独立变体上传接口缺口及替代方案见
[U44-01](UPSTREAM-044-granit-texture-residency.md)。CPU 候选按原 Manifest、变体索引与局部负载设计；
不能为了适应旧接口重新分配未选中变体的前缀。Granit 0.44 新入口已接入渲染后端，
异步 CPU 准备已只保留所选变体；上传后 CPU 负载释放与可重建来源尚未实现。

- 文件支持的纹理保存可验证的重建描述；原文件被替换、卸载或修改时，禁止悄悄用新内容重建旧资源。
  在稳定缓存、固定文件租约或保留 CPU 负载之间依据现有 VFS 契约选择，并记录成本。
- 上传完成回执之前保留必要负载；帧快照与上传任务通过租约维持有效期，不能清空共享对象中的数据。
- 审计回读、重新上传、后端重建和失败重试所需数据。无法可靠重建的内存创建纹理保留原有 CPU 所有权，
  不强制要求公共调用者提供文件路径。
- 测试旧帧持有资源、上传中销毁、关闭、重建失败、迟到回执、重复取消以及失败后重试。
  能否释放以真实所有权结束为准，不以减少统计值代替释放。

## M-289：预算与事务

- 在现有 Application/Service 装配边界协调预算，读取和分配前先预留；申请失败不启动无界工作。
  候选发布时转移归属，不重复累计共享纹理；上传暂存直到后端确认完成才退还。
- 活动场景占用不能被候选挤掉；预算不足时提供阶段、所需字节和可用预算，保留当前场景。
  上传分批复用现有调度，不忙等，不在主线程等待工作线程完成。
- 覆盖 Editor 与 Runtime 的加载、切换、取消和重试；公共接口若需扩展，同步评估 C/C++ 包装、
  文档、安装消费者及 ABI，不建立第二套运行时状态。
- 注入读取、准备、上传及发布前失败，确认候选隔离、全部回收、旧场景继续可用；测试共享纹理和
  缓存命中时预算不会漏计、双计或下溢。

## M-290：端到端验收

- 完整 4K Cook Sponza 保持全部几何、材质和贴图，记录选中格式、Mip、CPU/GPU 字节及阶段耗时。
  Debug/Release 分别采样，使用与基线相同的设备、配置和视角。
- 完成三次切换、读取阶段取消、上传阶段取消、就绪后取消、重试、退出，以及加载期间连续 resize、
  最小化恢复；线程池与协作模式分别报告响应性，不掩盖不可抢占任务造成的超时。
- 日常场景及原创小夹具回归颜色、数据、法线、镂空和透明材质；保存 PNG/BC7/RGBA8 对照图与误差指标。
  大模型保持外部资产，不提交到仓库或 Release。
- 对照版本计划门槛逐项给出通过、失败或未验证。真实全分辨率激活未通过时继续排查，不降低输入规模后宣称完成。

## M-291：平台与交付

按[构建指南](../guides/building.md)运行相关测试，再运行候选所需平台矩阵。
覆盖共享/静态库、安装 C/C++ consumer、公共头独立编译、格式检查及真实 GPU 校验；
区间读取覆盖原生目录与目录发布包，范围依据[发布包格式](../reference/package-format.md)。
只有影响结果的改动才重跑受影响的远端工作流。

实现完成后更新当前行为的 Guide/Reference，真实结果写 Record，发布后再新增版本归档。
未实测的独立显存、物理跨屏 DPI 或完整 Web 行为必须保留限制说明。

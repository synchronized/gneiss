# VER-048：0.48.0 C++ SDK 可读性与调用一致性

## 状态

2026-10-07，实现与本地/远端完整验收完成，待合并发布。基线为 0.47.0，SDK-001 样板纳入本版。
沿用样板分支与 PR #63，不拆分阶段 PR。
实施进度见 [DEV-048](DEV-048-cpp-sdk-readability.md)。

## 目标与范围

让公共头能直接展示日常使用方式，将转换、回调桥接和资源关闭实现集中维护。
不以减少行数、增加文件或消除所有模板作为验收标准。

| 范围 | 交付 |
| --- | --- |
| Application、World | 纳入已验证样板，补齐实体/节点前提与创建、运行、关闭示例 |
| Input、日志 | 值类型和事件读取入口与 ABI 转换分离，普通使用走 Application / Game Context |
| Scene、Render | 公共资源操作和转换/临时数组分离，明确拥有者与借用身份 |
| Reflection | 查询、注册、属性访问和回调适配职责分开，保留名称及字段的真实寿命 |
| Game Module | 日常上下文操作与 C 导出桥接分开，模板机制不进入普通业务示例 |
| Core 与聚合头 | 审查结果、ID、版本及总入口；小型值操作不机械拆分 |
| 消费者与文档 | 最小应用、属性检查、资源/输入/模块示例，独立头和干净安装验证 |

## 已确认决策

- 0.48 继续使用 result 与输出参数，常用调用采用局部 status 检查并传播错误。
  不在本次结构重构中加入 expected、异常工厂或新一套结果接口。
- 保持已有失败输出契约；例如活动相机查询失败会清空输出，不能为了形式统一偷偷改变行为。
- 借用视图的 const 仅表示句柄不变，不保证后端只读；World 与 Scene 的修改操作与既有变换操作对齐。
  显式成员函数指针需适配 const 类型，普通调用与 C ABI 不变。
- 拥有者不可复制、可移动，借用 ID/视图不延长寿命；关闭失败的处理不得被抽象隐藏。
- `.hpp` 维护公共表面，复杂 inline 定义放在对应 `detail/*.inl`。实现随 SDK 安装，
  不新增 C++ 二进制包装库，不承诺改善编译时间。
- 不为每个函数拆文件，不引入通用 owner 框架。小型 constexpr 值操作可以保留原处。
- 互操作保留明确命名与专门说明；ABI 转换不得用布局强转替代，不删除必要的回调存储。

## 非目标

不升级 Granit，不修改 C ABI 或引擎内部层次，不开发插件或整理 Editor API。
不改变根 apps 布局，不处理纹理驻留、性能预算或异步服务的新能力。
不承诺 C++ 二进制兼容；使用者需重新编译。

## 发布验收

1. 各模块审查普通入口、互操作、转换、所有权和线程约束，并在现有映射清单保持实现位置准确。
2. 示例真实运行，无 C 业务宏；Game Module 的实际导出仍使用 C ABI。
3. 错误输出、移动、关闭失败、父资源失效、回调寿命及线程边界回归通过。
4. 公共 C11/C++20 头独立编译；双编译单元检查 inline 链接；共享/静态及干净安装 C/C++ 消费者通过。
5. C ABI 布局与导出无意外变化；最终 Windows/Linux 必需手动矩阵通过，不跳过既有失败。
6. 更新当前参考、开发计划与发布说明；仅实际发布后创建版本归档。

## 风险

分离文件本身不会简化调用语法，也不会减少转换开销。本版通过示例可读性与模块职责审查判断结果。
已有 Linux IPC SIGPIPE 与资源压力风险不因 SDK 重构自动视为修复。

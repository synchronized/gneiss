# DEV-046：公共头目录整理开发计划

## 状态与依据

2026-10-06，目录整理及完整本地/远端验收已完成，[0.46.0 已发布](../versions/0.46.0.md)。
范围以 [VER-046](VER-046-0.46.0-public-header-layout.md) 为准；
已执行结果统一维护在[目录整理验收记录](../records/engine-public-header-layout.md)。
后续继续使用 `refactor/engine-public-headers` 分支，设计、实现、验收和修复合为一个任务、一个 PR。

## M-298：目录与安装归属

已完成项在发布前复核，不重新搬迁或复制接口实现：

1. 核对公共功能头及 `core` 类型都在 `include/gneiss/engine/`；根总入口仍只组织 Engine 能力。
2. 原路径保留最小转发头，不复用目标头的 include guard，避免先包含兼容头时遮蔽实际声明。
3. 生成版本头模板、构建输出与安装文件集使用新路径；旧版本头路径转发到新路径。
4. 检查新旧混合包含、只使用根入口及新路径直接包含，保证声明和包装只有一份。
5. 核对安装自有公共头集合，无模板、内部头或意外目录泄漏；以源文件集与生成头推导预期集合。

## M-299：检查与验证

当前清单与历史证据已经分离，继续核对以下闭环：

- `abi/cpp-api-inventory.json`、`abi/cpp-type-inventory.json` 指向规范头路径，覆盖范围不因迁移缩减。
- 边界检查同时识别新旧路径，内部模块不能利用新路径绕过公共包装依赖约束。
- 测试夹具每次重建，清理前验证目标位于构建目录内；验证旧构建目录重复运行不残留迁移前文件。
- 示例优先使用规范路径，兼容测试继续使用旧路径；不对无关源码进行机械批量修改。

构建命令以[构建指南](../guides/building.md)为准。已有专项结果不重复计作整版验证。

| 验证 | 实施要求 | 状态 |
| --- | --- | --- |
| 公共头编译 | 新路径独立 C11/C++20 编译，旧路径测试保留 | 两种链接配置专项通过 |
| 独立安装消费 | 共享/静态 C、C++、属性检查器，新旧路径混用 | 各 3/3 通过 |
| 清单及边界 | 正例、故意违规反例、夹具重复执行 | 专项通过 |
| ABI 与版本 | 对照导出、既有 ABI 消费者、版本与结果接口 | 专项通过 |
| 最终整版 | 调整版本号后完整共享/静态构建与 CTest | 已通过，详情见验收记录 |

不把共享库完整构建等同于完整 CTest，也不把静态 Engine/头目标编译等同于静态全量构建。
本版不进行新的大型资产性能优化或对照测量；常规运行时、Editor 与图形测试按既有矩阵执行。

### 远端验收

公共 SDK 路径影响所有消费者，最终候选使用既有 Windows/Linux 手动工作流的 `scope=all`，
不能只用 `editor` 范围代替。核对 MSVC、GCC/Clang、共享/静态安装消费者及既有宿主检查。
每个候选完整矩阵原则上一次；失败修复保留在同一分支和 PR，只重跑受影响任务。
文档补录不改变候选代码时，不重复触发 Actions。

## M-300：版本与交付

1. 在准备最终候选时将工程版本号调整为 0.46.0，重新生成版本头，并验证新旧包含路径报告一致版本。
2. 更新当前 Reference/Concept 和 CHANGELOG；保持旧版本归档事实不变，结果追加到现有验收记录。
3. 达到可评审状态后，以单一 PR 交付本版本；推送、Actions、合并和发布按仓库的当前版本授权规则执行。
4. 所需检查通过后合并，确认合并内容与验收候选一致，再创建 `v0.46.0` 标签与源码 Release。
5. 实际发布后补版本归档、版本索引和路线图状态；不提前创建已发布页面，不回写旧标签。

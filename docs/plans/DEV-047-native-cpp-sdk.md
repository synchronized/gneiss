# DEV-047：原生 C++ SDK 与公共头收口开发计划

## 状态与依据

2026-10-06 实施中。M-301 已建立独立迁移状态与严格门禁，全量语义审计仍在进行；
M-303 的 Input 子项已落地；M-304 已接入原生日志提交描述。其余任务尚未完成。
先行选择不涉及持久回调的 Input 小闭环，避免在 Application 回调寿命定稿前扩大改动。
本组实现与验证见 [M-301 / M-303 记录](../records/M-301-303-native-input-sdk.md)。
日志生产者迁移见 [M-304 记录](../records/M-304-native-log-message.md)，接收回调已随 Application 接入。
范围、兼容决策与发布条件以 [VER-047](VER-047-0.47.0-native-cpp-sdk.md) 为准。
设计依据为 [ADR-055](../decisions/ADR-055-native-cpp-sdk.md)。
整版使用一个特性分支及一个最终 PR，按下列顺序形成可独立验证的本地提交。

### M-301：建立语义清单

扩展现有 `abi/cpp-api-inventory.json`、`abi/cpp-type-inventory.json` 及其检查器，不建立重复清单。
每个 C 函数、描述、值类型、枚举、标志、常量、初始化宏与回调记录原生映射或明确的 ABI 边界例外。
区分拥有者、借用 ID、同步输入、长期保存配置、回调期视图和查询输出。
复核公共签名，而不是只扫描函数名；将当前别名和直接 C 参数标为待迁移。

扫描 include、src、apps、tests、examples、CMake、脚本、工程模板与活动文档的旧路径。
冻结 ABI 测试快照和历史文档单列，避免为通过检查改写历史基线。

### M-302～M-304：按闭环实施包装

先实现最小应用与变换，再覆盖全部既有接口。每组同时修改头、清单、测试、示例和对应参考。
转换在包装内部显式进行，不让 C++ 标准库对象进入 C ABI，不依赖 C/C++ 结构恰好同布局。
可借用的字节负载直接传递；需要元素转换的数组由调用期存储承载，记录分配成本及长度校验。
长期借用的数据不能放入栈上转换器；返回值不得持有已销毁转换数组的 span/string_view。

回调优先使用有明确上下文寿命的原生函数签名与 trampoline；需要稳定适配存储时由对应拥有者管理，
不引入全局闭包注册表。验证移动前后回调、关闭失败后上下文保留、关闭后的停止投递及异常隔离。
没有注销接口的访问器保持宿主规定寿命，不伪造“销毁即注销”的 RAII 承诺。
Game Module 真实动态库导出继续遵循 C ABI，使用场景和例外在参考中单独说明。

### M-305：移除兼容路径

删除 0.46 的根功能转发头及 `gneiss/core/` 转发目录，保留根总入口与 `gneiss/engine/`。
同步修改头清单、生成测试、路径扫描、安装消费项目和迁移指南。
使用全新安装前缀验证发布内容；旧路径负向测试须确认失败原因确为找不到头，而非其他编译错误。
存量安装迁移说明采用干净前缀，不能因为残留旧 SDK 文件而误判旧路径仍受支持。

### M-306：验收与收尾

以清单和实际消费闭环两种证据交叉复核，拒绝用 C 类型别名或未使用的包装填满覆盖率。
检查 C 导出、结构布局、结果码和现有资源生命周期没有意外变化。
记录本地共享/静态库、C/C++ 消费者、公共头独立编译及相关运行回归结果。
完整候选就绪后统一提交 PR；发布前按仓库规则手动验证 Windows/Linux，修复失败复用同一分支。
发布复核须执行 `cmake -DGNEISS_SOURCE_DIR=. -DGNEISS_REQUIRE_NATIVE_CPP_SDK=ON -P cmake/check_cpp_inventory.cmake`，不允许带 pending 项发布。
纯记录更新不重复触发同一候选矩阵。发布闭环需在用户授权推进本版时执行。

## 测试重点

- 默认描述语义与原 C 初始化值一致，Transform 单位旋转和单位缩放正确。
- 枚举、flags、可选数据及空数组双向转换正确；非法输入保留错误语义。
- 拥有者不可复制、可移动；借用不接管销毁，重复关闭、父资源失效和线程限制有回归。
- Reflection 注册与查询字符串、嵌套字段、属性值不悬空；失败不留下半注册包装状态。
- C++ 回调接收原生类型，异常不越过 ABI；用户数据与临时事件寿命明确。
- 普通 SDK 示例不使用 C 业务宏/描述；检查器允许内部转换和显式 ABI 导出，避免误禁所有预处理器。
- 安装目标不泄漏第三方包含目录，C11 消费者仍可只使用规范 C 头。

## 风险处理

回调与查询所有权是首要设计风险，应在 M-301 定稿对应契约后实施，不推迟到发布阶段补丁修复。
发现 C ABI 真实能力缺口时先记录并调整计划，不默认增加与现有状态重叠的 C++ 运行时。
本版不依赖 Granit 新能力；若发现通用后端缺口，遵循跨仓库协作规则提出需求，不直接修改上游。

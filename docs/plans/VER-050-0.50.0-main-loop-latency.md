# VER-050：0.50.0 后台加载主线程延迟

## 状态

2026-10-13，重复基线与有限等待优化已完成，诊断和发布验收进行中，尚未发布。
后续独立大资产响应仍有超标；部分样本已取得系统定时器唤醒与调度竞争证据，不能解释全部历史失败。
本版新增资产 I/O 优先统一到 libuv 的迁移范围，尚未实施；最新实测以
[M-321](../records/M-321-0.50.0-release-validation.md) 为准。
基线版本为 0.49.0。实施进度见 [DEV-050](DEV-050-main-loop-latency.md)。

## 背景与目标

0.49 完整场景 thread 首载最大主循环间隔 129.31 ms，样本 P95 最大值 17.36 ms。
这些是历史观测，不能直接证明主线程在等待后台任务；阶段标记不足以定位调用。
本版优先解释并改善 thread 模式的长停顿，cooperative 保留回归。
证据来源见 [0.49 验收](../records/M-313-316-loading-stability-validation.md)。

## 范围与已确认决策

- 分离宿主主动等待、更新回调、任务推进、结果接收、事件处理、渲染提交及回收。
- 用单调时钟串联同一轮的阶段耗时；嵌套耗时不重复相加。主循环与呈现帧率分开报告。
- 先使用测试宿主及内部观测；默认关闭详细采样，批量写出，检查插桩开销。
- 定位长帧时结合调用栈与线程运行/等待信息；单靠墙钟计时不推断锁竞争或 CPU 热点。
- 先复测并冻结量化目标，再修改生产路径。优先解决已证实热点，不预设增加线程或重构调度器。
- 保留完整资产、2 GiB 候选预算、来源校验、取消与清理分离及旧场景所有权。

## 资产 I/O 统一范围（待实施）

- 保留内部区间读取与请求所有权抽象，桌面资产文件 I/O 优先复用已有 libuv 平台设施。
- 覆盖打开、长度查询、区间读取、关闭，以及适用的路径/元数据操作；审计同步入口，
  不将同步路径检查遗漏在异步提交之前。不削弱根目录隔离与来源一致性校验。
- 用完成通知接回现有任务调度，保持轮询不执行 I/O；支持预算分块、进度、取消及关闭回收。
  1 MiB 仅为讨论示例，不固定为契约；限制并发请求数和在途缓冲总量。
- Windows/Linux 验证后移除被替代的 Windows 专用读取实现。只有明确的能力缺口与实测依据
  才引入原生优化；本版不新增 IOCP 专用后端。边界见
  [ADR-061](../decisions/ADR-061-libuv-asset-io.md)。
- 无线程构建不因迁移隐式启用 libuv 工作线程；能力受限的显式回退不宣称异步或有耗时上界。

## 非目标

不升级 Granit，不开发插件，不改变公共 SDK，不承诺所有设备最大间隔低于 16.7 ms。
不以缩减资产、放宽期限、降低校验等级或增加内存预算获得通过。
不将主动睡眠、系统调度噪声自动解释为产品阻塞；不以删除测试等待直接声称引擎优化。

## 验收

1. 固定设备、输入摘要、Release 配置、缓存策略；日常与完整场景 thread 各至少三次基线和对照。
2. 记录样本数、P50/P95/P99、最大间隔、超过 16.7/33.3/50/100 ms 的次数与比例。
   16.7 等阈值先用作分布观察，不是已冻结的跨设备实时承诺。
3. 每次长停顿能关联到同轮阶段；未解释时间、主动等待和采样开销明确列出。
4. M-319 在优化前冻结响应性、吞吐、内存门槛；未达标保留失败，不事后修改门槛。
5. 修复覆盖确定性回归与线程/生命周期边界；复测取消、重试、三次切换、resize、恢复和关闭。
6. libuv 迁移覆盖短读/EOF、越界、失败、取消后迟到完成、来源提前销毁、关闭在途请求、
   队列背压与缓冲预算；Windows/Linux 验证一致语义，无线程构建保持原线程边界。
7. 按影响运行共享/静态、消费者、真实 GPU 校验及 Windows/Linux 矩阵。
   发布授权到位且门禁通过后完成单一 PR、标签、源码 Release 与版本归档。

## 风险与未决问题

129 ms 峰值的具体归因未知；复现不足时必须保留不确定性，扩大样本而非猜测。
Windows 睡眠唤醒粒度、后台资源竞争和 GPU 队列均需证据。上游通用缺口形成需求文档交由用户处理。

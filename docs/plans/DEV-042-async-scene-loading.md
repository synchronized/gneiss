# DEV-042：真实大场景异步加载开发计划

实施中，先执行资产审计与同步基线。范围、里程碑和验收以 [VER-042](VER-042-0.42.0-async-scene-loading.md) 为准；
长期决策见 [ADR-050](../decisions/ADR-050-staged-scene-activation.md)。

## 实施顺序

1. **M-272：先审计和测量。** 获取固定 Intel Sponza，记录许可和校验值；分析 glTF 必需扩展、图片、
   材质、节点和资源规模。通过 `gneiss_assetc` 的现有导入路径建立转换报告，生成日常/完整测试配置。
   先测同步加载，再确定内存、上传、主线程推进及激活门槛，明确可运行完整版的硬件。
2. **隔离原型。** 用小型原创 Scene 与共享 Prefab 验证候选不会进入现有 World 查询、渲染和检查接口。
   比较独立候选 World 与现有 World 内隔离暂存的实现成本，补齐 ADR 的表示选择；不能只隐藏渲染对象。
   原型必须证明失败回收和最终激活的成本边界，然后才接入真实场景。
3. **M-273：纯准备。** 复用 Scene/Prefab 描述解析与校验，生成带来源身份的不可变描述及依赖清单。
   工作者只持有只读文件系统和自有数据；增加取消检查和节点数、依赖数、递归深度、字节数限额。
   不在工作线程调用 World、Scene Tree、RID 或后端服务。
4. **M-274：候选会话。** 扩展已有资产准备/上传实现，支持场景会话内的有界子批次和背压。
   子批次完成只表示候选可用，不能逐批覆盖公共缓存中的旧 RID 数据；明确资源版本租约与会话总预算。
   GPU 确认和场景最终激活分开，失败或取消按会话回收，避免新建第二套任务状态。
5. **M-275：实例化与激活。** 主线程按工作量和耗时预算推进，先分配可失败的数据，再在安全点激活。
   明确旧场景输入、游戏更新、相机、选中对象、检查镜像和资源回收顺序；最终步骤也必须计时。
   激活失败保留旧场景；提交后的模块回调错误单独报告，不假装可以回滚任意游戏副作用。
6. **M-276：Runtime/Editor 接入。** 初始加载期间维持窗口与 IPC；未就绪时不运行依赖启动场景的游戏更新。
   内部同工程切换入口关联请求、会话与目标场景，扩展既有控制/资产协议并协商能力，保持旧端明确拒绝。
   提供阶段与阶段内完成量、取消、重试；不要以未知总工作量显示虚假的总体百分比。
   完整切换与结构热重载互斥或显式排队，不能同时修改同一活动场景。
7. **M-277～M-278：验收与发布。** 先故障注入及资源生命周期，再跑 Sponza 多次窗口回归和性能采样。
   补齐实际跨进程取消验证，保留原有结构热重载和同步公共接口回归；更新 Guide/Record 后执行版本矩阵。
   用户已授权本版完整发布闭环；实施沿用同一分支与一个 PR。

## 主要落点

| 模块 | 计划工作 |
| --- | --- |
| `src/scene/scene_description.*`、`prefab_description.*` | 复用纯解析与校验，生成候选描述及依赖信息 |
| `src/scene/scene_instance_service.*`、`prefab_runtime_instance.*` | 分阶段候选、激活和回收，保留现有结构更新身份规则 |
| `src/asset/texture_load_service.*`、`src/render/render_asset_loader.*` | 复用混合资产事务，扩展场景会话内候选所有权和背压 |
| `src/render/granit/granit_render_service.*` | 复用 GPU 候选、回执及回读；不移入场景业务语义 |
| `src/application/`、`apps/runtime/` | 内部加载/切换请求，窗口推进、模块启动和退出顺序 |
| `apps/editor/`、`apps/common/ipc/` | 可见阶段、请求身份、取消/重试及切换后的镜像失效 |
| `tests/`、`tools/performance/` | 原创小夹具、场景资产获取/转换、交互回放和分阶段测量 |

上述是计划落点，不表示已经存在对应异步入口；新增内部类名和文件名在最小原型后确定。

## 工程约束

- 不复制一套调度器、缓存或公共运行时状态；Scene 加载协调业务阶段，宿主调度器只安排任务执行。
- 资源复用必须绑定不可变版本；同 URI 在加载期间变化不得混成一个成功场景，快照检测边界需记录。
- 区分在途源/解码/上传预算、候选累计驻留预算和旧场景驻留；分批不能掩盖累计资源超过容量。
- 旧帧可以继续引用旧资源；取消后的候选不能被下一请求接管，除非通过明确的共享版本所有权规则。
- 每阶段完成成功/失败/关闭边界的测试后本地提交；纯文档不跑完整构建，不将待执行检查写成通过。
- 若发现缺少通用 Granit 能力，按仓库跨仓库规则提供最小提案，由用户处理上游；不能直接修改上游。

## 待基线确认的实施参数

M-272 输出资产版本、原版和转换后的节点/资源数量、日常配置纹理尺寸、峰值预算和超额策略，
以及线程池事件响应、主线程推进、最终激活的验收阈值。每个参数都关联测量依据。
M-275 前固定候选隔离表示与模块生命周期时序；若无法满足整体可见性或提交成本边界，应修订设计，
不能通过关掉游戏查询、跳过图像验证或只测小场景来宣布完成。

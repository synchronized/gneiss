# VER-043：0.43.0 Granit 升级与 PBR 材质管线补齐

## 状态

2026-09-30 已按确认范围完成并发布 [0.43.0](../versions/0.43.0.md)。
实现、验收与上游协作历史保留在本计划及关联记录；发布结果以版本归档为入口。
完整测试证据见 [M-284～M-285](../records/M-284-285-0.43.0-validation.md)。

## 背景与目标

规划起点（0.42）：Granit 标准 PBR、环境光及 HDR 输出链路已经接入；Gneiss Material v3 只表达基础颜色、
基础颜色纹理、金属度与粗糙度。其他 PBR 纹理使用默认资源，GPU 切线为固定值。
当前格式见[渲染资产参考](../reference/render-asset-formats.md)，真实资产损失见
[Sponza 基线](../records/M-272-sponza-baseline.md)。

本版从导入、作者格式、离线构建、依赖加载到 GPU 呈现补齐标准 metallic-roughness 材质闭环，
让真实场景能正确使用法线、金属度/粗糙度、遮蔽和自发光贴图，并尽量完成镂空、双面与透明路径。
“补齐”以逐项验收为准，不宣称覆盖所有 PBR 技术或 glTF 扩展。

## Granit 升级目标

截至 2026-09-30，当前锁定 [Granit v0.43.0](https://github.com/synchronized/granit/releases/tag/v0.43.0)，
SHA 为 `555b1144b02be409c74b7cc971eff2e0ecf74e25`。初次 0.39 升级历史见
[M-279](../records/M-279-granit-0.39-upgrade.md)，上游补齐后接入与实测见
[M-283](../records/M-283-granit-0.42-material-states.md)。不跟随浮动 main。

审计 Fetch/Package、AssetTools、安装资产、Shader/Material Schema、Window、GPU 上传和回读契约。
Granit 0.39 的示例任务与资产管理器不等于 Gneiss 需要迁移调度器；保持现有 Service、RID 与宿主调度边界。
SDL3 后端切换不作为本版前置任务。

## 非目标

材质节点编辑器、任意 Shader 编辑、路径追踪、全局光照系统、OIT、折射/体积透射、clearcoat、
sheen、anisotropy、全部 glTF 扩展、动画蒙皮、完整引擎 Web 移植与新任务调度器。
不直接修改 Granit；Gneiss 的资产格式、场景语义、RID 和编辑器协议不下沉。

## 风险与未决问题

- 新增贴图可能使 0.42 的候选驻留预算不足；先测算再决定压缩/日常配置或明确超额拒绝，不能无依据放宽限额。
- 同图不同语义需要不同颜色空间或 Mip；现有“同图片不能声明不同颜色空间”规则需要设计后迁移。
- 透明 PBR 已接入上游标准阶段；对象级排序不能解决相交三角形。
- 标准资产的 UV、采样器与 Alpha 契约是否足够，须以公开接口和最小 GPU 实验确认。
- Sponza 只作真实负载之一；固定光照和曝光，以可解释的小夹具避免“截图看起来不错”掩盖通道错误。

## M-284 预算边界确认（2026-09-29）

完整 4K 配置成功重导入，但 72 张 RGBA8 基础贴图已需 4.5 GiB，超过既定 2 GiB 候选预算。
本版按上述风险条款采用明确超额拒绝，不扩大内存预算或静默丢图。完整配置验证拒绝及回收；
连续切换、窗口交互和取消/重试采用保留全部几何/材质的日常分辨率配置。
完整 4K 激活、切换和画面验收不计通过，在发布限制中保留，后续需要独立压缩驻留/流送设计。

# VER-049：0.49.0 大场景加载响应性与生命周期稳定性

## 状态

2026-10-07，范围已确认，开发计划已建立，实现与新基线测量待开始。基线为已发布 0.48.0。
本计划不代表能力已经实现，不修改当前构建版本号或创建发布归档。
实施顺序与任务状态见 [DEV-049](DEV-049-loading-stability.md)。

## 背景与目标

SDK 结构整理已完成，本版回到 Editor/Runtime 的真实场景加载路径。
[0.44 发布记录](../versions/0.44.0.md) 保留了 cooperative 长任务不可抢占、取消终态预算
缺少直接证明及实际显存未测量等限制；[0.48 发布记录](../versions/0.48.0.md) 仍保留
历史 IPC SIGPIPE 与灯廊启动时序风险。旧测量不能直接作为重构后的性能结论。

交付目标：加载期间可交互，取消后的资源归属和回收可核对，重复切换、故障重试与关闭稳定。

| 范围 | 预期交付 |
| --- | --- |
| 当前基线 | 固定输入与环境的完整 Cook 4K Sponza、日常场景和小夹具测量，分开 thread/cooperative |
| 加载响应性 | 定位并分阶段执行主要长任务，明确不能切分的调用及取消观察点 |
| 生命周期与预算 | 区分取消请求、终态、清理完成；验证候选、在途上传、旧帧及共享资源的实际归属 |
| IPC 与启动 | 断连/退出竞态复现、SIGPIPE 排查和灯廊启动阶段诊断，形成确定性回归 |
| 交付验收 | 同条件前后对比、Editor/Runtime 端到端与跨平台发布矩阵 |

## 已确认决策

- 先测量、后确定量化门槛、再优化。M-312 必须在性能实现前记录并冻结响应性、加载耗时及内存
  对比门槛；不能测完优化结果后倒推门槛。平台差异、重复次数和噪声处理同时记录。
- 保持完整资产与既有 2 GiB CPU 候选上限，继续复用单变体准备、负载租约和现有共享预算。
  不通过缩小场景、提高预算、去掉完整性检查或放宽既有测试期限获得通过。
- 复用现有任务调度器和 Service 生命周期。cooperative 的工作发生在调用线程，不能把
  时间预算当作对任意函数的抢占能力；优先在读取、哈希、准备和实例化的自然边界让出执行。
- 一次取消确认不代表内存已经释放。清理完成时，请求独占的预留应归零；旧场景、缓存或旧帧
  合法持有的共享资源应单列解释，并在所有权结束后验证回落，不要求 Application 总账一律为零。
- 先复用内部观测与现有快照。若验收确实需要新增公共字段，再评估 C ABI、C++ 原生包装、
  IPC 兼容、安装消费者及线程契约，不建立第二套资源账本。
- 不预设 SIGPIPE 或启动超时的根因；先保存失败上下文与可复现用例，再作局部修复。
  有限次数未复现只可记为未复现，不能标为根因已修复。
- 延续 [ADR-052](../decisions/ADR-052-texture-residency-and-budgets.md) 的所有权约束。
  若需要改变任务执行模型或跨层边界，先补 ADR；仅建立本版计划不新增推测性架构决策。

## 非目标

不继续大范围目录重排，不引入 expected 或插件 API，不整理 Editor 公共 API。
不实现虚拟纹理、视距 Mip 流送、全新调度框架或完整 glTF/PBR 扩展。
不将完整引擎 Web、实际独立显存统计或物理跨屏 DPI 作为本版隐含交付。
不默认升级 Granit；发现可复用底层缺口时记录最小接口和验收要求，由用户处理上游。

## 发布验收

1. 基线与最终测量使用一致的资产摘要、Cook 参数、设备、构建类型与视角，成功、失败样本分别报告。
2. thread/cooperative 分别报告阶段耗时、最长帧、交互与取消延迟、CPU/逻辑资源和上传峰值；
   未获得驱动实际显存时明确未测量，不以资源估算替代。
3. 两种模式完成完整场景加载、至少三次连续切换、加载期间窗口操作、分阶段取消、失败重试及关闭，
   达到 M-312 冻结的门槛；未达标时继续排查或明确重新评审范围，不将限制静默改为完成。
4. 取消和失败保持旧场景可用；迟到结果不重新激活旧请求；共享资源不双计、不漏计、不下溢，
   请求独占资源在清理完成后归零，并有确定性所有权测试与进程观测相互印证。
5. IPC 对端提前退出、写入期间断连、停止与关闭竞态有确定性回归；启动阶段证据能区分准备、
   建连、就绪及退出，实际发现的缺陷修复后按原门槛复验。
6. 本地相关检查及最终 Windows/Linux 手动矩阵通过；涉及公共 API 时覆盖共享/静态、独立
   C11/C++20 头与安装消费者。失败不得通过跳过测试或关闭警告处理。
7. 当前行为写入 Reference/Guide，证据写 Record；实际发布后新增版本归档。历史未复现问题保留准确限制。

## 风险与未决事项

- 第三方解析/解码可能是不可切分调用；M-312 明确影响，M-313 决定最小处理方式。
  若阻塞已确认响应性目标，应及时提出决策或上游需求，不把“移到线程”当作无线程模式的修复。
- 时间切片过小可能增加总加载耗时；内存统计、缓存与旧帧释放存在延迟，需同时验证吞吐和生命周期。
- 灯廊启动抖动可能来自环境负载，也可能来自协议竞态，尚无根因结论。
- 本次授权为版本规划与本地提交；实现及完整远端发布按后续任务授权执行。

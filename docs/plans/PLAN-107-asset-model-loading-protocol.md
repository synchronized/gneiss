# PLAN-107：资产对象与统一加载协议

## 状态与范围

2026-11-08：已确认，开始实施。归属 DEV-052，承接 PLAN-102 的真实剩余项。
决策见 [ADR-112](../decisions/ADR-112-asset-loading-protocol.md)。本计划允许调整内部 API 和布局，
不兼容未发布旧接口；不修改 Granit，不包含远端发布。

## 目标模型

- file_service 管理异步字节读取，asset_manager 管理资产身份、弱索引和加载操作，Render 管理 GPU 对象。
- 上层统一 ref<const texture/mesh/material/scene/prefab>；资产身份稳定，内容为成功加载的不可变快照。
- 加载请求观察一次操作；resource 表示身份，take 表示该次 CPU 加载结果，失败不清空旧内容。
- 同键记录只有一个弱缓存和当前操作；最后一个观察者与实际使用者均放弃才允许取消。
- Loader 只解码、声明依赖、装配内容，不调用服务或维护独立请求推进循环。
- content 依赖等待可用内容，reference 依赖只要求稳定身份；CPU 完成不等待 GPU。
- 通用序列化只遍历值与声明定位；引用保存 URI，缺失内容不能被写成 null。
- World 实例化消费组合后内容，来源与覆盖不进入运行对象。

## 实施阶段与删除条件

1. [x] 统一 Loader 依赖声明与装配协议。先迁移 Scene→Prefab 必需依赖，删除 scene_loader 的提交、轮询状态及 manager 参数。
2. [ ] 在统一操作中建立依赖边与类型化结果槽；支持 content/reference，检测等待环及最终强引用环，诊断包含 URI 链和属性路径。
3. [ ] 接入材质、网格、纹理及通用对象；删除各自重复依赖队列和解析器中的类型 switch，不建立第二个管理器。
4. [ ] 统一 load/reload/create/find 和 asset_request；五类身份与内容边界一致，匿名创建不进入 URI 缓存。
5. [ ] CPU 资产与后端关联解耦；仅有线程要求的后端释放入队，保留 GPU 在途安全回收。
6. [ ] 迁移 Editor/Runtime/导入器与样例，更新 Reference，删除旧入口并完成集中验收。

每阶段完成可编译闭环和相关测试后提交。中间实现必须标明已支持的依赖类型，不能把 Scene 原型
描述为所有 Loader 已统一。本计划替代 PLAN-102 的未决设计方向，后者保留历史审计证据。

## 验收

- 重复请求共享身份和一次读取；不同来源域、类型及产物选项不错误合并。
- 单请求取消不影响其他拥有者，全部放弃取消底层工作；关闭后迟到结果无权采用。
- content 失败阻断必要装配，reference 失败保留定位及可用旧内容。
- 直接环、间接环、并发根形成的环明确失败；成功结果不形成不可回收的资产强引用环。
- 空引用、匿名引用错误、缺失 URI 往返、固定快照保活、重载失败及类型错误可验证。
- Scene/Prefab 不等待视觉完成，同资产多实例独立；运行修改不改写文档。
- 每阶段默认编译和定向 CPU 回归，架构统一后集中平台验收；不默认运行大场景或远端 CI。

## 非目标

不实现流送、LOD、资源 GC、任意对象图循环持久化、嵌套 Prefab、跨文件事务或通用插件 ABI。
不为了文件数或类数机械合并身份、内容、请求和运行实例。

# M-01：0.1.0 最小运行时闭环

## 状态

- 状态：实现中
- 目标版本：0.1.0
- 优先级：P0
- 路线图阶段：最小运行时

## 背景与目标

Gneiss 已具备基础 CMake 工程和 version 示例，但尚未形成游戏运行时路径。`0.1.0` 的目标是建立
最小而真实的垂直切片，验证 Application、Service、World、Scene Tree、ECS、资源与 Granit 渲染
之间的职责和生命周期。

版本验收路径如下：

```text
启动 Application
→ 初始化 Platform、Resource 和 Render Service
→ 创建 World 与 Scene Tree
→ 创建 Camera 和可渲染实体
→ 更新 Transform 与系统
→ 通过 Granit 提交并呈现帧
→ 处理窗口退出事件
→ 逆序销毁场景、资源、服务和 Application
```

## 非目标

- 完整编辑器、正式 UI 系统和游戏 UI 布局。
- 场景文件格式、完整资产构建管线和热重载。
- 网络、音频、物理和脚本服务。
- 通用 Job System 或跨服务无锁调度框架。
- 在 Granit 之外实现第二套渲染后端。
- PBR、阴影、后处理等不影响架构验证的渲染功能。

## 已确认决策

- 使用 C++20 实现，公共 C ABI 与轻量 C++20 包装遵循现有代码规范。
- Granit 负责底层渲染、窗口和输入能力；Gneiss 不重复封装其全部 API。
- Scene Tree 负责层级，ECS 负责运行时数据处理，节点通过实体 ID 关联 ECS。
- Service 管理资源及后端对象；业务组件只保存纯数据或 RID。
- RID 为 64 位不透明值，零值无效，并校验类型、generation 和所属 Service。
- 首版从单线程、确定性更新顺序开始；并行调度只在性能证据出现后设计。
- Dear ImGui 不属于核心依赖；如需接入，只作为后续临时诊断 UI。
- 每个子阶段必须提供可运行测试或示例证据，不能只提交接口草案。

## 待决策事项

### ECS 实现

已由 [ADR-002](../decisions/ADR-002-ecs-reflection-boundary.md) 确认：使用 EnTT `3.15.0` 作为内部
ECS 实现，Gneiss 自己定义 entity、World、System 和未来的反射/序列化 Schema。EnTT 类型、Meta
标识和 Snapshot 格式不进入公共或持久化契约。

### Granit 集成方式

已由 [ADR-001](../decisions/ADR-001-granit-dependency.md) 确认：最低支持 Granit `0.3.0`，优先复用
父工程已有的命名空间目标，否则查找已安装的 CMake package。依赖保持为私有实现细节，不隐式
下载或硬编码相邻源码目录。

### 数学类型

优先复用 Granit 已公开且满足场景需求的数学值类型。只有在 Transform、Camera 或序列化需求不能
满足时才评估独立数学库，避免首版出现重复向量和矩阵类型。

## 公共模型草案

首版只锁定职责，不在本 Plan 中冻结最终函数名称。

### Application

- 拥有所有顶层 Service 和 World。
- 按依赖顺序初始化，按相反顺序销毁。
- 负责事件轮询、时间更新、系统执行和帧提交。
- 首版只允许在创建线程运行。

### Service

- 每类 Service 有唯一职责和明确依赖。
- 禁止隐式全局单例；由 Application 显式拥有和传递。
- Service 销毁时检测仍存活的用户资源，并在验证模式报告。

### World 与 Scene Tree

- World 拥有实体和组件存储。
- Scene Tree 拥有节点层级；节点可以关联一个实体 ID。
- 节点销毁与实体销毁的传播规则必须由测试锁定。
- Transform 的局部值和世界值只有一个权威存储位置。

### Render Service

- 消费 World 的只读渲染快照或明确生命周期的视图。
- 将 Camera、Transform、Mesh 和 Material 转换为 Granit 提交输入。
- ECS 组件不保存 Granit renderer、buffer、texture 等原生句柄。
- Granit 错误转换为 Gneiss 结果和诊断，不允许异常跨越 C ABI。

## 实施顺序

### M-01A：契约和验证基线

状态：已完成。

1. 确认项目目标、路线图和本 Plan。
2. 建立结果码、导出宏、公共头独立编译和最小测试组织。
3. 明确 Granit 依赖接入方式及最低版本。

验收：C11/C++20 公共入口可以独立构建，版本接口与运行库一致。

### M-01B：Service 与 RID

状态：已完成基础实现；公共诊断将在 Application 阶段接入。

1. 定义 Service 生命周期、依赖声明和错误传播。
2. 实现类型、generation、槽位和 Service domain 编码。
3. 覆盖零值、类型错误、旧 generation、跨服务使用和重复销毁。

验收：无效 RID 不会访问新资源，Service 能报告未释放资源。

### M-01C：ECS 与 World

状态：已完成基础 World、Entity、内部组件存储与确定性 System 调度；公共组件类型将在 Scene 与
Render 阶段按真实用途增加。

1. 完成 EnTT 与自研最小 ECS 技术验证。
2. 记录 ECS ADR 并实现选定方案的内部适配层。
3. 实现 World、Entity、最小组件注册和确定性 System 更新。

验收：实体创建、销毁、组件查询和失效边界具有确定性测试。

### M-01D：Scene Tree

状态：已完成基础实现。

1. 实现节点创建、父子关系、重挂接和销毁。
2. 建立节点与实体 ID 映射。
3. 实现最小 Transform 层级传播。

验收：层级更新、非法循环、节点/实体销毁顺序和 Transform 传播均有测试。

### M-01E：Application 与平台循环

状态：已完成基础实现，包括 Application 核心、Granit Window 适配、时间、暂停、退出与失败回滚。

1. 通过 Granit 创建窗口并轮询事件。
2. 实现单线程 Application 主循环和时间信息。
3. 定义暂停、窗口关闭、初始化失败和部分初始化回滚。

验收：无渲染内容时应用也能启动、处理退出并无遗漏地释放资源。

### M-01F：Render Service 与资源

1. 创建 Granit Renderer 和首版 Render Service。
2. 实现最小 Mesh/Material 资源缓存及对应 RID。
3. 从 World 提取 Camera、Transform 和 Mesh Renderer 数据。
4. 提交并呈现一个可见对象。

验收：业务组件中不存在 Granit 原生句柄；窗口调整和正常退出路径可重复运行。

### M-01G：示例与版本验收

1. 提供一个旋转三角形或等价简单场景。
2. 连续运行固定帧数的自动 smoke test，并执行完整清理。
3. 验证 Windows/Linux、共享/静态和 C/C++ consumer。
4. 补齐构建、最小使用和架构说明。

验收：端到端路径通过，`0.1.0` 当前能力与非目标在文档中清晰可见。

## 测试与验收

### 必需测试

- C11 与 C++20 公共头独立编译。
- Application 初始化失败、部分回滚、正常退出和重复运行。
- Service 依赖顺序、逆序销毁和资源遗漏诊断。
- RID 零值、类型、generation、domain 和重复销毁。
- Entity 与 Scene Node 的创建、映射、重挂接和销毁。
- Transform 层级传播和非法循环拒绝。
- Render Service 无窗口环境的可测试核心与真实窗口 smoke test。
- 共享库、静态库、C consumer 和 C++ consumer。

### 版本完成条件

- 示例完成“启动—更新—渲染—退出”的真实闭环。
- 所有 P0 任务完成，没有用占位实现绕过验收。
- 公共接口记录所有权、线程安全、错误和失效规则。
- 开发 preset 警告视为错误，相关测试全部通过。
- 当前能力已写入 Guide/Reference，未来能力仍保留在 Roadmap/Plan。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 首版范围膨胀 | 只保留端到端闭环必需的 P0 能力 |
| ECS 抽象过早冻结 | 先完成对比验证，以内部适配层隔离实现 |
| Gneiss 与 Granit 职责重叠 | 每个新增接口先检查能否直接复用 Granit |
| Scene Tree 与 ECS 双份状态 | 为每类数据指定唯一权威存储并测试同步边界 |
| RID 设计无法扩展 | 首版锁定类型、generation 和 domain，不暴露位布局 |
| 平台测试依赖图形环境 | 将纯逻辑测试与真实窗口 smoke test 分层 |
| 第三方依赖扩散 | 依赖默认私有，不传播头文件、宏和链接要求 |

## 后续任务

完成 `0.1.0` 后，根据示例暴露的真实问题进入 `0.2.0` 资源与场景阶段。异步加载、正式场景格式、
临时调试 UI 以及其他 Service 均需要独立 Plan，不在本计划中追加实现。

# VER-045：0.45.0 内部 C++ 分层与完整 SDK 包装

## 状态与目标

2026-10-05 已开始审计和 Core 迁移，尚未完成版本验收。以已发布 0.44.0 为基线，本版优先重构源码所有权与接口边界。
实施步骤以 [DEV-045](DEV-045-cpp-boundaries.md) 为准，架构决策见
[ADR-053](../decisions/ADR-053-cpp-core-and-c-abi.md)。

目标为内部 C++ 实现、薄 C11 ABI 与完整 C++20 包装三层。业务规则只实现一次，内部模块不为复用
功能绕回导出的 C 入口；目录与构建依赖表达一致的所有权，不以文件移动数量衡量完成度。

## 范围

| 优先级 | 交付 | 完成标准 |
| --- | --- | --- |
| P0 | 模块与接口审计 | 当前依赖、状态所有者、私有导出、公共接口及包装缺口均有清单 |
| P0 | C++ 内部与薄 ABI | 公共适配入口集中到 `src/api/c/`，核心规则回归所属模块 |
| P0 | 完整 C++ SDK | 所有已支持公共 C 功能可由 C++ 使用；拥有、借用、值类型与回调分别覆盖 |
| P0 | 生命周期清晰 | 父对象先销毁、移动、失败回滚、重复释放、异步取消与线程边界有契约和测试 |
| P0 | 依赖约束落地 | 模块私有依赖与自动检查阻止反向依赖、第三方泄漏和重复运行时状态 |
| P0 | 行为与发布验证 | 共享/静态、安装消费者、头独立编译、Editor/Runtime 和 GPU 回归通过 |

范围覆盖现有 Core、Application、Asset、World、Scene、Render、Input、Reflection、Log 与 Game Module
公共接口。私有任务、加载及宿主接口同样审计，但不为提高覆盖率自动转为公共 ABI。

## 非目标与兼容性

不新增渲染功能、Service、任务池或模块插件框架；不升级 Granit、不修改上游仓库。
0.44 的临时内存预留、取消回收测量与 cooperative 长帧继续保留为后续事项，不宣称由本次重构解决。
不直接套用图形学课程的作业布局；参考 Granit 的实际接口边界。用户所指课程项目尚未明确，
不假定其为 GAMES104/Piccolo，也不以此阻塞已经确认的分层决策。

默认保留 0.44 公共头路径、导出符号、C 布局及既有语义。C++ 新增包装优先保持源兼容。
遇到必须破坏兼容的变更先记录原因、影响和迁移方案，再明确调整范围，不通过删除接口满足覆盖率。

## 发布门槛

- C API 清单覆盖函数、类型、描述结构、常量、回调及所有权；每个函数都有 C++ 对应入口和测试映射。
  多个 C 函数可合并成一个有明确语义的包装，但不能以裸句柄逃生接口代替包装。
- 内部实现无需包含公共 RAII 包装；内部模块不调用导出的 C 函数复用核心逻辑。
  动态 Game Module 等真实 ABI 边界单独列明，不作为违规。
- C 入口只承担 ABI 校验、布局转换、句柄解析、异常隔离与委托；核心业务与资源唯一所有者留在内部。
- 不引入双份注册表、缓存、调度器或隐含强持有链；RAII 不让 Service/后端原生类型泄漏。
- 通过 C11/C++20 头独立编译、共享/静态安装后消费者、错误路径及生命周期测试。
  运行既有 Editor/Runtime 场景加载、取消、热重载、资源预算和 GPU 像素回归。
- 构建与依赖检查能够检出新增违规；历史债务必须列出归属，本版目标范围内不留无限期白名单。

用户已授权 0.45 完整开发与发布闭环；实际开发与发布进展另行记录，
完成发布前不创建 `docs/versions/0.45.0.md` 或提前宣称实现。

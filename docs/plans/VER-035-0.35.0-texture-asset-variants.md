# VER-035：0.35.0 平台纹理变体与流式上传

## 状态

- 状态：实现中
- 目标版本：0.35.0
- 优先级：P0
- 路线图阶段：游戏交付工作流

## 背景与目标

0.34.0 已能把 PNG 作者纹理确定性 Cook 为带完整 Mip 的 RGBA8 KTX2，但发布包仍只携带一种
GPU 表示，Runtime 也自行解释 KTX2 后逐级调用底层 Texture 写入。Granit 0.19.0 已提供 Texture
Asset Manifest、设备变体选择和逐 Mip Upload Batch 契约。

0.35.0 以 Granit 的上述能力为基础，以 Gneiss 运行纹理封装承载 Granit Manifest 和负载，交付
BC7 桌面颜色纹理与 RGBA8 回退的首个闭环，并让上传遵循既有渲染线程、背压和原子资源切换语义。

## 已确认决策

- Granit 基线升级至 0.29.1 正式发布提交，保留 0.23 的纯 UI 帧提交修复；迁移统一
  Window/Input、强类型 C++ 资源与 AssetTools 头。保留 Gneiss 主循环、主线程窗口和渲染线程
  分工，不接入托管 Loop 或扩展 Web 平台。
- 作者输入与交换格式继续使用 PNG/KTX2；发布包使用版本化的 Gneiss 运行纹理封装。该封装包含
  Granit Texture Asset Manifest 与其引用的负载，但不向 Gneiss 公共 API 暴露 Granit 类型。
- Gneiss 负责导入、离线转码、目标平台策略、缓存、文件 I/O、RID 和正式资源切换；Granit 负责
  GPU 格式布局校验、设备能力选择以及逐 Mip Upload Batch。
- 首批生产变体限定为 BC7 UNORM/SRGB 与 RGBA8 UNORM/SRGB。BC7 优先，RGBA8 必须作为兼容回退；
  法线 BC5、移动端 ETC2/ASTC 和 Basis 在线转码留给后续版本。
- BC7 编码器只能作为私有工具依赖，不进入 Runtime、安装 SDK 或公共 ABI；接入前记录版本、许可、
  确定性、质量和构建影响。若候选编码器不能满足门禁，本版本仍须完成 Manifest、RGBA8 回退与
  预压缩 BC7 输入链路，不以低质量临时编码器冒充生产路径。
- Manifest 变体顺序由平台构建配置确定，Runtime 只按声明用途和真实设备能力选择，不硬编码
  “某格式永远优先”的跨平台假设。

## 非目标

- 不在本版本支持 Texture Array、Cube、3D、HDR、虚拟纹理或稀疏驻留。
- 不实现压缩纹理运行时 Mip 生成、读回或运行时转码。
- 不把 Granit Manifest 作为作者格式，也不让 Granit 负责项目缓存、文件系统或资产生命周期。
- 不扩展 Mesh、Material、动画、音频或 Shader 的运行资产格式。
- 不以一次版本覆盖所有桌面、移动端和 Web 压缩组合。

- Granit FETCH、PACKAGE 和父工程目标均要求 0.29.1，并验证 Shared/Static 与安装 Consumer。
- 相同输入、配置和工具版本生成逐字节一致的运行纹理；格式策略或编码器版本变化使缓存失效。
- 封装和 Manifest 对截断、越界、重叠、摘要不匹配、未知版本及非法 Mip 布局明确失败。
- 支持 BC7 的设备选择 BC7；不支持时选择 RGBA8；两者均不可用时返回可定位的失败诊断。
- Upload Batch 容量不足可重试且不留下部分命令；上传或校验失败继续保留旧 RID 对应资源。
- 发布包不包含已 Cook 的作者 PNG、工具依赖或构建缓存；CLI 可检查封装、变体和 Mip 摘要。
- Lantern Gallery 在真实图形后端使用 Cook 产物完成 smoke，并记录变体选择与上传结果。
- Windows MSVC/Clang、Linux Clang/GCC、Shared/Static、安装 Consumer 与 Sanitizer 通过。

## 风险与未决问题

- BC7 编码质量、速度和确定性需要以 Lantern Gallery 及合成边界纹理实测后锁定参数。
- Granit Manifest 是稳定的 GPU 元数据契约，不等同于 Gneiss 文件封装；封装版本必须允许未来追加
  ETC2、ASTC 或分离 Payload，而不复制 Granit 的格式与布局规则。
- WebGPU 设备可能没有启用对应压缩格式族，因此 RGBA8 回退不能因桌面验证通过而删除。

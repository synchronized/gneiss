# VER-006：0.6.0 数据与属性基础

## 状态

- 状态：实施中
- 目标版本：0.6.0
- 优先级：P0
- 路线图阶段：数据与属性基础

## 背景与目标

Gneiss 已能通过版本化场景和资产格式建立运行时内容，但组件字段仍由各 Loader 和 API 单独处理。
后续编辑器属性面板、场景格式迁移、Undo/Redo 和 Prefab 都需要稳定的类型、字段和属性访问契约。
直接暴露 C++ 成员地址、EnTT Meta 或编译器类型信息，会让公共 ABI、持久化数据和工具绑定到实现。

`0.6.0` 的目标是建立一条最小、可验证的数据路径：注册稳定类型与字段元数据，通过类型安全的值
容器读写已注册属性，将首批 ECS 组件接入该路径，并用旧版场景迁移验证 Schema 演进能力。

```text
稳定 Type ID + Field ID + Schema Version
→ Type Registry 元数据查询
→ 属性值校验与读写适配
→ ECS 组件访问
→ 旧版数据迁移和新版场景保存
```

## 非目标

- 编辑器窗口、属性面板、场景视图或其他 UI。
- 任意 C++ 对象、私有成员、模板、函数或继承体系的自动反射。
- 把 EnTT Meta、编译器 RTTI、成员指针或内存偏移公开为项目契约。
- 完整代码生成器、脚本绑定、插件 ABI 或运行时模块热重载。
- Undo/Redo、Prefab、多人协作、网络复制或增量场景补丁。
- 通用二进制对象序列化、资产包格式或替换现有场景 JSON。
- 冻结 1.0 的完整反射 ABI；本版本只承诺首个版本化契约。

## 已确认决策

- [ADR-002](../decisions/ADR-002-ecs-reflection-boundary.md) 是本版本的上位约束：Gneiss 维护独立
  Type Registry，EnTT 只作为内部 ECS 实现。
- [ADR-016](../decisions/ADR-016-stable-type-property-boundary.md) 固定 Type ID、Field ID、注册阶段、
  属性适配、未知字段和首版多态边界。
- 公共 `.h` 继续保持 C11 ABI，`.hpp` 只提供轻量、无第二套状态的 C++20 包装。
- 类型和字段使用可持久化的稳定标识，不使用地址、注册顺序、`typeid`、编译器哈希或 EnTT ID。
- 元数据描述和属性值不直接暴露组件内存；读写通过已注册适配函数完成。
- 属性写入必须先校验值类型、范围、只读性和目标生命周期，失败不留下部分修改。
- Runtime 类型元数据是读取场景和编辑器查询的共同事实来源；JSON 仍是当前作者格式。
- Schema 迁移按明确版本逐步执行，未知字段、未来版本和迁移失败具有确定错误语义。
- 首批接入范围只覆盖能验证编辑器需求的 Transform 与 Camera；扩展其他组件时复用同一注册机制。

## 实施顺序

### M-39：反射用例、稳定标识与 ADR

状态：已完成。ADR-016 已确定显式 128 位 UUID Type ID、类型内非零 `uint32_t` Field ID、初始化期
注册与冻结后并发只读、getter/setter 属性适配、作者文档未知字段保留，以及首版不实现反射继承。
标识与冲突行为将在 M-40 通过实现测试验证。

### M-40：Type Registry 与元数据查询

状态：已完成。公共 C11 API 已提供 Type/Field 描述、Registry 创建、深拷贝注册、冻结、确定顺序
枚举和稳定标识查询；C++20 层提供独占 RAII 包装。Registry 冻结后支持并发只读，借用元数据在
Registry 销毁前有效。按 ADR-016，首版移除原计划的注销，不支持冻结后的模块卸载。

### M-41：类型安全的属性读写

状态：已完成。属性值容器支持布尔、定宽整数、浮点、UTF-8 字符串、稳定 Type ID、三维向量和
四元数；字段访问器在冻结前独立绑定，冻结后经统一入口校验并调用 getter/setter。借用字符串、目标
解释、线程安全及失败原子性均已形成公共契约，并由 C11/C++20 独立对象测试覆盖。

### M-42：ECS 组件属性适配

状态：已完成。Transform 与 Camera 已注册为首批内建反射类型，通过 World、实体 ID、Type ID 和
Field ID 定位属性。Transform 保持由 Scene Tree 拥有并通过实体关联访问，Camera 保持纯数据 ECS
组件；两者均不暴露 EnTT 或组件地址。失效实体、组件或节点缺失、跨 World、只读活动状态及失败
原子性已有测试覆盖，Scene Tree 节点仍只关联实体 ID。

### M-43：序列化版本迁移闭环

1. 为测试 Schema 建立至少两个连续版本和显式迁移函数。
2. 加载时先验证来源版本，再按顺序迁移到当前版本，最后实例化运行时对象。
3. 明确未知字段、缺省字段、未来版本、迁移链缺口和迁移失败的行为。
4. 验证迁移失败不会修改现有场景实例或覆盖原作者文件。

验收：旧版 fixture 可确定性升级并重新保存为当前格式；未来版本和损坏数据被稳定拒绝。

### M-44：属性示例与版本验收

1. 增加无 UI 的属性检查示例，枚举场景实体的类型和字段并修改允许写入的属性。
2. 通过属性 API 修改 Transform 或 Camera，验证后续 Render Snapshot 反映新值。
3. 覆盖加载、查询、修改、保存、重新加载和销毁的完整生命周期。
4. 执行 Windows/Linux、共享/静态、安装 Consumer 和公共头手动矩阵。

验收：示例不依赖 EnTT、Granit 原生类型或私有组件头，即可完成属性编辑与持久化闭环。

## 测试与验收

- 公共 `.h` 由 C11 编译器独立包含，公共 `.hpp` 由 C++20 编译器独立包含。
- 描述结构包含 `struct_size`，字符串使用 UTF-8 指针与长度并明确有效期。
- 稳定标识测试跨进程、注册顺序和链接方式保持一致。
- Registry 覆盖重复、冲突、注销、失效、跨 Registry 和并发只读查询。
- 属性访问覆盖全部值类型、边界值、非法值、只读字段和失败原子性。
- ECS 适配覆盖实体 generation 失效、组件缺失、跨 World 和派生状态刷新。
- 迁移覆盖旧版本成功、未来版本拒绝、迁移链缺口和原文件不被覆盖。
- Windows/Linux、共享/静态、核心、安装 Consumer 和相关 Granit 示例全部回归通过。

## 风险与未决问题

| 项目 | 当前处理方式 |
| --- | --- |
| Type ID 与 Field ID 的具体编码 | ADR-016 已确定 128 位 UUID 与类型内非零 `uint32_t` |
| 元数据字符串和动态模块的生命周期 | Registry 拥有元数据；首版冻结后不支持注销和模块卸载 |
| 数组、枚举、资源引用和嵌套结构 | 先由真实 Transform/Camera 用例确定最小集合，避免一次扩张完整类型系统 |
| 属性写入绕过组件不变量 | 使用组件专属适配函数校验，不公开裸偏移写入 |
| 反射与场景 Schema 形成两套事实 | Registry 提供字段元数据，场景格式只维护文档结构和版本迁移规则 |
| ABI 过早冻结 | 所有描述版本化并保留扩展位，0.x 阶段允许有记录的破坏性调整 |

## 版本完成条件

- M-39～M-44 全部完成并形成最终验收记录。
- 稳定类型与字段标识、元数据查询、属性读写、ECS 适配和迁移形成端到端闭环。
- 公共接口不泄漏 EnTT、STL、成员指针、内存偏移或第三方反射类型。
- 失败写入和失败迁移保持原状态，生命周期、所有权和线程边界有测试与文档。
- Windows/Linux 手动矩阵通过，属性示例可从安装后的 CMake package 构建运行。

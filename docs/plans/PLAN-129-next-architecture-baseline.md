# PLAN-129：下一轮架构重构与遗留验收

## 状态

2026-11-23：规划中。用户确认先收尾 0.52，再开展更大规模重构。
本计划承接退出 0.52 的事项，不代表目标 API 或完整新架构已获确认。
开发基线为发布后的 v0.52.0；发布前不启动新的结构迁移。

## 承接范围

- PLAN-128 P3：Runtime 协议适配、重载回调、检查状态与业务调度归属，消除 loading() 过渡借用入口。
- PLAN-128 P4：工作区、项目选择/CLI、宿主目标与命名空间；按真实消费者决定目标拆分。
- PLAN-128 手工尾项：高 DPI 连续操作、保存确认/取消、连续项目关闭重开。
- PLAN-115：真实设备丢失、GPU 上传饱和、代表性资产与跨硬件预算定标、完整拾取遮挡/MASK矩阵、浏览器非阻塞消费。
  已有自动化证据保留，默认预算不因缺少测量而调整。

具体历史条件见 [PLAN-128](PLAN-128-host-business-ownership.md) 和
[PLAN-115](PLAN-115-persistent-render-scene.md)。这些项目不是已经完成，也不机械照搬旧结构继续实现。

## 实施顺序

1. 用户明确下一轮重点后，复核真实调用方，给出初始化、正常使用、失败、取消与关闭的完整用例。
2. 明确状态唯一所有者、对象身份、借用寿命、线程边界和修改入口，再确定 API 与目录。
3. 记录与既有 ADR 的差异及取舍；不因本计划创建就视为新方案已接受。
4. 按完整业务链路迁移，同步删除旧路径，复用行为测试；禁止以新增包装或搬文件作为完成标准。
5. 每条链路提供验收证据，最后统一版本验收。

## 尚待设计的问题

下一轮重构的核心对象模型与范围尚未展开讨论；不能预设必须重写全部引擎。
0.52 的可靠基线和已知限制保留为对照，性能/设备验收与架构改造分别记录。

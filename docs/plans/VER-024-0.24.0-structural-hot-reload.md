# VER-024：0.24.0 Scene 与 Prefab 结构热重载

## 状态

- 状态：实现中
- 目标版本：0.24.0
- 优先级：P0
- 路线图阶段：Scene 与 Prefab 结构热重载

## 背景与目标

现有资产热重载只替换 Texture、Material 和静态 Mesh，修改 Scene 层级或 Prefab 来源后仍需重启
Runtime。0.24.0 在既有文件监听、自动导入、Asset IPC、场景实例和 Prefab 刷新能力上建立第一个
结构热重载闭环：Runtime 对完整候选描述生成身份协调差异，在主线程安全点事务提交，并让 Editor
展示成功、失败、冲突或需要重启结果。

## 非目标

- 不热重载 Game Module、原生动态库、脚本虚拟机或线程栈。
- 不实现跨工程场景切换、场景流式分区或多人协作编辑。
- 不通过 IPC 传输完整 Scene、Prefab 或资源字节。
- 不保证组件对象地址、迭代顺序或被删除实体 ID 稳定。
- 不自动解决未保存 Editor 文档与外部文件变化的内容冲突。
- 不新增 Stable C ABI；首版结构事务保持为 Runtime 与 Editor 内部 C++20 能力。

## 已确认决策

- Scene 节点以节点 UUID 协调；Prefab 节点以实例 UUID 和来源节点 UUID 的复合身份协调。
- 匹配且类型兼容的节点保留实体 ID；新增和删除节点分别创建新实体和使旧实体失效。
- 新作者描述覆盖作者字段，保留实体上的非作者 Runtime 状态继续存在；组件来源必须显式记录。
- Runtime 在完整解析、Schema、层级、覆盖和资源依赖验证后才进入事务提交，失败保留旧结构。
- 同源 Prefab 的全部实例作为一个批次刷新；失效覆盖产生冲突，不静默删除作者数据。
- 结构修订复用 Asset IPC 域和现有重同步机制，详细语义见
  [ADR-037](../decisions/ADR-037-scene-prefab-structural-hot-reload.md)。
- 单个修订请求只包含渲染资源或结构资产中的一类；Scene 首版只更新当前启动场景，Prefab 修订更新
  当前场景内全部同源实例。

## 实施顺序

### M-155：结构热重载边界与现状审计

盘点 Scene、Prefab、场景实例、实体映射、资源租约、Editor 作者文档和 Asset IPC 的现有所有权，
验证 ADR 决策能由当前接口表达，并记录缺少的最小内部能力。

状态：已完成。Scene 可复用既有作者描述和 UUID 映射；Prefab 当前刷新会整体重建并丢失实体身份，
需要改为实例内部协调；详细结果见
[M-155 审计记录](../records/M-155-structural-hot-reload-audit.md)。

### M-156：身份协调差异模型

建立与具体解析格式解耦的候选快照和确定排序差异，覆盖节点及作者组件的新增、删除、保留、重挂接、
重命名和字段更新，同时验证重复 UUID、环、缺失父节点和类型不兼容。

状态：已完成。新增纯数据差异模型，按稳定 UUID 输出父到子的新增、确定排序的更新和子到父的删除，
并在计算前拒绝重复身份、缺失父节点及层级环；详见
[M-156 实施记录](../records/M-156-structural-diff.md)。

### M-157：Scene 事务式结构替换

为当前运行 Scene 在主线程安全点准备并提交差异。保留匹配实体 ID 和 Runtime 状态，预先获取资源
租约，失败完整回滚，并处理连续修订与过期请求。

状态：已完成。现有 Scene 实例可在 Application 主线程通过内部宿主入口重新加载作者文件；提交前
完整解析候选描述并预取资源，匹配 UUID 的节点与实体保持身份，新增和删除按依赖顺序执行。Scene
UUID 或 Prefab 实例容器发生变化时拒绝本阶段事务，资源准备失败时保留旧结构。实现记录见
[M-157：Scene 事务式结构替换](../records/M-157-scene-transactional-structural-reload.md)。

### M-158：Prefab 批量刷新事务

将来源 Prefab 修订应用到所有同源实例，重新应用实例局部覆盖；任一实例验证或准备失败时保留全部
旧投影，成功后统一发布新来源修订。

状态：已完成。Prefab Runtime 实例按“实例 UUID + 来源节点 UUID”协调新旧投影，同源全部实例先完成
候选来源、资源与局部覆盖验证，再统一提交。实例根和匹配来源节点的节点/实体身份保持不变，新增与
删除按层级依赖排序，局部覆盖在新来源作者值之上重新应用；任一准备失败时全部实例保留旧投影。
实现记录见 [M-158：Prefab 批量结构刷新](../records/M-158-prefab-batch-structural-reload.md)。

### M-159：Asset IPC 结构修订接线

为 Scene 与 Prefab 注册资产类型和应用结果，复用现有 URI、修订、请求 ID、能力协商、重连重同步
与有界队列；未知版本或不支持的结构变化返回明确结果。

状态：待开始。

### M-160：Editor 冲突与状态反馈

接通保存、外部变化、自动重新导入和 Runtime 结果。未保存文档遇到外部变化时进入冲突状态，不自动
覆盖；Asset Browser 和相关工作区展示等待、应用、失败、冲突及需要重启。

状态：待开始。

### M-161：示例与跨平台验收

使用 Lantern Gallery 自动修改 Scene 层级、组件和 Prefab 来源，验证身份保持、覆盖传播、失败回滚、
连续保存与 Runtime 重连，并执行 Windows/Linux Shared/Static、Granit Runtime 和 Sanitizer 矩阵。

状态：待开始。

## 测试与验收

- 差异模型覆盖新增、删除、重挂接、重命名、组件增删、字段更新和无变化修订。
- 重复 UUID、层级环、无效父节点、未知类型、损坏资源和失效 Prefab 覆盖均在提交前失败。
- 匹配节点在成功更新后保留实体 ID；删除实体的旧 ID 失效，新增实体不复用仍存活身份。
- 提交中任一步失败时，旧层级、组件、资源租约、实体映射和已发布修订保持不变。
- Prefab 多实例要么全部刷新，要么全部保留旧版本；实例局部覆盖继续作用于正确来源字段。
- 未保存 Editor 文档不会被外部文件事件静默覆盖；重连后 Runtime 收敛到最后提交修订。
- Windows/Linux Clang/GCC Shared/Static、Granit Runtime Shared/Static、安装消费和 Sanitizer 通过。

## 风险与未决问题

- 当前场景实例若无法区分作者组件与 Game Module 临时组件，M-155 必须先补最小来源元数据，不能按
  组件类型粗略覆盖。
- Prefab 现有刷新实现是否保留匹配实体 ID 需要实测；若只能整体重建，应先扩展 Gneiss 场景服务，
  不将项目语义下沉到 Granit。
- 大型场景的候选副本与回滚日志会增加峰值内存；0.24.0 先保证正确性并记录规模数据，不提前引入
  增量流式协议。
- 物理、音频等未来服务可能有自己的安全替换点；首版只处理当前已实现且可验证的组件与资源类型。

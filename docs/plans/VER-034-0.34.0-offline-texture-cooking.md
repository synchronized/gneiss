# VER-034：0.34.0 离线纹理构建与 KTX2 运行链路

## 状态

- 状态：设计中
- 目标版本：0.34.0
- 优先级：P0
- 路线图阶段：游戏交付工作流

## 背景与目标

0.33.0 已建立确定性资产构建图、内容寻址缓存和 Shipping 裁剪，但 Texture 处理器仍保留 PNG/JPEG
等源表示，Runtime 也仍在启动路径解码 PNG。0.34.0 将完成第一个真实离线 Cook 闭环：作者纹理经
导入配置生成带完整 Mip 的 RGBA8 KTX2，发布包与 Runtime 只消费派生运行资产。

## 已确认决策

- 升级 Granit 至最新正式版 0.17.0，接入其 0.15～0.17 异步与背压修订，但不把 KTX2 解析下沉。
- KTX2 是 Gneiss 的运行时纹理容器；首版产物使用 RGBA8 UNORM/SRGB，Mip 由离线处理器生成。
- KTX-Software 评估后暂不引入：首版受约束 RGBA8 Writer/Reader 足以形成闭环，等 Basis 或块压缩
  进入真实需求时再以私有工具依赖接入；届时仅启用 Apache-2.0 范围，不构建或分发 `etcdec.cxx`。
- 导入配置与作者源纹理同属工具域，不进入运行包；缓存键包含其内容和处理器版本。
- 发布包 Runtime 路径只解析已验证的 KTX2 Level Index 和受支持格式，并把各 Mip 投影给 Granit；
  编辑器直接运行未 Cook 作者工程时暂留 PNG 兼容路径。
- Granit 块压缩能力未落地时不伪装支持 BC/ETC2/ASTC，也不阻塞 RGBA8 KTX2 闭环。

## 非目标

- 不在本版本完成 GPU 块压缩、HDR、Cube、Texture Array、虚拟纹理或在线转码。
- 不扩展 Mesh、动画、音频或 Shader Cook。
- 不公开 KTX-Software、libspng 或 Granit 原生类型。
- JPEG 只有在不扩大公共依赖和许可风险的前提下进入首版；否则明确诊断为待支持源格式，PNG 是
  必须完成的生产路径。

## 验收条件

- PNG 源纹理与导入配置确定性生成 RGBA8 KTX2；相同输入逐字节一致，变更配置会失效缓存。
- sRGB/Linear、Alpha 和完整 Mip 链信息可验证；1×1 结束且奇数尺寸处理明确。
- Texture 描述及 Material 依赖指向 Cook 后 URI，发布包不包含作者 PNG、导入配置或构建缓存。
- Runtime 拒绝损坏、越界、未知格式和不受支持超级压缩，成功路径不再解码 PNG。
- Granit 收到全部 Mip 数据；上传背压可重试，失败不会留下半初始化资源。
- Windows MSVC/Clang、Linux Clang/GCC、Shared/Static、安装 Consumer 与 Sanitizer 通过。

## 上游协作

本版本无需直接修改 Granit。块压缩 PR 仍按 M-215 的建议由用户提交；合并后 Gneiss 可在后续版本
增加目标平台格式选择，而无需改变 KTX2 容器与工程资产语义。

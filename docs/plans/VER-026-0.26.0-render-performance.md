# VER-026：0.26.0 渲染线程性能基线与帧资源复用

## 状态

- 状态：设计中
- 目标版本：0.26.0
- 优先级：P0
- 路线图阶段：渲染吞吐、延迟与内存复用

## 背景与目标

0.25.0 已让专用渲染线程独占 Granit GPU 对象，并以不可变 Frame Packet、有界 Frame/Command
队列和完成回执建立正确性边界。当前仍缺少可比较的阶段耗时、复制量、分配量和在途帧数据，不能
可靠判断后续应该优化帧包、CPU 渲染准备、资源上传还是后端提交。

0.26.0 先建立低开销性能观测，再以完成回执保护的 Frame Slot 复用逐帧 CPU 内存，并把稳定渲染
状态迁入渲染侧镜像。版本同时区分允许替换的实时帧与必须完成的请求，形成可验证的背压策略。

## 非目标

- 不实现完整 Render Graph、独立 RHI Thread 或通用 Job System。
- 不引入无锁队列、GPU-driven rendering、异步计算队列或多 GPU 调度。
- 不把 Granit 类型、线程执行器或性能统计加入公共 C ABI。
- 不用未经基线验证的固定帧率或百分比提升作为版本验收条件。
- 不在本版本并行化剔除、排序、动画采样或图形命令录制。

## 已确认决策

- 先记录 Frame Packet 构造、提交、排队、资源同步、Acquire、录制、Present 和完整渲染线程耗时，
  所有统计使用单调时钟并明确采样边界。
- 队列统计增加当前深度、高水位、已提交帧、已执行帧、已替换帧和过载命令；统计读取不得阻塞
  渲染工作超过一次短临界区。
- Frame Slot 首版使用固定 2～3 个槽位，由完成回执归还；槽内存可以复用，但提交后的内容在归还前
  仍不可修改。
- 静态 Mesh、Material、Texture 和稳定实例状态逐步进入渲染侧镜像；Frame Packet 只保留当前帧
  必需的相机、动态 Transform、可见性、姿态、UI 和 Debug Draw。
- 普通实时帧允许在执行前被更新帧替换；拾取、截图和自动验收等请求必须完成并产生对应回执。
- 背压优先避免构造必然被替换的昂贵帧包，不通过无限队列把吞吐不足转换为持续输入延迟。
- 0.25.0 Lantern Gallery 数据作为优化前基线；每次优化同时比较耗时、分配、复制量与交互延迟。

## 实施顺序

### M-169：渲染性能观测

定义内部统计快照，覆盖 Frame Packet 构造与提交、队列等待和高水位、替换帧、资源同步、Acquire、
录制、Present 及渲染线程总耗时；增加确定性单元测试并在诊断入口展示最小摘要。

状态：已完成。Frame Packet 捕获记录构造耗时和有效载荷复制字节；执行回执记录排队、资源准备、
Acquire、录制提交、Present 和渲染线程总耗时。线程安全队列快照提供当前深度、高水位、提交、执行、
替换和拒绝计数，Application 关闭时通过现有诊断通道输出摘要。实施结果见
[M-169：渲染性能观测](../records/M-169-render-performance-observability.md)。

### M-170：Frame Slot 资源池

建立固定容量的帧槽和回执归还协议，复用 UI、Debug Draw、实例和动态参数容器容量；覆盖满载、过期
回执、停止与初始化失败，保证槽位不会在渲染线程消费期间被生产者改写。

状态：已完成。每个 Frame 完成或被更新帧替换后，执行器把已消费 Packet 随回执归还；Render Service
维护最多三个可复用槽位，主线程只在收到回执后重新取得槽位。捕获逻辑清空旧内容但保留可安全复用
的容器容量，关闭时在执行器停止后统一释放槽位。实施结果见
[M-170：Frame Slot 资源池](../records/M-170-frame-slot-pool.md)。

### M-171：Render Scene 镜像

把稳定资源和实例状态迁入渲染侧镜像，以不可丢弃 Command 更新修订；缩小普通 Frame Packet，资源
更新失败继续保留旧投影，并记录每帧复制字节变化。

状态：待开始。

### M-172：帧请求语义拆分

区分可替换实时帧和必须完成请求。为拾取、截图与自动验收建立请求身份、完成回执、超时和关闭行为，
避免关键请求被实时帧替换策略丢弃。

状态：待开始。

### M-173：背压与帧节流

依据在途帧数和可用 Frame Slot 控制生产；渲染落后时跳过昂贵帧包构造或合并实时状态，同时保证
事件、输入和逻辑更新继续执行。

状态：待开始。

### M-174：性能与跨平台验收

使用 Lantern Gallery 和扩展压力场景比较 0.25.0 基线，记录分配次数、复制字节、队列延迟和阶段
耗时；完成 Windows/Linux Shared/Static、Granit Runtime、安装消费和 Sanitizer 验证。

状态：待开始。

## 测试与验收

- 统计字段具有明确采样边界，空闲、执行、替换、过载和关闭路径均能得到一致快照。
- Frame Slot 只在对应完成回执后复用；高负载和失败路径没有悬空引用或跨线程改写。
- 静态场景普通帧不再重复复制稳定资源正文，资源修订仍按顺序原子更新。
- 实时帧积压时只保留最新状态，必须完成请求不会被替换且能可靠关联回执。
- 背压不会阻塞窗口事件线程，也不会让逻辑线程无限领先渲染线程。
- 性能 Record 同时保存 0.25.0 基线、0.26.0 结果、环境和测量方法，不只记录最佳样本。
- Windows/Linux Clang/GCC/MSVC Shared/Static、Granit Runtime、安装消费和 Sanitizer 通过。

## 风险与未决问题

- 高频计时和统计锁本身可能扰动结果；M-169 需要测量观测开销并支持关闭详细采样。
- Frame Slot 复用降低分配，但槽位过少会限制并行，过多会增加延迟和内存；默认值由基线决定。
- Render Scene 镜像会增加增量同步复杂度，需要保持 RID generation、资源修订和失败原子性。
- 必须完成请求可能形成新的队列压力，需要容量、超时和取消语义，不能借用普通 Frame 的替换规则。
- 本版本先建立内部能力；是否向 Editor Console 暴露完整性能面板由实际诊断需求另行规划。

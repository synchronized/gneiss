# VER-042：0.42.0 真实大场景驱动的异步加载与切换

## 状态

2026-09-28 完成，归档于 [v0.42.0](https://github.com/synchronized/gneiss/releases/tag/v0.42.0)。
资产审计、同步基线、异步正式矩阵与完整场景补测通过，验收与限制见
[M-273～M-278](../records/M-273-278-0.42.0-validation.md)。
完整实现使用 `feat/0.42-async-scene-loading` 分支与 [PR #57](https://github.com/synchronized/gneiss/pull/57)。

## 背景与目标

0.41 已支持渲染资产依赖准备与 GPU 确认后的整批发布，初始 Scene 与 Scene/Prefab 结构更新仍同步。
当前行为以[调度指南](../guides/task-scheduling.md)为准，性能基线见
[0.41 验收记录](../records/M-265-271-0.41.0-validation.md)。

本版目标是在真实大场景加载及同工程场景切换期间继续处理窗口与控制事件，允许取消、失败恢复，
并且不暴露部分构造的场景。先建立可复现负载和同步基线，再实施后台准备、分阶段实例化与完整切换。

## 交付范围

- Intel 官方 Sponza 基础场景的来源、许可、兼容性、规模和内存审计，以及可重复生成的测试配置。
- 内部 Scene 加载请求：后台解析场景和 Prefab 依赖、准备渲染资源，复用宿主调度器。
- 主线程有预算地构造不可见候选，渲染线程分批准备 GPU 资源；最终在安全点切换活动场景。
- Runtime 初始场景加载和同工程完整场景切换，Editor 提供阶段、取消、失败与重试反馈。
- 两种调度模式的生命周期验证；真实场景的 Debug/Release 耗时、内存、窗口操作及图像验收。

Prefab 在本版作为新场景的依赖展开和实例化。已有同场景 Scene/Prefab 结构热重载保留
[ADR-037](../decisions/ADR-037-scene-prefab-structural-hot-reload.md) 的身份协调语义并执行回归；
将其全部改为跨帧原地事务不列为本版交付。完整场景切换可以产生新实体身份，不能冒充结构热重载。

## 非目标

公共异步 SDK/API 冻结、跨工程切换、Game Module 热替换与状态迁移、完整 Web 移植、Emscripten
pthreads、任意资产流送、任务抢占、全面实现 glTF 扩展或完整 PBR 效果均不属于本版。
不因引入大型测试场景就增加新的任务池或通用 Service 注册框架；不包含 Granit 跨仓库操作。

## 真实资产策略

主负载为 [Intel 官方 Sponza Base Scene](https://www.intel.com/content/www/us/en/developer/topic-technology/graphics-research/samples.html)。
官方页面提供 glTF 和其他格式，基础下载包标注约 3.71 GB、4K 纹理及 Creative Commons Attribution
许可；这是多格式下载包大小，不是导入后大小或运行内存。已完成固定包获取、兼容修复及 Debug/Release 同步三次采样，见 [M-272 记录](../records/M-272-sponza-baseline.md)。

- 首次获取时记录最终 URL、下载时间、文件 SHA-256、包内许可与署名、所选 glTF 入口和转换工具版本。
  后续回归校验固定文件身份，不静默跟随上游替换。
- 原始包与大型派生资产使用仓库外缓存；仓库只维护清单、获取/转换脚本、配置和小型原创回归夹具。
  许可与来源记录须随允许分发的派生产物保留。
- 日常配置优先只降低贴图分辨率，保留节点层级、网格数量和依赖关系；完整版用于压力测试。
  如果转换确实需要改变结构或材质，逐项记录差异，不能把变换后的负载称为无损原版。
- 同时保留原创小场景用于确定性故障注入，以及合成多节点/共享 Prefab 场景覆盖真实静态模型缺少的情况。
- Bistro 作为后续交叉验证候选，不作为本版必需下载项，避免格式转换和第二套大型资产扩大首版范围。

M-272 必须先核对必需扩展、图片编码、材质特征、Transform、节点/实例/三角形数量、纹理解码大小
和依赖闭包。当前导入器拒绝必需扩展、动画/蒙皮，基础颜色图片只接受 PNG；不能假定原始包直接可用。
兼容转换需保留可追溯报告。不支持的特征应明确报告；不得为获得通过结果静默删除对象或贴图。

## 测试与验收

- 正确性：依赖缺失/损坏、重复身份、无效层级、Prefab 循环、覆盖冲突、源变化、缓存版本变化及超额拒绝。
- 原子性：候选不进入渲染、ECS 系统、拾取、检查镜像和游戏查询；任意批次失败时旧场景和资源版本保持。
- 生命周期：准备/上传/实例化阶段取消；提交点的迟到取消有明确结果；请求 A 取消后提交 B、迟到回执、
  连续重试、断连和退出均不串批次；旧帧结束后资源才能回收。初始加载失败显示错误并允许重试或退出。
- 交互：真实窗口中移动相机、连续 resize、最小化恢复和关闭；覆盖 Editor 到 Runtime 的实际取消与重试，
  不仅测试协议编解码。完整切换刷新检查镜像和选择，旧 ID 不被复用成其他对象。
- 图像：小夹具使用 GPU 回读精确验证旧/新场景与失败保留；Sponza 固定相机记录参考图及容差策略，
  配合对象/资源数量检查，防止空场景或丢失对象造成虚假的性能提升。
- 性能：Debug/Release 每配置每模式至少三次；分别记录离线转换、CPU 准备、主线程单次推进、最终激活、
  GPU 上传、首个正确呈现帧、事件响应、峰值内存/显存可用指标、取消与退出等待。缺少显存测量时明确标注。
  报告冷缓存与热缓存策略、硬件、样本数、P50/P95/最大值，分开统计窗口最小化与正常窗口的帧间隔。
- 两模式必须语义一致；协作模式单个解析/解码仍不可抢占，其停顿单独报告，不能宣称等同于线程池响应性。
- 小型确定性用例进入常规 CI；大型场景通过显式获取缓存的验收流程运行，CI 缺少资产时必须可见地标为
  未执行，不能返回假成功。发布要求具有可复查的大场景实测记录。
- 发布门禁沿用 Windows/Linux 共享/静态、公共头文件与安装 C/C++ Consumer、最小浏览器调度回归。
  完整引擎浏览器不由最小宿主通过推导；同一候选完整矩阵只跑一次，修复仅复验受影响范围。

## 基于 M-272 固定的实施预算与目标

2026-09-25 在异步宿主接入前，根据完整配置约 3.7 GiB 进程峰值和约 36 秒同步停顿固定以下目标：

- 原始 Scene/Prefab 描述合计最多 16 MiB，实例化节点最多 65,536，依赖最多 65,536，组合层级深度最多 1,024。
- 资产子批次的输入快照和解码输出各沿用 256 MiB 上限，两者并存时合计最多 512 MiB；
  GPU 单次命令沿用 4 项/8 MiB 预算及单项超预算规则。
  场景候选累计 CPU 资源预算 2 GiB，旧场景驻留单独计数；重复 URI 不重复计最终驻留，暂存旧版本仍须计峰值。
- 主线程实例化每次最多 64 个工作项（描述安装、节点或覆盖）或 2 ms；这是可暂停边界间的软预算，单次不可分操作单独记录。
  安全点激活目标不超过 5 ms，模块回调和旧域回收另行计时，不混入或隐藏。
- 线程池模式加载期间，非最小化窗口的事件处理间隔 P95 目标不超过 100 ms、最大值不超过 250 ms；
  测量主线程响应与渲染呈现两条独立时间线，不承诺 UHD 630 渲染此场景达到 60 FPS。
- 激活前取消目标 3 秒内确认终态；必须覆盖 CPU、GPU 与实例化阶段。协作模式不可抢占单次解析/解码，
  相同数值不作为响应性承诺，其最大停顿必须实测并报告。
- 完整场景切换的进程峰值驻留目标不超过 10 GiB；同时记录旧/新 CPU 资源及在途数据，缺少显存计数时标明。

若任何目标无法满足，保留失败结果并修订实现；变更目标需要记录原因与范围影响，不能直接改成实测结果。

## 风险与未决问题

候选采用独立 World/缓存，首次启动和切换生命周期已接入；最终激活与回收已有小场景测试和
大场景完整验收。旧场景与候选并存会增加峰值内存；暂存与已驻留资源必须分别记账。
性能门槛与完整负载硬件配置已由基线固定在上文；正式验收不得按最终结果倒设门槛。

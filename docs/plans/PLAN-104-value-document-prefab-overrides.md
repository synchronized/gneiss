# PLAN-104：场景文档归属、编辑版本与 Prefab 覆盖

## 状态与范围

2026-11-07：实施中，按高内聚、低耦合目标调整剩余范围和实施顺序。
结构化 value、反射捕获/恢复、值编辑/diff、Prefab 冲突回放和不可变快照已经实现；
文档权威来源、组件实例身份及统一版本历史尚未完成。
阶段验收见[实施记录](../records/2026-11-07-structured-value-editing.md)。
归属 [DEV-052](DEV-052-architecture-cleanup.md)，决策见 [ADR-109](../decisions/ADR-109-value-document-model.md)。

本次调整保留已验证能力，不把统一 value 扩大成所有模块共用一套文档/事务协议。
允许删除旧快照和旧写入入口，不兼容未发布旧格式；资产加载继续遵循 [PLAN-102](PLAN-102-resource-object-loading.md)。

## 已完成基础与当前缺口

- [x] 不可变结构化 value、结构比较、稳定路径和值编辑操作。
- [x] 反射捕获/恢复、多态引用转换、外部资产身份及错误路径。
- [x] Prefab 有序覆盖、来源重放、失效目标与锚点冲突保留。
- [x] 移除 property_snapshot 的 JSON 中转，文档、子树和组件历史冻结内容。
- [x] 属性撤销只恢复编辑路径；编辑其他字段不丢弃无关 Prefab 冲突。
- [x] 组件适配器及描述集合 update 隔离内嵌引用候选；集合 update 校验后提交，失败回调不改写来源。

当前 scene_document 仍绑定运行时场景，部分保存与历史从 World/Scene 捕获；
组件通过类型定位而没有独立实例 UUID；文档内容、资源准备、历史推进和运行时恢复仍存在耦合。
这些是下一步需替换的实际入口，不能把已有值树能力描述为文档归属已经迁移完成。

## 已确认边界

| 层 | 职责 | 禁止承担 |
| --- | --- | --- |
| Core / Meta | 值、属性路径、反射转换、值编辑 | 场景层级、Prefab、历史、资产加载 |
| Scene 领域逻辑 | 对象/组件身份、层级校验、Prefab 组合与差异 | 编辑器历史、文件 I/O、GPU |
| Editor 文档 | 当前编辑版本、编辑入口、撤销重做、保存点 | 反向推测 World 中的用户编辑意图 |
| World 适配 | 将领域内容安装/更新到运行时，报告同步结果 | 修改编辑内容的权威版本 |

分层通过依赖方向和纯函数实现，不为每个阶段增加 Service、注册表或拥有者。
纯文档内容及候选计算不得依赖 Application、World 或历史执行器；宿主适配负责这些对象的连接。

## 数据模型目标

领域结构保持强类型，组件属性内容统一使用 value。下面是目标示意，尚非当前 API：

```cpp
struct component_record {
  guid uuid;  // 组件实例身份
  guid type;  // 类型身份，用于恢复和校验
  value properties;
};
struct object_record {
  guid uuid;
  guid parent;
  std::string name;
  math::transform transform;
  std::vector<component_record> components;
  // 显式 Prefab 来源与覆盖信息由场景领域模型表达。
};
```

对象/组件身份、父子关系不依靠通用字段路径猜测。类型 GUID 不代替组件实例 UUID；
删除后重建同类型组件具有新身份，旧覆盖不得自动绑定。首版仍可限制每类型一个组件。
文档版本逻辑不可变，优先复用现有不可变值；按实际需要共享未修改记录，不先建设通用持久化树框架。
普通无身份列表整体替换；有稳定身份的集合才使用元素增删移动。资产保留来源身份，运行时引用由绑定适配负责。

## 三种修改语义

- 编辑命令表达意图：set_property、add/remove_component、reparent_object、remove_subtree 等。
  领域命令执行对应校验，不把改父节点和删子树伪装成任意字段 set。
- 历史以前后文档版本为准；操作服务于执行、合并和变更通知，不要求永久重复存储完整前后根与完整日志。
  连续拖动可以合并为一个历史条目，新编辑清除 redo 分支。
- Prefab 覆盖保存实例相对来源的持久差异，不保存完整交互日志。
  同路径 set 归并、恢复来源值删除无效差异；集合操作保留必要顺序，失效覆盖及诊断保留。

三者共用 value、稳定身份和路径，不共用一套生命周期或事务状态机。
跨字段约束在完整候选上校验；无关冲突不撤销成功的独立覆盖。结构非法拒绝接受候选；
资源暂未就绪不否定已经合法的编辑内容。

## 实施顺序与验收

### 1：领域结构与依赖边界

- [x] 分离纯文档内容/候选计算与宿主历史/运行时恢复，删除内容头文件对运行拥有者的依赖。
- [x] 落地强类型对象/组件内容记录，替换文档、子树及 Prefab 放置历史的整场景 value 存储。
- [ ] 组件 UUID 贯穿文件、编辑、覆盖、恢复与复制；现有记录仍按组件类型定位。
- [ ] 统一对象/组件身份与属性路径边界，拒绝重复身份；不为无身份容器生成临时 ID。

验收：纯候选构建无需 Application/World；同类型组件重建不继承旧覆盖；文件往返保持身份。

### 2：唯一编辑入口

- [ ] 场景文档持有当前不可变领域版本；编辑先生成并校验候选，再接受版本。
- [ ] 属性、组件生命周期、父子调整和子树操作使用明确领域入口，复用值操作而非旁路写 World。
- [ ] 保存、查询和历史读取文档版本；删除反向捕获 World 推测编辑内容的入口。

验收：修改运行时状态不偷偷改变保存内容；结构错误不接受新版本；无第二套长期双写权威数据。

### 3：版本历史与子树

- [ ] 历史以前后版本为准，支持合并、保存点、redo 分支清除与现有条数限制。
- [x] 子树复制通过领域记录重映射对象/父关系和嵌套值中的内部对象引用；外部引用保留原身份。
- [ ] 接入组件实例身份重映射；外部目标存在性及失效诊断由文档引用校验补齐。
- [ ] 来源刷新历史保留当时的不可变源内容和覆盖；历史资源保活由所属层显式持有。
- [ ] 删除被统一版本取代的专用内容捕获/恢复路径。

验收：旧版本不随新编辑变化；撤销不读文件；清空历史释放保活；未参与编辑的属性不被回退。

### 4：Prefab 持久差异

- [x] 来源节点变换、来源组件及本地新增组件的编辑候选计算与 World 分离，统一差异归并、恢复来源及无关冲突保留；运行时入口调用该计算。

- [ ] 相同领域编辑入口生成覆盖；整体替换才以 diff 补充，不从运行时有效结果丢弃未解决冲突。
- [ ] 组件 UUID、来源对象身份参与目标定位，明确本地新增与来源组件边界。
- [ ] 归并重复 set、恢复来源、稳定集合操作及冲突诊断；保持独立覆盖可继续生效。

验收：来源删除/重建组件不误绑定；修改无关字段保留冲突；序列重排不造成错位；资源引用不深拷贝资产。

### 5：World 同步与收尾

- [x] 文档整场景恢复不等待视觉资源就绪；历史保活实际绑定身份，加载失败仍可捕获、保存及撤销重做。

- [ ] 明确文档版本与已同步运行时版本，失败保留文档、记录诊断并允许重试。
- [ ] 首版允许对象/子树级重建；结构非法与资源未就绪的处理分开，不承诺精细增量更新。
- [ ] 运行时不携带编辑器历史；来源与资产解析通过现有接口连接，不新增服务层。
- [ ] 同步 Reference、格式、测试与调用方，扫描旧旁路写入并完成编译验收。

验收：World 更新失败不反向覆盖文档，也不报告已经同步；资源未就绪不丢失编辑；保存不依赖投影成功。

## 后续独立阶段（不作为本轮完成条件）

以下能力仍在路线中，明确延后而非视作已完成；另立计划后实施：

- 嵌套 Prefab：实例路径与来源身份的组合、循环来源拒绝、局部覆盖与多层冲突。
- 精细增量投影：根据测量结果缩小更新范围，保持上述权威边界。
- 精确历史内存预算：共享节点去重计量与资源保活成本；本轮保留条数限制。

## 非目标与验证约束

不实现自动共享对象图、循环引用捕获、CRDT、跨文件事务或 GPU 回滚；
不动态化每帧 ECS，不把 Service/RID/后端对象写入文档，不深拷贝外部资产。
JSON 的动态值继续使用 $kind/$content，内存编辑不经 JSON；文件头和领域校验保持既定边界。

每阶段优先相关编译与定向测试，不运行 GPU 大场景或耗时远端 CI。
连贯改动通过验证后本地提交，记录真实状态，不自动推送或发布。

# VER-017：0.17.0 Runtime 实时属性编辑

## 状态

- 状态：设计中
- 目标版本：0.17.0
- 优先级：P0
- 路线图阶段：Runtime 实时属性编辑

## 背景与目标

0.16.0 已建立 Runtime 权威采样和 Editor 只读镜像。0.17.0 在保持进程、线程和作者数据隔离的前提
下，让开发者从 Editor 修改 Runtime 的受支持属性，获得明确的成功、拒绝和冲突反馈，并可选择把
稳定结果应用回作者场景。

首个完整闭环聚焦 Transform：暂停或运行期间修改平移、欧拉角展示对应的四元数和缩放；Runtime
主线程执行后，Editor 通过权威镜像观察结果。默认修改不保存，只有显式“应用到作者场景”才进入
现有撤销/重做与保存流程。

## 非目标

- 不实现任意内存、脚本变量、调用栈、断点或远程设备调试。
- 不允许写入未登记、只读或不具备类型安全转换的字段。
- 不把运行时生成节点、RID、后端句柄或整个 Runtime 场景回写到作者场景。
- 不建立多用户协同编辑、分布式事务或跨机器网络协议。
- 不重构 ImGui 工作区，不在本版本启动自研 GUI。
- 不承诺属性写入协议属于稳定公共 ABI。

## 已确认决策

- 采用 [ADR-030](../decisions/ADR-030-runtime-property-editing.md) 的命令、确认与显式回写模型。
- Runtime 是运行值的唯一权威；Editor 镜像不进行乐观写入。
- 写入命令复用现有鉴权 IPC、控制优先级和专用 I/O 线程，在 Runtime 主线程安全点执行。
- 属性使用 Type ID、Field ID 和受限值类型寻址，不依赖 C++ 成员偏移或第三方类型。
- 期望修订号用于拒绝过期编辑；Editor 收到冲突后刷新镜像，不自动覆盖更新值。
- 默认运行态编辑随会话销毁；作者回写必须由用户显式触发。

## 实施顺序

### M-109：属性写入协议与版本协商

提升私有协议次版本并协商 `runtime_property_edit_v1` 能力。定义写入命令、结果、命令 ID、属性地址、
期望修订号、规范值和有界类型化负载；覆盖未知消息、错误类型、超长值和旧版本降级。

### M-110：Runtime 主线程命令执行

建立 I/O→主线程有界命令队列。主线程校验会话、对象 generation、组件、字段权限、值类型和修订号，
通过既有属性访问路径执行写入，并返回稳定错误语义。I/O 线程不得访问 Scene Tree 或 ECS。

### M-111：Editor 待处理状态与结果反馈

为每个属性跟踪至多一个在途命令，显示待处理、已应用、被覆盖或被拒绝状态。处理超时、断线、Stop、
对象删除和新会话；结果不得污染作者命令历史。

### M-112：Transform 运行态编辑闭环

在 Runtime Inspector 中开放平移、旋转和缩放。编辑器继续以欧拉角交互、四元数传输和存储；拖动输入
合并为有限频率的最新值。验证暂停时稳定写入，以及运行时游戏逻辑可能覆盖结果的真实行为。

### M-113：显式应用到作者场景

通过持久化 UUID 将选中的受支持 Runtime 属性映射到作者节点。应用操作生成既有 Editor 命令，支持
撤销、重做、脏状态和保存；缺少映射、运行时生成对象及只读字段必须拒绝。

### M-114：冲突、过载与故障恢复

覆盖修订冲突、重复结果、响应乱序、队列满、慢 Runtime、崩溃和连续 Play。属性流量不得阻塞
Pause、Resume、Stop、心跳和致命错误；断线后不自动重放旧写入。

### M-115：示例与跨平台验收

使用 Lantern Gallery 自动验证编辑、暂停稳定、游戏逻辑覆盖提示、显式作者回写、撤销/重做、保存和
新会话隔离。完成 Windows 本地矩阵以及 Linux Shared/Static、Granit Runtime 与 Sanitizer Actions。

## 测试与验收

- 协议测试覆盖命令/结果往返、边界长度、未知类型、旧版本和错误负载。
- Runtime 测试证明写入只发生在主线程，并覆盖对象失效、字段只读、类型错误和修订冲突。
- Editor 测试覆盖待处理状态、结果乱序、超时、断线、停止和新会话隔离。
- Transform 测试覆盖平移、欧拉角与四元数转换、缩放及 Runtime 规范值回传。
- 作者回写测试覆盖 UUID 映射、撤销/重做、脏状态、保存和拒绝临时对象。
- 过载测试证明控制消息优先，属性写入和结果队列保持有界。
- 最终形成 M-115 验收记录，并在发布前手动执行远端矩阵。

## 风险与未决问题

- 游戏逻辑持续写同一字段时，运行态编辑可能只保持一帧；首版明确展示“被覆盖”，不引入属性锁。
- 是否在拖动期间每帧发送或仅在提交时发送，需要用延迟和队列水位测试确定；默认先节流并合并。
- 首版作者回写只覆盖 Transform；Camera 等组件在具备真实编辑需求后再扩展。
- 多字段原子事务、批量编辑和 Prefab 覆盖留给后续版本，不扩大首个闭环。

## M-325：基准与采样

1. 在真实 Editor 加载完成、后台加载与上传状态已明确后开始稳定阶段采样。
   首次移动与预热后的移动分别记录，不能通过预热隐去首次使用尖峰。
2. 固定相机初始姿态与按时间推进的路线，覆盖旋转、平移、拉近拉远，以及室内外/遮挡变化。
   静止相机使用同等采样时长。相机动画只测绘制变化；若声称输入响应改善，另测输入投递到
   相机状态消费，不把队列等待直接当作输入到屏幕延迟。
3. 记录提交、二进制、资产摘要、CPU/GPU/驱动、Release 配置、分辨率、DPI、呈现模式、
   质量设置、缓存/预热策略与外部负载。性能采样不与构建或其他 GPU 测试并行。
4. 日常小场景与完整 Sponza 各至少三次独立进程重复；保留失败、超时和原始数据。
   先固定时长与路线，再运行；不按结果延长或缩短样本以获得通过。

## M-326：成本分解与对照

优先复用现有内部计时和异步 GPU 回执，不创建第二套渲染状态。逐帧数据关联帧号、
相机快照和对应 GPU 回执；回执未就绪标记缺失，不能重复最近值伪装成全帧分布。
CPU 与 GPU 流水重叠，acquire/present 等待也可能重叠，不简单求和或相减推断未知开销。

记录主线程场景/快照开销、渲染线程资源准备、命令录制提交、交换链获取、呈现等待，
以及 GPU 阴影、不透明和其他实际启用阶段；同时记录 draw call、三角形、可见物体、
上传量、队列深度和可取得的资源内存指标。暂不支持的计数明确标记不可用。

在相同相机路线下逐项对照：

- 视口分辨率变化：检验像素着色与带宽方向，不能据此单独断定具体 Shader 热点。
- 阴影开关：量出阴影相关成本，保持其余设置不变。
- 绘制对象数量变化：只修改诊断绘制集合，保持场景身份、相机和资源驻留可比，
  避免加载资源变化与几何成本混杂；诊断集合不作为完整场景验收输入。
- 静止与移动：检查剔除、资源上传、管线编译或其他随视角变化的工作。

以帧时间 P50/P95/P99、最大值及超限比例报告，显示 FPS 用实际呈现数/采样时长计算。
详细观测开关作开销对照；必要时用 Tracy/RenderDoc 辅助，捕获结果不代替无捕获基线。
完成归因后，在生产优化前登记数值目标、对照方式、质量要求与内存/加载回归上限。

## M-327：实现选择与边界

根据 M-326 选择最主要且可独立验证的一至两项优化，明确其余候选的暂缓理由。
先核实上游已有能力及实际调用路径；不因引擎通常使用 LOD 就直接建设完整 LOD 系统。
若选择预览质量，设置不能修改作者材质或场景内容，必须支持完整质量切回。
若选择 LOD 或流送，先补离线资产生成、资源所有权、取消/淘汰、预算和失败回退的 ADR。

上游需求待归因后登记，当前没有确认的新需求。登记应包含复现证据、通用性、
最小接口与行为、线程边界、成功/失败/生命周期测试及 Gneiss 接入方式。
不得把待上游实现描述为已完成；被阻塞时明确本事项可交付范围，不静默删除目标。

## M-328：测试与验收

- 同设备、相同完整输入及质量配置，基线与候选各至少三次，报告组结果与所有异常样本。
- 默认画质保持正确，检查阴影、材质、透明物体、网格和选中/Gizmo 叠加；涉及剔除或 LOD
  时补可见边界、相机跨越与切换稳定性验证，不能通过错误漏绘提高帧率。
- 回归持续相机运动、连续 resize、最小化恢复、加载取消、场景切换及退出，保持资源预算。
- 保留 0.50 的加载响应与生命周期门槛；小场景、完整质量和低质量模式分别报告。
- 根据改动运行相关单元/集成测试、真实 GPU、Windows/Linux；公共接口变更同时覆盖
  C11/C++20、共享/静态和安装消费者。只更改文档不重复触发矩阵。

通过冻结目标后才完成版本收口。结果归档在 Record，发布后才创建 对应版本的归档页；
保留未解释成本、未验证设备与画质权衡，不把单机改善描述成跨设备流畅保证。

# VER-005：0.5.0 基础 3D 场景闭环

## 状态

- 状态：设计中
- 目标版本：0.5.0
- 优先级：P0
- 路线图阶段：基础 3D 场景

## 背景与目标

`0.4.0` 已能加载纹理资产并渲染可交互的 2.5D 场景，但对象遮挡仍依赖显式 Z 排序，没有 Camera、
深度缓冲、法线或光照。`0.5.0` 的目标是建立第一条真正的 3D 内容路径：场景提供 Camera 与带法线
Mesh，World 提取稳定的视图和渲染实例，Granit 使用深度测试和基础光照渲染，示例允许用户从不同
角度观察空间关系。

```text
Scene Tree Transform + Camera 组件 + Mesh/Material 资产
→ World 变换传播与 Render Snapshot
→ View/Projection + 深度缓冲 + 基础光照
→ 可观察、可遮挡、可卸载的 3D 场景
```

## 非目标

- 完整 PBR、阴影、点光源、聚光灯、IBL、HDR、后处理和 Render Graph。
- 骨骼动画、蒙皮、粒子、地形、LOD、实例化和 GPU 驱动渲染。
- glTF 完整导入器、离线资产烘焙器和通用内容构建管线。
- 物理、音频、网络、脚本、反射系统和编辑器 UI。
- 在公共接口暴露 Granit、Vulkan 或平台相关矩阵类型。
- 以本版本冻结长期渲染 API 或资产 ABI。

## 已确认决策

- 3D 坐标、Camera 和后端变换的拟议边界见
  [ADR-012](../decisions/ADR-012-3d-camera-coordinate-boundary.md)，已由 M-32 数学测试验证并接受。
- Camera 是 ECS 纯数据组件，活动 Camera 的选择由 World/Application 状态管理，不由节点持有后端对象。
- Render Snapshot 携带完成一帧渲染所需的不可变值，不携带 Camera 指针、Scene Node 或 Granit 类型。
- 首版每个 World 只允许一个活动 Camera；多视口、Render Target 和编辑器 Camera 留待真实需求出现。
- 现有 2.5D Z 排序仅作为无深度兼容路径；3D 不以排序代替深度测试。
- Mesh v1/v2 和 Material v1/v2 继续可读；新增字段通过新 Schema 版本引入。
- 基础光照只包含一个方向光和环境项，参数先由场景或 Application 描述提供，不建立通用灯光系统。

## 实施顺序

### M-32：3D 坐标、Camera 与后端边界

状态：已完成。内部 Camera 数学模块已经固定列主序、右手视图、Camera 缩放忽略规则，以及 Vulkan
深度范围与帧缓冲 Y 方向适配；已知点和非法参数测试通过。

1. 用最小数学测试验证右手坐标、观察方向、矩阵存储和深度范围约定。
2. 明确引擎空间到 Granit/Vulkan 裁剪空间的唯一转换位置。
3. 确认 Camera、Render Snapshot 和 C ABI 描述结构的字段、所有权与扩展方式。
4. 验证通过后将 ADR-012 状态改为“已接受”。

验收：同一组已知点在 C、C++ 和 Granit 路径得到一致的可见性、屏幕方向和深度关系。

### M-33：Camera 组件与帧提取

1. 增加透视 Camera 的版本化 C11 描述和轻量 C++20 包装。
2. 在 ECS 中保存纯 Camera 数据，并提供活动 Camera 的设置、查询和失效语义。
3. 扩展 Render Snapshot，提取 Camera 的世界变换、视图矩阵、投影参数和视口尺寸。
4. 覆盖无 Camera、重复切换、实体销毁、跨 World 使用和窗口尺寸变化。

验收：无 Granit 后端即可确定性提取一帧 Camera 数据，销毁活动 Camera 后返回稳定错误或明确降级。

### M-34：深度缓冲与 3D 遮挡

1. 为 Granit 交换链路径建立与尺寸匹配的深度资源、附件和 Pipeline 状态。
2. 在窗口创建、重建和销毁时同步管理深度资源生命周期。
3. 使用相交或前后重叠几何验证遮挡与清除，不再依赖 ECS 遍历顺序。
4. 保留无深度 2.5D 路径的兼容测试，明确其适用范围。

验收：交换绘制顺序不改变 3D 遮挡结果，窗口重建后深度资源有效且无泄漏。

### M-35：3D Transform 层级传播验收

1. 审核现有平移、四元数和缩放组合是否满足 3D 父子节点传播。
2. 增加旋转父节点、非均匀缩放、深层层级和 reparent 的数学与场景测试。
3. 明确不可逆变换、零缩放和非有限输入的错误或降级语义。
4. 仅在测试证明现有实现不足时修改 Transform 契约。

验收：三层以上场景树的世界变换与独立参考计算一致，节点与实体映射保持稳定。

### M-36：Mesh v3 法线与基础光照材质

1. 为 Mesh v3 增加每顶点法线，并保持 v1/v2 严格解析与兼容。
2. 定义法线变换规则，处理非均匀缩放和退化输入。
3. 扩展 Granit 着色器，实现一个方向光、环境项、base-color Texture 和颜色因子。
4. 为旧 Mesh 提供明确的无光照兼容路径，不隐式生成质量不可控的法线。

验收：法线方向、颜色空间和材质乘法可由确定性场景测试区分；旧资产显示结果保持可解释。

### M-37：3D 场景、观察控制与版本验收

1. 将原创神殿扩展为具有地面、立柱、前后遮挡和不同法线方向的 3D 场景。
2. 提供轨道观察或自由观察控制，并保留确定帧数的 Smoke Test 模式。
3. 验证加载、窗口重建、Camera 切换、输入、卸载和退出完整生命周期。
4. 执行 Windows/Linux、共享/静态、Granit 运行时与安装 Consumer 手动矩阵。

验收：干净构建可从场景 URI 进入 3D 场景，移动观察视角后遮挡和光照正确，资源可完整卸载。

### M-38：glTF 导入与工具需求评估

基于手写 Mesh v3 场景的真实成本，记录是否需要 glTF 子集导入、离线转换或调试 UI。该任务只形成
结论和后续范围，不阻塞 `0.5.0`，也不得把第三方格式结构直接变成运行时公共契约。

## 测试与验收

- 公共 C11 头和 C++20 包装独立编译，新增描述结构包含 `struct_size`。
- Camera 生命周期覆盖零值、类型错误、generation 失效、跨 World/Application 和重复销毁。
- 数学测试覆盖视图/投影、父子 Transform、非均匀缩放、非有限输入和窗口宽高变化。
- 深度测试覆盖绘制顺序独立性、清除、重建和前后裁剪边界。
- Mesh v1/v2/v3、Material v1/v2 与现有场景继续通过回归测试。
- Linux 无头图形环境执行真实 3D 示例；Windows 无 Vulkan ICD 时只执行无需 GPU 的运行时测试。
- Windows/Linux、共享/静态、核心、Granit 与安装 Consumer 矩阵全部通过。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 坐标与矩阵约定分散 | ADR 固定引擎约定，后端转换集中在 Render Service 边界 |
| Camera 状态侵入 Scene Node | Camera 保持 ECS 纯数据，节点只通过实体 ID 关联 |
| 深度资源随窗口重建泄漏 | 建立明确的尺寸代次和销毁测试 |
| Mesh v3 破坏旧资产 | 版本分支严格解析，旧版本走明确兼容路径 |
| 光照范围扩张为 PBR | 只实现单方向光和环境项，其他能力独立规划 |
| 过早引入导入工具 | 先用真实 3D 场景量化手写资产成本，再执行 M-38 评估 |

## 版本完成条件

- M-32～M-37 全部完成，M-38 可明确暂缓或形成后续计划。
- Camera、Transform、深度和基础光照形成加载、渲染、交互、诊断与退出闭环。
- 旧资产兼容，新增后端资源不进入公共 ABI，窗口重建和卸载后资源无泄漏。
- 远端 Linux/Windows 手动矩阵通过并形成 `0.5.0` 验收记录。

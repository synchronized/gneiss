# VER-044：0.44.0 大场景纹理内存与加载

## 状态与背景

2026-09-30 已开始 M-286 容量统计与源码审计，运行时优化尚未实现。当前发布版本为 [0.43.0](../versions/0.43.0.md)。
实施步骤见 [DEV-044](DEV-044-texture-residency.md)，所有权决策见
[ADR-052](../decisions/ADR-052-texture-residency-and-budgets.md)。

0.43 的完整 4K Sponza 作者 PNG 加载路径超过 2 GiB CPU 候选预算，未完成激活；实际测量见
[M-284～M-285](../records/M-284-285-0.43.0-validation.md)。这不是 Cook 后 BC7 路径的测量结果。
项目已有 BC7 与 RGBA8 回退变体；当前运行纹理加载器读取整个封装并保存全部负载，渲染后端才选择变体。
本版先测清这些路径，再减少读取、复制与驻留，不将已有压缩支持视为问题已解决。

## 目标与范围

在支持 BC7 的验证设备上，使用现有 Cook 链路保留完整 Sponza 的几何、材质、原始 4K 分辨率及
约定 Mip 链，在现有候选预算内完成加载、三次场景切换及取消重试。不得通过降低分辨率、裁剪资产、
跳过贴图或扩大候选预算替代验收。全进程内存和 GPU 占用另行报告，不等同于候选计数。

| 优先级 | 交付 | 边界 |
| --- | --- | --- |
| P0 | 分阶段内存和耗时证据 | 区分文件读取、解码、候选、上传暂存、活动资源与 GPU 资源 |
| P0 | 仅准备所选纹理变体 | 设备选择与工作线程读取分离，保留格式校验和 RGBA8 回退 |
| P0 | 明确 CPU 负载驻留与重建 | 上传完成、旧帧、重试、资源重建及文件变化均有所有权契约 |
| P0 | 统一预算预留和回收 | 覆盖活动资源、候选及上传暂存，共享租约只计一次 |
| P0 | Runtime 与 Editor 闭环 | 共用加载路径；显示阶段、预算失败及取消结果，保留原子切换 |
| P0 | 真实场景和平台验收 | 完整 Cook 场景、日常配置、原始 PNG 兼容路径及发布矩阵 |

不支持 BC7 的设备必须正确选择 RGBA8；容量不足时保留旧场景并明确拒绝，
不承诺未压缩完整 4K 场景也能进入 2 GiB 候选预算。原始 PNG 路径保留现有能力和错误语义。

## 非目标

视距驱动的 Mip 流送、虚拟纹理、几何 LOD、新压缩格式家族、通用全引擎内存管理器、
第二套任务池、SDL3 切换及完整引擎 Web 移植。不会将 Gneiss 资产格式、RID 或场景语义下沉到 Granit。

## 验收门槛

- 保留 2 GiB CPU 候选上限。活动资源和上传暂存的独立限额、进程峰值目标在 M-286 根据实测冻结，
  实现前写入开发计划；不能只统计选中负载却遗漏仍然持有的文件、解码或上传副本。
- 沿用大场景响应性门槛：事件间隔 P95 不超过 100 ms、最大不超过 250 ms、激活不超过 5 ms、
  取消完成不超过 3 s。分别记录 Debug/Release、线程池/协作模式结果；不把协作任务描述为可抢占。
- 三次切换后回到同一场景的资源与预算稳定；取消、失败、关闭后候选与暂存归零，活动资源按租约释放。
  RSS 不要求回到精确起始值，但必须解释持续增长及分配器保留，不能只用 RID 数证明无泄漏。
- 小夹具验证全部 PBR 贴图、颜色空间、法线、Alpha 与 Mip；BC7 是有损格式，采用固定视角和
  M-286 冻结的误差门槛比较，不要求与 PNG 图像逐字节相等。
- 完整场景成功目标未达成即保留阻塞状态；任何缩减范围需明确说明，不能将预算拒绝当作成功加载。

# PLAN-051：统一资源强引用与生命周期规则

## 状态

已完成。Windows Clang Debug 全目标编译、clang-format 检查和架构边界静态检查通过；
测试代码已编译，未执行测试、大场景或 CI。决策见 [ADR-077](../decisions/ADR-077-asset-references.md)。

## 目标与范围

提供基于 shared_ptr 的 asset_ref<T>，统一通用 CPU 资产、Prefab 和渲染资产的强引用入口。
删除重复的专用 lease 类和无意义的引用转换，不引入资源基类或第二套引用计数。
不修改公共 C ABI、ECS 的 RID 存储或 GPU 后端同步，不增加跨线程销毁队列。

## 实施顺序

1. 实现强引用、只读转换、别名引用和最终释放的契约。
2. 通用请求与同步加载返回 asset_ref；Prefab 使用同一引用类型。
3. 渲染资产统一缓存条目强引用，类型、URI 和 RID 使用显式辅助访问。
4. 统一缓存显式回收规则；清除通用管理器遗漏的来源二次读取。
5. 调整引用生命周期、缓存回收、失败和重载测试，编译全部目标。

## 验收

源码不再声明旧专用 lease 类；缓存回收不销毁在途请求或仍被引用的资源。
CPU 重载保留旧引用内容；渲染重载维持稳定 RID；失败保留既有成功数据。
验证强引用最后释放一次、别名保活、常量转换及缓存回收后再次加载。
按用户要求只编译测试目标，不执行测试、大场景或 CI。

## 风险

强引用不提供对象数据线程安全，不改变渲染服务必须晚于资产引用销毁的约束。
CPU 描述和可变渲染槽位的更新行为不同，必须明确记录，不能将 RID 就绪等同于引用非空。

# VER-023：0.23.0 核心 API 与依赖基线

## 状态

- 状态：实现中
- 目标版本：0.23.0
- 优先级：P0
- 路线图阶段：核心 API 与依赖基线

## 背景与目标

0.22.0 已完成首批渲染资产热重载。在继续扩展 Scene、Prefab 或 Game Module 热重载前，0.23.0
先收口两项已经暴露的基础问题：Gneiss 使用的 Granit 锁定点落后于 v0.5.0 发布基线；C++ 结果
接口仍以枚举和重复自由函数表达，调用方式不够集中。

本版本不增加用户功能，而是建立可重复的 Granit 依赖解析、统一的轻量结果值接口，并重新验证
C/C++ Consumer、Shared/Static 与跨平台运行路径，为后续结构热重载减少基础设施变量。

## 非目标

- 不增加 Scene、Prefab、Game Module 或原生动态库热重载。
- 不改变 `gneiss_result` C ABI、既有结果码数值或错误文本所有权。
- 不把 Granit 类型暴露到 Gneiss 公共接口。
- 不升级与本次兼容性无关的第三方依赖。
- 不冻结 1.0.0 的 Stable API 范围或 C++ 二进制 ABI。
- 不新增渲染特性、Editor 面板或项目格式迁移。

## 已确认决策

- Granit 继续通过完整提交哈希锁定，目标为 v0.5.0 发布基线；不跟踪浮动分支。
- `PACKAGE` 模式要求与锁定基线同代的 Granit 0.5 package，不静默接受 0.4 package。
- `gneiss::result` 只保存一个 `gneiss_result`，提供 `ok()`、`failed()`、显式布尔转换、
  `native()` 和 `message()`。
- 默认构造结果为 `unknown`，避免尚未赋值的对象静默表示成功。
- 未发布阶段删除含义重复的 C++ 结果自由函数，不保留平行兼容层；C API 保持不变。
- 用户显式指定的 Granit 仓库或提交必须保留；项目默认锁定点升级不能被旧默认缓存永久遮蔽。

## 实施顺序

### M-151：Granit v0.5.0 依赖基线

更新完整提交锁定，按 Granit 0.5 迁移说明适配结果判断和底层结果码访问，验证现有窗口、输入、
渲染管线和 Runtime 路径没有语义变化。

状态：已完成。Granit 已更新至 `eb970c74570e278678ee39530c68afc40101879f`，Windows 与 Linux
Shared/Static、Granit Runtime 和 Sanitizer 验证均通过。

### M-152：C++ Result 值类型

将 `gneiss::result` 从枚举改为轻量值类型，迁移 Gneiss 自有调用点，补充布局、平凡复制、未知值
保留、布尔语义和错误文本测试，并同步公共接口参考。

状态：已完成。C ABI 与结果码数值未改变；重复的 `succeeded()`、`failed()` 和 `result_message()`
自由函数已删除。

### M-153：Granit Provider 可重复性

审计 `AUTO`、`PACKAGE`、`FETCH` 与父工程目标复用路径。更新 package 最低版本；为默认提交缓存
建立可验证的升级语义，使项目默认值变化能更新沿用旧默认值的构建目录，同时保留用户显式覆盖。
补充全新配置、旧默认缓存和显式固定版本三类测试或配置验收。

状态：待开始。

### M-154：0.23.0 发布验收

更新版本号与 Changelog，验证 C11/C++20 Consumer、Shared/Static、Granit `PACKAGE`/`FETCH`、安装
消费、Windows/Linux、Runtime 和 Sanitizer。形成发布验收记录后再创建 `v0.23.0` 标签。

状态：待开始。

## 测试与验收

- `gneiss_result` 的类型宽度、数值、导出符号和 C11 Consumer 与 0.22.0 保持兼容。
- `gneiss::result` 保持单个 32 位字段、标准布局和平凡复制；默认值、已知值和未知值行为有测试。
- Gneiss 源码不再调用已删除的 Granit 或 Gneiss 结果自由函数。
- 全新 `FETCH` 配置准确检出锁定提交；沿用旧默认值的缓存能够升级；用户显式覆盖不被改写。
- `PACKAGE` 模式接受 Granit 0.5 兼容 package，并明确拒绝缺失组件或过旧版本。
- Windows/Linux Clang/GCC、Shared/Static、Granit Runtime、Sanitizer 和安装 Consumer 通过。

## 风险与未决问题

- CMake 无法仅凭当前缓存值判断它来自旧默认值还是用户显式覆盖，需要记录上一默认值或采用等价的
  可追踪方案，不能通过无条件 `FORCE` 覆盖用户选择。
- Granit v0.5.0 删除桌面 WebGPU Provider；Gneiss 当前桌面路径使用 Vulkan，不在本版本恢复该
  后端。
- `result` 从枚举改为结构体会造成 C++ 源码迁移，但项目尚未发布，不为旧自由函数增加弃用周期。
- 下一版本是否选择 Scene/Prefab 结构热重载，需要在 0.23.0 收口后单独讨论并建立 ADR，不在本
  Plan 预先承诺。

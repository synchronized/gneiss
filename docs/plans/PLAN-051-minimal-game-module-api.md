# PLAN-051：收缩公共 SDK，保留游戏模块边界

## 状态

实施中。前两步已落地：模块头文件独立、调用原生对象，模板及 Lantern Gallery 已迁移。
Game Context 用例初始化改为原生对象；C11 头文件检查拒绝引入完整 SDK。
公共 C++ 值头已迁入 src，实体/节点 ID 不再依赖 C 布局，结果类统一为 engine::result。
旧值转换暂存在 src/engine/values，不安装；其 C 布局依赖及完整 C API 删除仍待完成。
输入重复值类型和 C API 查询包装已删除；三个图形示例的创建、输入、主循环、场景加载和节点操作
均使用原生接口，不再绑定 Application 兼容桥。URI 校验及内建类型 ID 的闲置辅助入口已删除。
内建 Transform/Camera 身份改为 Core 原生常量，编辑器面板不再调用类型 ID 的 C 入口；
未使用的旧 RID 包装已删除，反射共享值不再引入结果转换头。
重复日志消息/事件包装已删除，日志用例改用原生 Application；C 边界保留布局检查，
消息语义校验统一在 Core。重复 Transform 值已删除，编辑文档、相机和 Gizmo 使用原生
Transform；编辑文档相机数据和操作参数也改用原生描述。当前仍不能删除整个 include 目录。

稳定反射身份统一为 `engine::type_guid`，运行期键更名为 `engine::type_id`；静态名称和身份
定制点移至 `core/traits`。既有组件 GUID 与场景序列化字段保持不变；注册表身份、注册描述与内部查询键也已使用原生 GUID。
属性访问与候选回调使用原生属性值、目标和类别，Prefab 覆盖不再构造 C 属性值；
原生快照读写与元数据查询直接访问注册表记录，不再往返 C 布局。闲置的 reflection/world
汇总值头、反射转换 inl 和旧描述类型已删除。属性检查器示例改用原生元数据枚举、
属性访问、场景保存和重载接口。场景服务和实例持有原生 Registry 引用，Prefab 操作直接借用，
不再通过公共句柄创建、查询和销毁注册表。旧 C 查询缓存、C 回调身份及公共 Registry 句柄仍待清理。

## 目标与非目标

同源码构建的 Engine、Runtime、Editor 和工具统一消费 src 原生接口与共享值。
游戏动态模块保留生命周期、输入、日志及实际游戏行为所需的显式协议。
不通过把整套 SDK 改名搬进 src 宣称完成，不新增第二套对象状态。

## 已确认决策

见 [ADR-080](../decisions/ADR-080-minimal-game-module-api.md)。

## 实施顺序

1. 切断 Game Module 对完整 Application/World/Reflection API 的传递依赖；回调直接调用原生对象。
2. 提取模块协议的最小值类型闭包，迁移游戏模板及游戏示例。
3. 将内部共享值移入 src，消除重复结果和标识类型；转换只在真实协议边界存在。
4. 删除完整 C API 的生产适配层与安装声明；有价值的功能用例迁移至原生入口，删除纯 SDK 契约用例。
5. 收敛包配置、consumer 示例、ABI 检查和文档，编译所有保留目标。

## 当前剩余工作

- 清理 `src/engine/values` 剩余布局转换，保留有实际用途的值类型。
- 完成反射注册表内部原生化：身份、注册描述与属性回调已原生化，原生查询已直接读取记录，旧 C 查询缓存、C 回调身份和公共 Registry 句柄仍待清理。
- 逐项清理 RID、反射属性与渲染描述对 C 结构布局的依赖，转换留在 API/模块边界；
  整理仍位于根命名空间的旧共享值，避免与原生拥有型属性值混淆。
- 将仍使用完整 C API 的仓内示例和功能用例迁为原生调用，随后删除对应适配层、导出及头文件。
- 最后清理旧 C ABI 清单与安装 consumer，保留最小游戏模块的编译和边界验证。

## 验收与风险

公共 include 只包含游戏模块协议及必需类型；内部不依赖 Application 等公共 API。
原生结果、标识及值类型不维护内外两套定义。动态游戏模块仍可构建。
按用户要求持续完成全部迁移，只编译并做格式/边界检查，不执行最终测试、大场景和 CI。
运行期类型 ID 注册表已实现并接入资源键，区别于先前的 traits 移植；见 ADR-081。
最后保留独立的最终验证待办，包括运行期身份、资源重载、场景和编辑器用例的实际执行。
这是接口收缩，原完整 SDK 消费者不再兼容；阶段完成不能描述成全部迁移完成。

# VER-009：0.9.0 场景创作工作流

## 状态

- 状态：设计中
- 目标版本：0.9.0
- 优先级：P0
- 路线图阶段：Editor 场景创作

## 目标

在 0.8.0 资产工作流上形成首个完整场景结构创作闭环：

```text
创建或打开场景 → 创建节点 → 重命名/重挂接/复制 → 增删组件
→ 编辑 Transform → Undo/Redo → Save/Save As → 重新打开验证
```

用户应能在不手写场景 JSON 的情况下组装由空节点、Camera 和 Mesh Renderer 构成的层级场景。
Scene Instance 负责作者描述、World 投影和资源租约的一致性，Editor 不建立第二份场景事实来源。

## 非目标

- Prefab、场景继承、多人协作、增量补丁或版本控制冲突合并。
- 脚本组件、插件组件工厂、任意 C++ 类型构造或通用反射代码生成。
- GPU ID Picking、复杂选择集、框选、吸附、局部/全局轴完整 DCC 操作集。
- 完整 Docking、可保存工作区布局、多窗口、多视口或游戏内 UI 编辑器。
- 自动保存、崩溃恢复、后台场景加载或运行中热重载。

## 已确认决策

- 采用 [ADR-020](../decisions/ADR-020-scene-authoring-boundary.md)：Scene Instance 是打开场景的
  唯一可写作者边界，Runtime ID 不进入命令或持久化数据。
- 节点命令使用 UUID 和作者值快照；子树按父子顺序恢复，不保存组件地址或资源 RID。
- 首批组件创作只覆盖 Transform、Camera 与 Mesh Renderer，组件增删使用显式契约。
- 场景文件仍使用当前版本 JSON 和 `asset://` URI；Save As 只能写入工程资产根内。
- 新建、切换或关闭场景遇到未保存修改时必须显式提示，不静默丢弃。
- 视口操纵器首版只作用于层级当前选择；实现方案先做依赖与交互 Spike，再决定复用小型第三方库
  还是基于现有 UI Draw List 实现，不提前把候选依赖写成既定事实。

## 实施顺序

### M-58：通用作者节点修改契约

扩展 Scene Instance C11/C++20 API，支持创建空节点、重命名、重挂接和读取完整作者快照。重挂接
拒绝环、跨实例父节点和非法 UUID；失败时作者描述与 World 保持原状。

状态：已完成。

### M-59：子树复制、删除与恢复

以稳定 UUID 映射复制或删除整个子树，快照包含层级、Transform 和首批组件作者值。资源预取、UUID
分配、父子提交和失败回滚形成原子测试；不得依赖递归销毁的隐式副作用。

状态：已完成。快照使用当前场景 Schema 的受控值子集，复制要求调用方提供完整 UUID 映射。

### M-60：可扩展 Editor 命令模型

把 UI 中的临时 lambda 组合收拢为独立命令模型，覆盖节点、组件与属性操作；增加连续值编辑合并、
保存点脏状态和历史容量边界。失败 Undo/Redo 保持当前位置，新编辑清空 redo。

状态：已完成。独立命令接口支持专用命令扩展，现有 UI 通过函数命令适配器渐进迁移。

### M-61：层级创作与组件操作

Scene Hierarchy 增加创建、重命名、拖放重挂接、复制和删除；Inspector 增加 Camera、Mesh Renderer
的显式添加/移除及资产引用替换。UI 只调用会话与命令边界，不直接操作 JSON 或 ECS。

状态：已完成。层级操作、右键菜单、快捷键与组件增删均通过会话和 UUID 命令完成；Mesh Renderer
添加及引用替换复用 Asset Browser 的资产选择。

### M-62：场景文档生命周期

增加 File 菜单中的 New Scene、Open Scene、Save 与 Save As，校验目标位于工程资产根且使用规范 URI。
切换、关闭和退出统一处理未保存修改；失败保存保留原文件、当前会话和历史。

状态：已完成。未命名场景使用独立空实例；Open/Save As 经资产根路径边界转换，场景切换、菜单退出
和平台窗口关闭统一进入 Save/Discard/Cancel 确认。

### M-63：Transform 操纵器最小闭环

先以 Spike 验证坐标约定、输入占用、矩阵分解、许可证和构建传播，再为当前选择提供最小平移、旋转
和缩放操作。一次拖动合并为一个命令；父节点非均匀缩放和不可分解矩阵必须明确拒绝或稳定处理。

状态：已完成。显式 TRS 逆变换稳定覆盖非均匀正缩放父级，负缩放和剪切首版明确拒绝；ImGuizmo
仅链接 Editor。Scene View 提供平移、旋转和缩放工具栏，拖动期间独占指针输入，释放时记录一条
可撤销命令。决策见 [ADR-021](../decisions/ADR-021-transform-gizmo-boundary.md)。

### M-64：启动诊断、示例工程与版本验收

使用 Lantern Gallery 从空场景组装层级、添加 Camera 和 Mesh Renderer、复制展品、调整 Transform、
撤销重做、Save As 并重新打开。完成 Windows/Linux、共享/静态、工具关闭、安装 Consumer 和无头
Editor 图形矩阵。

Editor 在创建窗口前失败时不得只返回退出码。命令行参数、工程发现与解析、资产根校验、Application
创建、UI 初始化、场景打开和 Editor Camera 初始化等阶段，均向标准错误输出失败阶段、稳定结果码、
结果消息及相关工程或资产路径。已创建窗口后的可恢复错误继续在 UI 中显示；本任务不扩展为磁盘日志、
日志轮转或远程遥测。

状态：实施中。启动诊断已覆盖命令行、Project Manager、工程加载、Application、UI、World、场景、
Editor Camera 与事件循环，并保留 `1`～`4`、`64`、`65` 等退出码；示例工程和构建矩阵验收待完成。

## 测试与验收

- 节点操作覆盖重复 UUID、非法名称、环、跨实例父节点、根节点和三层以上子树。
- 子树复制/删除覆盖资源预取失败、提交中断、旧 Runtime ID 失效及 UUID 映射确定性。
- 命令历史覆盖连续属性合并、保存点、失败 Undo/Redo、节点重建后继续编辑和容量淘汰。
- 组件操作覆盖重复添加、缺失移除、主 Camera 切换、资产缺失和资源租约释放。
- New/Open/Save As 覆盖目录逃逸、目标冲突、只读文件、未保存取消及未知字段保留。
- 操纵器数学使用独立参考值测试；UI smoke 只验证组合，不承担全部业务正确性。
- Editor 启动诊断测试至少覆盖非法参数、工程文件缺失或无效、启动场景缺失、Application 创建失败
  和场景打开失败；断言标准错误包含阶段、结果码与相关路径，且成功启动不产生误导性错误。
- `GNEISS_BUILD_EDITOR=OFF` 与 `GNEISS_BUILD_TOOLS=OFF` 时 Runtime 和安装 package 保持独立。

## 风险与未决问题

| 风险或问题 | 当前处理 |
| --- | --- |
| 子树命令快照随场景增大 | 首版设置可测试容量上限，超限操作失败而非无界增长 |
| 连续拖动产生大量命令 | 以激活、更新、提交三个阶段合并为一个命令 |
| Transform 矩阵分解不稳定 | M-63 Spike 先锁定坐标和拒绝边界，再接入 UI |
| 主 Camera 删除或复制产生歧义 | 组件契约显式维护至多一个活动 Camera，并覆盖回滚 |
| 通用组件需求扩大范围 | 0.9.0 只实现三个已存在组件；插件构造协议另立 Plan/ADR |
| 启动失败只有退出码，用户无法定位 | M-64 为窗口创建前的失败提供结构化文本上下文，保留退出码供脚本判断 |

## 完成条件

- M-58～M-64 全部完成并形成 0.9.0 验收记录。
- 用户无需编辑 JSON 即可从空场景完成层级和首批组件创作并保存为新场景。
- 任一失败修改、失败命令或失败保存不留下部分作者状态、Runtime 对象或资源租约。
- Runtime、公共 ABI、安装 package 与 Editor 命令/UI 实现保持分层。

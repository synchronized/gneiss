# VER-032：0.32.0 构建配置与发布包管线

## 状态

- 状态：设计中
- 目标版本：0.32.0
- 优先级：P0
- 路线图阶段：游戏交付工作流

## 背景与目标

0.31.0 已能创建工程并导出可复制目录包，但只使用 Debug 预设，调用方需要事先提供已构建 Runtime，
目录包也没有机器可读清单或归档形式。0.32.0 将发布配置提升为明确的工程语义，并由一个工作流完成
配置、构建、收集、校验和归档，使输出可以脱离源码、构建目录和 SDK 独立运行与核验。

## 非目标

- 不制作安装器、增量补丁、自动更新器或平台商店上传能力。
- 不实现代码签名、加密、DRM、崩溃上报或符号服务器。
- 不进行跨平台交叉编译；一次导出只面向当前宿主平台与架构。
- 不在本版本引入完整资产烘焙、纹理压缩或 Shader 变体裁剪系统。
- 不以隐藏致命错误为代价删除 Shipping 诊断；最低限度启动与崩溃信息仍须保留。

## 已确认决策

- 引擎定义 `Debug`、`Development`、`Shipping` 三种稳定配置语义，工程负责把语义映射到自己的
  CMake configure/build preset；Editor 与命令行不猜测生成器或构建目录。
- 0.31.0 工程继续可加载并视为仅声明 Debug 配置；新模板声明完整配置，不要求用户手工迁移后才能
  打开旧工程。
- Development 是交互式导出的默认选择；Shipping 必须显式选择，并排除开发 UI、测试夹具、非必要
  符号和源码，同时保留致命故障诊断。
- 发布工作流先生成同级临时目录，在文件收集、清单生成、包内启动验证和可选归档全部成功后提交；
  不覆盖既有输出。
- 包清单使用版本化 JSON，记录 Gneiss 版本、工程标识、配置、平台、架构、入口及按路径排序的文件
  大小和 SHA-256；路径统一使用正斜杠并禁止逃逸包根。
- ZIP 是目录包的可选确定性封装；相同输入、工具版本和配置应产生相同文件顺序、元数据与归档字节。
- 0.31.0 的低层目录收集能力保留为内部构件，外部入口统一调用完整发布工作流。

## 测试与验收

- 新模板三种配置均可从安装 SDK 完成配置、构建和导出；旧版工程仍可按 Debug 路径运行。
- Debug、Development 与 Shipping 的模块和 Runtime 配置一致，禁止混装不同配置的二进制文件。
- 清单路径稳定排序，文件大小及 SHA-256 与包内内容一致；篡改、遗漏和路径逃逸能够被明确拒绝。
- 相同输入连续两次导出的目录内容和 ZIP 哈希一致，不把临时目录、绝对路径或当前时间写入产物。
- 导出失败、目标已存在、预设缺失、构建失败、依赖缺失和归档失败均不留下已提交的半成品。
- 包可从任意工作目录启动，且机器上不需要 Gneiss 源码、构建树或 SDK。
- Windows MSVC Shared/Static、Linux Clang/GCC Shared/Static、安装 Consumer 与 Sanitizer 通过。

## 风险与未决问题

- 需要先确认现有归档依赖能否稳定控制 ZIP 时间戳、权限和文件顺序；不能满足时应采用小型独立实现
  或明确锁定工具版本，不把宿主 `zip` 命令作为隐式依赖。
- Windows PDB 与 Linux 拆分调试信息的长期存储策略不在本版本解决；本版本只明确是否进入交付包。
- Editor 首版只展示必要配置、输出路径、进度和错误，不在 ImGui 中扩展为通用发布配置编辑器。

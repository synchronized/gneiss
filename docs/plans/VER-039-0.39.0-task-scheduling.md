# VER-039：0.39.0 任务调度基础与资产服务接入

## 状态

- 状态：定义范围已完成，发布验收通过。
- 目标版本：0.39.0。
- 分支：`feat/0.39-task-scheduling`；规划与后续实现沿用同一分支。
- 2026-09-25 用户确认规划，并明确授权推进本版直到发布，包括提交、推送、PR、合并与发布。

完成结果与保留边界见 [0.39 验收记录](../records/M-250-255-0.39.0-validation.md)。
性能验收分别保留真实资产应用循环、合成输入及受阻导入期间的原生窗口回归，不把无头循环
当成渲染帧时保证；物理跨屏与全负载渲染帧时跟踪仍未覆盖。

## 背景与目标

0.38 已实现资产后台处理，但执行器仍独占一条线程；渲染和 libuv 各自已有专用执行器。
作者 Scene/Prefab 文件的枚举、指纹计算和变更判断尚在主线程。
本版提供可复用的内部任务调度基础，以导入和作者资产检查两个实际场景验证所有权、并发和退出规则。
当前基线及限制见 [0.38 验收记录](../records/M-246-249-0.38.0-validation.md)。

目标是复用线程资源及任务生命周期协议，同时保留 Service 对资源、事务和错误语义的控制。
不把某个 Service 整体交给任意线程运行，也不要求各服务采用相同的逐帧更新方式。

## 非目标

- 不迁移 GPU 操作、渲染提交、libuv 事件循环或音频实时回调到通用池。
- 不引入 ECS 自动并行调度、协程运行时、工作窃取或可动态修改的通用任务图。
- 不扩展公共 C ABI/C++ 包装，不引入第三方调度依赖，不修改 Granit，不切换 SDL3。
- 不把整个 Scene/Prefab 加载与应用搬到后台；文档冲突、Scene/ECS 修改及撤销历史仍归主线程。
- 不承诺抢占第三方解析器或消除 Windows Debug 调试堆争锁；不把线程池等同于硬实时保证。
- 不新增跨进程导入、外部 glTF 依赖图、跨进程资产事务或断电恢复机制。

## 已确认决策

架构与执行位置以 [ADR-046](../decisions/ADR-046-task-scheduling-service-boundary.md) 为权威来源。
本版先实现调度核心和确定性测试，再迁移导入，最后迁移作者资产检查。
任务接口保持内部 C++20；内部契约由 `src/core/tasks/task_scheduler.h` 实现，不属于已安装公共 API。

| 能力 | 首版计划契约 |
| --- | --- |
| 调度器与任务作用域 | 宿主持有调度器并注入服务；每个服务持有可取消、可等待收尾的任务作用域，禁止进程全局单例 |
| 提交和容量 | 待依赖、就绪、运行及尚未回收的结果均计入预算；满载立即拒绝，主线程不等空位，已接受结果不静默丢弃 |
| 任务句柄 | 校验所属调度器和有效性；无效或跨实例依赖在提交时失败，返回的句柄不暴露线程及业务资源对象 |
| 依赖关系 | 只引用此前成功提交的任务，提交后不可改边；未满足依赖不占用工作线程等待 |
| 失败传播 | 异常转为任务失败；显式前置依赖失败或取消时，依赖任务不运行并返回可辨识原因 |
| 串行队列 | 同一队列内按接受顺序执行且不重叠；无需固定线程身份；前一项失败不自动取消无显式依赖的下一项 |
| 取消 | 未启动任务可取消；运行任务在协作检查点退出；取得业务提交许可后仍按服务规则完成或回滚 |
| 完成通知 | 每个已接受任务只产生一次终态；主线程按预算消费，回执携带所有者代次，关闭后的所有者不被回调访问 |
| 优先级与诊断 | 首版普通/后台两档、非抢占；记录任务名称、状态、排队/执行时间、容量拒绝和失败计数，避免后台任务永久饥饿 |
| 关闭 | 停止接收、取消未提交任务、完成或回滚已提交任务并收回结果，最后释放线程；禁止从池内自等待或自行 join |

## 资产接入顺序

1. **Import Service**：先将现有工作线程循环改为有限任务和延迟调度，不把永久循环塞进线程池。
   保留去抖、稳定读取、补扫、暂存、源哈希复核、提交许可、回滚、取消和重试语义。
   工程索引及派生目录仍只有一个串行写入者；浏览器快照读取与提交保持协调。
2. **作者资产检查**：后台枚举和计算指纹，返回 URI、文件状态和检查代次等纯数据。
   主线程根据消费时的当前场景、脏状态、Prefab 引用及自身保存修订决定冲突或应用。
   保存确认不能要求主线程再次计算大文件哈希；确认后的旧扫描结果必须失效。
3. **主线程应用**：不让后台任务捕获 Session、ImGui、World 或未受任务作用域保护的服务裸指针。
   同一路径连续修改、删除后重建、打开另一场景和服务销毁均要校验结果归属与新旧关系。
4. **导出与关闭**：保留 0.38 的导出写入暂停规则；队列暂停不占用池线程。
   一个服务停止只结束自己的作用域，不关闭仍被其他服务使用的调度器。

## 测试与验收

- 使用屏障和显式事件控制顺序，超时仅发现挂死；不靠短暂 sleep 证明线程安全。
- 覆盖 1、2 及更多工作线程：依赖链/分叉/汇合、非法句柄、跨实例依赖、异常、取消竞态、队列满载。
- 验证依赖未完成不占满线程池；低容量下结果未消费也不会丢失终态，关闭不等待已销毁的主线程消费者。
- 同一工程事务永不并发，独立队列可前进；串行任务失败后后续无依赖任务仍能执行。
- 取消与提交许可竞争保持至多一次提交；暂停导出、退出和作用域销毁不出现悬空捕获或写入一半的产物。
- 作者资产覆盖创建、修改、删除、重建、丢事件补扫、自身保存、脏场景、Prefab 引用及切换场景。
  判定使用主线程消费时的状态，已知旧修订不得覆盖较新文档或清除新的冲突。
- 保留 0.38 合成大文件基准，并加入有来源/许可证记录的实际几何、纹理和多 Prefab 工程。
  同时记录导入、扫描、主线程应用的耗时，以及帧间隔、完成队列消费耗时和排队峰值。
- 在导入和检查期间验证相机、连续 resize、最小化恢复、编辑/保存、打包与关闭。
  分别记录 Debug/Release，不将任务总耗时、轮询耗时或阻塞回调测试当作真实全帧性能。
- 运行相关格式/静态检查，Windows 本地共享/静态回归及 Linux/Windows 手动矩阵。
  保留 C/C++ 头文件和安装 Consumer 门禁；同一代码候选完整矩阵原则上只跑一次。

## 风险与实施前收口项

- 线程数、普通/后台预算、延迟检查调度和防饥饿策略在 M-250 明确；使用显式配置及保守默认值，
  为渲染、I/O 和主线程保留资源。长解析与同步文件读取需要并发限额，不能占满全部执行资源。
- 最小依赖接口不支持向已提交任务追加前置条件，避免环和运行中修改图带来的额外状态。
- 作者保存与扫描的修订来源、删除/重建判定在 M-254 实施前写入测试；不能仅依赖文件时间戳。
- 真实资产规模及性能门槛先记录硬件和基线再确定，不凭单次最大值承诺固定帧率。
- 若通用池无法隔离长阻塞导入，应根据测量保留受限导入执行域，并更新 ADR；不为统一名称破坏响应性。

# VER-020：0.20.0 Prefab 作者工作流

## 状态

- 状态：验证中
- 目标版本：0.20.0
- 优先级：P0
- 路线图阶段：Prefab 作者工作流

## 背景与目标

0.18.0 和 0.19.0 已支持引用型 Prefab、来源刷新和实例字段覆盖，但 Prefab 资产仍主要依赖手工编写。
Editor 尚不能把已有场景子树提取为 Prefab，也不能把实例修改显式应用回来源或解除实例关系。

0.20.0 建立最小可用的 Prefab 作者闭环：用户可从场景子树创建 Prefab，将实例字段覆盖显式应用到
来源资产，并将实例 Unpack 为普通场景节点。所有资产与场景修改必须具备原子保存、冲突检测、
Undo/Redo 和失败恢复，且其他同源实例在来源提交后得到一致刷新。

## 非目标

- 不实现嵌套 Prefab、Prefab Variant、继承或跨工程引用。
- 不实现节点增删、父级调整或组件增删等结构覆盖。
- 不提供独立 Prefab 编辑器、自动文件监听或运行中热重载。
- 不允许 Runtime 直接修改 Prefab 来源资产；来源写入只发生在 Editor 作者会话。
- 不冻结 Prefab JSON、场景 v4 或内部作者事务为稳定公共 ABI。
- 不重构 IPC；本版本新增能力不形成新的 Runtime 双向协议域。

## 已确认决策

- Prefab 来源写入由 Editor 作者事务负责，Runtime、Scene Instance 和渲染后端均不直接写文件。
- 创建 Prefab 使用“先写临时来源并验证，再替换场景子树”的原子流程；任一步失败均保留原场景。
- Apply 只提交当前实例已有的字段覆盖，不把实例根 Transform 或场景父级写入共享来源。
- Apply 前校验来源资产身份与基线修订；来源已变化时拒绝覆盖，避免静默覆盖外部修改。
- Apply 成功后清除已提交覆盖，并原子刷新全部同源实例；任一实例无法重建则整体回滚。
- Unpack 生成拥有新场景 UUID 的普通作者节点，移除 Prefab 复合身份，同时保留当前可见值与层级。
- 创建、Apply 和 Unpack 都进入 Editor 命令历史；撤销必须恢复场景作者数据、来源文件和实例投影。
- Prefab 来源仍使用现有 VFS 与 JSON Schema，不新增并行资产表示。

拒绝包含现有 Prefab 实例的子树，避免提前引入嵌套语义。

状态：已完成。结果见

把当前实例的字段覆盖写入对应来源节点，清除已应用覆盖并刷新全部同源实例。验证多实例差异、来源
冲突、字段失效、保存失败和刷新失败时的整体回滚。

状态：已完成。结果见
[M-133 将实例覆盖应用到来源实施记录](../records/M-133-apply-prefab-overrides.md)。

状态：已完成。结果见

## 测试与验收

- 作者事务覆盖成功提交、临时写入失败、替换失败、来源冲突及回滚失败诊断。
- Create Prefab 保持节点内容、相对层级和世界变换，并原子替换场景子树。
- Apply 只修改目标来源字段，清除对应覆盖并刷新全部同源实例，不写入实例根变换。
- Unpack 保留当前可见结果，生成无 Prefab 身份的普通节点，并可保存重开。
- 三类命令均覆盖 Undo/Redo、脏状态、选择恢复和关闭时未保存提示。
- Shared/Static、C/C++ Consumer、Editor/Runtime 关闭和无头图形组合保持通过。

## 风险与未决问题

- 跨两个文件的事务无法依赖通用文件系统原子性；M-131 已通过磁盘清单、前后镜像、提交标记和
  启动恢复落实持久化顺序，后续作者命令仍需保证只通过该事务入口提交多文档修改。
- Apply 会改变所有同源实例，界面必须预览影响范围并避免把实例局部意图误提交为共享来源。
- Unpack 的新 UUID 映射会使旧 Runtime 身份失效；执行后应显式重建镜像并清理待处理请求。
- 来源文件位于只读或非 Native FileSystem 挂载时，作者操作应明确拒绝，不把写能力扩散到通用 VFS。
- 若实现中出现节点结构差异需求，应停止扩张并单独规划结构覆盖，不能隐式编码为字段覆盖。

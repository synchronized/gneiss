# VER-002：0.2.0 资源与场景闭环

## 状态

- 状态：设计中
- 目标版本：0.2.0
- 优先级：P0
- 路线图阶段：资源与场景

## 背景与目标

`0.1.0` 已验证通过代码创建 Application、World、Scene Tree 和渲染资源的完整路径，但 Mesh、
Material 与场景结构仍由示例在内存中手工构造。`0.2.0` 的目标是建立第一条可持久化内容路径：使用
逻辑资产 URI 加载 Mesh 与 Material，读取带版本的场景描述，原子地实例化 World 内容并完成渲染。

版本验收路径如下：

```text
启动 Application
→ 挂载资产根目录
→ 读取并校验场景描述
→ 解析对象 UUID、层级、组件和资产 URI
→ 同步加载并缓存 Mesh 与 Material
→ 原子提交 Scene Node、Entity 和组件
→ 持续更新与渲染
→ 卸载场景并释放资产引用
→ 确定性退出
```

## 非目标

- 完整运行时反射、代码生成器和编辑器 Inspector。
- Prefab、场景继承、场景差异合并和 Undo/Redo。
- 通用资产数据库、内容寻址存储、增量构建和分布式缓存。
- 后台线程池、异步 I/O、GPU 流式上传和取消协议。
- 热重载、文件监视和运行中资源替换。
- 通用材质图、PBR、模型动画和复杂导入管线。
- 将 EnTT Snapshot、运行时 entity ID 或 RID 写入持久化文件。

## 已确认决策

- 场景对象使用稳定 UUID；entity ID、Scene Node ID 和 RID 只在本次运行中有效。
- 场景文件只保存逻辑资产 URI，不保存绝对路径、构建目录或 Granit 原生句柄。
- URI 在进入缓存前统一规范化；同一 Application 内相同 URI 共享一个资源实例。
- 首版加载在 Application 创建线程同步执行，但 API 与内部状态显式保留
  `unloaded/loading/ready/failed` 生命周期，避免未来异步化破坏契约。
- Mesh Renderer 继续只借用 Mesh/Material RID；场景实例持有资产引用，并在销毁实体后释放引用。
- 场景加载采用“解析与校验—暂存资源—提交 World”三阶段；任一步失败都回滚本次创建内容，不留下
  半个场景或缓存引用泄漏。
- Schema 由 Gneiss 定义，序列化实现不能暴露到公共 ABI；EnTT Meta 和 Snapshot 不作为文件契约。
- `0.2.0` 只为 Transform、Camera 和 Mesh Renderer 建立显式 Schema，不提前抽象任意组件系统。
- Texture 为 P1；只有 Mesh/Material 场景闭环稳定后才扩展顶点格式、Shader 和材质引用。
- 场景描述采用 UTF-8 JSON；解析库通过 Spike 选择，第三方类型不得进入公共 ABI。

## 待决策事项

### JSON 解析库与格式细节

M-13 将对候选 JSON 解析库做最小 Spike，比较许可证、CMake 接入、错误定位、未知字段策略、数值
行为和二进制体积。决定后新增 ADR 并锁定版本；在 ADR 接受前不公开文件扩展名或稳定格式承诺。

### 资产 URI 规则

需在 M-14 确认 scheme、大小写、分隔符、`.`/`..`、UTF-8、根目录逃逸和符号链接策略。首版只支持
本地只读资产根目录；URI 规范化规则一旦进入场景文件即属于持久化契约，必须通过测试锁定。

### 资源引用模型

候选方案为显式 acquire/release 或拥有型资源租约。公共 C ABI 必须保持整数句柄和明确错误码；
场景组件不承担引用计数。M-14 用重复加载、失败重试、场景卸载和 Application 销毁四条路径确定方案。

### Mesh 与 Material 文件边界

首版优先采用 Gneiss 自有的最小中间描述，避免把 OBJ、glTF 或图像解码器直接变成运行时契约。
M-16 将用三角形资产验证“源内容—加载器—运行时资源”的边界，再决定是否需要独立离线转换工具。

## 公共模型草案

### 资产

- `asset_uri`：UTF-8 逻辑标识，经规范化后作为缓存键，不直接等同于操作系统路径。
- `asset_state`：至少包含 unloaded、loading、ready 和 failed；failed 保存稳定结果码和诊断上下文。
- Mesh、Material 与未来 Texture 使用不同 RID 类型，跨类型和跨 Application 使用继续失败。
- 缓存只负责运行时实例与引用生命周期；源文件格式和导入策略由对应 Loader 负责。

### 场景描述

- 顶层包含格式标识、Schema 版本、场景 UUID 和对象数组。
- 每个对象包含稳定 UUID、可选父 UUID、Transform 及显式组件描述。
- Camera 保存透视参数和 primary 标记；Mesh Renderer 保存 Mesh/Material 资产 URI。
- 加载时先检查 UUID 唯一性、父引用、非法循环、组件字段和资产 URI，再修改 World。
- 当前版本拒绝未知的未来 Schema 版本；同版本未知可选字段的策略由格式 ADR 锁定。

### 场景实例

- 场景实例由 Application 拥有，记录本次创建的对象映射、Scene Node、Entity 和资产引用。
- 卸载顺序为组件与实体、Scene Node、资产引用；失败加载使用同一逆序回滚路径。
- 首版只允许在 Application 创建线程加载、查询和卸载，不支持与主循环并发修改 World。

## 实施顺序

### M-13：格式 Spike 与 ADR

1. 用单个三角形场景验证候选 JSON 解析库。
2. 锁定 Schema 版本字段、UUID 表示、未知字段和错误定位策略。
3. 记录依赖版本、许可证、替代方案、构建与 ABI 影响。

验收：ADR 被接受；格式选择有可运行 Spike 和失败样例，不由偏好直接决定。

### M-14：资产 URI 与 Resource Service 生命周期

1. 实现 URI 解析、规范化、资产根挂载和目录逃逸拒绝。
2. 建立资源状态、缓存键、引用获取/释放和失败重试语义。
3. 覆盖重复加载、类型冲突、跨 Application、卸载和销毁回滚。

验收：相同规范化 URI 复用资源；非法 URI 不访问资产根之外的文件。

### M-15：版本化场景 Schema

1. 定义场景、对象、层级、Transform、Camera 与 Mesh Renderer Schema。
2. 实现纯解析、验证和中间描述，不在解析阶段修改 World。
3. 覆盖重复 UUID、缺失父对象、循环、非法数值和不支持版本。

验收：有效文件产生确定的中间描述；所有失败均包含稳定结果码和可定位诊断。

### M-16：Mesh 与 Material Loader

1. 定义最小 Mesh/Material 中间描述和同步 Loader。
2. 将 Loader 输出接入现有 Mesh/Material RID 创建路径。
3. 验证缓存复用、格式错误、资源创建失败和释放顺序。

验收：三角形的几何与材质完全来自资产文件，示例不再内嵌顶点和颜色。

### M-17：场景实例化、示例与版本验收

1. 建立对象 UUID 到运行时 entity/Scene Node 的临时映射。
2. 按层级创建对象，绑定组件并持有资产引用。
3. 实现场景卸载及解析、资产、World 任一阶段失败时的完整回滚。
4. 将旋转三角形示例改为从磁盘加载场景与资产。
5. 验证 Windows/Linux、共享/静态、C/C++ consumer 和安装后资产路径。

验收：加载失败前后 World 与资源存活计数一致；干净构建目录可通过一个场景 URI 完成
“加载—渲染—卸载—退出”闭环。

### M-18：Texture P1 扩展

1. 基于真实材质用例决定图像解码依赖和 Texture RID。
2. 扩展 Mesh 顶点属性、Material 描述与 Granit 上传路径。
3. 提供无纹理回退并覆盖解码、上传和引用失败。

验收：纹理材质由场景资产加载并渲染；失败不会破坏无纹理 Mesh/Material 路径。

## 测试与验收

- URI 覆盖规范化等价、UTF-8、根逃逸、绝对路径、空值和不存在文件。
- 缓存覆盖首次加载、命中、失败缓存/重试、引用归零、类型错误和跨 Application。
- Schema 覆盖成功、语法错误、字段错误、UUID 冲突、层级循环和未来版本拒绝。
- 场景实例覆盖空场景、多根节点、层级 Transform、重复加载、卸载和每阶段失败回滚。
- 资源覆盖 Mesh/Material 成功、格式失败、RID 失效和 Application 销毁时仍有引用。
- 公共 `.h` 继续由 C11 独立编译，`.hpp` 由 C++20 独立编译。
- 共享/静态库、Windows/Linux、本地 package 与 FetchContent 路径保持通过。

## 版本完成条件

- 示例不包含硬编码 Mesh/Material 内容，只通过场景 URI 创建可渲染 World。
- 场景文件不包含运行时 entity ID、Scene Node ID、RID 或第三方原生值。
- 任意可预期失败不会留下部分场景、悬空组件或资源引用泄漏。
- Schema 版本、资产 URI、所有权、线程限制和失败语义具有 Reference 与测试。
- 所有 P0 阶段完成；Texture 未完成时可作为明确 P1 延后，不阻塞 `0.2.0`。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 过早建设完整反射 | 只为三个现有组件维护显式 Schema，以重复证据驱动抽象 |
| 文件格式绑死 ECS | 持久化对象 UUID 和组件值，不保存 EnTT/运行时标识 |
| 路径兼容与安全问题 | 逻辑 URI 统一规范化并限制在显式资产根内 |
| 加载失败污染 World | 解析、暂存、提交分阶段，所有提交共享逆序回滚路径 |
| 引用计数与 RID 混淆 | 场景实例拥有资产引用，组件只借用 RID |
| Texture 扩大渲染范围 | 作为 P1 独立阶段，不阻塞无纹理场景闭环 |
| 异步接口过早冻结 | 首版同步执行但显式建模状态，异步化另立 Plan/ADR |

## 后续边界

`0.2.0` 完成后再以真实场景工作流评估反射代码生成、Prefab、异步加载和热重载。编辑器只能依赖已
稳定的资源与场景契约，不得反向要求运行时保存编辑器专用状态。

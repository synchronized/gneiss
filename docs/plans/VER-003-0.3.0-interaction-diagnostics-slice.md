# VER-003：0.3.0 交互与诊断闭环

## 状态

- 状态：设计中
- 目标版本：0.3.0
- 优先级：P0
- 路线图阶段：交互与诊断

## 背景与目标

`0.2.0` 已能从场景 URI 加载并渲染内容，但示例仍按时间自动旋转，应用无法通过稳定的 Gneiss
接口消费键盘、指针等输入，运行时错误也没有统一的外部诊断通道。`0.3.0` 的目标是建立第一条可
交互、可观察的运行时路径：平台后端产生输入事件，Input Service 更新动作状态，业务逻辑据此修改
场景，同时调用方能够接收结构化诊断。基础运行状态快照作为 P1 建立在同一诊断边界上。

版本验收路径如下：

```text
启动 Application 并加载场景
→ Input Service 从平台后端采集事件
→ 依据版本化动作映射生成动作状态
→ 示例使用动作移动或旋转场景对象
→ Escape 动作请求退出
→ 诊断回调接收可定位的运行时消息
→ 卸载场景并确定性退出
```

## 非目标

- 正式游戏 UI、布局系统、字体资产管线和 UI 序列化格式。
- 编辑器 Inspector、Docking、撤销重做和工具插件框架。
- 完整手柄数据库、震动、触摸、IME 和平台辅助功能。
- 网络输入同步、回放、确定性锁步和输入预测。
- 全局日志框架、磁盘日志轮转、远程遥测和性能追踪平台。
- 任意形状调试渲染器、GPU Profiler 和 RenderDoc 集成。
- Texture、PBR 或材质系统扩展；它们另属后续图形能力切片。

## 已确认决策

- Input Service 属于运行时服务层；Granit 输入系统只存在于 `src/platform/granit/` 后端，不进入
  World、Scene、ECS 组件或公共接口。
- 公共 `.h` 提供定宽的输入事件、动作状态和诊断结构；`.hpp` 只提供轻量强类型包装。
- 输入只在 Application 创建线程采集和查询，每帧在业务更新回调前形成不可变快照。
- 原始事件与动作状态是两层契约：动作映射服务于游戏逻辑，原始文本和指针事件为未来工具保留，
  二者不互相替代。
- 动作名称是 UTF-8 逻辑标识，动作映射通过 `asset://` JSON 加载；运行时不把平台扫描码写入场景。
- 首版绑定支持键盘键、指针按钮和指针轴；组合键、手柄和重绑定 UI 按真实用例后续扩展。
- 诊断为 Application 级借用回调，消息指针仅在回调期间有效；回调不得重入或销毁 Application。
- Gneiss 统一严重度、类别和稳定结果码，后端原生消息只作为诊断文本，不成为程序控制契约。
- 临时 ImGui UI、统计面板和调试绘制均为 P1；不得让运行时核心反向依赖编辑器或正式 UI 模块。

## 待决策事项

### 动作标识与状态模型

已由 [ADR-008](../decisions/ADR-008-action-identity-and-folding.md) 确认：动作使用映射代次与槽位组成
的 Application 局部句柄；状态同时表达 `pressed`、`held`、`released` 和标量值，并保留同帧出现
的多个边沿。

### 输入事件队列

需要为固定容量队列定义溢出行为、文本 UTF-8 边界、指针坐标空间和滚轮单位。失去焦点时必须合成
释放或清空状态，避免动作永久卡住；窗口关闭继续由 Application 生命周期处理，不伪装成输入动作。

### 诊断存储与回调

P0 只承诺同步回调和稳定字段，不默认维护无界日志历史。M-22 将验证是否需要固定容量的最近消息
环形缓冲，以支持临时 UI，同时保证诊断回调抛弃消息或回调缺失不改变原操作结果。

### Dear ImGui 接入

Granit 已提供可选 ImGui 渲染集成，但 Gneiss 需要先验证输入转发、Overlay 阶段、纹理解析和依赖
传播。Spike 通过前不新增 `src/ui/`，通过后也只建立诊断宿主，不定义正式 UI 架构。

## 公共模型草案

### 原始输入事件

- 事件包含 `struct_size`、类型、时间戳、窗口逻辑标识和定宽数据联合体。
- 键盘事件使用 Gneiss 自有物理键枚举；文本输入单独提供 UTF-8 字节，不由按键推导字符。
- 指针位置明确使用窗口内容区逻辑坐标，移动增量、滚轮和按钮状态分别表达。
- 未识别的后端事件可以忽略或转换为 unknown，不泄漏 Granit 枚举值。

### 动作映射

- 映射资产包含格式标识、Schema 版本、动作列表和每个动作的绑定列表。
- 动作状态是当帧快照，不作为 ECS 组件持久化，也不写入场景文件。
- 多个绑定可驱动同一动作；数字动作采用确定的合并和裁剪规则。
- 加载失败保持旧映射不变；初次设置失败时 Input Service 仍可提供原始事件。

### 诊断与统计

- 诊断包含严重度、类别、结果码、UTF-8 消息及可选来源模块。
- 统计查询返回调用瞬间的值副本，不借用内部容器，也不保证跨帧累加稳定。
- P0 统计至少覆盖帧序号、帧时间、实体数、场景实例数及 Mesh/Material 存活数。
- 统计接口失败不得影响主循环；未启用的后端字段使用零值并通过有效位说明。

## 实施顺序

### M-20：输入契约与 Granit 后端

状态：进行中。公共输入 ABI、固定容量帧队列、焦点清理、无后端行为和 Granit Input 适配已完成；
仍需补齐 Linux 平台验证后关闭任务。

1. 建立输入事件、键、按钮、轴和状态的 C11 ABI 及 C++20 包装草案。
2. 扩展 Granit provider 以解析 `Input` 组件，并在 Application 生命周期中创建、轮询和销毁后端。
3. 在业务更新前形成每帧快照，处理焦点丢失、队列溢出和后端失败。
4. 用无后端注入器和 Granit 集成测试覆盖 Windows/Linux 语义。

验收：测试注入的按下、保持、释放、文本和指针事件产生确定快照；Granit 类型不出现在公共头或
安装 package 的普通接口中。

### M-21：版本化动作映射

状态：已完成。动作标识与状态折叠由 ADR-008 确认；严格 JSON v1、VFS 事务加载、代次句柄及
每帧动作查询均已实现，并覆盖失败保留、成功替换失效和跨 Application 隔离。

1. 用 Spike 确定动作标识、状态折叠和多绑定合并规则，必要时建立 ADR。
2. 定义动作映射 JSON v1，并通过现有 VFS 与严格 JSON 校验加载。
3. 提供设置映射、查询动作状态和失败时保留旧映射的公共接口。
4. 覆盖未知键、重复动作、非法绑定、加载失败和跨 Application 使用。

验收：同一业务动作可由不同物理输入驱动；业务代码不依赖 Granit 或平台键码。

### M-22：统一诊断通道

状态：待开始。

1. 定义严重度、类别、消息生命周期、线程和重入约束。
2. 将 Gneiss 内部失败与 Granit 诊断转换到 Application 级回调。
3. 验证回调缺失、消息被丢弃和回调内只读查询不会改变原操作结果。
4. 根据临时 UI 用例决定是否增加有界最近消息缓冲。

验收：故意触发无效资产、输入映射和后端错误时，调用方获得稳定结果码及可定位诊断，且不会收到
第三方原生结构。

### M-23：交互示例与版本验收

状态：待开始。

1. 将三角形示例改为由动作映射控制旋转或移动，并用退出动作结束主循环。
2. 增加无窗口的输入注入集成测试和 Granit 平台 smoke test。
3. 验证场景加载、交互、诊断、卸载和退出的完整生命周期。
4. 执行 Windows/Linux、共享/静态、安装 Consumer 与手动远端矩阵。

验收：用户可通过映射动作控制资产驱动场景并退出；故障可通过统一诊断定位，退出后没有场景、
输入或资源状态泄漏。

### M-24：运行时统计快照

状态：待开始，P1。

1. 定义不暴露内部容器的帧、World、场景和资源统计快照。
2. 明确采样时点、有效位、计数成本及线程约束。
3. 为诊断输出和临时面板提供同一份只读数据源。

验收：统计值与测试构造的实体、场景和资源生命周期一致，不为查询引入每帧堆分配。

### M-25：临时诊断 UI 与调试绘制 Spike

状态：待开始，P1。

1. 验证 Granit ImGui Overlay、输入转发和依赖隔离。
2. 显示帧统计、最近诊断和场景摘要，不提供编辑能力。

## 测试与验收

- C11/C++20 公共头独立编译，事件结构布局和可扩展字段通过静态与运行时检查。
- 输入覆盖按下、保持、释放、重复、焦点丢失、UTF-8 文本、指针和队列溢出。
- 动作映射覆盖加载、替换、失败回滚、多绑定、数字合并和未知动作。
- 诊断覆盖严重度、类别、消息生命周期、回调缺失、后端转换和重入拒绝。
- 生命周期覆盖 Application 创建失败、部分服务回滚、场景卸载和销毁顺序。
- Windows/Linux、共享/静态、核心无窗口和 Granit 平台路径保持通过。
- 安装 Consumer 验证新增公共接口，手动 Actions 只在发布或明确授权的阶段运行。

## 版本完成条件

- 所有 P0 任务完成，交互示例不直接使用 Granit 或平台键码。
- 输入快照时点、动作边沿、焦点丢失和队列溢出行为具有 Reference 与测试。
- 可预期失败同时返回稳定结果码，并可选产生不改变控制流的诊断。
- 场景交互与退出形成端到端闭环，销毁后不保留输入、场景或资源状态。
- M-24、M-25 未完成时可以作为明确 P1 延后，不阻塞 `0.3.0`。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 输入 API 过度贴近后端 | 使用 Gneiss 自有事件与键枚举，Granit 只在平台适配层转换 |
| 每帧字符串查询与分配 | Spike 后选择可缓存标识，状态快照复用容量 |
| 焦点变化造成卡键 | 焦点丢失显式清空并产生确定释放语义 |
| 诊断回调影响控制流 | 回调结果被忽略，限制重入并保持原始结果码 |
| 临时 UI 演变为正式框架 | 仅提供只读诊断宿主，不建立 `src/ui/` 或编辑能力 |
| 调试绘制扩大渲染架构 | 先用单一真实形状验证，超出最小批次则独立延期 |

## 后续边界

`0.3.0` 完成后，再根据交互示例暴露的真实需求决定 Texture 图形切片、Player 宿主或编辑器基础设施。
反射、序列化和编辑器只能消费稳定的运行时输入、诊断、资源与场景契约，不反向拥有运行时状态。

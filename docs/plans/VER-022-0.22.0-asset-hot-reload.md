# VER-022：0.22.0 资产热重载

## 状态

- 状态：实现中
- 目标版本：0.22.0
- 优先级：P0
- 路线图阶段：资产变更与 Runtime 热重载

## 背景与目标

Editor 已支持手动导入和重新导入，Runtime 也具备资源缓存与独立进程宿主，但源资产变化仍要求
用户手动重新导入并重启 Runtime。0.21.0 已将本机 IPC 拆为可独立扩展的协议域，本版本以真实的
Asset 域验证该边界，并建立“源文件变化、派生产物提交、Runtime 原子替换、Editor 反馈”的闭环。

## 非目标

- 不热重载 Game Module、脚本虚拟机或原生动态库。
- 不热重载 Scene、Prefab 层级、节点身份或组件结构。
- 不建立公共文件监听、异步任务或 Network Service API。
- 不支持远程设备、多人协作、资产流式传输或内容分发。
- 不引入通用资产数据库、构建农场或任意导入器插件 ABI。
- 不调整 Dear ImGui、字体或游戏内 GUI。

## 已确认决策

- Editor 是源资产监听和重新导入的唯一协调者；Runtime 不监视作者目录。
- 文件系统事件只表示“可能变化”，真实变化由规范化路径、稳定读取和内容校验和确认。
- 自动导入经过防抖并按源资产串行化；同一资产不会并发运行多个导入事务。
- 派生产物全部成功写入后才发布新修订；失败保留旧产物和旧运行时资源。
- Asset IPC 只传递资产 URI、类型与修订，不通过控制通道传输资产正文。
- Runtime 在主线程安全点加载候选资源，成功后替换缓存映射；已有租约的生命周期必须明确。
- 首批只覆盖 Texture、Material 和静态 Mesh；详细边界见
  [ADR-036](../decisions/ADR-036-asset-hot-reload.md)。

## 实施顺序

### M-144：资产依赖与热重载边界 ADR

盘点源资产、导入索引、派生产物、资源缓存、渲染后端镜像和 IPC 线程所有权，确定修订标识、失败
回滚、依赖传播及首批支持类型。

状态：已完成。结果见
[M-144 资产热重载边界记录](../records/M-144-asset-hot-reload-boundary.md)。

### M-145：工程文件变更监听

建立 Editor 私有监听器，递归观察工程 `sources/`，将平台事件转换为规范化候选路径。覆盖重复事件、
重命名、删除、监听目录失效和 Editor 关闭，不向公共接口泄漏 libuv 类型。

状态：已完成。结果见
[M-145 工程源资产文件监听实施记录](../records/M-145-asset-file-watcher.md)。

### M-146：自动重新导入队列

以内容校验和过滤无变化事件，加入防抖、稳定读取、单资产串行化和有界队列。复用现有导入 SDK 与
索引事务，向 Editor 暴露等待、导入、成功、失败和需要重启状态。

状态：已完成。结果见
[M-146 自动重新导入队列实施记录](../records/M-146-automatic-asset-reimport.md)。

### M-147：Asset IPC 协议域

增加资产修订通知、应用结果和必要的全量重同步操作。域独立声明版本、方向、负载上限与能力；未知
资产类型或旧修订返回可诊断结果，不损坏会话。

状态：已完成。结果见
[M-147 Asset IPC 协议域实施记录](../records/M-147-asset-ipc-domain.md)。

### M-148：Runtime 资源事务重载

在 Runtime 主线程安全点加载候选资源并验证依赖，成功后提交新缓存映射，失败时保留旧资源。明确
旧 RID、已有资源租约、GPU 对象延迟销毁和连续修订合并语义。

状态：已完成。结果见
[M-148 Runtime 资源事务重载实施记录](../records/M-148-runtime-resource-transaction-reload.md)。

### M-149：首批资源类型

接通 Texture、Material 和静态 Mesh 的依赖顺序及场景实例刷新。Material 在 Texture 之后应用，Mesh
更新保持节点与实体身份；不扩展骨骼、动画、Morph Target 或 Scene Schema。

状态：已完成。结果见
[M-149 首批渲染资产热重载实施记录](../records/M-149-first-render-asset-hot-reload.md)。

### M-150：Editor 状态与跨平台验收

在资产工作区展示变化检测、导入修订、Runtime 应用结果和失败诊断。使用 Lantern Gallery 验证成功
更新、损坏输入回滚、快速连续保存、Runtime 断线重连和 Windows/Linux Shared/Static 矩阵。

## 测试与验收

- 文件监听覆盖重复、重命名、删除、目录失效、关闭及事件洪峰。
- 防抖后每个稳定内容版本最多产生一次导入，失败不覆盖最后成功索引和派生产物。
- Asset 域覆盖方向、能力、未知操作、修订关联、过期结果和重同步。
- Runtime 更新失败继续渲染旧资源；成功更新不改变场景节点、实体和作者数据。
- 低优先级资产事件积压时，Stop 和心跳仍在既有限时内完成。
- Lantern Gallery 修改 Texture、Material 或 Mesh 后无需重启 Runtime 即可观察到更新。
- Windows 与 Linux 的 Shared/Static、无头运行时及 Sanitizer 验证通过。

## 风险与未决问题

- Windows 与 Linux 文件监听语义不同，平台事件不能直接作为一次完整写入的证明。
- glTF 一次导入可能产生多个 Mesh、Material 和 Texture；修订必须以整次导入事务发布。
- Granit 后端对象若缺少安全的替换或延迟销毁能力，应向用户提出最小 Granit PR 建议，不在 Gneiss
  绕过资源生命周期。
- 资源租约与 RID 在替换后的具体语义由 M-148 结合现有缓存实现验证，不提前承诺公开 ABI。

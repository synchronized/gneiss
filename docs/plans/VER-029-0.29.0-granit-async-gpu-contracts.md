# VER-029：0.29.0 Granit 0.14 异步 GPU 契约接入

## 状态

- 状态：开发中
- 目标版本：0.29.0
- 优先级：P0
- 路线图阶段：异步 GPU 契约与跨后端指标收敛

## 背景与目标

Granit 0.13.0 发布了后端无关的异步 GPU 操作句柄；0.14.0 进一步让 RenderPipeline 在 Vulkan 与
浏览器 WebGPU 后端统一采用异步 Timestamp 回读。Gneiss 0.28.0 已使用 RenderPipeline 最近完成
指标，本版本升级依赖并收敛异步采样的序列、失败和关闭语义。

本版本先升级 Granit 基线，再推动 RenderPipeline 在内部采用异步回读。Gneiss 继续只消费
`granit_render_pipeline_get_metrics` 的非阻塞快照，不持有管线内部 Query Pool 或异步操作句柄。

## 非目标

- 不在 Gneiss 增加 WebGPU、浏览器或 Emscripten Runtime 宿主。
- 不把 Granit 异步句柄、Timestamp Query Pool 或后端类型暴露到 Gneiss 公共 API、Scene 或 IPC。
- 不把 Granit 异步操作误用为 CPU 线程池、资产导入任务或 Gneiss 渲染命令调度器。
- 不在本版本增加新的渲染效果、材质字段或性能分析 UI。
- 不复制 Granit Model Viewer 的网络、glTF 解析或示例任务调度代码。

## 已确认决策

- Fetch 锁定 Granit 0.14.0 正式发布提交 `74a1083b9c8182168ed814c594f6186f0b0fa06e`，
  PACKAGE 最低版本同步提升到 0.14。
- Gneiss 的独立渲染线程继续拥有 Renderer 与所有 Granit 资源；主线程不轮询 Granit 异步句柄。
- RenderPipeline 拥有自身 Timestamp Query Pool 和异步读取操作，负责轮询、复制结果、销毁和关闭排空。
- Gneiss 只接收最近一个已完成样本，并原样保存 Granit 的独立样本序列。当前公共接口没有来源 Frame
  标识，因此不得用提交队列猜测映射；`NOT_READY` 和能力不足不阻塞当前帧。
- 0.13.0 没有改变 Shader、Material 和 Environment 持久化格式，0.28.0 的资产投影保持不变。
- 本次不需要新的 Gneiss ADR；线程所有权和后端投影边界沿用现有决策。

## Granit 上游协作

用户提交的 Granit PR 已由 0.14.0 发布，RenderPipeline 的每个指标 Slot 持有异步读取操作，并在
复用、失败、取消与销毁阶段管理其生命周期。公开指标仍提供最近完成样本与单调样本序列。

- 每个管线 Frame Slot 同时拥有 Query Pool 和至多一个异步读取操作。
- Slot 再利用前非阻塞查询操作；成功时复制结果并发布样本，失败或取消时清理操作且不破坏渲染。
- Pipeline 销毁时安全请求取消、销毁或排空全部操作，再销毁 Query Pool。
- 保持 `granit_render_pipeline_get_metrics` 的非阻塞“最近完成样本”语义；相关序列字段通过描述结构末尾
  扩展或等价的版本化接口加入，不泄漏 Query Pool 与异步操作句柄。
- 同一 Contract Test 覆盖 Vulkan、WebGPU 支持路径、能力不足、`NOT_READY`、失败、取消和关闭生命周期。

0.14.0 未公开来源 Frame 标识，因此 Gneiss 明确把 `sample_sequence` 作为样本身份，而非 Frame
身份。若未来确有逐帧关联需求，再向 Granit 提议调用方相关标识；当前不阻塞本版本。

状态：已完成。已确认通用异步操作本身可用，但 RenderPipeline 指标仍直接调用同步读取；上游 PR
范围已冻结。结果见
[M-188：异步 GPU 契约与管线指标缺口确认](../records/M-188-async-gpu-contract-audit.md)。

### M-189：RenderPipeline 异步指标上游协作与接入

状态：已完成。用户完成 Granit PR 后，Gneiss 已升级到 0.14.0 发布提交；公开非阻塞指标接口兼容。

### M-190：Gneiss 指标序列、失败与关闭语义收敛

校正延迟指标的样本序列语义，覆盖长期 `NOT_READY`、能力不足、单次异步失败和 Renderer 关闭；

状态：已完成。Gneiss 删除待处理 Frame 队列，直接保存 Granit 样本序列。

Gneiss 不把未实现宿主写成当前能力。

状态：已完成。单元测试与 Granit 平台冒烟测试通过；WebGPU 真实执行继续由 Granit 上游负责。

### M-192：版本验收

完成 Windows/Linux、Shared/Static、安装消费、Granit Runtime 与 Sanitizer 验证，提升版本号并收口
路线图、变更记录和验收记录。

## 测试与验收

- AUTO、PACKAGE、FETCH 和父工程目标均解析 Granit 0.14。
- 旧默认 0.13 缓存自动升级，显式提交覆盖保持不变。
- Gneiss 源码不直接创建 RenderPipeline 内部 Timestamp Query Pool 或异步操作。
- GPU 指标读取不阻塞渲染线程；延迟结果携带单调样本序列，不伪造来源 Frame 映射。
- 不支持 Timestamp 的设备稳定降级；失败和取消不终止渲染，也不留下 Granit 资源。
- Renderer 关闭前所有异步操作与 Query Pool 均完成安全清理，资源统计归零。
- Windows/Linux Clang/GCC/MSVC Shared/Static、安装消费、Granit Runtime 和 Sanitizer 通过。

## 风险与未决问题

- Granit 0.14 已完成 RenderPipeline 异步回读；异步 Upload Batch 暂不纳入本版本。
- Vulkan 可能立即完成异步读取，测试仍必须遵守非阻塞状态机，不能依赖特定完成时序。
- 若上游选择新增异步 Pipeline API 而不是保持现有快照接口，需要重新评估 Gneiss 是否应直接持有操作；
  默认建议保持封装，避免泄漏管线内部资源所有权。

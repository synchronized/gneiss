# VER-031：0.31.0 游戏工程创建与目录包导出

## 状态

- 状态：已完成
- 目标版本：0.31.0
- 优先级：P0
- 路线图阶段：外部游戏工程工作流

## 背景与目标

0.30.0 已证明安装 SDK 可以配置、构建并运行独立 Game Module，但 Editor 新建工程仍只生成旧的
最小场景，首次运行也假定工程已经配置。0.31.0 将模板变成唯一脚手架来源，贯通新建、首次配置、
构建、运行和可复制目录包导出。

## 非目标

- 不制作安装器、压缩归档、签名、加密、补丁或商店发布流程。
- 不设计 Shipping 优化、资产烘焙或跨平台交叉打包。
- 不在导出包内携带源码、构建目录或完整 SDK。

## 已确认决策

- `templates/game` 是新工程内容的唯一权威来源；Editor 与命令行复用同一工作流。
- 新建工程使用临时同级目录并原子提交，失败不留下半成品。
- Editor 运行前先执行 configure preset，再执行 build preset，避免缓存缺失或 SDK 位置改变造成隐式失败。
- 首版导出物是可检查的目录包，根目录包含工程描述、资产、模块和平台启动脚本。
- 导出只复制 Runtime 所需文件，拒绝覆盖既有目标目录。

## 测试与验收

- 新建工程具有唯一显示名和模块 ID，并完整包含模板所需文件。
- 安装树外的新工程无需手动 configure 即可由 Editor 运行。
- 导出包不包含 `sources`、`build`、CMake 工程文件或 SDK，能够从任意目录启动。
- 已存在目标、缺少模板、配置失败、构建失败和缺少 Runtime 依赖均返回明确错误。
- Windows、Linux、Shared 安装消费和 Editor/Runtime 相关测试通过。

# VER-028：0.28.0 Granit 0.12 资产契约收敛

## 状态

- 状态：设计中
- 目标版本：0.28.0
- 优先级：P0
- 路线图阶段：上游资产契约收敛与重复实现清理

## 背景与目标

0.27.0 基于 Granit 0.10 接通了标准 PBR、Environment Map 和 GPU 时间戳，但当时 Granit 尚未
公开部分资产契约。Gneiss 因此临时维护 Shader Asset 固定偏移解析、自有标准 PBR Material 归档，
并针对不同 Granit 消费方式推导资产目录。

Granit 0.12.0 已公开 Shader Asset 元数据检查、标准 PBR Schema 与 `pbr_standard.grmat`，同时统一
PACKAGE、FetchContent 和父工程消费时的 RenderPipeline 资产目录。0.28.0 将升级到该正式版本，
以公共契约替换 0.27.0 的临时实现，同时保持 Gneiss 作者资产、RID、场景语义和渲染线程所有权不变。

## 非目标

- 不把 `.grshader`、`.grmat` 或 Granit 类型暴露到 Gneiss 公共 API、Scene、工程文件或 IPC。
- 不在本版本增加透明材质、完整 glTF PBR 纹理集、材质编辑器或 Shader Graph。
- 不因 Granit 0.11 的 WebGPU 对等能力而承诺 Gneiss Web 或 WebGPU 产品支持。
- 不重做 0.27.0 已完成的 PBR 投影、环境光照、渲染线程或 GPU 时间戳。
- 不保留未发布临时后端格式的迁移兼容层。

## 已确认决策

- 依赖锁定 Granit 0.12.0 正式发布提交，PACKAGE 最低版本同步提升到 0.12。
- 使用 `granit_shader_asset_inspect` 或其 C++ 包装读取 Shader Asset 元数据，删除固定字节偏移解析。
- 使用 Granit 发布的 `pbr_standard.grmat`、PBR 参数名、Binding、常量偏移和顶点布局验证接口，删除
  Gneiss 自有的同构 PBR Material 归档与常量副本。
- `granit_RENDER_PIPELINE_ASSET_DIR` 是三种消费模式下唯一的 Granit 后端资产入口；Gneiss 仍自行
  决定嵌入、安装和异步加载策略。
- 延续 ADR-039：Granit 资产只作为可失效后端投影，Gneiss 的作者数据和资产身份不下沉。
- 本次不需要新的 Granit PR；0.27.0 发现的通用缺口已经由 Granit 0.12.0 补齐。

## 实施顺序

### M-181：Granit 0.12.0 升级与兼容审计

升级 Fetch 锁定提交、PACKAGE 最低版本、安装消费和依赖缓存默认迁移；验证 0.10 构建目录能够自动
升级，同时保留用户显式固定其他提交的能力。

状态：已完成。Fetch 默认提交、PACKAGE 最低版本、传递依赖和构建指南均已升级；旧 0.10 默认缓存
自动迁移，显式覆盖保持不变。结果见
[M-181：Granit 0.12.0 升级与兼容审计](../records/M-181-granit-0.12-upgrade.md)。

### M-182：Shader Asset 公共检查接口接入

用 Granit 公共元数据检查接口替换 `pbr_shader_resolver` 中对清单魔数、固定摘要偏移和最小长度的
私有解析。解析失败必须返回明确错误，不得读取未经验证的内容 ID。

状态：已完成。Resolver 已改用 Granit 公共检查接口，磁盘和内嵌资产不再依赖私有清单布局。结果见
[M-182：Shader Asset 公共检查接口接入](../records/M-182-shader-asset-inspection.md)。

### M-183：标准 PBR Schema 与 Material 收敛

改用 Granit 标准 PBR 头文件和 `materials/pbr_standard.grmat`，删除 `gneiss_pbr.grmat` 及重复参数、
Binding、常量偏移；在 GPU 投影边界继续把 Gneiss Material 数据映射到 Granit Material Instance。

状态：已完成。后端投影使用 Granit 标准 Material、参数和顶点布局契约，仓库内同构归档已删除。
结果见 [M-183：标准 PBR Schema 与 Material 收敛](../records/M-183-standard-pbr-contract.md)。

### M-184：资产目录与打包路径统一

删除从 Granit 源码布局反推资产目录的兼容逻辑，统一使用公开资产目录变量；同步检查构建树、安装包、
FetchContent 和父工程目标下的嵌入及安装行为。

状态：已完成。三种消费方式只使用 Granit 公共资产目录，标准 Material 已进入构建暂存与安装检查。
结果见 [M-184：资产目录与打包路径统一](../records/M-184-render-asset-directory.md)。

### M-185：跨后端契约与失败语义验证

验证 Vulkan SPIR-V 与 WebGPU WGSL sidecar 的选择和元数据一致性，但只把它作为后端中立性测试，
不新增 Gneiss WebGPU 宿主。覆盖缺失 sidecar、内容 ID 不匹配、布局不兼容和标准材质缺失。

状态：已完成。Vulkan/WebGPU sidecar、标准 Material、顶点布局和主要失败输入均已覆盖。结果见
[M-185：跨后端契约与失败语义验证](../records/M-185-pbr-contract-failures.md)。

### M-186：重复实现清理与版本验收

删除失效适配代码和测试夹具，更新构建、参考文档及变更记录；完成 Windows/Linux、Shared/Static、
安装消费、Granit Runtime 和 Sanitizer 验证。

状态：待开始。

## 测试与验收

- AUTO、PACKAGE、FETCH 和父工程目标均解析 Granit 0.12，并取得一致的 RenderPipeline 资产目录。
- 旧默认 0.10 缓存自动升级；用户显式覆盖的提交不被改写。
- Shader 元数据只通过 Granit 公共接口读取，源码中不存在固定清单偏移或私有格式解析。
- 标准 PBR Material、参数、Binding 和顶点布局只以 Granit 公共契约为权威来源。
- 删除 Gneiss 自有同构 PBR 归档后，Lantern Gallery 的基础颜色、纹理、金属度和粗糙度保持正确。
- 后端资产缺失或不匹配时失败可诊断，已生效资源与渲染线程生命周期不被破坏。
- Windows/Linux Clang/GCC/MSVC Shared/Static、安装消费、Granit Runtime 和 Sanitizer 通过。

## 风险与未决问题

- Granit 标准 Material 的内容 ID 与 Gneiss 0.27 内嵌归档不同，必须整体替换 Material 与 Shader
  资产，不能混用新旧内容。
- 公共顶点布局验证可能暴露当前导入布局与完整 PBR 纹理变体的差异；本版本只修正现有能力所需布局，
  不顺带扩展完整纹理集。
- 若构建树已有旧 FetchContent 源目录，必须验证默认提交更新确实触发重新获取，避免配置缓存继续引用
  旧资产。

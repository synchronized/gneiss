# VER-007：0.7.0 编辑器基础闭环

## 状态

- 状态：实施中
- 目标版本：0.7.0
- 优先级：P0
- 路线图阶段：编辑器基础

## 背景与目标

Gneiss 已具备窗口、输入、基础 3D 渲染、版本化场景、Type Registry 和类型安全属性访问，但这些
能力目前只能通过示例或代码调用。`0.7.0` 的目标是建立独立 Editor 宿主，让用户能够打开场景、
在层级面板中选择节点、在场景视图中观察结果、通过属性面板修改 Transform 或 Camera，并将修改
保存回场景文档。

```text
打开场景 → 构建层级 → 选择节点 → 查询组件属性 → 编辑并即时预览 → 保存 → 重新加载验证
```

Editor 只消费公开运行时能力和工具侧适配，不成为 `gneiss` Runtime 的隐式依赖。首版以形成稳定
的编辑数据流为目标，不追求完整编辑器体验。

## 非目标

- 完整 Docking 工作区、主题系统、多窗口或可插拔面板框架。
- Gizmo、网格吸附、框选、拖放层级重排或复杂快捷键系统。
- Undo/Redo、命令历史、Prefab、资产浏览器、缩略图和导入队列。
- 脚本编辑、调试器、性能分析器、游戏内正式 UI 或 UI Runtime。
- 动态插件、模块热重载、多人协作或跨进程编辑协议。
- 在本版本扩展通用反射继承、容器反射或任意 C++ 对象反射。

## 已确认决策

- Editor 位于 `apps/editor/`，作为独立可执行宿主依赖 Runtime；Runtime 不依赖 Editor。
- 编辑器选择使用场景节点 ID，属性目标继续使用 World 与实体 ID，不保存组件地址或 EnTT 类型。
- 层级、属性和保存功能通过公共 C/C++ API 完成；若现有 API 不足，先补最小、可复用的 Runtime
  查询接口，不让 Editor 包含 `src/` 私有头。
- 场景视图复用现有 Application、Camera、Render Service 和 Granit 后端，不建立第二套渲染状态。
- 属性控件由 Type Registry 的字段种类、能力和约束驱动；控件代码不硬编码组件内存布局。
- 场景保存继续输出当前版本作者 JSON，并保留未知字段；保存采用显式用户操作，不在每次属性修改后
  自动覆盖源文件。
- UI 技术、事件转发和渲染后端接入在 M-45 Spike 后通过 ADR 固定；依赖不得泄漏到公共 ABI。
- `0.7.0` 期间继续允许调整 0.x API，但任何破坏性变化都必须同步测试、文档和迁移说明。

## 实施顺序

### M-45：Editor 宿主与 UI 接入 Spike

状态：已完成。[ADR-017](../decisions/ADR-017-editor-ui-render-composition.md) 已确定单一 Renderer、
Swapchain 与提交生命周期，以及 Editor 生成后端无关 UI Draw List 的边界。`apps/editor/` 已接入
固定版本 Dear ImGui，通过公共输入 API 和 UI Draw List 完成字体纹理、输入与同帧渲染闭环；首版
窗口固定为 1280×720，待公共窗口尺寸与 DPI 查询能力落地后再启用缩放。

### M-46：编辑器查询边界与场景会话

状态：已完成。公共接口可按作者顺序枚举场景节点、读取可选显示名称和当前父子关系；旧场景缺少
名称时由 Editor 回退显示 UUID。Editor 会话拥有当前场景句柄、层级快照、选择和脏状态，打开失败
保留既有会话，关闭或节点失效后选择自动清空。序列化接口继续作为后续显式保存的数据来源。

### M-47：场景视图与选择

状态：已完成。中央视图通过透明工具层显示现有 World 渲染结果，并使用独立 Editor Camera 提供
移动、环视、滚轮推进和聚焦所选节点。层级面板与场景视图共享同一选择状态，视图以边框和名称
提供反馈；首版不实现鼠标拾取或离屏 Viewport Texture。

### M-48：层级面板与属性面板

状态：已完成。层级面板按稳定顺序展示节点树；属性面板通过独立于 ImGui 的模型枚举所选实体的
Transform 与 Camera 字段，并按属性元数据生成布尔、标量、向量和四元数控件。写入统一经过 Type
Registry setter；非法输入、只读字段和目标失效会保留原值并给出诊断，成功写入才标记会话为脏。

### M-49：编辑回写、脏状态与保存闭环

状态：已完成。属性修改通过统一 setter 回写 World，并在同一帧渲染中可见；成功修改才标记会话
为脏。Inspector 提供 Save 按钮与 `Ctrl+S`，将序列化结果写入场景同目录的临时文件后原子替换源
文件。保存失败不覆盖既有文件且不清除脏状态；重新加载测试验证修改和未知字段均被保留。

### M-50：Editor 示例场景与版本验收

状态：实施中。Editor 已改为读取版本化 `gneiss.project.json`，由工程描述确定资产根和初始场景；
`examples/editor_demo/` 提供可直接启动的最小工程。工程解析已覆盖固定工程根入口、缺失工程文件、
非法或缺失资产根、缺失初始场景和路径穿越。无参数启动会显示独立 Project Manager，Windows 可
通过系统目录选择器选择工程；选择窗口销毁后才创建正式 Editor。后续仍需完成最近工程、新建工程、
跨平台原生选择器、构建矩阵、安装 Consumer、交互验收记录和版本收尾。Project Manager 与正式
Editor 已统一应用参考 Catppuccin Mocha、使用 Peach 强调色的 `Gneiss Mocha` 主题。

## 测试与验收

- Runtime 公共 `.h` 继续由 C11 编译器独立包含，`.hpp` 由 C++20 编译器独立包含。
- Editor 关闭时按确定顺序释放 UI、场景、渲染资源、Application 和窗口，不留下后端资源。
- 场景会话覆盖打开失败、重复关闭、失效节点、空选择、保存失败和脏状态转换。
- 层级枚举覆盖多根节点、父子顺序、销毁节点和跨 World/场景句柄误用。
- 属性面板覆盖可写、只读、非法值、组件缺失、实体 generation 失效和失败原子性。
- 保存闭环覆盖修改后重新加载、未知字段保留、目标文件不可写和失败不覆盖。
- Windows/Linux 至少各完成一次 Editor 启动与场景闭环验证；无图形环境仍可运行非 UI 单元测试。

## 风险与未决问题

| 项目 | 当前处理方式 |
| --- | --- |
| UI 库和 Granit 接入成熟度 | M-45 用最小 Spike 验证，并以 ADR 固定依赖和所有权 |
| Runtime 缺少节点枚举或组件枚举 | 只增加 Editor 之外也可复用的最小查询接口，并保持 C11 ABI |
| UI 输入与游戏输入冲突 | UI 捕获状态在宿主层仲裁，不改变 Runtime 输入动作语义 |
| 保存目标与 VFS 只读挂载 | M-46 明确作者源路径与写入能力；首版不假定所有 VFS 都可写 |
| 四元数不适合直接编辑 | 首版可先提供受校验的基础控件；欧拉角展示需单独定义转换与连续性 |
| UI 自动化在无图形 CI 中不稳定 | 会话和面板模型独立测试，图形闭环使用本地及手动 Actions 验收 |

## 版本完成条件

- M-45～M-50 全部完成并形成 `0.7.0` 验收记录。
- 用户能够从 Editor 打开测试场景，选择层级节点，修改 Transform 或 Camera，并立即看到结果。
- 保存后的场景可重新加载，修改与未知作者字段均保持，失败保存不破坏原文件。
- Editor 不依赖 Runtime 私有头，Runtime、公共 ABI 和安装 Consumer 不依赖 UI 库。
- Windows/Linux 手动矩阵通过，构建与运行入口由构建指南统一说明。

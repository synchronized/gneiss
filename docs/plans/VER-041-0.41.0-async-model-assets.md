# VER-041：0.41.0 模型资产异步加载与热更新

## 状态与目标

已完成定义范围与发布验收，版本 `v0.41.0`。2026-09-25 用户授权本版完整发布闭环。
沿用单一分支 `feat/0.41-async-model-assets`，完整任务形成一个 PR。

在 0.40 纹理异步事务基础上，覆盖 Mesh、Material、Texture 的实际模型修订。依赖准备在共享
调度器执行，GPU 候选完成后整批发布；失败不出现半更新，完成回执与渲染内容一致。
以 GPU 回读补齐上一版无法通过系统截图验证实际像素的缺口。

## 交付与非目标

- 保留现有线程池和协作模式，扩展现有资产加载服务，不建立第二套任务状态。
- 纯纹理与混合渲染资产使用同一事务入口；支持已有 JSON/二进制 Mesh、Material、PNG/KTX2/运行纹理格式。
- 依赖解析、读取、解码和源一致性复查在 CPU 准备阶段；主线程负责身份、RID 和原子发布。
- 渲染线程负责 GPU 暂存、确认和失败回收；明确上传字节/批次预算与单资源不能抢占的限制。
- Editor 显示准备、上传、成功、失败与取消状态，保留请求/修订身份与有界队列。
- 实际模型重导入、错误恢复、窗口操作、取消和退出均有可复现验证。

不承诺完整场景异步实例化、任意资产流送、公共异步 SDK、完整 Web 移植、自动抢占任务或统一
所有 Service 装配。Scene/Prefab 结构更新保留原路径。不开启 Granit 跨仓库修改。

## 已确认设计原则

事务契约见 [ADR-049](../decisions/ADR-049-model-asset-transactions.md)，实施顺序见
[DEV-041](DEV-041-async-model-assets.md)。

- 准备阶段持有有界源快照；同 URI 去重，类型冲突、过期缓存身份和源变化明确失败。
- 材质依赖纹理必须纳入候选或稳定引用；不能在主线程隐式读取缺失依赖。
- 旧帧持有旧资源快照，新帧只能观察完整发布后的同批版本。
- 提交许可前取消不发布；获得许可后完成或回滚，终态只产生一次。
- 回读验证真实渲染结果，不把上传成功或空白截图当作像素正确。
- 上传拆分只影响准备过程，不提前发布批次中的部分资源。

## 验证要求

CPU 与服务测试覆盖两种调度模式、缺失/损坏依赖、同 URI 合并、输入与候选超额、取消、旧身份
失效、关闭后无回调及作用域隔离。渲染验证使用真实 GPU 输出回读，检查前后颜色和失败保留；
重载包含材质改引用以及几何变化，防止只更新纹理却遗漏 Mesh/Material。

实际负载采用仓库已有合法来源模型，分别记录 Debug/Release 准备、排队、提交、GPU 阶段、
实际呈现间隔和退出耗时。协作模式保留大任务不可抢占事实，不以忙等无头循环代替窗口验证。

发布前执行 Windows/Linux 共享/静态、公共头文件与安装 C/C++ Consumer、原有浏览器最小宿主
回归。完整远端矩阵对候选运行一次；失败修复只重跑受影响工作流，文档归档不重复矩阵。

## 风险

已采用独立网格缓冲和 GPU 回读，无需 Granit 修改。剩余限制与真实测量见
[验收记录](../records/M-265-271-0.41.0-validation.md)。

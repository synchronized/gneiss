## M-312：当前基线与复现

- 复用 scripts/performance/measure_scene_loading.py、measure_texture_loading.py 与现有场景夹具，
  检查当前参数和输出；缺少的观测先在测试/测量层补充，不预先扩展公共 API。
- 保存源码提交、设备/驱动、构建类型、执行模式、资产哈希、Cook 配置、缓存状态及视角。
  Release 作为性能比较配置，Debug 独立记录功能/诊断结果；不得混合比较。
- 完整 Cook 4K Sponza、日常场景各模式至少三次可完成样本；冷/热缓存分开，失败样本保留。
  外部资产缺失时记录来源与准备步骤；先用小夹具验证方法，不伪造完整场景结果。
- 分阶段测量读取、来源复验、解析/解码、实例化、上传、激活、清理；记录帧间隔的分位数与最大值、
  事件响应、取消请求到观察/终态/清理的延迟、进程内存与资源分项峰值。
- 审查 scene_load_service、scene_load_preparation、scene_load_builder、texture_load_service
  与 core/tasks 的执行边界。明确时间预算约束哪些操作、单次不可分割调用多长。
- 建立短读/损坏/预算不足/上传失败/迟到完成的小夹具，以及 IPC 对端退出和启动阶段日志。
- 建立实际测量 Record，在其中冻结环境相关门槛表：最长加载帧、交互/取消延迟、总加载耗时
  可接受回退、内存峰值与清理期限。说明阈值依据与无法观测的项，后续任务链接该权威记录。

## M-313：分阶段执行与响应性

- 在测得的主要热点引入可恢复的批次或状态，复用调度器现有任务与取消机制；不每个 Service 建新线程池。
- 每批有工作量边界和取消检查，临时缓冲跨批的所有者明确；让出执行后不得依赖失效的栈数据。
- 审计错误传播、最终回调唯一性、零任务与空资产、极小预算、重复取消和公平推进；禁止忙等。
- 对 thread/cooperative 验证相同最终资产和错误语义。通过可控夹具验证让出次数/工作上限，
  真实场景计时用于响应性验收，不以易抖动的微秒断言替代正确性测试。
- 若必须调整长期任务契约，先记录 ADR；不可切分的第三方调用明确列出决策与残余影响。

## M-314：回收证据与预算生命周期

- 画清请求、候选、活动场景、缓存、旧帧和在途上传的所有权，复用既有账本与租约。
- 先评估内部诊断和既有预算快照能否表达请求清理；确需字段时定义单位、统计范围、快照时点、
  所属请求身份和线程安全，贯通 C/C++、IPC 与 Editor/Runtime，保持旧消息兼容。
- 测试读取、准备、上传、ready、激活前取消，重复取消、失败后重试、关闭期间完成与旧请求迟到。
  旧场景继续可用，销毁后的请求不能被迟到事件复活。
- 注入共享资源与缓存命中，检查预留转移、回收次数及峰值重叠；终态尚在清理时不伪报全部释放。
  检查所有引用结束后账本回落，进程内存只作辅证，不要求分配器立即把页面归还操作系统。

## M-315：IPC 与启动诊断

- 从 platform/ipc 传输和 Runtime 会话现有测试入手，用同步屏障/可控对端退出复现读写竞态，
  避免仅靠 sleep 或大量重跑碰运气；覆盖正常断连、半关闭和发送期间退出。
- 在 Linux 验证 SIGPIPE 不意外终止宿主、错误能正确传播；如修改信号处理，限制影响范围并说明
  对调用进程的影响，不能未经审计全局改变信号策略。Windows 验证等价断连语义。
- 灯廊记录启动各阶段与第二次启动资源状态，保留原期限；分别检查空闲与受控负载环境。
  环境噪声与产品错误分别归因，未复现的历史迹象如实保留，不宣称已修复。

## M-316：端到端对比

- 同一输入、环境和配置复测，逐项比较冻结门槛，列出通过/失败/未验证。
- Editor/Runtime、thread/cooperative 完成加载、至少三次切换、各阶段取消、失败重试、退出，
  加载期间执行连续 resize 与最小化恢复，检查旧场景保留、主线程响应及资源最终归属。
- 检查 PNG 兼容、BC7 选择与 RGBA8 回退；只在真实设备支持的格式上进行 GPU 验证。
- 保存可复现命令、结果数据与必要画面对照，确认场景内容未因优化缺失；第三方资产不入仓库。

## M-317：平台与交付

按[构建指南](../guides/building.md)先完成相关格式、静态检查和专项测试，
再完成共享/静态、安装消费者及所需本地完整回归。真实 GPU 路径保留 Vulkan 校验。
完整候选手动运行 Windows/Linux 矩阵一次；仅在相关改动后复验受影响工作流。

实现事实写 Reference/Guide，测量和故障过程写 Record；更新迁移说明和 CHANGELOG。
发布授权到位且门禁通过后完成同一 PR 的合并、标签和源码 Release，实际发布后归档。
不将通过最小 task-web 测试描述为完整 Web 引擎已验收，不自动操作 Granit 仓库。

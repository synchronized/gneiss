# 网格与纹理描述、数据和异步加载

状态：本轮实现完成，编译与静态检查通过；运行验收待统一安排。
验证见 [实施记录](../records/async-render-assets-2026-10-26.md)。关联 [异步文件服务](PLAN-051-async-file-service.md)、
[ADR-085](../decisions/ADR-085-render-asset-loading.md)。

## 目标与范围

运行时 texture_load_service 的 Mesh/Texture 路径统一使用 file_service：等待文件时不占 CPU
任务，文件完成后提交纯内存解码，再交渲染服务上传。保留材质独立加载及依赖队列。
本轮完成全量数据异步加载，不实现 mip/LOD 流送、稀疏驻留、首次绘制触发加载或新的版本事务。
显式同步工具接口继续保留；浏览器后端、异步宿主关闭属于 PLAN-051 后续范围。

## 已确认的数据职责

| 数据 | 权威来源 | 生命周期 |
| --- | --- | --- |
| 源文件和导入设置 | 美术输入、现有导入配置 | 编辑与重新导入 |
| 纹理描述 | 现有 texture JSON：负载 URI、颜色空间、用途 | 描述解析至依赖读取 |
| 纹理布局 | gneiss-texture Manifest：尺寸、变体、mip 布局 | 解码及运行资源 |
| 网格布局 | 现有 GNMS 头部与布局字段 | 二进制校验与解码 |
| 实际负载 | 纹理容器、网格文件中的字节 | 有界异步读取至解码完成 |
| 运行资源 | CPU 数据、稳定 RID、GPU 后端对象 | 由引用和渲染服务管理 |

不重复生成保存同一尺寸/格式信息的 JSON。图集、序列帧以后使用独立描述引用纹理；
不把编辑内容混入自动生成的导入产物。源文件或导入设置变化复用现有构建流程重新生成产物。
本轮不增加文件监视器，也不宣称运行时自动重新导入。

## 实施顺序（代码已完成）

1. 提取纹理描述类型和纯内存准备入口，复用格式解析/校验；不得让解码器访问真实文件后端。
2. Mesh 异步读取文件后解码；Texture 异步读取描述、解析依赖、异步读取负载、解码。
   每个 CPU 阶段只执行一次；执行器容量不足可重试提交，文件等待不反复提交任务。
3. 资源来源身份统一从管理器文件服务解析，兼容注入文件服务与旧 VFS 导入挂载。
4. 保留 GPU 完成确认、稳定 RID、失败保留旧资源、取消及迟到回调隔离。
5. 编译相关测试与主工程，完成格式和边界静态检查；运行验收留待用户安排统一验证。

## 取舍与限制

本轮整读有明确大小上限，纹理容器可能包含多个变体，因此临时输入仍可能大于 GPU 上传量。
运行时只保留选中变体的 CPU 负载，释放整容器输入；恢复上传直接用该内存，不同步重新读盘。
代价是选中变体常驻 CPU 内存；这属于当前全量加载方案，不冒充按需流送。
描述就绪、CPU 数据就绪、GPU 可用是三个不同阶段；只有后端确认上传完成才标记应用成功。

后续流送须单独设计可独立解码块、范围读取、在途内存预算及 GPU 子资源可见性。
范围读取减少 I/O，并不自动减少完整纹理分配的显存。PNG 和内联 JSON 网格不保证局部解码。

## 验收条件

- 异步运行路径没有真实同步文件读取或同步回退；不在解码任务中轮询文件请求。
- Mesh、PNG/KTX2 和运行纹理容器使用相同调度规则；颜色空间、摘要、边界、预算仍校验。
- 描述或负载缺失/损坏失败，不上传半成品；取消/析构后的迟到回调不得访问已销毁对象。
- 新服务注入和旧 VFS 导入的资源身份一致；旧资源更新失败仍可用。
- 测试覆盖文件等待期间不提交 CPU 任务、负载分阶段读取、纯内存解码、失败与取消。
- 当前只要求编译与静态检查；未执行的运行测试明确记录为待验收。

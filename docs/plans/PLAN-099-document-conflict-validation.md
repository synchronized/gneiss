# PLAN-099：文档恢复冲突检查审计与优化

状态：已完成审计与提交前检查优化；未引入场景修订号。

## 修改入口审计

| 入口 | 当前修改路径 | 修订计数的覆盖要求 |
| --- | --- | --- |
| 名称、父子关系、变换 | Scene 接口及 World 的节点接口 | 不能只在文档命令中计数 |
| 相机、网格等组件 | World 接口与组件适配器安装/移除 | 组件替换及失败后的部分变化都须覆盖 |
| 通用 ECS 修改 | `world_state::get<T>()` 返回可变指针，系统回调接收 `world_state&` | 可变借用后的写入无法由普通 setter 计数完整追踪 |
| Prefab 来源、属性与组件覆盖 | Scene / `prefab_binding` 的实例记录 | World 计数不能独自覆盖这些保存意图 |
| 撤销重做 | 文档命令、组件适配器、Scene 快照恢复 | 必须覆盖实际底层写入，不能只依赖历史条数或 dirty |

现有 World、Scene 没有覆盖这些入口的统一修订通知。当前新增计数会产生漏检或迫使重构全部可变
访问入口；该工作不属于本次局部优化。未来真正引入修订号前，须先约束可变借用并统一 Scene
覆盖记录与 ECS 修改通知，不能删除最终内容校验后再补覆盖。

## 本次实现

保留开始时捕获的序列化内容作为基线。等待期间仅检查应用/文档身份、关闭及历史占用状态，
并轮询自己的资源请求；依赖就绪后，在所属线程比较当前序列化内容，再同步提交历史。
成功路径由每次轮询编码整场景降为开始和提交前各一次，不新增状态副本或通知系统。

取舍：内容冲突延后到提交前报告，资源可能继续准备一段时间；加载失败优先报告加载错误。
判断的是提交时内容与基线是否相同，不承诺检测已经修改又恢复原值的过程。
文档关闭、切换、取消仍即时结束。该方案不改变直接 World 修改的最终覆盖保护。

# C51-07：CAORS 统一 VFS 与异步读取实施方案

0.4.0 基线后的缓存刷新、分块读取和快照性能研究见
[C51-08～10 后续提案](UPSTREAM-051-caors-vfs-followups.md)。本页保留原实施方案，不作为上游完成记录。

## 状态与目标

2026-10-19，提交给 CAORS 评审的实施草案，尚未实施或提交上游 PR。
用户负责上游交接；本文件不授权修改 CAORS，不变更当前版本发布范围。
前置需求见 [CAORS 接入约束](UPSTREAM-051-caors-integration-contracts.md)。

本次核对 CAORS `d2d6b3e0b38e2d7a5fe3040779cff6c03803f8ca`（工程版本 0.3.0）：
已有外部 executor、异步 Loader、独立订阅取消与 asset_group；无需重复实现。
本方案补充文件访问层，目标是最终只维护一套 CAORS 路由和挂载，由 Gneiss 提供 libuv 后端。
CAORS asset_manager 负责通用资源管理；Gneiss 保留资产版本校验、格式解析与渲染提交。

以下类型名和接口均为概念草案，不是现有 API。实现前由 CAORS 固定公开契约；
Gneiss 接入前另建立 ADR 确定依赖布局、所有权与旧接口退出方式。

## 现状与差距

CAORS 路径相对于其仓库；Gneiss 路径链接到本仓库。

| 能力 | 当前依据 | 本次要求 |
| --- | --- | --- |
| URI 与挂载 | CAORS `io/file_system_resolver.h`、`io/mount_file_system.h` | 同步和异步共用路由，不维护第二张挂载表 |
| 后端寿命 | CAORS resolver/mount 借用 `file_system` | 新异步路径捕获后端寿命；不能仅保存路由表中的裸指针 |
| 打开输入流 | CAORS `io/file_system.h` 默认通过 `read_all()` 打开 | 异步随机读取不得隐式退化为整文件读取 |
| 资源来源转发 | CAORS `resources/source.h`、`file_source`、provider | 转发异步能力，资源 Loader 不另做 URI 路由 |
| 范围与来源寿命 | Gneiss [read_source](../../src/engine/asset/read_source.hpp) | 保留真正范围读取、已打开文件独立存活语义 |
| 挂载身份 | Gneiss [virtual_file_system](../../src/engine/asset/virtual_file_system.hpp) | 挂载快照与来源身份稳定，不因重新挂载串用资源 |
| 来源修订 | 历史方案，已撤销 | 普通加载不再强制复验，见 [ADR-075](../decisions/ADR-075-remove-source-revalidation.md) |
| libuv 访问 | Gneiss [uv_async_file](../../src/engine/platform/io/uv/uv_async_file.hpp) | 复用底层 I/O，适配 CAORS 协议，不建立第二套 VFS |

## 目标边界

```text
CAORS asset_manager / provider
  → Gneiss async_loader（解析资源、验证版本）
  → CAORS source / VFS 路由快照
  → Gneiss libuv_file_system（一个后端，无独立挂载表）
  → libuv loop → 读完 → worker 解析 → completion 所属线程提交
```

- CAORS：通用路由、可选异步读协议、范围约束、请求终态与所有权契约、模拟后端测试。
- Gneiss：libuv loop/文件请求、现有 executor 适配、预算、资产校验与具体 Loader。
- GPU 就绪与场景事务不下沉；不能将“文件读完”直接等同于“渲染资源可发布”。
- 不新增线程池、不要求 CAORS 核心依赖 libuv，不改造其同步写入、目录枚举或文件监听。
- 不包含网络文件系统、压缩包格式、异步写入、自动热卸载与全套反射迁移。

## 推荐接口形态

扩展现有 `file_system` 的可选能力，不另建 `async_vfs` 路由器。
新增能力默认返回 unsupported；resolver、mount 和 file_source 必须转发实际目标能力。
新虚函数会影响 C++ ABI，应随 CAORS 版本更新并要求相关宿主重新编译，不承诺旧 DLL 二进制兼容。

| 概念入口 | 输入与结果 | 关键契约 |
| --- | --- | --- |
| `snapshot()` / `resolve()` | URI → 拥有式解析结果 | 捕获来源标记、后端、目标路径；解析不执行磁盘 I/O |
| `start_open_read()` | 解析结果、上下文、完成凭证 → 启动状态 | 不在提交线程执行阻塞 open/stat；成功交付拥有式随机读取文件 |
| `read_file::start_read_at()` | uint64 offset、长度、预算、完成凭证 | 请求拥有结果缓冲，支持同文件不同偏移并发读 |
| `read_file::size()` | 打开时捕获的长度 | 只是范围边界，不代表内容不可变 |
| `read_all_bounded()` helper | 文件、最大允许字节数 | 分配前限额检查，分块读取，超限明确失败 |

异步上下文复用 CAORS executor 和停止信号的通用类型，包含 stop_token、完成 executor、
结果 allocator 与单请求字节上限；IO 层不得依赖 resources 层的 load_completion。
完成凭证可复用相同设计原则，但须以 IO 结果类型定义，避免引入反向依赖。
首版不增加面向调用方裸缓冲区的异步重载，降低取消和跨线程时的缓冲寿命风险。

### 能力声明与同步兼容

- 分开声明异步打开、异步随机读取、真正范围读取；不能仅用 seek 标记推导这些能力。
- 同步后端继续可用；无异步能力时默认 unsupported，不悄悄读取整个文件或阻塞等待。
- 可提供显式的 worker 同步适配器，但须标明占用工作线程、不代表内核非阻塞 I/O。
- 内存后端可立即产生结果；用户完成通知仍遵守完成 executor 的调度契约。
- libuv 文件访问可能使用其内部线程池，本方案只保证调用方不阻塞等待，不宣称内核级异步。
- 同步入口不得在主线程或 I/O loop 中通过等待异步结果来实现。

## 生命周期、线程与错误契约

### 挂载和来源身份

推荐将现有路由记录升级为可共享的不可变记录，并让 snapshot 持有这些记录和后端拥有者。
这是同一挂载状态的只读快照，不是同步/异步各自维护的两份权威路由。
已有借用 mount 可保留给同步使用；缺少寿命保证时，异步解析须拒绝或要求显式 owner token。
拥有者必须覆盖后端对象、实现代码及 allocator，shared_ptr 本身不自动解决 DLL 卸载。

- 修改挂载仅影响新快照；同一次加载的依赖解析使用同一快照，避免半途中切到新来源。
- unmount 不销毁已有快照、文件或在途请求依赖的后端；这些对象按自身寿命释放。
- 新挂载即使 URI 相同也有新来源标记；复制快照保留原标记，透明转发不制造伪来源。
- 来源标记为进程内身份，不充当持久 GUID、文件内容摘要或资产类型 ID。
- 不在异步解析前调用 exists/status 做同步预检查；打开失败由实际操作返回。
- 大小写、分隔符和路径逃逸规则继承已明确的后端/路由契约，不能因异步入口而改变。

### 范围与缓冲

- 采用精确范围读取：先检查 offset、length 及溢出，再分配缓冲；不得先读取全文件。
- 零长度允许位于 EOF；越界参数报错。读取中截断产生短读错误，不交付伪成功的完整缓冲。
- 外部文件增长不扩大已打开文件的长度边界；内容原地变化仍需资产层复验。
- 底层分段短读可继续累计，只有达到长度才成功；实际提前 EOF 明确失败。
- 长度超过 size_t 或后端单次限制时，拒绝或内部拆分，不能截断转换；首版结果缓冲仍受总预算限制。
- 缓冲由操作拥有，成功后转移给结果；allocator 至少存活到结果及全部回调清理结束。
- 全局在途字节/请求数预算由宿主执行，拒绝时不遗留 pending；不在上游固定 1 MiB 等分块常量。

### 请求终态和取消

- 启动成功表示接管请求，最终恰好一次成功、失败或取消；不保证稍后才完成，应支持同步重入。
- 启动拒绝不产生用户完成通知，内部凭证和缓冲必须回收；接口应有防止重复交付的实现。
- 取消是协作请求，不证明底层 I/O 已停止。完成与取消竞争须有唯一终态裁决点。
- 操作句柄销毁仅放弃结果/请求取消，不在析构中等待 I/O；迟到回调仍完成底层清理。
- 底层文件在全部请求回收后关闭；关闭错误有诊断，不能泄漏句柄或在任意线程调用 loop 私有操作。
- 用户通知交给指定完成 executor。若其拒绝或销毁任务，请求置为投递失败/放弃终态并释放结果，
  不改在 I/O 线程强行执行用户回调；需有可查询终态或受控清理路径，不能永久 pending。
- 保留后端错误码供诊断；not_found、permission、unsupported、取消、内存不足、短读和队列关闭可区分。

### libuv 与关闭顺序

1. 宿主停止新的资源请求；保留完成 executor 和 loop 的运行能力。
2. 取消订阅并将底层 stop 转交 loop；不能从任意线程释放 uv 请求。
3. 排空真实 I/O、解析任务和完成清理；取消句柄状态不能替代此步骤。
4. 释放资源结果、文件、挂载快照和后端对象。
5. 关闭适配 executor、libuv loop，最后释放 allocator 和模块 pin。

不得在任务内部阻塞 close 自己所属的 executor，也不能先停主线程完成队列再等待它执行清理。
Gneiss 当前 uv 接口以 poll 回执为主，接入需在底层完成处提供通知或由已有 pump 有界推进；
禁止给每个请求新建等待线程或在 worker 忙轮询，以免掩盖异步接口缺失。

## 实施批次与交付

| 批次 | 负责方 | 实施内容 | 完成条件 |
| --- | --- | --- | --- |
| A：契约与快照 | CAORS | 固定接口、错误和寿命；共享路由记录、owner 与身份；明确 ABI 变化 | 同步/异步解析一致，重挂载与销毁测试通过 |
| B：异步读取协议 | CAORS | 打开、范围读、完成凭证、限额和取消；内存/可控假后端 | 无整文件回退；竞争、拒绝、放弃和短读测试通过 |
| C：资源来源转发 | CAORS | resolver、mount、file_source/provider 复用同一解析结果；异步 Loader 示例 | manager→Loader→VFS 全链路，混合同步/异步能力正确 |
| D：真实 libuv 适配 | Gneiss | 锁定 CAORS；宿主 executor、loop、libuv_file_system；一个 CPU 资源 | 真实范围读、取消及关闭，不阻塞 worker 等待 I/O |
| E：资产路径迁移 | Gneiss | Prefab 描述，再 Mesh/材质/纹理；迁移来源身份与摘要复验 | 原有来源变化、失败回滚及预算行为不退化 |
| F：收敛与删除 | Gneiss | 切换全部调用者，移除旧路由和重叠接口，更新文档/边界检查 | 唯一权威 VFS；兼容桥无调用后删除 |

CAORS 可以按 A—C 组成一个可独立评审的功能 PR，先发布契约再补实现；
D—F 在 Gneiss 独立实施，不需要将 libuv 后端或项目格式提交到 CAORS。
迁移阶段允许旧 VFS 转发到新 VFS，但禁止双写两套挂载表；兼容桥不得建立独立资源缓存。
资源管理器版本切换/GPU 发布适配是并行的独立工作，不能因本方案结束就宣称整套资产迁移完成。

## 必须覆盖的验收

| 场景 | 预期 |
| --- | --- |
| 同 URI 同快照同步/异步访问 | 路由到同一后端和路径 |
| 打开期间 unmount、remount、销毁路由器 | 旧操作完成或按约定取消，新请求访问新来源，无悬空引用 |
| 请求 A/B 同时读一个文件的不同区间 | 数据正确，无共享 seek 游标竞争 |
| 大文件仅读取小范围 | 实测读取/分配量符合范围和预算，不调用 read_all |
| 文件增长、截断、修改 | 长度契约正确；资产层复验发现变化并拒绝发布旧候选 |
| 取消前、进行中、完成时、最后句柄销毁 | 唯一终态，迟到回调安全，文件与缓冲不泄漏 |
| 完成 executor 拒绝/丢弃、allocator 失败 | 明确失败且完整回收，无永久 pending |
| 多订阅者共享加载，一个取消 | 其他订阅者继续成功；最后订阅退出才按策略请求停止 |
| 不支持异步的后端 | 返回 unsupported，显式 worker 适配行为可观察 |
| 主线程与 loop 关闭 | 无相互等待死锁，不以提高超时或跳过测试解决 |

CAORS：Windows/Linux、共享/静态安装 consumer，跨模块寿命和并发压力；条件允许时 ASan/UBSan。
Gneiss：现有 uv-file-reader/uv-async-file 测试、来源修订、纹理范围读取、场景切换取消及关闭回归。
测量主线程间隔、在途内存、实际读字节和完成耗时；只比较同环境基线，不预先承诺帧时上限。

## 待上游确认与恢复条件

- 快照/解析结果最终命名、owner token 与已有借用 mount 的兼容方式。
- 完成 executor 拒绝时的终态观察接口；不允许静默丢失或错误线程执行回调。
- IO 通用身份如何穿过 provider/file_source，确保不泄漏 Gneiss 资产类型或版本策略。
- 异步能力采用可选虚接口还是等价能力表；必须维持一份路由及相同契约。

上述是待评审细节，不要求现在扩展为完整异步文件系统框架。
若上游暂不接受 A—C，可先仅接入 async_loader 与宿主 libuv，但旧 VFS 保留为显式过渡，
不得记录“VFS 已统一”，也不得为赶进度删除来源验证和预算保护。

# VER-021：0.21.0 IPC 模块化重构

## 状态

- 状态：实现中
- 目标版本：0.21.0
- 优先级：P0
- 路线图阶段：Editor–Runtime IPC 模块化

## 背景与目标

现有本机 IPC 已承载控制、日志、场景检查、统计和属性写入，但消息编号、能力判断与双方处理逻辑仍
集中在少数类型和会话函数中。0.21.0 在不改变用户工作流的前提下，将协议重构为可独立扩展的协议
域、统一信封与注册式分发，为后续资产重载、调试命令等真实协议域提供稳定内部边界。

## 非目标

- 不新增 Editor 或 Runtime 用户功能。
- 不更换回环 TCP，不引入命名管道、Unix Domain Socket 或公网监听。
- 不建立游戏 Network Service、远程设备发现或分布式调试。
- 不把全部 JSON 负载改成二进制格式，也不引入外部 RPC/序列化框架。
- 不公开 IPC C ABI，不承诺跨版本 Editor 与 Runtime 兼容。
- 不保留未发布的 IPC v1 兼容层。

## 已确认决策

- 协议 v2 使用协议域、域内操作、消息语义标志和请求 ID 进行统一寻址与关联。
- `session` 域负责握手、能力协商、心跳与协议错误；业务处理器不能绕过握手状态。
- 通用 Dispatcher 不解析域内业务字段；每个协议域拥有独立编解码和双端处理器。
- I/O 线程、主线程安全点、有界队列和控制优先级保持不变。
- 各域独立声明版本能力、允许方向、负载上限、队列预算和过载策略。
- Editor 继续作为 Server，Runtime 继续作为 Client；独立 Runtime 不要求 IPC 参数。
- 详细边界见 [ADR-034：本机 IPC 使用协议域与统一分发](../decisions/ADR-034-modular-ipc-protocol.md)。

## 实施顺序

### M-137：现有 IPC 耦合审计与模块化 ADR

盘点帧、全局消息枚举、能力协商、双方集中分发和线程所有权，确定 v2 域划分、请求关联、兼容策略
与非目标。

状态：已完成。结果见
[M-137 IPC 耦合审计与模块化决策记录](../records/M-137-ipc-modularization-audit.md)。

### M-138：v2 帧信封与请求关联

实现协议域、域内操作、消息标志和请求 ID 的网络字节序帧，覆盖截断、非法标志、未知版本、超限
负载和增量解码。为保证特性分支内每个提交均可构建，迁移期间允许 v1 与 v2 实现暂时共存；M-142
完成双方迁移后统一移除 v1 帧与全局消息类型。

状态：已完成。结果见
[M-138 IPC v2 信封与请求关联实施记录](../records/M-138-ipc-v2-envelope.md)。

### M-139：协议注册表与统一 Dispatcher

建立固定所有权的域处理器注册表，统一校验握手状态、方向、能力、域内操作和负载预算；未知域与
未知可选操作可诊断拒绝，不能导致会话状态损坏。

状态：已完成。结果见
[M-139 IPC 协议注册表与统一分发实施记录](../records/M-139-ipc-dispatcher.md)。

### M-140：Session 与 Control 域迁移

迁移握手、能力协商、心跳、运行状态、暂停、恢复、停止、关闭完成及协议错误，保持控制消息优先级
和现有状态机行为。

状态：已完成。结果见
[M-140 Session 与 Control 域协议实施记录](../records/M-140-ipc-session-control.md)。

### M-141：数据与属性域迁移

分别迁移 Log、Inspection、Statistics 和 Property 域。属性请求与结果改用通用请求 ID；检查分片、
顺序戳、重同步及各域过载策略保持原有语义。

状态：已完成。结果见
[M-141 IPC 数据域协议实施记录](../records/M-141-ipc-data-domains.md)。

### M-142：Editor 与 Runtime 会话组合

以双方域处理器组合替换集中式消息特判，把主线程命令和 UI 事件作为强类型队列暴露；删除失效的
v1 类型、能力常量和重复分发测试。

当前进展：Runtime 与 Editor 已通过标准域集合、Dispatcher 和强类型队列完成端到端 v2 迁移；
Transport 已删除 v1 模式，只接受 v2 信封，并通过 Shared/Static 双向收发与会话回归。Inspection、
Statistics 和 Property 域的 JSON 载荷编解码仍在内部借用旧 `ipc_frame` 容器；下一步改为直接读写
字节载荷，再删除旧帧、全局消息类型、能力常量及其重复测试。

### M-143：兼容、故障与跨平台验收

使用 Editor Demo 和 Lantern Gallery 验证运行、暂停、检查、属性编辑、日志、停止、连续会话、错误
方向、未知域、慢消费者及断线恢复，并完成 Windows 与 Linux 全矩阵。

## 测试与验收

- v2 帧覆盖完整、分片、粘包、截断、超限、非法版本、域、操作、标志和请求 ID。
- Dispatcher 覆盖重复注册、未注册域、错误方向、缺失能力、处理失败和可选未知操作。
- Session 与 Control 行为保持现有握手、心跳、暂停、恢复、停止和关闭语义。
- 日志、检查、统计和属性域保持现有数据内容、顺序、背压和主线程所有权。
- 低优先级域过载时，停止与心跳仍可在限定时间内完成。
- Shared/Static、Editor/Runtime 关闭、无头图形和 Sanitizer 矩阵保持通过。

## 风险与未决问题

- M-138 已确定 24 字节帧头和 32 位请求 ID；后续迁移必须继续按字段编码，不能复用平台结构体布局
  直接传输。
- M-139 已确定能力协商结果使用“域 + 版本”；域的人类可读能力名仅用于握手编码和诊断。
- 注册表必须具有确定所有权和生命周期，不允许 I/O 回调持有会话销毁后失效的业务对象。
- 模块化后仍需限制每帧主线程消费量，不能因为处理器拆分而形成多个可叠加的无界预算。

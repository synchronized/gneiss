# VER-019：0.19.0 Prefab 实例属性覆盖

## 状态

- 状态：已规划，待实施
- 目标版本：0.19.0
- 优先级：P0
- 路线图阶段：Prefab 实例属性覆盖

## 背景与目标

0.18.0 已让多个场景实例共享同一份 Prefab 来源，但来源子节点仍完全只读。真实场景创作还需要在
保留来源关系的同时，为单个实例调整少量属性，例如移动某盏灯笼、改变缩放或调整 Camera 参数。

0.19.0 建立首个字段级覆盖闭环：场景以“实例 UUID、源节点 UUID、Type ID、Field ID”保存覆盖，
实例化和刷新时把覆盖合并到来源投影；Editor 能识别、编辑和恢复覆盖，Runtime 属性回写也遵守同一
作者身份。首个验收用例继续使用 Lantern Gallery，证明同源实例可以保留各自差异并接受来源更新。

## 非目标

- 不实现嵌套 Prefab、Variant、继承或跨工程引用。
- 不实现把实例修改 Apply 回 Prefab 来源资产，也不提供 Prefab 独立编辑模式。
- 不覆盖节点增删、重排、组件增删、名称或父级；首版只覆盖已有组件的受支持字段。
- 不实现自动文件监听、后台刷新、异步流式加载或运行中 Prefab 热重载。
- 不把编辑器专用命令、JSON 表示或 Prefab 作者身份下沉到 Granit。
- 不承诺场景 v4 和覆盖 Schema 已达到稳定公共 ABI。

## 已确认决策

- 覆盖以稳定 Type ID 与 Field ID 寻址，不使用显示名称或字段偏移。
- 节点目标使用实例 UUID 与源节点 UUID 的复合身份；Runtime ID 只用于当前投影，不写入资产。
- 覆盖值复用属性系统的类型语义，并由类型注册表验证字段存在、类型匹配和可写能力。
- 场景只保存与来源值不同的稀疏覆盖；恢复来源值后删除对应覆盖记录。
- 应用顺序固定为“加载来源 → 创建独立投影 → 应用实例根 Transform → 应用字段覆盖”。
- Prefab 刷新必须重新验证并原子应用覆盖；失效覆盖使刷新失败并保留旧投影，不静默丢失作者数据。
- Editor 的覆盖编辑与恢复均进入现有 Undo/Redo、脏状态和保存流程。
- Runtime 的“应用到作者场景”若目标为 Prefab 来源节点，则写入对应实例覆盖，而不是修改来源资产。

## 实施顺序

### M-123：覆盖身份、合并语义与 ADR

用最小 Prefab 验证复合节点身份、Type ID/Field ID 寻址、值相等规则、稀疏保存和刷新冲突行为，形成
长期架构决策。明确 C11 可表达的数据结构，不先接入 Editor UI。

### M-124：场景 v4 覆盖格式

为 Prefab 实例声明增加版本化字段覆盖集合，建立严格校验、确定性排序和未知字段保留。仓库内场景、
示例与测试直接升级到 v4；旧 v3 明确拒绝，不维护尚无外部兼容承诺的迁移路径。覆盖解析失败不得
发布半成品场景。

### M-125：Runtime 投影与刷新合并

实例化时通过现有属性访问器把覆盖写入来源投影；刷新时先构建并验证完整替代投影，再原子切换。
覆盖多实例隔离、资源租约、源字段删除、类型变化、失败回滚和旧句柄失效。

### M-126：Editor 覆盖编辑与状态呈现

允许在 Inspector 和 Transform Gizmo 中编辑受支持的 Prefab 来源节点字段。界面区分来源值与覆盖值，
只在提交有效变更后创建命令，并保持选择、聚焦和场景视图同步。

### M-127：恢复来源值与命令历史

提供字段级和节点级“恢复来源值”，删除相应稀疏覆盖。编辑、恢复和刷新均支持 Undo/Redo，撤销后
准确恢复覆盖标记、作者值、Runtime 投影和脏状态。

### M-128：Runtime 属性回写到 Prefab 覆盖

扩展 0.17.0 的显式作者回写：普通节点继续写入场景对象，Prefab 来源节点按复合身份写入当前实例的
字段覆盖。来源刷新或 Runtime 镜像过期时拒绝错误目标并给出明确状态。

### M-129：Lantern Gallery 差异化实例与跨平台验收

让三个灯架共享一个来源但保留可见的实例差异，覆盖来源更新、编辑、恢复、保存重开、Runtime Play
与作者回写。完成 Windows 本地矩阵，并在获得授权后运行 Linux Shared/Static、Granit Runtime 和
Sanitizer Actions。

## 测试与验收

- 格式测试覆盖重复目标、未知 Type/Field ID、值类型错误、非有限数、确定性排序和旧版本拒绝。
- 投影测试覆盖同源多实例隔离、覆盖合并、来源更新、字段删除、类型变化和原子失败回滚。
- 属性测试覆盖 Transform 的 translation、rotation、scale，以及 Camera 的首批可写字段。
- Editor 测试覆盖覆盖标记、Gizmo/Inspector 编辑、字段级与节点级恢复、Undo/Redo 和脏状态。
- Runtime 回写测试覆盖普通节点与 Prefab 来源节点分流、陈旧身份拒绝和确认结果。
- 保存重开后覆盖集合保持稀疏且语义一致，不写入 Runtime ID 或展开副本。
- Lantern Gallery 自动测试证明一个来源更新不会抹除三个实例各自的有效覆盖。
- Shared/Static、Editor/Runtime 关闭、安装 Consumer 和无头图形组合保持通过。

## 风险与未决问题

- 浮点值的“等于来源”需要确定性规则；M-123 应选择与序列化精度一致的比较方式，避免覆盖反复出现。
- 字符串属性的所有权与存续期尚需按现有属性 ABI 验证；首批范围不因抽象完整性强行加入字符串。
- 来源字段被删除或更改类型时不能静默丢弃覆盖；首版选择刷新失败，未来可增加显式迁移工具。
- 场景格式仍处于 1.0 前实验阶段；没有真实外部兼容需求时直接升级仓库内容，不积累格式迁移代码。
- 节点或组件结构覆盖会显著扩大合并、身份和撤销复杂度，应由后续真实用例单独规划。
- Apply 回来源会影响所有实例和资产写入事务，不与本版本的实例局部覆盖混合实现。

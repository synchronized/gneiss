# SDK-001：Application 与 World 可读性样板

## 状态

样板已实现并完成本地验证（2026-10-07），现已纳入
[0.48.0](VER-048-0.48.0-cpp-sdk-readability.md) 的 M-307。后续范围与进度由 VER-048 / DEV-048 维护。

## 背景与目标

0.47 已补齐原生值类型和生命周期契约，但公共头混合了日常接口、C ABI 适配和所有权实现。
先用 Application 与 World 检验更清晰的接口组织，并提供真实可运行的调用样例。

## 非目标

- 不修改 C ABI、引擎内部层次、Editor API、插件系统或 Granit。
- 不改变错误码、输出参数、线程约束或回调存储寿命。
- 不引入第二套运行时、全能 owner 模板、异常式 API 或第三方 expected 依赖。
- 不以头文件行数或文件数量作为质量验收标准；本次不声称改善编译时间。

## 已确认决策

- 模块 `.hpp` 展示公共类型、方法声明和所有权结构；非平凡适配定义放在对应
  `detail/*.inl`，由模块头自动包含并随 SDK 安装，使用者不直接包含实现文件。
- C++ 包装仍为 inline，依赖原有 C ABI，不增加导出符号或独立二进制包装库。
- Application 创建和 adopt 共用私有替换操作：旧对象关闭失败时不转移候选所有权。
- 普通示例使用 application 拥有者、world_ref 借用视图和 entity_id；回调状态由调用方持有。
- 保留逐步检查 result 的写法，避免在同一轮同时更换接口组织与错误协议。

## 实施顺序

1. 提供创建应用、借用 World、创建实体、读写变换、回调退出的完整示例。
2. 拆出两个模块的适配实现，收敛 Application 重复的所有权替换逻辑。
3. 运行生命周期、失败输出、线程边界回归；验证共享/静态构建与安装消费者。
4. 结合可运行示例评审下一步调用风格，再决定是否推广到其他模块。

## 测试与验收

- 示例使用 callback 平台，无窗口和外部资产；三次更新后主动退出，校验最终坐标。
- 示例使用两个编译单元，同时验证 inline 定义的链接行为。
- 公共 C11/C++20 头独立编译；现有 Application、World、owner 测试继续验证错误和寿命。
- 干净安装前缀下构建 C/C++ consumer 和同一示例，覆盖共享库与静态库。
- 格式、静态检查和 API 清单检查通过；C ABI 头与导出清单不变。

本地验收：Windows Clang Debug 共享库相关回归 8/8、静态库 6/6；两种干净安装包
消费者各 4/4（C、C++、属性检查、双编译单元样例）。C11/C++20 公共头编译、
clang-format、改动相关 clang-tidy（告警视为错误）、API 清单及负向检查通过。
本样板未运行 Linux、Web 或远端完整发布矩阵，也未测量编译时间。

## 风险与未决问题

- 拆分实现不会消除转换代码和传递 include，也不会自动缩短调用代码。
- 带值结果类型是否值得引入，需比较最小示例的改写效果、移动所有权和失败访问规则后决定；
  不能把 C++23 std::expected 直接当作当前 C++20 基线能力。
- raw interop 与普通接口是否进一步拆分，其他模块是否采用同样组织，留待样板评审。

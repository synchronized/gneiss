# VER-046：0.46.0 公共头目录整理

## 状态与目标

2026-10-06，以已发布 0.45.0 为基线，规划 0.46.0 为公共头目录整理版本。
`refactor/engine-public-headers` 分支的 `73158e4` 已实现目录迁移及本地专项验证；
工程版本号已调整为 0.46.0，正在整版验收，尚未发布。

目标是让现有 Engine SDK 的归属清晰，同时保持已有使用者的包含路径及接口兼容。
实施顺序见 [DEV-046](DEV-046-public-header-layout.md)，目录决策沿用
[ADR-054 的公共目录补充](../decisions/ADR-054-source-layout-and-host-boundaries.md#公共目录补充2026-10-06)。
实际验证结果以[目录整理验收记录](../records/engine-public-header-layout.md)为准。

## 范围与已确认决策

- 现有公共功能头迁入 `include/gneiss/engine/`，基础类型和生成版本头归其 `core/`。
- 根总入口 `gneiss/gneiss.h`、`gneiss/gneiss.hpp` 保留；旧功能头及 `gneiss/core/` 仅转发到规范路径。
- `.h` / `.hpp` 继续提供 C11 ABI / C++20 包装；不改函数、类型布局、命名空间、所有权或行为。
- 安装文件集、版本头生成、示例、当前 API 清单与路径检查随迁移同步调整。
- 当前清单维护在 `abi/`，0.45 发布时的原始清单保持不变。
- 本版不移除旧路径，不添加弃用警告，不要求所有内部使用者一次性更换 include。

当前目录与迁移用法由[公共头路径](../concepts/repository-layout.md#公共头路径)统一说明，
本计划不再复制完整目录树。

## 非目标

不开发插件系统，不整理或开放 Editor API，不建立 Runtime、Editor、Tooling 或插件公共占位目录。
不再次调整内部源码分层，不升级 Granit，不改变依赖或 DLL 拆分方式。
此前建议的大场景加载耗时、cooperative 响应性、预算回收及显存观测不纳入 0.46；
这些问题保留为后续独立规划事项，本版不宣称解决。

## 发布门槛

1. 新路径逐头通过 C11/C++20 独立编译，旧路径及根总入口仍可用；混合包含不产生重复定义。
2. 新旧路径均随共享/静态 SDK 安装，独立 C/C++ 消费者可配置、构建并运行；不依赖源码私有头。
3. 公共 C 导出与 0.45 基线一致，结构布局和既有 ABI 消费者通过；不新增公共或私有导出。
4. API 清单和边界检查覆盖新路径，正反例均通过；历史清单不作为当前可变检查输入。
5. 版本号调整后完成本地完整共享/静态构建测试；最终候选按构建指南完成 Windows/Linux 手动矩阵。
   纯验收记录更新不重跑，失败修复只重跑受影响任务，不降低原有检查标准。
6. 发布说明准确区分目录变化和旧路径兼容；已知大场景限制继续保留。
   完成合并、标签及源码 Release 后再创建 `docs/versions/0.46.0.md`。

## 风险与未决项

- 增量构建或测试夹具可能残留旧版生成头，必须兼顾复用构建目录与全新安装树。
- 只更新 include 文本可能漏掉安装列表、依赖检查或清单路径，以编译及安装消费证据验收。
- 旧路径移除时间不在本版决定；将来如需移除，应另行规划源码兼容迁移。
- 当前只有本地专项结果，不能提前把 Linux/MSVC 或完整运行时矩阵写为通过。

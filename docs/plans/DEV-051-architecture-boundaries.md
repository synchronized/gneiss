# DEV-051：源码架构与模块边界开发计划

## 状态与工作方式

2026-10-15，计划已建立，实现待开始。范围以 [VER-051](VER-051-0.51.0-architecture-boundaries.md)
为准；在 feature/0.51-architecture-boundaries 分支持续推进，设计、实现与验证复用同一分支。
本轮仅修改规划文档，不修改公共版本号、源码或已发布版本归档，不触发 Actions。

| 任务 | 状态 | 完成条件 |

## M-329：先审计再调整

建立一份审计记录，至少包含：

- 模块路径、职责、允许/实际依赖、对外内部接口、私有实现及对应构建目标。
- 请求、执行器、VFS、资产来源、候选场景、活动场景、渲染资源和帧快照的拥有/借用关系。
- 创建、开始关闭、停止接收工作、处理在途工作、资源释放和执行器停止的顺序。
- 公共 C API、C++ 包装、动态游戏模块入口、内部 C++ 接口的调用方与用途。
- 打开场景到退出的当前调用链、目标边界与逐文件迁移表，禁止仅按名称归类。

重点核对 Application 的装配与业务状态、asset 与 render 的资源依赖、加载协调部分的实际归属。
审计结论须有源码依据；未审计部分标记待确认，不把目标结构描述为现状。
记录已发布 0.50 基线与已知失败；实现前固定同设备/输入/配置的性能对照方案、重复次数、
容许波动和新增回归判定，不能等结果出来后选择阈值。历史性能门槛保持原值。

## M-330：目录与构建

按审计结果逐模块调整，不一次性移动所有文件。模块源码就近维护构建声明，明确内部接口
包含范围与私有实现范围；使用 target 依赖或现有检查设施阻止反向/越界依赖。
保留最终 Engine 库和安装布局的独立决策，不能为了划分模块无条件增加动态库。
添加能验证约束有效的越界依赖反例，并确认合法消费者仍可构建。
每批迁移更新源码列表、包含路径、相关测试及文档链接，避免无关格式化。

## M-331：完整加载链路

建议职责按下表审计，最终归属由 M-329 的依赖证据确定：

| 责任 | 目标归属 |
| --- | --- |
| 文件操作、回执、底层句柄释放 | 平台 I/O |
| URI、格式、来源校验、依赖准备和资产预算 | 资产模块 |
| 场景结构、实例构造和场景资源归属 | 场景模块 |
| 候选事务、进度、取消、旧场景保留及激活协调 | 审计后确定的加载协调模块 |
| GPU 资源、上传、帧快照及渲染线程 | 渲染服务 |
| 用户操作、文档/选择状态及进度显示 | Editor |

Application 负责组装和推进上述能力，业务细节归其生命周期负责人。
明确取消终态与真正清理完成、迟到回执、失败保留旧场景、切换后帧快照仍持有资源的行为。
用对象组合、RAII 和显式关闭契约表达关闭依赖；有等待的关闭接口须说明调用线程和前置条件。
不使用全局服务定位器、共享万能上下文或第二套资源表转移耦合。

## M-332：内部接口与对外适配

遵循 [ADR-062](../decisions/ADR-062-internal-cpp-and-sdk-boundaries.md)。
内部 C++ 直接调用明确模块接口；C ABI 适配只做验证、转换、句柄解析及错误边界。
已有 RID 继续使用，不因是内部 C++ 就改为无生命周期约束的裸指针。
外部 RAII 包装继续覆盖公开能力，不承担另一套业务状态；动态库入口仍使用约定 ABI。
同源码宿主和独立安装消费者分别验证，不能通过改用私有头让 SDK 测试失去意义。

apps 保留入口和宿主接线；Editor 模型、会话、命令、面板与可复用业务归编辑器内部模块。
离线工具依赖不反向传播给运行时。不扩展 Editor 公共 API 或预建插件机制。
默认保持公共 API；确需改变时先记录范围、迁移及验证方案。

## M-333：验收与资料

- 确定性测试覆盖成功、失败保留旧场景、取消、迟到回调、重试、切换、在途关闭及资源释放。
- 覆盖线程池与协作模式，确认无线程路径不隐式创建工作线程。
- RID 保留零值、类型、代次、跨服务及重复销毁约束。
- 同源码宿主、公共 C11/C++20 独立头、共享/静态、安装消费者和 Windows/Linux 按变更影响验证。
- 使用小夹具快速回归，再以固定完整 Sponza 验证图像、数量、预算及生命周期，不以缩减资产获得通过。
- 分别记录加载耗时、主循环响应、稳定呈现与资源占用；保留历史失败，报告新增回归和未解释残余。
- 将最终职责、依赖及源码入口写入 Concept/Guide，将测试结果写入 Record，避免在 Plan 堆积日志。

只有实际边界调整及相应验证完成才可标记本版完成。未通过项必须修复或明确提出范围决定，
0.50 的例外发布决定不自动成为 0.51 的验收豁免。

# VER-047：0.47.0 原生 C++ SDK 与公共头收口

## 状态

2026-10-06 实施中，已开始输入 SDK 与原生迁移门禁；其余范围尚未完成。
基线为已发布的 0.46.0；本文列出整版目标，当前能力以模块 Reference 为准。
实施顺序见 [DEV-047](DEV-047-native-cpp-sdk.md)，长期决策见
[ADR-055](../decisions/ADR-055-native-cpp-sdk.md)。

## 背景与目标

当前包装已提供 RAII 所有者和强类型 ID，但多种描述、快照仍别名到 C 结构，普通 C++ 调用仍需要
C 初始化宏、枚举常量和回调签名。既有函数映射覆盖不能等同于原生 C++ 使用体验完整。
当前事实见 [C++ SDK 参考](../reference/cpp-sdk.md)。

本版完成两项交付：现有公共 Engine 能力均可通过原生 C++ 类型使用；移除 0.46 引入的旧路径
转发头，仅维护规范模块路径和总入口。两项都属于发布范围，不只完成 Application/Transform 示例。

## 范围

| 接口组 | 目标 |
| --- | --- |
| Core、版本、结果、RID | 保持结果码语义，补齐强类型常量与默认无效值 |
| Application、World、Scene | 原生描述、Transform、组件、场景查询和映射；保留拥有者与借用区别 |
| Render | 原生资源描述、采样与材质枚举、绘制数据；明确数组转换和资源 ID 借用 |
| Input | 原生事件、状态、动作枚举及标志组合 |
| Reflection | 原生注册描述、属性值、查询结果和访问器；明确嵌套数据寿命 |
| 日志、诊断、Game Context | 原生消息、帧数据及回调参数；真实动态模块入口保留显式 C ABI 边界 |
| 公共头与消费方 | 删除旧转发路径，迁移源码、测试、示例、模板、工具、安装与当前文档 |

使用 `enum class`、有类型约束的标志操作、带默认值的 C++ 结构及 `inline constexpr`。
根据所有权选择 `std::array`、`std::span`、`std::string_view` 或拥有型容器，不统一把输出改为借用视图。
`struct_size`、保留字段、指针长度和 C 初始化宏由适配层处理；默认 Transform 为零平移、单位旋转、单位缩放。
保持既有 result/输出参数风格，不同时改成异常或另一套工厂协议。

## 兼容与边界

- 这是有意的源码不兼容版本：旧 include 路径、C++ 类型别名及依赖 C 描述的普通调用需要迁移，
  不为它们再保留转发头或兼容重载。
- 保留 `gneiss/gneiss.h`、`gneiss/gneiss.hpp`；模块头使用 `gneiss/engine/`，Core 使用其下的 `core/`。
- 保持规范路径下 C API 的函数、结构布局、结果与所有权契约；不因 C++ 改造改变 C ABI。
- C++ 包装继续调用 C ABI。新增值类型和必要的转换存储不构成第二套运行时资源状态。
- 显式原生句柄互操作和 Game Module 导出边界允许 C 类型；普通 C++ 使用路径不要求 C 描述、
  业务枚举宏或初始化宏。导出、条件编译等基础设施宏不属于本次消除目标。
- 历史版本归档与历史记录保持原貌；活动文档及生成模板迁移。已有安装前缀的旧文件不能靠覆盖
  安装自动消失，迁移指南须要求使用干净 SDK 前缀，不执行不受控目录清理。

## 非目标

不开发插件、不整理或公开 Editor API、不调整根 apps 与 src 布局、不升级 Granit。
不新增异步公共接口、取消协议、Service 或资源注册表，不将既有内存与加载性能事项并入本版。
不承诺 C++ 二进制 ABI 稳定；消费者需重新编译。

## 发布验收

1. 全量函数、类型、常量、回调清单逐项对应原生入口或有理由的显式 ABI 例外，不以存在同名 `.hpp`
   或 `using X = gneiss_X` 认定完成。
2. 普通 C++ 示例涵盖创建应用、场景变换、资源提交、输入、属性访问与回调，不依赖 C 业务类型及宏。
3. 转换覆盖默认值、未知枚举、非法标志、长度溢出与失败；生命周期覆盖移动、关闭失败、父资源失效、
   借用数据和回调线程边界。没有异常穿过 C ABI，没有临时转换对象形成悬空视图。
4. 每个规范 `.h` 由 C11 独立编译、`.hpp` 由 C++20 独立编译；干净安装含总入口及规范头，旧路径缺失。
   共享/静态库及 C/C++ 安装消费者通过，导出与 C 布局相对基线核对。
5. 本地必要回归与最终 Linux/Windows 手动矩阵通过。既有未解释的 IPC SIGPIPE 风险继续明确记录；
   若阻塞候选验收则调查修复，不跳过测试。构建命令以 [构建指南](../guides/building.md) 为准。
6. 当前参考、迁移指南、示例、清单和发布说明同步；实际发布后才建立版本归档。

## 风险与待细化项

回调适配在拥有者移动后必须保持上下文有效；Reflection 输出的嵌套视图不能引用转换临时量。
M-301 需逐接口确定借用或拷贝，以及回调异常的结果/诊断映射；无法安全借用的输出使用拥有型结果。
Render 数组逐元素转换可能分配与拷贝，需记录实际成本，不以布局相似为由直接重解释两种结构。
这些设计细节在实现对应模块前定稿，不降低完整覆盖目标。

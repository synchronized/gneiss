# VER-040：0.40.0 统一任务调度与 Runtime 异步资产加载

## 状态

- 状态：实施中；尚未达到发布门禁。
- 目标版本：0.40.0。
- 分支：`feat/0.40-cooperative-scheduling`；规划与实现沿用同一分支。
- 2026-09-25 用户确认扩版规划，纳入 Runtime 纹理异步加载闭环；随后明确授权本版实施、提交、
  推送、PR、合并及版本发布完整闭环。

## 背景与目标

0.39 已提供内部任务调度器及两个 Editor 资产消费者，详见
[0.39 验收记录](../records/M-250-255-0.39.0-validation.md)。当前构造器直接创建工作线程，
拒绝零线程配置；延迟等待和关闭包含条件变量等待、线程 join，尚无协作驱动模式。
导入服务持锁提交任务，任务体也会取服务锁，不能将 submit 直接改成同步调用任务体。

用户报告 Granit 已支持 Emscripten。具体上游版本和覆盖范围尚未核对；本版调度器最小 Web
验证不依赖 Granit，也不将上游后端支持等同于 Gneiss 整体可在浏览器运行。

目标是让 Editor 与 Runtime 复用同一套任务契约和实现，以纹理异步准备与热更新形成真实消费者闭环。
支持桌面线程池和无工作线程的宿主协作驱动；浏览器验证范围仍为最小调度宿主。
当前 Runtime 同步调用资产修订应用，纹理读取、解码及资源创建尚在同一调用链，不属于已实现的异步能力。
调度模式以 [ADR-047](../decisions/ADR-047-cooperative-task-execution.md) 为准，资产阶段与事务边界以
[ADR-048](../decisions/ADR-048-runtime-asset-preparation.md) 为准。

## 版本交付

| 范围 | 发布时应具备的能力 |
| --- | --- |
| 共用调度 | 两种执行模式使用相同任务状态、作用域、取消、容量与诊断 |
| 宿主与服务 | Editor、Runtime 各自持有并注入调度器，同一宿主消费者共享执行资源 |
| Runtime 纹理 | 显式纹理加载请求及已加载纹理热更新走异步准备、受控提交和失败保留旧资源流程 |
| 编辑器联动 | 资产修订接受与实际应用完成分离，Editor 收到真实终态，帧更新继续运行 |
| Web 基础 | 最小无线程 Wasm 宿主在浏览器运行；不宣称完整 Runtime Web 支持 |

版本范围与验收以本文为权威来源；源码落点、开发依赖和各阶段完成条件见
[0.40 开发计划](DEV-040-runtime-task-integration.md)。

## 非目标

- 不实现提交即执行的 immediate inline 模式，不让 poll、query 或状态读取隐式运行任务。
- 不实现完整场景异步实例化、任意资产流送、完整 Editor/Runtime Web 移植、浏览器文件监听或 Web 打包发布。
- Mesh/Material 独立异步加载不作为本版交付；涉及它们的混合修订保留完整事务，可明确采用原同步路径。
- 不迁移 Granit 渲染执行器或 libuv loop，不统一所有 Service 的逐帧 update 或重构 service_registry。
- 不扩展公共 C ABI，不加入协程、抢占、工作窃取、自动拆分任务或通用异步 I/O 运行时。
- 不承诺把单个不可中断解析任务限制在帧预算内，不消除 Debug 调试堆争用。
- 不修改 Granit 仓库；只有完整引擎 Web 接入确实依赖缺失通用能力时才另行提出上游需求。

## 已确认决策

以下为计划契约，具体接口名称在 M-256 收口，当前尚不可调用。

| 项目 | 计划契约 |
| --- | --- |
| 模式选择 | 创建时显式选择线程池或协作模式，实例运行期间不切换；现有桌面默认值保持线程池 |
| 提交 | 两种模式均只入队，不在提交调用栈中执行任务；容量满立即返回 |
| 执行 | 线程池由工作线程驱动；协作模式只由所属宿主线程显式驱动就绪任务 |
| 预算 | 驱动支持任务数量与时间预算，零预算不执行；检查发生在任务之间，单任务可以超时 |
| 延迟 | not_before 到期前不执行；协作驱动遇到无就绪任务立即返回，不 sleep 或忙等 |
| 通知 | poll 只消费完成回执，query 只观察；继续计入未消费结果容量，不引入完成回调重入 |
| 依赖与串行 | 共用原有依赖、失败传播和串行顺序规则；取消中间项不能越过运行中的前项 |
| 取消 | 未启动任务可终止；运行任务协作响应，已经取得业务提交许可的操作完成或回滚 |
| 关闭 | 提供请求关闭、查询收尾和完成回收的非阻塞路径；桌面宿主外部保留受约束的等待便利接口 |
| 所有权 | 服务先收尾再销毁，调度器最后销毁；驱动中禁止递归驱动、自等待及销毁当前执行对象 |
| 构建 | 无线程构建排除工作线程实现及线程链接选项；请求不可用模式明确失败，禁止静默降级 |

协作模式的宿主须在不持有消费者业务锁时驱动任务。线程池模式的并发限额在单线程模式下不会
制造额外线程；优先级、公平性和串行语义仍保留。用户代码可提交后继任务，但不能递归运行任务队列。
同一实例的驱动线程归属、跨线程提交能力和非法操作错误语义需在 M-256 写成测试，不默认允许任意线程驱动。

| M-264 | 文档、模式矩阵与发布验收 | 桌面、浏览器及消费者门禁通过，记录能力与性能边界 | 待开始 |

M-259 在桌面验证资产消费者的协作模式，不要求将整个资产工具链编译到浏览器。
M-260 使用只依赖调度模块的最小测试宿主；不靠关闭既有桌面检查来获得构建成功。
M-261 在 M-258 完成后开展，M-262 依赖纹理准备模型，M-263 在提交与回执契约稳定后接入。
M-260 与 Runtime 接入没有代码前置依赖，但两者均是 M-264 的必需门禁。
后续实现及修复沿用一个版本 PR；不按基础调度和 Runtime 接入拆成两套实现或多个版本 PR。

## Runtime 加载范围与契约

- 以显式内部纹理加载请求和运行中纹理修订为入口；同步 acquire 与初始场景加载保留现有行为，
  不将同步函数包装后在主线程立即等待，也不宣称初始场景已无阻塞。
- 后台持有不可变请求、资产字节与 CPU 候选，不访问可变资源缓存、World、Scene、RID 表或 Granit 对象。
  纹理描述及其源数据作为一次准备输入，记录校验信息；提交不在主线程重新读取和解码。
- 支持已有 PNG、KTX2 和运行纹理封装的受支持路径，保持原有格式限制与诊断，不顺带新增编码格式。
- 主线程在安全点校验宿主/会话代次、目标资源 generation 与请求修订；渲染执行器继续独占 GPU 操作。
  候选完成、资源提交与 GPU 就绪的含义必须分别定义，不把已入队标为已应用。
- 一个 Service 的任务作用域与队列停止不会结束另一个 Service。正常纹理加载失败不关闭调度器。
- 加载或重载失败不替换旧映射；首次加载失败不留下资源。缓存/材质引用及旧 GPU 资源退役沿用现有所有权。
- 纯纹理修订批次整体准备和提交。混合 Texture/Material/Mesh 批次不拆开发布；明确使用完整同步事务
  或完整候选事务。后续修订不得令旧批次中未被覆盖的资源变化丢失。
- 取消与提交许可具有明确先后；提交许可后完成或回滚，再发终态。Editor 不因仅接收请求就显示更新成功。
- 任务数预算之外增加待处理字节、候选字节及提交/上传批次预算，容量满时可观察地拒绝或延后。
  同一 URI 的合并、请求完成回执和缓存去重均须明确，不以无限排队解决压力。

## 测试与验收

- 同一组无阻塞任务契约分别在协作模式与 1、2、4 个工作线程下执行；线程竞争测试另保留屏障控制。
  不把依赖工作线程解锁的阻塞测试原样用于无线程模式。
- 覆盖依赖链/分叉/汇合、依赖失败、非法及跨实例句柄、串行取消中间项、结果恰好一次与容量恢复。
- 用可控时钟验证延迟与时间预算边界，验证零预算、无就绪任务立即返回、取消远期延迟任务后可关闭。
  不依赖短暂 sleep 推断顺序，不为超时任务宣称抢占能力。
- 提交期间任务体不会进入；任务内部提交后继不会递归执行；非法驱动线程、递归驱动和自等待明确失败。
- 运行中请求关闭、关闭一服务而另一服务继续、重复关闭及结果回收后句柄失效均有回归。
  浏览器主线程不走条件变量等待或 join；延迟任务不会让关闭等待其原定到期时间。
- 两种模式下验证 Import Service 的提交许可、失败回滚、取消重试、导出暂停，以及作者资产保存修订。
  桌面原生窗口在有限协作任务间继续更新；记录长任务的实际超预算，不以通过率代替响应性数据。
- 固定 Emscripten SDK 与浏览器版本，构建调度器最小无线程宿主，确认无 pthread 链接要求；在真实浏览器
  中验证依赖、跨回调延迟、背压与关闭，并记录事件循环在多次驱动之间继续前进。
  Node 执行或仅编译通过不能替代浏览器验证。
- Emscripten pthreads 作为独立产物的探索项，记录工具链、隔离头和 Worker 配置；本版不承诺支持。
  若未验证，发布说明明确区分“无线程浏览器已验证”和“Web 多线程未验证”。
- Runtime 两种模式均验证首次加载、缓存复用、热更新、损坏及缺失源、分配/提交失败、取消前后边界、
  资源卸载重建、会话替换、退出和请求回执恰好一次；旧 RID 不被异步结果复活。
- 验证描述与 payload 连续修改、同 URI 快速更新、多个不同 URI 的相邻修订及混合批次失败，
  确保修订编号前进不会吞掉未应用资源，失败不会暴露半个批次。
- 用实际纹理负载验证 Editor 通知到 Runtime 显示更新，期间相机、resize 和关闭可推进；分别记录
  准备、排队、主线程提交、GPU 上传/就绪及真实帧间隔，并保留峰值候选字节与退出耗时。
  分离 Debug/Release 与两种执行模式，记录基线和重复采样，不以无头循环代替真实渲染帧时。
- 保留 Windows/Linux、共享/静态、公共头文件及安装 Consumer 门禁；新浏览器测试命令和 CI 接入
  在可运行后写入构建指南。实施时完成相关格式、静态检查；纯文档归档不重复执行完整远端矩阵。

## 风险与未决问题

- 最小 Emscripten 构建入口需避免拉入整个引擎及 Granit、libuv；优先复用模块 target 定义，避免重复维护源码列表。
- 当前实现依赖 C++ 异常处理。需明确 Wasm 异常配置及错误回执验证，不能悄悄取消异常捕获契约。
- 确定时间预算的计时注入方式、驱动统计结构和非阻塞回收接口，避免为测试暴露多余公共 API。
- 异步浏览器 I/O 未来必须以完成事件推进任务；本版不支持任务体阻塞等待浏览器回调。
- 浏览器事件循环接管后的宿主对象必须持续存活，不能依赖退出 main 时析构局部调度器。
- 若工具链或浏览器环境不可用，M-260 保持未完成；不得将桌面协作测试描述为 Emscripten 支持已完成。

- Runtime 纹理服务的内部接入点须兼容 Application 的所属线程及现有同步调用，避免 Editor 与 Application
  各自再建一个默认线程池。具体注入桥、字节预算及 IPC 超时行为在 M-256/M-261 收口。
- GPU 上传确认、候选失败回收与现有后端协议是否足够需验证；缺少通用能力时按跨仓库规则提出 Granit
  最小需求，由用户处理上游，不直接修改。不能用 CPU 提交成功掩盖 GPU 阶段失败。

# VER-018：0.18.0 Prefab 与可复用场景基础

## 状态

- 状态：已完成（M-116～M-122）
- 目标版本：0.18.0
- 优先级：P0
- 路线图阶段：Prefab 与可复用场景基础

## 背景与目标

Gneiss 已支持场景子树复制，但复制只产生彼此独立的作者节点。0.18.0 建立首个引用型 Prefab 闭环，
让一棵可复用节点树作为独立资产被多个场景实例引用，并在源资产更新后通过显式刷新传播变化。

首个真实用例是 Lantern Gallery 的重复灯架：一个 Prefab 源资产定义灯柱、横梁和灯笼子树；场景只
保存多个实例的放置信息。用户可以从 Asset Browser 放置实例、移动实例根、保存并重新打开场景，
修改源资产后刷新即可观察所有实例更新。

## 非目标

- 不实现嵌套 Prefab、Variant、继承、引用环或跨工程引用。
- 不实现任意子节点或组件字段覆盖，也不提供 Apply、Revert 或 Unpack。
- 不在本版本内建设完整 Prefab 独立编辑模式或多文档编辑器。
- 不实现文件监听、后台刷新、异步流式加载或运行中热重载。
- 不改变 Runtime 属性编辑协议，不把 Prefab 作者身份暴露为公共 RID。
- 不承诺首版 Prefab 或场景 v3 Schema 属于稳定公共 ABI。

## 已确认决策

- 采用 [ADR-031](../decisions/ADR-031-prefab-instance-boundary.md) 的引用实例与复合作者身份模型。
- Prefab 使用独立格式标识和版本，不把完整 Scene 文件隐式解释为 Prefab。
- 场景实例声明只保存 Prefab URI、实例 UUID、父级、名称和根 Transform。
- 源节点使用 Prefab 内稳定 UUID；实例节点由实例 UUID 与源节点 UUID 复合寻址。
- Scene Instance 继续拥有作者描述、Runtime 投影、依赖租约和失败回滚。
- 首版源子节点只读，所有实例级作者修改限定在实例根，避免提前冻结覆盖合并规则。
- 更新传播由用户显式触发，成功后作为一条可撤销 Editor 命令提交。

## 实施顺序

### M-116：Prefab 格式、身份与组合 Spike

用最小灯架子树验证独立 Prefab envelope、单根约束、源节点 UUID、复合作者地址、Transform 组合和
错误路径。确定场景 v3 实例声明及 C11 可表达的数据结构，不实现正式 Editor UI。

状态：已完成。结果见
[M-116 Prefab 格式、身份与组合 Spike 记录](../records/M-116-prefab-format-identity-spike.md)。

### M-117：Prefab Loader 与依赖缓存

建立严格 UTF-8 Prefab 解析、版本校验、规范 URI、节点树校验和 Mesh/Material 依赖收集。复用现有
VFS 与资源缓存；缓存键包含规范 URI，不把 JSON DOM 或第三方类型泄漏到公共接口。

状态：已完成。结果见
[M-117 Prefab Loader 与依赖缓存实施记录](../records/M-117-prefab-loader-cache.md)。

### M-118：原子实例化与生命周期

让 Scene Instance 从 Prefab 描述创建独立 Runtime 子树，组合实例根 Transform，并持有正确资源租约。
覆盖多实例、销毁、源缺失、依赖失败、部分创建回滚和旧 Runtime ID 失效。

状态：已完成。结果见
[M-118 Prefab 原子实例化与生命周期实施记录](../records/M-118-prefab-runtime-instance.md)。

### M-119：场景格式 v3 与实例声明

扩展场景作者描述与序列化，保存 Prefab URI、实例 UUID、父级、名称和根 Transform；建立 v2→v3
迁移。未知字段继续保留，保存不得写入展开节点或 Runtime 标识。

状态：已完成。结果见
[M-119 场景格式 v3 与 Prefab 实例声明实施记录](../records/M-119-scene-v3-prefab-instances.md)。

### M-120：Editor 放置与层级呈现

Asset Browser 识别 Prefab 资产并允许放置到当前场景。Hierarchy 展示实例根和来源子节点，明确标记
Prefab 边界；源子节点只读，选择、聚焦和 Runtime 检查仍可正常工作。

状态：已完成。结果见
[M-120 Editor Prefab 放置与层级呈现实施记录](../records/M-120-editor-prefab-placement.md)。

### M-121：根级覆盖、更新传播与命令历史

支持实例根重命名、Transform 编辑、复制、删除及显式刷新。操作进入现有 Undo/Redo、脏状态和保存
流程；刷新失败保留旧投影，成功刷新可撤销并恢复有效选择。

状态：已完成。结果见
[M-121 Prefab 根级编辑与刷新事务实施记录](../records/M-121-prefab-root-edit-refresh.md)。

### M-122：Lantern Gallery 复用示例与跨平台验收

把重复灯架整理为项目自有 Prefab，验证多个实例、不同根 Transform、源更新传播、撤销/重做、保存、
重开和 Runtime Play。完成 Windows 本地矩阵，以及获授权后的 Linux Shared/Static、Granit Runtime
和 Sanitizer Actions。

状态：已完成。结果见
[M-122 Lantern Gallery Prefab 复用实施记录](../records/M-122-lantern-gallery-prefab.md)。

## 测试与验收

- 格式测试覆盖错误标识、未知版本、重复 UUID、多个根、环、目录逃逸和未知字段保留。
- 复合身份测试覆盖同源多实例、实例复制、源节点增删和 Runtime 投影重建。
- 实例化测试覆盖依赖预取、失败原子性、资源租约、销毁顺序和旧句柄失效。
- 场景迁移测试证明 v2 内容升级到 v3 后语义不变，保存结果不包含展开副本。
- Editor 测试覆盖放置、选择、只读边界、根级编辑、刷新、Undo/Redo、脏状态和保存。
- Lantern Gallery 自动测试证明修改一次源资产可以更新所有实例，且各实例根 Transform 保持独立。
- Shared/Static、Editor/Runtime 关闭、安装 Consumer 和无头图形组合保持通过。

## 风险与未决问题

- 复合作者地址会影响当前只接受单 UUID 的命令和选择模型；M-116 必须先限定最小改造面。
- 源节点被删除时，旧选择和未来覆盖如何处理；首版清空失效选择，不保留孤立覆盖。
- Prefab 已复用场景节点 Schema 与校验路径；后续提取共享编码层仅在序列化产生真实重复时进行。
- 实例根已确定作为源根父节点，并通过现有 Scene Tree 的父子 TRS 参考值测试固定组合顺序。
- 大型 Prefab 刷新可能产生可感知停顿；首版保证有界失败和原子替换，异步刷新留待测量后规划。

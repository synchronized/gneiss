# VER-013：0.13.0 结构化日志与 Editor Console

## 状态

- 状态：设计中
- 目标版本：0.13.0
- 优先级：P0
- 路线图阶段：结构化日志与 Editor Console

## 背景与目标

0.12.0 已让独立 Game Module 在 Runtime 中运行，但模块尚无正式日志入口。Runtime 当前只把阶段化
文本同时写入标准流和单个轮转文件，Editor 也只能显示子进程原始输出，无法按来源、级别或分类筛选。
Application 诊断回调用于报告 Engine 事件，不应继续承担游戏代码的普通运行日志。

0.13.0 建立一条从 Engine、Runtime 和 Game Module 到 Editor Console 的结构化日志链路。版本完成
后，游戏模块可以通过 Game Context 写入日志；独立 Runtime 能将事件送往控制台、轮转文件和 Editor；
Editor 能在不阻塞作者会话的前提下查看、筛选和复制日志，并明确显示日志丢弃和进程异常。

## 非目标

- 不实现性能分析器、分布式追踪、GPU 标记或崩溃转储。
- 不实现网络日志服务器、远程 Console 或多机聚合。
- 不开放任意格式字符串 ABI，也不让第三方日志库类型进入公共接口。
- 不在首版提供任意键值字段、日志脚本命令或可执行控制台。
- 不移除现有 Application 诊断回调，也不把所有诊断降级为普通文本日志。
- 不承诺日志文件是存档、审计或长期兼容的数据格式。

## 建议决策

- 采用 [ADR-026](../decisions/ADR-026-structured-logging-transport.md) 提议的不可变日志事件、受控
  Sink 和带前缀 JSON Lines 子进程传输。
- 诊断表示 Engine 已识别的状态或失败；日志表示组件主动记录的运行信息。诊断可转换为日志事件，
  但仍保留结果码和诊断分类。
- C ABI 使用 UTF-8 指针与长度，并在调用期间复制；Game Module 只通过借用的 Game Context 提交，
  不接触 Sink、文件或 Editor 状态。
- 日志提交支持多线程，进入有界队列；投递和 UI 消费串行化。队列溢出必须累计并报告丢弃数量，
  不能无限增长或递归记录自身故障。
- Runtime 的标准输出承载可识别的结构化事件帧；标准错误和无法解析的普通输出继续作为原始进程输出，
  便于保留第三方库和崩溃前信息。
- 首版自行维护最小契约与实现，不引入 `spdlog` 等新依赖；以后可替换内部 Sink，但不改变公共 ABI。

## 实施顺序

### M-83：日志事件与提交契约

定义级别、来源、分类、消息、时间、线程和可选结果码的事件模型，以及日志提交、复制、线程安全和
重入规则。明确与 Application 诊断的转换关系，补充 C11/C++20 头文件与 ABI 测试。

当前进展：已增加 Experimental `gneiss_log_message`、不可变 `gneiss_log_event`、C++20 构造辅助、
独立校验和线程安全的 Application 提交入口。Engine 补充事件序号、单调时间、线程与可信来源，同一
Application 的可选接收回调串行执行且禁止重入；已识别的 Application 诊断会恰好转换为一个保留
来源、分类和结果码的事件。测试覆盖复制所有权、多线程提交、事件顺序、无回调、失效句柄和诊断
转换。M-83 已完成。

### M-84：Engine 日志服务与基础 Sink

实现有界多生产者队列、串行投递、标准流 Sink 和单文件轮转 Sink。复用并逐步替代 Runtime 私有
`runtime_log`，覆盖队列溢出、文件不可用、轮转失败、Sink 重入及关闭时排空。

当前进展：已增加每个 Application 独立的有界多生产者队列和专用消费线程。提交时复制消息，Sink
串行异步执行；队列溢出会累计丢弃数量，并在已有事件之后生成 `backpressure` 告警。Application
销毁会等待队列排空和消费线程退出。Runtime 的标准流与单文件轮转 Sink 已支持结构化事件并完成并发
写入保护，Application 诊断不再通过旧回调重复写出，首帧事件已改走新链路。测试覆盖背压合并、
Sink 重入、消息转义、文件不可用、单文件轮转和关闭排空。M-84 已完成。

### M-85：Game Context 日志入口

向 Experimental Game Context 增加模块日志接口，由 Engine 自动标记游戏模块来源。覆盖空消息、非法
级别、失效 Context、跨线程提交、模块关闭期间提交和消息所有权；Lantern Gallery 增加可观察日志。

### M-86：Runtime 结构化输出协议

让 Runtime 将 Engine、诊断和 Game Module 事件统一编码为版本化、带前缀的 JSON Lines 帧，同时保留
人类可读文件和原始标准错误。覆盖特殊字符、超长行、分块读取、协议版本错误和异常退出前排空。

### M-87：Editor Console

在 Editor 增加 Console 面板，解析 Runtime 事件并支持级别、来源和分类筛选，以及搜索、暂停、清空、
复制和自动滚动。无法解析的输出进入 Raw 视图；缓冲区有明确上限并显示丢弃计数，停止或重启 Runtime
不会误归属旧会话事件。

### M-88：示例、安装与跨平台验收

验证 Editor 启动 Runtime、Game Module 产生日志、筛选查看、文件回退和重复运行闭环。覆盖 Windows、
Linux、构建树与安装树，并形成 0.13.0 验收记录。

## 测试与验收

- 公共 C 头可由 C11 独立包含，C++20 包装不建立第二套日志状态。
- 提交后调用方可立即释放消息内存；并发提交不产生数据竞争或无界内存增长。
- 诊断转换后保留严重级别、模块、结果码和消息，且不会重复投递。
- Runtime 文件不可写、队列溢出或协议编码失败时仍保留至少一个可见的降级通道。
- Editor 能正确处理分块、多事件、未知版本、非协议文本和子进程异常退出。
- Game Module 日志可在 Editor 中按模块来源筛选，并能在独立 Runtime 日志文件中定位。
- Windows/Linux 代表性构建和测试通过，安装树示例不依赖源码目录。

## 风险与未决问题

| 风险或问题 | 当前处理 |
| --- | --- |
| 日志与诊断形成重复接口 | 以“主动记录”和“Engine 事件”划分语义，诊断只单向转换为日志 |
| 高频日志拖慢主循环 | 有界队列、批量排空和丢弃计数；性能基线在 M-84 建立 |
| 标准输出混入第三方文本 | 协议帧使用固定前缀，其他内容进入 Raw 视图 |
| JSON 编码增加开销 | 仅跨进程边界编码，进程内使用定型事件；以后可替换传输格式 |
| 模块伪造 Engine 来源 | Game Context 自动补充模块来源，不接受调用方指定宿主来源 |
| Console 缓冲无限增长 | Editor 使用有界环形缓冲，并明确展示被丢弃的历史数量 |

## 完成条件

- M-83～M-88 全部完成并形成 0.13.0 验收记录。
- Engine、Runtime 与 Game Module 共用同一事件语义，Editor 能稳定消费隔离进程日志。
- 日志线程安全、所有权、背压、降级和关闭顺序均有文档与自动化测试。
- 现有启动失败诊断和 Runtime 原始输出能力没有回归。

# 共享资产与场景实例实施设计

## 状态与范围

2026-10-15，目标设计已记录，资产共享迁移尚未实施。属于
[DEV-051 的 M-329～M-333](DEV-051-architecture-boundaries.md)，决策依据为
[ADR-064](../decisions/ADR-064-shared-assets-and-scene-instances.md)。本轮只整理文档。
当前已实现的协调拆分见 [M-331 记录](../records/M-331-scene-session-extraction.md)。

## 当前与目标

当前每个 `application_scene_state` 拥有 resource_cache、render_asset_loader、prefab_asset_loader、
World 和场景实例服务；Application 级渲染资源服务由各域共享。缓存项和资产租约通过共享引用
持有资产，帧快照另有数据持有；不能据此宣称已经实现跨域资产加载去重。

目标是资产系统统一管理共享资产，运行场景持有使用引用，场景协调只管理实例切换事务。
场景资产可多次实例化，各实例共享适合共享的资源，但实体、变换和运行状态独立。

## 目标对象与目录

以下路径均相对 `src/`，是建议布局；不表示每一行都需要新建类或文件。

| C++ 对象 | 目标目录 | 职责与拥有关系 | 迁移起点 |
| --- | --- | --- | --- |
| `asset_manager` | `engine/asset/` | Application 拥有；管理资产身份、依赖、加载去重和缓存记录 | 整合现有缓存与准备流程 |
| `asset_ref<T>` | `engine/asset/` | 使用者持有；保持一个资产版本存活，不直接拥有后端设备 | 从既有资产租约演进 |
| `asset_load_request` | `engine/asset/` | 发起者持有；表示一次请求的进度、取消与结果，不等同共享任务 | 整理现有异步请求状态 |
| `scene_asset`、`prefab_asset` | `engine/function/scene/` | 资产系统管理，通过引用共享；保存层级、组件初始数据和依赖 | 复用现有 scene/prefab 描述与解析 |
| `scene_instance` | `engine/function/scene/` | 实例服务拥有；记录本次实例化的实体、节点映射与资产引用 | 整理现有实例记录，不再造实例表 |
| `scene_instance_service` | `engine/function/scene/` | 场景运行环境拥有；在指定 World 创建、查询、销毁实例 | 保留现有服务并调整资产依赖 |
| `application_scene_state` | `engine/function/application/` | 协调对象拥有；保留 World 与实例服务，退出共享缓存的所有权 | 从当前场景域逐步迁移 |
| `scene_controller` | `engine/function/application/` | Application 拥有；管理候选请求、当前域、旧域及安全切换 | 由当前 scene_session 演进并更名 |
| `render_resource_service` | `engine/function/render/` | Application 拥有；管理 RID 与渲染资源数据，后端 GPU 操作仍交渲染后端 | 复用现有资源服务与帧持有 |
| `application_state` | `engine/function/application/` | 宿主拥有；装配资产、场景与后端系统，推进主循环和整体启停 | 继续收敛现有实现 |

`resource_cache` 作为资产系统内部机制继续评估复用，不与 asset_manager 各自维护一份权威索引。
具体场景、Mesh、Material、Texture 的解析及加载实现留在所属模块；在 Application 装配时注册
到资产系统定义的接口。Asset 不包含上层具体资产头；注册机制不扩展为动态插件系统。
内部对象不自动安装到 `include/`，不要求每个方法再包装 C ABI。

## 所有权与依赖概念示意

```text
Application
├─ asset_manager                         跨场景域共享
├─ render_resource_service               跨场景域共享
└─ scene_controller
   ├─ 候选加载请求 → 候选运行环境
   ├─ 当前运行环境
   │  ├─ World
   │  └─ scene_instance_service
   │     ├─ 实例 A → 资产使用引用
   │     └─ 实例 B → 资产使用引用
   └─ 待退役运行环境

场景资产
├─ 对象层级与组件描述                     组成关系
├─ 预制体资产引用                         资产依赖
└─ MeshRenderer 描述
   ├─ Mesh 资产引用
   └─ Material 资产引用 → Texture 资产引用
```

一个运行环境可能包含多个场景实例，不把 application_scene_state 简单改名为 scene。
Scene Tree 节点只关联实体 ID，ECS 组件只存数据或 RID；引用由实例服务的持有记录管理。
RID 是服务资源身份，不替代资产身份或资产使用引用。

## 加载、发布与释放

1. 协调对象发起场景资产请求；资产系统查找已加载或在途的兼容版本并准备依赖。
2. 请求得到资产引用后，实例服务在候选运行环境中构造实体与节点。资源就绪不等于实例已激活。
3. 候选准备不直接替换活动场景使用的资产。完整验证成功后，宿主在安全时机请求激活。
4. 切换失败保留旧环境；成功后旧环境退役，释放其实体和资产引用。
5. 资源在没有使用引用后才可回收；缓存保留与后端帧持有另行约束，不承诺引用归零立即释放显存。

同一身份的兼容版本可共享。身份必须区分来源域、类型、来源版本及影响产物的配置，不能仅凭 URI
合并不同项目、修改前后或不同设备准备结果。具体键格式仍待审计决定。
已发布数据按版本保持稳定；热重载如何更新使用者与 RID 需单独明确，不能让候选加载隐式改写它们。

请求取消只撤销该请求的订阅和引用；仍有使用者时共享任务继续。所有使用者均取消后如何停止
底层任务、处理迟到回执和清理，需沿用现有执行器与服务契约。不能让取消接口强制销毁共享依赖。
资产依赖可能形成环；必须在方案实现前明确拒绝或处理规则，不能直接把全部边变成强引用。

整体退出先停止接收请求，再取消或排空在途任务，销毁场景实例及其引用，清理资产系统持有；
资源服务必须晚于引用它的租约释放，渲染后端及 I/O 必须在所有借用工作完成后关闭。
最终顺序需结合现有上传回执和帧快照验证，不按对象名称机械排列析构。

## 实施顺序与验收

| 阶段 | 工作 | 验收要求 |
| --- | --- | --- |
| 职责复核 | 核对缓存键、租约、来源版本、实例与帧引用；明确候选发布 | 有实际调用与销毁关系证据，列明身份和版本未决项 |
| 共享资产最小闭环 | 演进缓存及租约，跨两个场景域请求相同兼容资产 | 复用一次加载；不同来源/版本不错误合并；释放一个使用者不影响另一个 |
| 场景资产与实例分离 | 复用描述解析，明确资产引用和实例资源记录 | 同一场景资产实例化两次；实体独立且共享依赖；销毁其中一个后另一个有效 |
| 请求与候选隔离 | 分离请求订阅与底层工作，保留失败/取消隔离 | 取消一个请求不取消其他使用者；失败不污染旧版本；迟到回执可清理；可重试 |
| 接入协调与关闭 | controller 更名，迁出场景域缓存，收紧内部接口 | 无双份状态、无后端反向依赖；切换及在途退出无泄漏、悬空 RID 或死锁 |
| 整体验证 | 沿用 DEV-051 的线程、消费者、平台及性能矩阵 | 小夹具后再完整 Sponza；共享数据按实际持有计量，不重复统计或隐藏峰值 |

每阶段先验证再进入下一阶段。既有协调拆分保留，但其内部成员可以随资产归属迁移，不能将
当前“拥有纹理加载服务”固定为最终架构。共享资产与独立任务框架、LOD、预算缓存不是绑定交付。
不新增预算缓存策略、流送系统或任意多世界功能；资产共享方向纳入 0.51，若需拆分交付须明确
记录未完成项并讨论，不提前分配后续版本号。

## 实施前需要讨论的细节

- 资产稳定身份与版本如何编码；现有 URI、source revision 和设备 profile 如何组合。
- 热重载是显式切换版本引用还是保持部分 RID；哪些对象允许实例局部修改。
- 依赖环的合法范围与检测规则，以及无使用者的共享任务清理时机。
- 最小加载器注册接口与完成通知线程；继续支持线程池、协作执行和无线程配置。

上述细节不因记录本方案而被默认为已确认；到达相应实现阶段时给出具体证据、选项和建议。

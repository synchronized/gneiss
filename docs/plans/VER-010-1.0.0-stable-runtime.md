# VER-010：1.0.0 稳定运行时

## 状态

- 状态：实施中
- 目标版本：1.0.0
- 优先级：P0
- 路线图阶段：首个稳定运行时

## 背景与目标

0.9.0 已贯通 Application、World、Scene、资源、渲染、输入、属性、资产工具与 Editor 的主要开发
路径。1.0.0 不以继续增加模块为目标，而是证明一组边界清晰的运行时能力可以被下游项目长期使用：

```text
稳定能力清单 → 代表性游戏样例 → API/ABI 审计 → 兼容与升级验证
→ 性能及故障基线 → 可重复发布
```

完成后，使用稳定 C11 API 的下游项目应能升级到兼容的 1.x 版本而无需重新编译；C++20 包装承诺
源码兼容，不承诺跨编译器或标准库的二进制兼容。未进入稳定清单的模块必须显式标记为实验性，
不能因随 1.0.0 一同发布而获得隐含兼容承诺。

## 非目标

- 不为达到 1.0.0 临时加入物理、音频、网络、脚本或完整 PBR。
- 不承诺 Editor、资产编译器及其内部协议在 1.x 保持兼容。
- 不冻结 Granit 原生接口、私有实现布局、RID 位编码或后端资源对象。
- 不承诺不同 C++ 编译器、运行库或标准库之间的 C++ ABI 兼容。
- 不建立插件市场、通用热重载、多人协作或完整发布平台。

## 已确认决策与待确认项

- 稳定性按 `Stable`、`Experimental`、`Internal` 三级管理；M-65 审计后形成唯一权威清单。
- 1.x 对 `Stable` C ABI 遵循语义化版本：保留已有符号、枚举值和已发布结构字段，只允许兼容追加。
- C++20 包装以稳定 C ABI 为事实来源，承诺同一主版本内的源码兼容，不建立第二套 ABI 承诺。
- 场景、工程、动作映射和二进制 Mesh 格式继续独立版本化；兼容范围由各格式 Reference 定义。
- Editor 与 `gneiss_assetc` 首版保持 Experimental，除非代表性样例证明某项工具 SDK 必须进入稳定面。
- 1.0.0 的代表性样例类型、稳定 API 最小集合和性能目标值仍需在 M-65、M-66 中用测量确认。

## 实施顺序

### M-65：稳定能力与兼容策略审计

逐项审计公共头、导出符号、C++ 包装、CMake target、安装组件和持久格式。为每项能力标记稳定级别，
补齐所有权、线程安全、错误、结构扩展和弃用规则；形成 1.x 兼容策略与首份 ABI 基线。审计期间
允许在 1.0.0 前收敛不合理接口，但必须记录迁移方式，不能静默保留含义重叠的旧接口。

状态：已完成。稳定级别与兼容边界见 [ADR-023](../decisions/ADR-023-public-api-stability.md)，模块
分类、83 个导出符号基线和冻结阻塞项见
[M-65 公共 API 审计记录](../records/M-65-public-api-audit.md)。

### M-66：代表性游戏样例

建立一个只消费已安装 SDK 和公开资产格式的小型可交互样例，覆盖应用生命周期、输入、场景加载、
层级变换、资源、渲染和确定性退出。样例不包含引擎私有头，也不依赖源码树路径；以其实际调用面
反向验证 Stable 清单是否足够且没有不必要扩张。

状态：已完成。独立 CMake Consumer、安装资产定位、三帧图形 smoke 和 Stable 候选收敛结果见
[M-66 稳定运行时代表性样例验收记录](../records/M-66-stable-runtime-sample.md)。

### M-67：公共 API、ABI 与错误语义加固

修复 M-65、M-66 暴露的问题，完成 C11 独立包含、C++20 包装、共享/静态导出、结构大小、枚举值、
字符串生命周期、跨线程拒绝和失败原子性测试。建立导出符号与关键布局基线，并验证兼容追加不会
破坏使用旧头文件构建的 Consumer。

状态：已完成。四组公开枚举已改为定宽常量，反射查询结构采用版本化 `struct_size`，83 个导出均
进入稳定性清单，37 个 Experimental 导出在头文件可识别，并由冻结头 Consumer 验证新共享库。
详见 [M-67 公共 API 与 ABI 加固记录](../records/M-67-api-abi-hardening.md)。

### M-68：安装、升级与依赖消费闭环

验证 Windows/Linux 的 Shared/Static package、纯 C/C++ Consumer、Granit `PACKAGE`/`FETCH` 路径
和离线安装说明。增加从最后一个 0.x 版本升级到 1.0.0 的迁移验证，并确保公开依赖、许可证、运行时
动态库和 CMake 组件传播准确。

状态：已完成。核心 Shared/Static 安装 Consumer 已与源码树隔离；Granit `PACKAGE`/`FETCH` 构建均
可从独立安装前缀配置、构建并运行代表性 Consumer。0.9.0 Application v1 布局兼容测试及
[升级指南](../guides/migrating-0.9-to-1.0.md)已落地，Windows/Linux 手动 Actions 矩阵全部通过。
详见 [M-68 安装、升级与依赖消费验收记录](../records/M-68-install-upgrade-validation.md)。

### M-69：性能、内存与故障诊断基线

对代表性样例记录冷启动、场景加载、稳定帧时间、CPU 内存、GPU 资源和退出泄漏基线。阈值先通过
固定环境重复测量确定，再作为回归门槛；不得先写任意目标数字。启动失败、资产错误、设备初始化
失败和资源泄漏必须提供可操作的阶段、结果码与上下文。

状态：实施中。按以下顺序建立最小可复现闭环：

1. 为稳定运行时样例增加机器可读的测量模式，固定预热帧、采样帧、场景和 Release 配置；测量输出
   必须区分 Application 创建、场景加载、预热、稳定帧和完整退出阶段。
2. 使用独立脚本执行多轮冷启动并汇总中位数、P95、波动范围和进程峰值内存，同时记录操作系统、
   编译器、构建类型、Gneiss/Granit 提交和样本数量；首轮只记录基线，不设置失败阈值。
3. 建立配置无效、资产缺失、格式损坏和设备初始化失败的故障注入矩阵，验证阶段、结果码、诊断类别
   和上下文；失败后必须能够重新创建、加载或退出，不遗留半初始化状态。
4. 在支持的工具链上增加退出泄漏检查，并记录 Gneiss 逻辑资源计数。GPU 原生资源统计只有在 Granit
   提供可复用、后端无关的诊断能力后接入，不向 Gneiss Stable ABI 暴露后端对象。

完成条件：固定环境至少完成 1 次预热和 10 次有效样本，原始数据与汇总可复查；故障矩阵和退出泄漏
检查自动化通过；只有获得重复测量证据后，才在独立改动中提出回归阈值。

### M-70：1.0.0 发布候选与发布验收

冻结候选提交，完成版本号、Changelog、兼容清单、迁移说明、许可证与发布包校验。手动运行完整
Windows/Linux 矩阵，安装发布产物后重新构建代表性样例；候选期只接受阻塞发布的问题修复，最终
形成验收记录并创建 `v1.0.0` 标签。

## 测试与验收

- Stable C 头由 C11 编译器独立包含；C++ 包装由 C++20 编译器独立包含。
- 导出符号、枚举值、公开结构大小和关键字段偏移与冻结基线比较。
- 旧头文件 Consumer 能加载新 Shared Library，并覆盖成功、失败和销毁路径。
- Windows/Linux、Shared/Static、C/C++ Consumer 与 Granit package/fetch 矩阵通过。
- 代表性样例只使用安装产物运行，找不到源码树时仍能加载资产并确定性退出。
- 性能基线使用固定场景、固定配置、预热策略和多次采样，记录环境与波动范围。
- 故障注入至少覆盖配置无效、资产缺失、格式损坏、后端初始化失败和资源未释放。
- Experimental API 在头文件、文档和 package 中可识别，不被兼容测试误当成 Stable。

## 风险与未决问题

| 风险或问题 | 当前处理 |
| --- | --- |
| 稳定范围过大导致 1.x 无法演进 | 先由代表性样例收敛最小 Stable 清单，其余明确标记 Experimental |
| 0.x 接口存在需要修正的设计 | 只在 M-65 审计期调整，提供迁移说明并在 RC 前冻结 |
| C++ ABI 受编译器和标准库影响 | 只承诺 C++ 源码兼容，二进制兼容以 C11 ABI 为边界 |
| 性能阈值缺少可信依据 | 先建立可复现测量和基线，再确定回归阈值 |
| Granit 变化影响发布可重复性 | 锁定已验收版本，并同时验证 package 与 fetch 路径 |
| 样例演变成新功能集合 | 样例只验证已确认稳定能力，缺口先回到 Stable 清单评审 |

## 完成条件

- M-65～M-70 全部完成并形成 1.0.0 验收记录。
- Stable、Experimental 与 Internal 能力有唯一、可查的权威清单。
- 代表性样例仅使用安装后的稳定 SDK 完成可交互运行时闭环。
- 1.x C ABI 兼容策略、C++ 源码兼容策略、弃用规则和格式兼容范围均已发布。
- 完整构建、安装、升级、性能、故障和发布矩阵通过，不存在未说明的阻塞风险。

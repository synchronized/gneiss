# PLAN-093：引用持久化与编辑器共享操作

状态：实施中，2026-10-31。

## 已确认边界

- 内嵌对象归当前文件所有；跨文件只引用独立资源 URI，不引用子对象 ID。
- 同一文件共享通过对象表恢复；无 URI 的对象分别保存到不同文件即产生独立副本。
- 保存不级联写入外部资源，不引入多文件事务。加载依赖由资源层异步解析。
- 引用环明确拒绝；失败不发布半成品，不留下共享环泄漏。
- 普通值文件保持现有布局，ref 不承担文件归属、加载状态或资源缓存职责。

## 实施顺序

1. 内嵌引用：对象表、null、共享身份、类型检查、失败清理和环检测。
2. 外部引用：选择材质描述作为首个 CPU 数据入口，接入既有 URI、异步依赖和缓存。
   运行时 material_resource 与可编辑 material_description 不混用，Meta 不访问文件系统。
3. 编辑器：另存为共享资源、复制为本地对象；接入现有保存和撤销入口，明确失败时原引用不变。

## 当前接入约束

Scene/Prefab 的组件 codec 与材质格式包装器已有独立编解码入口。对象表上下文必须明确其
传播边界，不能声称互不共享上下文的 codec 可以保留整个文件范围内的共享身份。
现有 mesh_renderer_description 只有 material_uri，尚无可内嵌材质槽；第三项需要先补齐
描述模型及运行加载适配，不用孤立按钮冒充已完成。

## 验收

相关 Debug 编译和 CPU 测试。覆盖共享/独立、空值、非法 ID、类型错误、环和失败清理；
外部引用覆盖依赖加载失败和缓存复用；编辑器覆盖保存失败、撤销及保存不级联。
暂不运行 GUI/GPU、大场景或远端 CI。每项实现与验证分别记录，不提前标记完成。

## 阶段一结果

已实现纯反射编解码范围内的对象表、null、共享恢复、类型检查、环拒绝及失败清理。
Debug 全目标编译及 22 项相关 CPU 测试通过。自定义 codec 各自建立序列化上下文；
带自定义 codec 的引用目标仍拒绝，尚未完成整个 Scene/Prefab 文件跨 codec 的共享。

## 实施方法

- 先阅读模块调用示例，再调整声明、类型、适配与所有权实现；不机械抽走所有函数体。
- 普通使用入口优先 Application、World 和 Game Context；C 互操作保留清晰的边界说明。
- 转换临时存储留在调用内；长期回调存储继续由拥有者携带，不隐藏全局状态。
- 维护 abi/cpp-api-inventory.json 的实现候选路径，明确 detail 文件不构成新公共入口。
- Core、日志等小模块如拆分不改善阅读，可保留并记录理由，不能只为目录一致制造碎片。

## 测试与验收

每组运行改动相关格式和静态检查、模块行为测试以及公共头编译。
涉及分发的改动验证共享/静态与干净安装消费者；最终再执行整版矩阵。
重点覆盖失败时输出是否保持、回调状态移动、错误线程关闭、借用对象失效、
数组与文本有效期以及多编译单元链接。测试不依赖弹出窗口展示三角形。

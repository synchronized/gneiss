# VER-027：0.27.0 Granit 0.10 能力接入与 GPU 可观测性

## 状态

- 状态：实现中
- 目标版本：0.27.0
- 优先级：P0
- 路线图阶段：标准渲染资产、环境光照与 GPU 诊断

## 背景与目标

0.26.0 已建立独立渲染线程、帧资源复用、渲染镜像和 CPU 阶段统计，但仍只能从 CPU 侧估算 GPU
工作，基础材质与环境光照也继续由 Gneiss 私有路径维护。Granit 0.8～0.10 已公共化运行时 Shader、
标准 PBR 资产和 Environment Map，并提供 Timestamp Query。

0.27.0 先将依赖升级到 Granit 0.10.0，再以最小端到端用例接入 GPU 时间测量、标准 PBR 资产和
Environment Map。Gneiss 继续拥有资产身份、资源 RID、场景语义和线程调度；Granit 只作为渲染后端，
其类型和持久格式不得进入普通公共 API。

## 非目标

- 不实现完整 Render Graph、GPU Profiler、通用 Job System 或异步计算队列。
- 不重做 0.26.0 已有的 Frame Slot、Render Scene 镜像、构造前背压和上传进度。
- 不承诺本版本支持全部 glTF PBR 扩展、透明排序、阴影、后处理或多环境混合。
- 不把 `.grmat`、`.grshader`、`.grenv` 或 Granit 句柄暴露为工程作者接口或 Gneiss 公共 ABI。
- 不直接复制 Granit Model Viewer 的示例私有执行器、Worker 或 UI 状态。
- 不以 Debug 构建的一次 GPU 时间作为跨设备性能承诺。

## 已确认决策

- Granit Fetch 锁定 0.10.0 正式发布提交；PACKAGE 与安装消费最低版本同步提升至 0.10。
- Timestamp Query 由渲染线程创建、写入、读取和销毁；结果延迟回收，禁止为读取本帧结果阻塞 GPU。
- 首版只测量稳定且可解释的整帧 GPU 区间，并与现有 CPU 阶段、Frame 序列和完成回执关联。
- 标准 PBR Shader 由 Granit 安装资产提供；Gneiss 生成 Material 后端归档，适配层负责资源 RID、
  参数映射、Shader Resolver 和失败回退。
- 工程仍引用 Gneiss 资产 URI。Granit 运行时资产只允许作为导入缓存或后端投影存在。
- Environment Map 首版提供内建回退环境和单个工程环境资源，支持强度与水平旋转；加载失败继续使用
  已生效环境或内建回退。
- 新指标复用现有诊断快照和 Editor–Runtime 通道，先提供紧凑摘要，不在本版本建设完整 Profiler UI。

## 实施顺序

### M-175：Granit 0.10.0 升级与兼容审计

升级 Fetch 锁定提交和 PACKAGE 最低版本，验证旧默认缓存迁移、Shared/Static 构建、安装消费及
现有渲染路径兼容性。

状态：已完成。本地 Windows Clang Shared 131/131、Static 129/129 测试通过，结果见
[M-175：Granit 0.10.0 升级与兼容审计](../records/M-175-granit-0.10-upgrade.md)。

### M-176：Granit 运行时资产边界与接入 ADR

审计 Granit 标准 PBR、Shader Asset、Material 与 Environment Map 的公共接口，明确源资产、Gneiss
导入产物、Granit 后端投影、缓存失效和热重载边界；形成 ADR 和最小适配接口。

状态：已完成。审计确认接入需要迁移整个后端投影而非只替换 Shader，并固定作者资产、派生缓存、
Granit 对象及热重载边界。结果见
[M-176：Granit 运行时资产边界与接入审计](../records/M-176-granit-render-asset-boundary.md)，长期决策见
[ADR-039：Granit 渲染资产只作为后端投影](../decisions/ADR-039-granit-render-asset-projection.md)。

### M-177：异步 GPU 时间戳

在渲染线程内建立按在途帧分槽的 Timestamp Query 生命周期，记录整帧 GPU 起止时间；将可用结果
关联到原 Frame 序列并纳入统计快照。覆盖不支持、暂不可读、Resize、丢弃帧和关闭路径。

状态：待开始。

### M-178：标准 PBR 资产适配

用 Granit 0.10 安装的标准 PBR Shader 和参考 Render Pipeline 替代 Gneiss 中含义重叠的后端
Shader/Material/Pipeline 组装，建立基础颜色、金属度、粗糙度及现有纹理参数映射；失败时保留当前
有效投影。

状态：待开始。

### M-179：Environment Map 最小闭环

增加 Gneiss 环境资源描述和渲染镜像命令，支持内建环境以及从 VFS 读取单个已导入环境资源；把环境
强度与水平旋转纳入场景/项目配置、热重载和 Lantern Gallery 验收。

状态：待开始。

### M-180：诊断整合与版本验收

把 CPU 帧阶段、GPU 整帧时间、查询可用性和环境资源状态接入现有日志与诊断摘要；完成无能力后端、
资源失败、热重载、Windows/Linux Shared/Static、安装消费、Granit Runtime 和 Sanitizer 验证。

状态：待开始。

## 测试与验收

- AUTO、PACKAGE、FETCH、父工程目标和旧 0.7 默认缓存升级均能确定解析 Granit 0.10。
- Timestamp Query 不支持时渲染继续工作并明确报告不可用；支持时结果能关联正确 Frame 序列。
- 查询结果读取不造成逐帧 GPU 等待，Resize、帧替换和关闭不会泄漏或误复用查询槽。
- Lantern Gallery 使用 Granit 标准 PBR 资产后保持基础颜色、纹理、金属度和粗糙度结果正确。
- 环境资源加载、替换和失败回退具备事务语义，旧环境不会因无效更新提前失效。
- Granit 类型和专用持久格式不出现在 Gneiss 公共 C/C++ API、Scene 或项目作者格式中。
- Windows/Linux Clang/GCC/MSVC Shared/Static、Granit Runtime、安装消费和 Sanitizer 通过。

## 延后项及理由

- Model Viewer 的构造前背压已分别存在于 Granit 0.10 和 Gneiss 0.26，本版本不重复移植。
- 上传阶段与工作量回执已由 M-166 实现；只有发现 Granit 公共 API 缺少可复用底层信号时，才向用户
  提出 Granit Pull Request 建议。
- Frame Packet 回收和稳定资源绑定属于 Gneiss 上层场景与调度策略，暂不下沉 Granit。
- 完整 GPU Profiler 面板、逐 Pass 时间、Pipeline Statistics 和历史曲线留到数据证明有诊断需求后。

## 风险与未决问题

- Timestamp Query 的能力和结果可用时机因后端而异，必须以能力查询和显式不可用状态处理。
- 标准 PBR 资产可能与现有顶点布局、参数命名或材质热重载存在差异，M-176 先做契约审计。
- 环境贴图体积和上传时间可能明显增加，仍须走不可丢弃命令与现有进度回执，不能进入普通 Frame。
- 若 Granit 公共 Environment Map 缺少 Gneiss 所需的线程安全或增量替换契约，只提出最小通用能力
  的 PR 建议，由用户决定并向 Granit 提交。

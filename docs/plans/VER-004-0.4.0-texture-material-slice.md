# VER-004：0.4.0 纹理与材质闭环

## 状态

- 状态：实现中
- 目标版本：0.4.0
- 优先级：P0
- 路线图阶段：图形与工具基础

## 背景与目标

`0.3.0` 已建立资产驱动、可交互和可诊断的运行时，但渲染内容仍只有位置顶点与固定颜色。
`0.4.0` 的目标是建立第一条纹理内容路径：VFS 读取图片源资产，Texture Service 创建稳定 RID，
Material 引用 base-color Texture，Granit 后端上传并采样，示例加载带 UV 的资产完成端到端验收。

```text
图片 URI → 解码后的 RGBA8 → Texture RID → Material 租约
→ Mesh UV + Material 实例 → Granit GPU 镜像与绑定 → 带纹理场景
```

## 非目标

- 完整 PBR、法线/金属度/粗糙度贴图、灯光和阴影。
- glTF 导入、离线资产烘焙器和通用内容构建管线。
- 压缩纹理、Mip 自动生成、纹理数组、Cube、Render Target 和流式加载。
- 通用 Render Graph、GPU 驱动渲染、bindless 和材质节点图。
- 正式游戏 UI、编辑器 Inspector、资产浏览器和缩略图数据库。
- 为实现纹理而直接采用 Granit 完整 Material/Pipeline 高层系统；是否迁移需独立验证。

## 已确认决策

- 纹理资源和后端镜像边界由
  [ADR-010](../decisions/ADR-010-texture-resource-boundary.md) 确认。
- 公共接口只接收已解码像素，不承诺图片文件格式；图片解码位于 VFS Loader 内部。
- Material v1 与 Mesh v1 继续可读；v2 只增加完成 base-color 纹理所需的最小字段。
- 首版 UV 使用归一化二维坐标，base-color 计算为纹理采样值乘以线性 RGBA 因子。
- Texture、Mesh、Material 的 CPU 资源由 Render Service 管理；Granit GPU 镜像留在后端。
- 图片解码器必须先完成许可证、版本、错误语义、内存上限和替代方案 Spike，不能因易接入直接锁定。
- 临时诊断 UI 与调试绘制不阻塞版本，只在纹理闭环稳定后作为 P1 重新评估。

## 待决策事项

### 图片源格式与解码器

M-27 比较小型解码库与系统库，P0 至少需要一种带 Alpha 的常见无损格式。选择必须锁定版本并记录
许可证；解码结果统一为 RGBA8，拒绝尺寸乘法溢出、超限分配和截断输入。

### GPU 上传与镜像时机

优先采用首次可见时按需创建、随后按 Texture RID 缓存的镜像。实施时需验证 Granit 的同步上传、
帧内销毁和设备失败语义；若同步上传会阻塞真实场景，再单独规划异步上传，不在本版本提前引入。

## 实施顺序

### M-26：Texture 契约与资源生命周期

状态：已完成。Texture C11/C++20 契约、RGBA8 与颜色空间、行跨度归一化、资源上限和 RID 生命周期
已经实现，并通过无后端资源测试与 Granit 全量回归测试。

1. 增加 Texture RID、RGBA8 像素格式、线性/sRGB 颜色空间及 C11/C++20 创建销毁接口。
2. 在 Render Service 中复制并校验像素，覆盖类型、代次、跨 Application 和重复销毁。
3. 明确尺寸、行跨度、最大分配、线程和父 Application 失效行为。

验收：无 Granit 后端即可创建、查询内部资源并确定销毁；公共头不包含图片库或 Granit 类型。

### M-27：图片解码 Spike 与 Texture Loader

状态：已完成。解码器 Spike 已由 [ADR-011](../decisions/ADR-011-png-decoder.md) 确认采用 libspng
`0.7.4` 与 miniz `3.1.2`；版本化 Texture 描述、VFS 解码、缓存租约和失败重试已经实现。

1. 比较候选解码器的格式、许可证、体积、错误信息、CMake 接入和畸形输入行为，建立 ADR。
2. 定义版本化 Texture 源描述或明确图片 URI 约定，通过 VFS 解码并创建缓存租约。
3. 覆盖 Alpha、sRGB、截断文件、超限尺寸、失败重试和同 URI 复用。

验收：一个逻辑 URI 可稳定得到 Texture 租约，失败不污染缓存，也不泄漏第三方类型。

### M-28：Mesh/Material v2 与依赖租约

状态：待开始，P0。

1. 为 Mesh v2 增加每顶点 UV，为 Material v2 增加可选 base-color Texture URI 和颜色因子。
2. 保持 v1 严格解析与既有场景兼容；v2 拒绝未知、缺失、非有限或越界字段。
3. Material 租约持有 Texture 租约，失败和卸载按依赖逆序回滚。

验收：v1 资产行为不变，v2 Material 存活期间 Texture RID 有效，卸载后资源计数恢复。

### M-29：Granit 纹理管线与 GPU 镜像

状态：待开始，P0。

1. 扩展着色器、顶点布局、Bind Group Layout、Sampler 和按材质绘制批次。
2. 按 Texture RID 创建并缓存 Granit Texture/View 镜像，处理上传失败和确定销毁。
3. 为无纹理 v1 Material 提供白色默认纹理，保持颜色乘法行为。

验收：同帧可绘制不同纹理材质；无效 RID 返回稳定错误并产生诊断，后端类型不向上泄漏。

### M-30：纹理场景与版本验收

状态：待开始，P0。

1. 增加小型可审查的纹理资产，将交互示例迁移到 Mesh/Material v2。
2. 验证加载、交互、窗口重建、诊断、卸载和退出完整生命周期。
3. 执行 Windows/Linux、共享/静态、Granit 运行时与安装 Consumer 手动矩阵。

验收：干净构建可从场景 URI 显示带纹理对象并交互退出，资源与 GPU 镜像均无生命周期泄漏。

### M-31：工具能力重新评估

状态：待开始，P1，不阻塞 `0.4.0`。

基于已存在的 Texture 和诊断契约，重新评估运行时统计、调试绘制与只读诊断 Overlay；若需要正式
工具宿主、字体管线或编辑能力，则建立独立版本计划，不并入 Render Service。

## 测试与验收

- C11/C++20 公共头独立编译，Texture ABI 布局、所有权和错误语义通过测试。
- Texture RID 覆盖零值、类型错误、generation 失效、跨 Application 和重复销毁。
- 解码与 Loader 覆盖格式、颜色空间、Alpha、畸形输入、上限、缓存和失败回滚。
- Mesh/Material v1/v2、场景原子实例化和资源租约同时保持通过。
- Granit 覆盖上传、采样、默认纹理、多材质、窗口重建和后端失败。
- Windows/Linux、共享/静态、核心、Granit 与安装 Consumer 矩阵通过。

## 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 图片解码扩大依赖和攻击面 | 先做候选 Spike，锁定版本，限制尺寸并测试畸形输入 |
| Material v2 破坏已有资产 | v1/v2 分支严格解析，持续运行 v1 回归测试 |
| GPU 对象侵入资源层 | CPU 资源与 Granit 镜像分离，公共 RID 不暴露后端句柄 |
| 每帧重复上传或创建绑定 | 以 RID 缓存镜像，销毁与失效路径显式测试 |
| 范围扩张为完整 PBR | 只实现 base-color Texture 与颜色因子，其他通道后续独立切片 |

## 版本完成条件

- M-26～M-30 全部完成，M-31 可明确暂缓。
- v1 资产兼容，v2 纹理场景形成加载、渲染、交互、诊断和退出闭环。
- 图片解码依赖与 GPU 镜像均不进入公共 ABI，资源销毁后旧 RID 和镜像失效。

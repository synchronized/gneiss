# M-331：Editor 模态资产替换

2026-10-15，按用户确认的模态交互规则接入资产浏览器“应用到节点”的网格/材质替换。
规则与其他入口迁移顺序见 [开发计划](../plans/DEV-051-architecture-boundaries.md)。

## 已实现

资产已就绪或 URI 不变时直接使用选定租约，不显示加载窗口；缺失资源进入现有任务执行器的
固定版本准备及上传流程。该准备请求不修改现有使用者或默认选择。
进度窗口沿用场景加载的居中布局及阶段进度方式，加载期间主循环只提交进度 UI，
跳过文档编辑、相机、Gizmo、历史和文件监听应用入口。成功后提交节点修改和历史，
再采用对应版本选择。失败或取消保留旧节点和历史，临时租约释放后回收无使用者候选。
上传已开始后取消仍推进到安全终态，丢弃结果，不把无法中断 GPU 上传解释成无法取消编辑。

新内部场景接口捕获实际网格/材质租约，提交时检查服务归属、节点所属场景、原租约与 ECS
预期值；全部验证及作者描述分配成功后才写入。撤销重做持有前后版本租约，不依赖文件内容。
历史执行先预留记录容量，避免资源切换成功后才因历史空间不足进入回滚；零容量拒绝执行。

窗口系统事件仍由 Application 处理。关闭请求取消编辑，完成清理后回到原有未保存/退出流程；
宿主退出时也会清理未完成请求，历史租约先于 Application 销毁。未以窗口交互人工验收替代测试。

## 验证与限制

Windows Clang Debug Editor、相关测试构建通过，定向 CTest 6/6 通过：editor.asset-edit、
editor.scene-loader、editor.command-history、scene-load-builder、core-boundary、core-boundary-negative。
新增迟到回执测试后 editor.asset-edit 再次通过。定向测试覆盖协作和线程池模式下的
准备期间不改文档/历史、重复请求拒绝、成功提交、坏文件后的撤销重做、已采用版本快捷命中、
失败与取消。场景测试覆盖错误类型、非所属线程、旧租约失配和不读文件的来回切换；
历史测试补充零容量不执行；文档关闭后的成功回执不得提交历史或采用新版本。
相关实现执行 clang-tidy，新控制器最终检查未报告自有源码告警；其他文件既有复杂度、
参数类型相似及格式告警仍保留，不宣称整个项目静态检查零告警。

本轮仅接入资产浏览器对已有 Mesh Renderer 节点的替换；新增节点、Prefab、子树恢复、
删除组件的旧历史以及作者文档同步重开尚未迁移。不宣称所有 Editor 操作已异步化。
未完成真实窗口 resize/最小化/关闭的人工验收、完整 Sponza、GPU、跨平台和安装矩阵；
未执行远端操作，也未发布 0.51。

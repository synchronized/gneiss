## 分阶段 trace 诊断

两版分别额外采集一次 `thread initial trace`，只用于定位，不替换上面的正式样本。
摘要与原始 trace 哈希见 [诊断 JSON](artifacts/0.51-native-migration-trace-summary.json)。
候选最长区间约 53.516 ms，其中更新回调 53.497 ms，显式 `sleep_for(1 ms)` 53.457 ms，
场景轮询 0.0021 ms，回调外约 0.0194 ms；另一较长区间包含约 36.636 ms 回调外时间。
重构前也出现等待恢复和回调外间隔：最长区间约 36.264 ms，其中等待 15.399 ms、
回调外 20.857 ms；另一区间等待约 34.459 ms。

本轮尖峰不能由场景轮询工作量解释；墙钟等待可能包含线程失去调度，回调外包含渲染与事件等，
尚不能仅凭 trace 区分系统调度、驱动或其他进程。诊断样本没有复现原正式样本的 71 ms，
因此不能声称所有尖峰已经归因，更不能删除等待以通过既定门槛。

当前进程不是管理员，进一步线程调度 ETW 需要管理员终端协助。下一步采集两版相同
场景的调度事件和栈，核对线程 Waiting/Ready/Running 状态，再决定是否需修改实现或测量口径。
任何门槛调整均须另行确认；当前记录仍为未通过验收。

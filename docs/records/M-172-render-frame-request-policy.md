# M-172：帧请求语义拆分

## 结果

渲染执行器现在明确区分可替换实时帧和必须完成帧。实时帧在队列满载时可以替换最旧的尚未执行实时
帧；必须完成帧不会成为替换目标，也不会为了接纳新帧而被删除。

必须完成帧具有统一序列号和完成回执。Render Service 可以返回序列并单独交付完成结果，供后续拾取、
截图和自动验收调用；容量不足时返回 `not_ready`，调用方决定重试时机。停止流程排空已接纳任务。

## 验证

- 阻塞执行线程并填满单帧队列，验证后续实时帧不能替换待执行的必须完成帧。
- 验证必须完成帧的提交、执行、拒绝计数和完成身份。
- `gneiss.render_executor` 在 Windows Clang Debug 下通过。

## 边界

- 首版不提供执行中取消；已接纳的必须完成帧只能完成或随执行结果失败。
- 超时属于上层请求等待策略，不会暗中取消渲染线程任务。
- 当前 Application 普通显示路径仍只提交可替换实时帧。

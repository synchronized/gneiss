# M-138：IPC v2 信封与请求关联实施记录

## 结果

已建立独立于域内业务负载的 IPC v2 通用信封、编码器和有界增量解码器。当前实现先与 v1 共存，
供后续里程碑逐域迁移；M-142 完成双端组合后删除 v1，不形成兼容承诺。

## 帧格式

帧头固定为 24 字节，所有整数使用网络字节序：

| 偏移 | 宽度 | 字段 |
| --- | --- | --- |
| 0 | 4 | 魔数 `GNI2` |
| 4 | 2 | 协议主版本 |
| 6 | 2 | 协议次版本 |
| 8 | 2 | 协议域 |
| 10 | 2 | 域内操作 |
| 12 | 2 | 消息语义 |
| 14 | 2 | 保留字段，必须为零 |
| 16 | 4 | 请求 ID |
| 20 | 4 | 负载字节数 |

首批域为 Session、Control、Log、Inspection、Statistics 和 Property。事件的请求 ID 必须为零；
请求、响应和错误的请求 ID 必须非零，响应由域处理器复用对应请求 ID。单帧负载上限为 1 MiB。

通用解码层允许非零未知域通过结构校验，M-139 的注册式 Dispatcher 负责产生可诊断的未知域拒绝，
使结构解析与会话策略保持分离。

## 验证

- 验证固定网络字节序布局、分片输入和粘包输入。
- 验证坏魔数、非零保留字段、非法消息语义、零域、零操作、版本错误和超限负载。
- 验证事件及请求/响应的请求 ID 约束。
- 验证结构失败后的粘滞错误和显式重置行为。

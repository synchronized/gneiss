日期：2026-10-05。完成 C 入口位置与调用方向这一子任务，0.45 其余验收继续进行。

## 结果

稳定性清单中的 102 个公共 C 函数全部位于 `src/api/c/`，没有缺项、重复或额外定义。
新增清单检查将定义与现有声明、SDK 审计清单交叉核对；反例覆盖缺失、重复和未登记函数。
内部边界检查扩大到整个 `src`（C 适配目录除外），拒绝 C 导出、拥有型公共 SDK 包含及已迁移的
World/Application/Reflection/Game Context/Asset URI C 调用。

- Game Module 的描述校验留在 C 适配，不创建没有业务职责的内部模块包装。
- Game Context 的身份与线程校验留在 Game 模块，适配仅取非拥有型身份视图；动作和退出在 C
  适配层复用 Application 的参数校验。注册表实现不再调用 Application C API。
- 日志仍允许跨线程，在锁内借用来源文本；普通上下文操作仍限所属线程，违反时保持原有无效句柄结果。
- Asset URI 的指针长度检查移至 C 适配，解析规则继续使用 Asset 的 `string_view` 内部接口。
- Scene/Prefab 的类型 ID、反射注册及属性操作直接调用内部契约；补上 noexcept 调用点的异常转换。
- Game Context、Asset URI 的内部头迁为 `.hpp`；公开头、符号及数据布局不变。

内部没有新增资源状态副本或注册表，Game Context 身份视图不延长 Application、World 或实体寿命。
上下文无效和动作参数无效的校验顺序有显式回归测试。

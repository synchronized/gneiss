# M-331：Prefab 异步放置与历史恢复

日期：2026-10-16。

## 已接入的链路

Editor Asset Browser 的放置入口改用 `editor_prefab_edit`，不再调用同步
`add_prefab_asset`。CPU 准备复用 Scene/Prefab 的有界读取、格式校验、父节点优先排序及
来源复读检查；提交到已有任务执行器，兼容线程池和协作模式。依赖资产优先取得已就绪租约，
缺失部分交给现有固定版本资产准备服务，不在节点构造中同步补读文件。

`prefab_placement` 负责 Application 与 Scene 实例服务的接线。节点在活动 World 的
发布组中隐藏构造，每次最多推进 64 个构造步骤。Editor 镜像先在私有容器中分步准备，
历史空间在场景提交前预留。资源版本采用、组发布、作者记录插入及镜像交换完成后禁止取消；
后续继续分步释放旧镜像，结束时记录历史。整个期间不开放其他编辑操作。

放置命令保留不可变 Prefab 描述、拓扑顺序和实际渲染资产租约。撤销先准备整个实例的退出，
检查其子树没有混入其他发布组的节点，再一次性使该组不可见，逐步释放节点及记录。
重做从命令持有的快照创建新实例，不重读同 URI 的最新文件，不在历史中保留整套隐藏实体。
旧同步实例可逐项加入发布组；结构重载会维护新节点成员及销毁顺序。

## 交互与生命周期

- 放置、撤销和重做期间显示模态进度，暂停编辑、相机操作、保存及历史操作。
- 提交前取消逐步清理候选，保留原场景和历史位置；失败也先完成清理。
- 提交后显示完成清理，不再允许取消；关闭请求等清理结束后继续退出流程。
- 宿主退出时先取消并排空在途操作，再清空历史、关闭 Session、销毁 Application 与执行器。
- 迟到的 CPU 准备结果若发现 Session 已关闭，不得提交；终态释放临时回执和未入历史的命令租约。
- 编辑器视角继续使用独立视口相机；隐藏候选不抢占运行时主相机。

## 本地验证

Windows Clang Debug 下相关目标构建通过。15 项测试通过，包括新 Prefab 编辑集成测试、
CPU 准备、Prefab Runtime、Scene Builder、历史、资产编辑、结构重载、Scene 实例、C++
刷新、World 服务边界、渲染快照、Editor 场景加载和一次 Editor demo 冒烟。

新增集成夹具包含 150 个来源节点及 Mesh/Material 依赖，根位于来源数组末尾，覆盖：

- 线程池和协作模式的异步放置、重复请求拒绝、隐藏构造与构造中途取消。
- 撤销和重做提交前取消，历史位置不变；成功后镜像数量与实例 UUID 正确。
- 原始 Prefab、Mesh、Material 文件被破坏后仍可重做。
- 缺失依赖、非法来源和 Session 关闭后的迟到结果不修改场景或历史。
- 提交后取消不反向回滚，继续推进至资源清理终态。

新增三个实现文件的 clang-tidy 检查通过，无告警。格式检查与 `git diff --check` 通过。

## 验证边界

本项完成的是 Asset Browser 放置及其撤销/重做闭环。独立删除、手动刷新等既有 Prefab
命令不因此自动成为异步事务；同步底层入口仍保留。Prefab v1 仍要求单根，不支持嵌套实例。
发布后通用业务通知尚无实际接收者，本项不新增插件信号总线。

64 步是数量预算，不是毫秒上限；容器分配、描述复制、发布验证和来源快照最终析构仍可能
与数据规模相关。协作模式的单次 JSON 解析也不可抢占。本轮夹具不是大型场景性能验收，
未运行 Linux、静态安装消费者、完整 Sponza，未自动验证真实操作系统的最小化/关闭输入。
0.51 的完整发布验收及共享资产所有权迁移仍按开发计划继续。

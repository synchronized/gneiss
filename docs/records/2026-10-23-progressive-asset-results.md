# 普通渲染请求逐项生效与更新顺序

日期：2026-10-23。

## 实施范围

普通加载在每次成功上传回执后逐项填充稳定 RID，不再等待全部上传完成才生效。
后续失败或取消只清理未生效数据；已经成功的资源继续可用。
回执增加逐项结果，包含显式请求及已发现依赖；失败/取消仍报告已成功项。
结果元数据不持有资源，未生效项的错误表示停止处理的原因，不代表已有内容失效。

普通请求不再以全局缓存 revision 拒绝更新，改由每资源的最新请求序号阻止过期完成。
序号在任务被执行器接受后登记，提交失败不会取代旧任务；迟发现的依赖也不能覆盖较新的请求。
不同资源互不使对方失效。新请求失败时保留当前成功内容，不恢复过期任务。

## 验收

覆盖协作与线程池下的部分生效后取消、未生效数据清理、逐项结果，以及无关资源更新、
旧任务在准备前/上传后被新请求取代。沿用失败保旧、预算等待、销毁迟到和像素测试。
Windows Clang Debug 完整构建及 201/201 回归通过；静态检查发现的新增窄化转换与嵌套条件
已修正，修正后定向重建及加载服务测试 1/1 通过。格式与差异检查通过。
clang-tidy 仍报告既有大函数复杂度等告警；本组没有跨平台/静态库矩阵或场景早激活验收。

## 剩余边界

固定版本路径仍服务场景和编辑器，尚未删除。CPU 准备仍以批次为单位，准备错误会结束本批；
后续上传错误也会停止剩余项，不表示已具备独立失败后继续处理所有资源的完整调度。
逐项结果尚未贯通 Runtime IPC 和编辑器显示。来源/配置身份隔离、场景早激活、历史消费者迁移
及旧协议整体删除按[重建计划](../plans/PLAN-051-progressive-render-assets.md)继续完成。

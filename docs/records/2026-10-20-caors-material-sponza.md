# CAORS 材质文档：Sponza 首次异步加载对照

## 结论

2026-10-20，本机 Release 日常 Sponza 对照完成。各组有效样本 3 次；开启 CAORS 的加载中位数
为 61.953 秒，关闭为 61.669 秒（相对差 +0.46%）。
进程峰值工作集中位数分别为 1368.44 MiB 和
1368.10 MiB。样本不足以认定性能改善或回退；未见明显整场景内存收益。
7 次加载均成功、节点数均为 553，固定相机 GPU 回读图逐字节一致；已目视确认不是空场景。
继续保持材质开关默认关闭，不以本次数据宣称加载加速、渲染优化或交互卡顿解决。

## 方法与输入

提交 `901838cc061adf06926efb33f404482c8c46e729`；Windows 10、i5-8600K、约 32 GiB RAM、UHD 630、驱动 31.0.101.2140，
Clang 23.1.1，Release，Granit 平台开启、CAORS 输入和 profiling 关闭。两组只改变
GNEISS_ENABLE_CAORS_MATERIAL；使用同一个构建目录依次构建并保存各组 bin 目录，分别加载各自 DLL。
没有并发编译或其他基准进程；不控制其他桌面任务，不清空操作系统文件缓存，不能称为冷启动。
第 1 次开启组与资产身份清单校验短暂重叠，仅保留为预热记录，不参与统计，补跑第 7 次。
有效顺序为 off、off、on、on、off、on；不是随机化或统计显著性试验。

输入为本机 `D:/sunday/workspace/asset-cache/intel-sponza/0.43-daily-assets-2`，身份见
[原始数据](artifacts/0.51-caors-material-sponza.json)。场景有 553 节点、405 渲染对象、28 个唯一材质 URI，
材质文档合计 26,846 字节，最大 982 字节；这些是输入清单计数，不是运行时文档对象或堆分配计数。
固定版本渲染缓存原本就共享相同材质产物，不能把 405 个使用者当成原先存在 405 份文档的证据。
资产来源及许可沿用 [Sponza 基线](M-272-sponza-baseline.md)，本记录不重新分发场景。

基准为现有 gneiss_scene_load_baseline，参数：

```powershell
<on或off目录>/gneiss_scene_load_baseline.exe <资产目录> <唯一输出前缀> thread initial
```

每次独立进程、真实异步场景加载、隐藏窗口与 GPU 回读。测量的是引擎场景加载入口，
不是完整 Editor UI 启动或人工相机操作；不能推断编辑器稳定帧率。
本地原始日志、CSV、PPM、二进制快照及完整资产哈希清单位于 `build/caors-material-comparison/`。
归档 JSON 保存命令、引擎/可执行文件哈希、资产清单摘要及完整基准报告。生成文件和第三方资产不提交。

峰值工作集来自基准进程完整生存期的系统峰值，包含渲染、驱动及截图阶段，不是单独 CAORS 堆内存，

主循环间隔包含等待和调度；后台准备累计耗时不是纯 CPU 执行时间，不与各阶段指标简单相加。

## 范围与后续

当前实现仍逐批读取、解析和复验，之后才共享不可变 CPU 文档。本场景材质输入总量很小，
端到端差值容易被纹理、网格、帧推进、系统调度等成本掩盖，不能据此评估大量重复材质重载的收益。
未测完整 4096 配置、重复重载/多场景并存的文档保留量、独立显存、Linux 或其他硬件。
若继续研究共享收益，应单独测跨批次文档复用及释放；若研究约一分钟的总加载耗时，应另做
阶段时间线排查，不能预设瓶颈就在 CAORS。接入范围见[共享材质计划](../plans/PLAN-051-caors-shared-material.md)。

# M-250～M-255：0.39.0 任务调度与资产服务验收

## 状态

2026-09-25，验收进行中；尚未发布。实现及测试范围见
[VER-039](../plans/VER-039-0.39.0-task-scheduling.md)。

## 正确性覆盖

- 1、2、4 个工作线程下验证依赖分叉/汇合；未满足依赖不占工作槽。
- 非法及跨调度器句柄、未消费结果容量、延迟取消、异常传播、普通/后台公平性和独立作用域关闭。
- 串行任务不重叠；取消中间项也不能让后项越过仍在运行的前项。无显式依赖时前项失败不阻断后项。
- Import Service 复用池线程执行有限批次；保留 0.38 的提交许可、回滚、过期源重排及导出暂停回归。
- 作者文件后台分批检查，消费时再判断脏文档；测试自身保存使旧回执失效、保存后外部修改不被吞掉、
  删除重建、多文件补查、路径越界及关闭后其他服务仍可提交。
- 主线程保存将已序列化字节移交后台计算基线，不重新读取磁盘确认自身保存。
- 原生窗口回归继续覆盖受阻导入期间的相机、resize、最小化恢复及合成 DPI/坐标一致性。

## 实际资产响应性

手动基准使用仓库 Lantern GLB（9,564,264 字节，实际几何及内嵌 2048×2048 PNG）和 64 个作者
Prefab 文件。模型来源、SHA-256 和 CC0 许可见
[示例资产来源](../../examples/lantern_gallery/assets/ASSET_ORIGINS.md)；Prefab 使用项目原创 MIT 测试数据。
基准先导入及建立基线，再同时后台重导入 GLB 和补查 64 个发生变化的 Prefab；每份回执都在主线程
重新加载引用这 64 个 Prefab 的场景，保留实际应用成本。

```powershell
./build/windows-clang-debug/bin/gneiss_editor_task_response_benchmark.exe ./build/0.39-real-debug examples/lantern_gallery/assets/source/Lantern.glb
./build/windows-clang-release/bin/gneiss_editor_task_response_benchmark.exe ./build/0.39-real-release examples/lantern_gallery/assets/source/Lantern.glb
```

输出目录必须尚不存在。`max_poll_ms` 是两服务回执及状态消费耗时；`max_apply_ms` 是单次场景重载，
`max_loop_interval_ms` 包含同批多次应用和 1 ms 主动等待，不是渲染帧时统计。基准不显示窗口，
不能把其结果当作真实全帧或复杂模型通用性能保证。

| 构建 | 初始导入 ms | 基线扫描 ms | 后台与应用总耗时 ms | 最大消费 ms | 最大单次应用 ms | 最大循环间隔 ms | 保留任务峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Windows Clang Debug | 186.918 | 220.255 | 861.946 | 2.689 | 12.807 | 79.013 | 2 |

以上为单轮观测；Debug 与 Release 分开记录，不能作为统计分位数或硬实时阈值。
Windows Debug 调试堆争用限制仍适用，原理及上一版对照见
[0.38 记录](M-246-249-0.38.0-validation.md)。

## 发布验证

Windows Clang Shared Debug 完整测试 149/149 通过，123.39 秒；随后调度器析构契约和
任务批次容量预分配调整后，调度及作者服务两项针对性回归再次通过。静态库、Release 和远端矩阵待归档。

## 保留边界

本版提供内部 C++ 调度模块，不新增安装公共 ABI，不迁移渲染或 libuv 专用执行器。
长解析不能抢占，单个大作者文件哈希在文件边界响应关闭；Scene/ECS 加载与应用仍可能阻塞主线程。
检查快照不提供跨进程文件锁或事务读隔离；外部 glTF 依赖哈希、断电恢复、物理跨屏 DPI 和 SDL3
切换不属于本版。发布方式沿用源码标签和 GitHub Release，不附预构建 SDK。

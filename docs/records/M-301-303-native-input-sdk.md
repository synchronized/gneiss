# M-301 / M-303：原生输入 SDK 与迁移门禁

2026-10-06，0.47 开发分支的首组实现。整版未完成，范围以
[VER-047](../plans/VER-047-0.47.0-native-cpp-sdk.md) 为准。

## 交付

原清单的 reviewed 表示既有包装审查，不能证明原生类型完成。102 个函数、96 个类型与 281 个
常量现在分别记录 native_review；本组确认 6 个输入函数和 10 个输入类型的原生映射，其余项
保持 pending，等待逐项复核，不据此认定既有 Core 包装缺失。
常量记录目标映射或 ABI 例外理由；严格模式拒绝待办，负向测试覆盖非法状态、空映射、C 别名
误标与发布门禁。此门禁是显式检查命令，尚非已执行的整版发布矩阵。

输入 SDK 采用独立枚举、标志和值快照，事件负载改为 variant，文本使用自有固定容量数组。
转换逐字段执行，不重解释 C 布局，不动态分配，不持有运行时资源。普通查询不再填写结构尺寸。
删除裸 action 别名及对应自由函数重载；Application、Game Context、三个示例和安装消费者同步接入。
调用与迁移细节以[输入参考](../reference/input.md)为准。

原 C++ 头测试中的“与 C 结构同尺寸、标准布局”断言不再适用，改为独立类型和无异常复制断言；
C 头独立编译与 ABI 消费者测试保留。C 宏仅将位移量改为无符号字面量，值、结构与导出不变。
四个需保留未知 32 位值的枚举局部说明 enum-size 检查例外，不缩窄协议数据以消除提示。

## 验证

环境：Windows、Clang 23.1.1、C++20/C11，开发构建保留 warnings-as-errors。

| 检查 | 结果 |
| --- | --- |
| windows-clang-debug 全量构建 | 通过，包含 Editor、Runtime、示例与公共头 |
| 相关 C++、输入、Game Context 及清单测试 | 19 项通过；其中负向门禁修复后单独复验 |
| 静态库相关构建、C11/C++20 公共头 | 通过 |
| 静态库输入与 Game Context 回归 | 3/3 通过 |
| 干净共享/静态安装消费者（C、C++、属性检查） | 各 3/3 通过 |
| API 稳定清单及 0.9/1.0 ABI 消费者 | 3/3 通过 |
| 输入测试及 input.hpp clang-tidy、改动源码格式 | 通过 |

最初全量编译发现三个示例残留裸动作调用，迁移后通过。安装消费者最初缺少 Granit package
路径，明确指定已有 Granit 安装前缀和本次 Gneiss 前缀后通过。严格门禁的中文错误匹配在 Windows
遇到子进程编码误读，execute_process 指定 UTF-8 后复验通过；没有绕过失败或降低检查等级。

# M-284～M-285：0.43.0 PBR 与发布验收

## 状态与环境

Granit 修复已接入，候选 `1d683e0`（Granit v0.43.0）最终门禁已通过，2026-09-30 已发布 [0.43.0](../versions/0.43.0.md)。
前序功能候选 `7d3d08d`、诊断提交 `360c5ac` 基于 Granit v0.42.0，历史结果保留如下；PR #58。
本地为 Windows Clang / Intel UHD 630，资产身份与硬件沿用
[M-272](M-272-sponza-baseline.md)。原始资产不随源码分发。

## 正确性与修复

五槽材质、Mip、切线、UV1、顶点色、采样器与透明层次的接入证据见
[M-283](M-283-granit-0.42-material-states.md)。本轮增加 MASK 阴影整帧比较：透明 MASK 与
不投影的零 Alpha BLEND 一致；不透明 MASK 与 OPAQUE 一致，并与透明结果不同。
这覆盖遮罩对阴影的影响，不承诺所有双面投影语义。

候选累计驻留原先漏计切线、UV1 和颜色，现与单批准备共用字节计算；v3 网格测试验证这些属性全部计入。
PNG 超出候选剩余预算返回 OUT_OF_MEMORY，不再误报格式/尺寸错误。1×1 RGBA 输入分别验证
3 字节预算拒绝、4 字节成功；真正损坏格式仍返回 INVALID_ARGUMENT。

Release 完整 CTest 162/162（87.25 s）；最终 Debug 导入、PNG、场景候选和 GPU 专项 4/4（13.27 s）。
共享/静态 Debug 前序完整回归见 M-283。配置的 clang-tidy 已运行并修复本版相关建议；
既有大函数的复杂度等提示仍存在，不将本次静态检查描述为零告警。

首轮远端暴露两处可移植性问题：旧布局测试的类型别名违规，以及大型 Shader 的
std::to_array 常量求值超过 GCC 限额（MSVC 同位置发生编译器栈溢出）。改用真实描述对象验证
旧大小忽略非法尾部，以及直接初始化静态字节数组，保留警告与 Sanitizer 检查。

## 真实场景方法与边界

另建 `0.43-daily-assets-2` 与 `0.43-full-assets`，未覆盖 0.42 基线。两配置均保留
405 个 Mesh、553 个节点、28 个材质和 72 张贴图；只对日常配置缩小纹理分辨率。
72 张贴图包括 25 张基础颜色、24 张 MR 和 23 张法线；原场景未使用的槽由原创夹具验证。
导入修复一个退化切线 Primitive 和一处一 ULP 自发光越界，均保留诊断。

每个首载样本独立进程，不清文件缓存，不称为冷盘。峰值 RSS 包括驱动映射，不是独立显存。
候选资源字节只计有效数组，不包含容器 capacity、GPU 镜像等全部内存。
日常回读用于确认真实场景可呈现，不作为可信参考图误差验收或完整原作外观还原。

Release 首载三次分别为 20.62、20.30、20.39 s，事件间隔 P95 最大 16.48 ms、最大间隔 40.96 ms；
激活最大 0.212 ms。候选资源 464,453,832 B，505 个 RID，峰值 RSS 约 1.334 GiB。
0.42 同机日常 Release 加载中位数 14.91 s、候选约 215 MB；本版保留更多属性与材质依赖，
总加载与内存上升，不能宣传成加载加速。M-283 的旧候选字节漏计扩展属性，已由本轮数据替代。

Debug 日常线程池三次为 84.92、84.46、84.47 s；事件 P95 最大 16.31 ms、最大间隔 80.93 ms，
激活最大 1.041 ms，峰值 RSS 约 1.348 GiB。均满足既定线程池响应与激活门限。

Release 协作模式一次为 16.88 s，事件 P95 124.73 ms、最大 1960.09 ms。
单次解析、哈希、解码不可抢占，未达到线程池响应门限，不能称为流畅的大场景加载方案。

### MASK 崩溃定位

阶段日志定位至首个 MASK（Alpha 0.25、cutoff 0.5、UV1/Color 变体），GDB 显示 Lavapipe
工作线程段错误，Gneiss 与 Granit 提交线程在等待 GPU。随后在 Windows Intel UHD 630 上
强制启用 Vulkan SDK 1.4.321.1 的校验层，得到两个确定的非法 Vulkan 用法：

- `VUID-VkGraphicsPipelineCreateInfo-layout-07988`：阴影顶点 Shader 读取 Set 1 / Binding 0
  的材质常量（uv1_mask），但 Granit 材质布局只声明 FRAGMENT 可见。
- `VUID-VkShaderModuleCreateInfo-pCode-08740`：标准 Shader 声明 DemoteToHelperInvocation，
  Vulkan 设备没有启用相应特性。

单独 `--probe-mask` 复现三个 08740 和一个 07988；Windows 图像和进程退出仍成功，
所以此前“像素通过”不能代替合法性校验。原始输出见
[校验日志](artifacts/0.43-mask-vulkan-validation.log)。尚未修改上游或通过 A/B 修复证明
某一问题是 Linux 崩溃的唯一原因，不把所有软件驱动问题归于这一处。

修复范围、上游源码位置、复现步骤和验收已整理为
[U43-06/07](../plans/UPSTREAM-043-granit-pbr.md#u43-06mask-阴影顶点阶段的材质常量可见性)。
按跨仓库规则由用户提交 Granit；Gneiss 未分叉 Shader、屏蔽 MASK 或减少图像断言。
0.43 保持未发布，待上游修复后升级固定依赖，验证无上述 VUID 并通过 Linux 门禁。

Windows 托管 Runner 无 Vulkan ICD，GPU 验收由本地和 Linux 窗口测试承担。
矩阵覆盖共享/静态、安装 C/C++ 消费者、Sanitizer 和最小 Web 调度；最小 Web 不是完整 PBR 浏览器验收。
JPEG、KHR 灯光、相交透明几何/OIT、双面阴影完整语义、独立显存和物理跨屏 DPI 不在本版通过声明内。

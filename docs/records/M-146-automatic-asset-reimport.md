# M-146：自动重新导入队列实施记录

## 结果

Editor 资产模块新增主线程驱动的 `asset_reimport_queue`，并将 M-145 的文件候选事件接入编辑器
帧循环。重复路径会合并并重置 250 ms 防抖期限；防抖结束后，内容哈希必须在间隔 100 ms 的两次
读取中保持一致，才允许进入现有事务式重新导入流程。

队列按规范化源相对路径去重，同一源资产不会并发导入；每帧默认最多执行一次同步导入。队列与
结果流均有容量上限，候选溢出会被统计并返回 `not_ready`。哈希未变化、未跟踪源文件、删除、导入
成功和失败均产生独立状态；失败继续保留既有索引和派生产物。`restart_required` 状态已作为后续
不支持热替换时的结果语义预留，但本里程碑不会主动产生该状态。

## 边界

- 仅自动重新导入已经存在于资产索引中的 glTF/GLB；新源文件仍由用户显式导入。
- 导入仍在 Editor 主线程同步执行，首版通过每帧预算控制工作量，不引入通用任务系统。
- 本里程碑不通知 Runtime，也不承诺资源已在运行进程中替换；该闭环由 M-147 至 M-150 完成。

## 验证

- Windows Clang Shared Debug：资产队列、导入、浏览器、文件监听及 Editor smoke 测试通过。
- Windows Clang Static Debug：相同 5 项测试通过。
- 专项测试覆盖无效路径、防抖合并、稳定读取、无变化过滤、真实重新导入、未跟踪文件、删除和
  有界队列溢出。

Linux 文件监听与完整端到端行为仍按 M-150 统一验收。

# M-295：CPU 准备与资源发布分开编译

日期：2026-10-05。按 ADR-054 继续收窄资产准备与渲染服务之间的依赖。

## 实施结果

- `render_asset_preparation.hpp/.cpp` 独立承载批次准备、纹理准备与源版本复验；不包含加载器、
  缓存或 RID 服务。准备函数体仅移动与格式化，不改变预算、取消、输入快照或设备变体选择。
- `render_asset_parsing.hpp` 是同步加载与后台准备共用的私有解析契约，避免复制格式解析实现。
- `render_resource_data.hpp` 集中既有资源值类型；资源服务持有 RID 表，加载器负责缓存租约、
  候选和发布。值类型本身不拥有服务实例。
- 修正调用方依赖间接头文件的问题，各自显式包含资源服务声明。
- 新增独立 CPU 准备测试目标，只链接基础值头、解析/解码依赖、Granit Core 与线程库，
  不链接 Gneiss Engine、资源缓存或资源服务实现。覆盖后台成功准备、VFS 退出后的数据所有权、
  取消、预算拒绝、源变化、缺失来源与失败清空输出。
- 边界检查增加准备代码反向包含加载器、资源服务、缓存和 RID 表的拒绝反例。

## 限制

准备数据仍复用 Render 的材质结构，结构中保留尚未解析为资源的纹理 RID 字段，准备阶段填零；
本轮没有宣称数据契约完全独立于 Render，也没有将这些类型直接下沉 Asset。
后续要拆分材质参数与纹理依赖引用，再在发布边界绑定 RID；不得复制一套运行时资源状态。
公共 C/C++ SDK、资源布局、上传回执和缓存事务行为保持原有契约。

## 验证

- Windows Clang Debug 共享配置全量构建成功；完整 CTest 175/175 通过，182.87 秒。
- Windows Clang Debug 静态配置全量构建成功；准备、发布、纹理加载、场景加载、像素、
  安装后 consumer 与边界相关测试 13/13 通过，30.78 秒。
- 独立准备测试的 Ninja 链接输入不含 Engine、缓存、资源服务或加载器实现。
- 修改文档的 339 个相对链接校验通过；`git diff --check` 通过。
- 新增测试经过 `clang-tidy` 修正并复查，无自有代码告警。搬移的解析代码仍报告复杂度、
  相邻同类型参数和格式等建议，本轮保留算法；未将该文件记为零告警通过。

未运行远端 Actions、Linux/macOS、Emscripten 或外部大型场景；本记录不是完整发布验收。

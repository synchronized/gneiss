# M-322：资产 libuv I/O 迁移记录

## 状态

2026-10-13，进行中。已完成平台同步读取基础层，尚未切换资产生产路径。
范围与后续步骤以 [DEV-050](../plans/DEV-050-main-loop-latency.md) 为准。

## 已实现

在现有 `gneiss_io_uv` 内增加 `uv_file_reader`，通过 uv_fs_open/fstat/read/close
实现 UTF-8 路径打开、已打开对象长度、精确偏移读取和 RAII 关闭。接口不暴露 libuv 类型，
不启动 loop 或线程；这是明确可阻塞的同步入口，不称作异步完成。

读取按实际字节数推进，短读继续、提前 EOF 报错，范围按打开时长度校验；并发调用序列化。
打开失败清空输出；文件重命名、删除和同路径替换后仍指向原打开对象。

## 验证

- Windows Clang Release 新增文件测试通过，覆盖中文路径、空文件、缺失文件、目录、
  内嵌零字符、越界、并发区间读取、文件替换/删除和截断后短读。
- libuv 文件、执行器、压力及结果映射测试合计 4/4 通过。
- 新实现 clang-tidy 无告警；修正参数可互换和整数比较告警后重建并复测文件测试通过。
- 格式和差异检查通过。未进行 Linux、安装消费者或性能对照，未改依赖版本与公共 ABI。

## 未完成

资产 native_file_system 尚未接入新基础层；Windows OVERLAPPED 路径仍然保留。
异步打开/路径校验、完成回执、取消与关闭回收、请求/字节背压尚待实现。
还需解决核心 Engine 独立构建的 libuv 私有依赖、静态安装包与无线程构建选择。
当前基础层不能作为卡顿修复或跨平台迁移完成的证据，不改变 M-321 发布阻塞状态。

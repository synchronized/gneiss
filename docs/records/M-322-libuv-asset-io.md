# M-322：资产 libuv I/O 迁移记录

## 状态

2026-10-13，进行中。已完成平台同步读取基础层，并接入桌面线程构建的资产整文件/有界读取。
异步区间和打开阶段尚未切换，不代表迁移完成。
范围与后续步骤以 [DEV-050](../plans/DEV-050-main-loop-latency.md) 为准。

## 已实现

在现有 `gneiss_io_uv` 内增加 `uv_file_reader`，通过 uv_fs_open/fstat/read/close
实现 UTF-8 路径打开、已打开对象长度、精确偏移读取和 RAII 关闭。接口不暴露 libuv 类型，
不启动 loop 或线程；这是明确可阻塞的同步入口，不称作异步完成。

读取按实际字节数推进，短读继续、提前 EOF 报错，范围按打开时长度校验；并发调用序列化。
打开失败清空输出；文件重命名、删除和同路径替换后仍指向原打开对象。

## 异步打开契约与来源复验推进

新增内部 `open_read_operation` 与 `begin_open_read_for_validation`。提交接口不得同步
查询路径或打开文件，poll 仅接收结果，成功只交付一次来源；不支持的后端明确返回
UNSUPPORTED，由调用方选择同步回退。请求须独立持有在途状态，销毁不等待 I/O。
这是对后端的契约要求，当前原生后端尚未实现该异步入口。

VFS 按最长挂载点路由，版本包装保留共享账本而不捕获包装对象指针；来源交付后仍须
complete_validation 登记摘要。来源复验游标可保留打开请求，NOT_READY 时结束当步，
取消/失败释放请求且保持粘滞终态。只有提交阶段明确 UNSUPPORTED 才允许同步回退；
已接受请求的完成失败不能转成同步整文件读取。

确定性后端覆盖未完成、成功单次交付、失败粘滞、版本冲突、取消/迟到完成、挂载/包装销毁、
URI 越界、最长挂载、不支持回退，以及轮询不读取内容。Windows Release 读取来源、来源
复验与资产准备回归 3/3 通过；增加完成失败禁止回退断言后来源复验复测通过。
本阶段尚未接 libuv 异步提交和资产准备的异步打开状态，也未移除 Windows OVERLAPPED。
没有进行新的实景性能采样或宣称卡顿修复；Linux 与最终平台矩阵仍待完成。
`source_revision_file_system.cpp` 的新增复杂度提示经拆分处理后消除，clang-tidy 无告警；格式与差异检查通过。

## 资产准备接入延迟打开

资产准备的描述与 payload 读取现在优先提交异步打开；打开尚未完成时结束当前推进步，
不读取内容或分配整文件缓冲。完成后再检查字节上限，完成失败不会退回同步读取。
短 Mesh 预取最多保留八个打开请求；旧后端仍沿用明确的同步打开回退。
取消清理同时释放当前打开和预取请求，候选依旧在全部来源复验通过后发布。

确定性后端验证等待、取消释放、重试成功、打开失败和长度越界，且支持异步打开时同步
打开计数为零。Windows Release 来源、复验、准备测试 3/3 通过，新增失败/越界用例后
准备测试再次通过。clang-tidy 完成，新增代码无诊断；文件其他既有区域仍报告纹理解析
复杂度、尾逗号和条件写法等告警，未关闭检查或进行无关重构。格式与差异检查通过。

此处接通的是消费端状态机；原生后端仍返回不支持异步打开，libuv 异步请求及关闭的
生命周期管理尚待实现，不能据此宣称生产主线程已经消除文件打开阻塞。

## libuv 异步路径解析基础

平台层新增 `uv_path_resolver`，通过现有 I/O loop 提交 `uv_fs_realpath`。提交与轮询均不
同步查询磁盘；结果使用 UTF-8，成功仅交付一次，失败保持结果码。解析器不启动线程，
执行器由外部宿主管理；已提交请求及回执不借用解析器或执行器对象。

并发上限同时计算排队与在途请求。调用方销毁请求仅放弃回执，不等待 I/O，也不提前
归还在途容量；完成回调清理 libuv 请求并释放容量。显式停止执行器仍具有排空等待语义，
应留在宿主关闭阶段，不能由每个资产请求触发。解析器只解析路径，资产根目录隔离判定
仍须由资产层完成。

Windows Release 平台 I/O 回归 5/5 通过，覆盖中文路径、未启动执行器、非法路径、容量
耗尽、取消后容量保持、停止排空、解析器销毁、晚取结果和缺失文件。新增代码的静态
检查告警已修正。实际资产打开链尚未接入此能力；本次未验证 Linux、符号链接隔离或
实景响应门槛，也没有消除已有 Windows 文件读取实现。

## 异步文件后端与 Application 接入

新增通用 libuv 文件后端，实际使用回调式 open/fstat/read/close。读取持有同一打开对象，
不按区间重新打开路径；处理短读、EOF、越界及部分完成，提供轮询和仅供工作线程使用的
有限等待。显式同步 read_at 保留调用方缓冲，不把同步方法描述为无阻塞。

请求数量与读取缓冲共同限额，完成回执在销毁前仍计入容量。取消仅丢弃观察者；在途对象
保留至回调结束，最后一次使用后通过文件自己的通知句柄关闭。常规析构不执行文件 I/O。
异步关闭提交失败时只在 I/O loop 上同步关闭兜底；尚未对低内存提交失败做故障注入。

原生资产后端接入异步路径解析，随后用词法相对路径检查隔离，再异步打开文件。来源、读取
请求独立于 VFS 生存。Application 在线程池模式下注入执行器，先释放服务/场景再停机；
协作模式及无线程构建不启动该后端。标准流/旧 Windows 路径仍保留给未注入的同步后端，
尚未满足删除旧实现的跨平台验收条件。

# M-322：资产 libuv I/O 迁移记录

## 状态

2026-10-13，进行中。已完成平台同步读取基础层，并接入桌面线程构建的资产整文件/有界读取。
异步区间和打开阶段尚未切换，不代表迁移完成。
范围与后续步骤以 [DEV-050](../plans/DEV-050-main-loop-latency.md) 为准。

## 已实现

在现有 `gneiss_io_uv` 内增加 `uv_file_reader`，通过 uv_fs_open/fstat/read/close
实现 UTF-8 路径打开、已打开对象长度、精确偏移读取和 RAII 关闭。接口不暴露 libuv 类型，
不启动 loop 或线程；这是明确可阻塞的同步入口，不称作异步完成。

读取按实际字节数推进，短读继续、提前 EOF 报错，范围按打开时长度校验；并发调用序列化。
打开失败清空输出；文件重命名、删除和同路径替换后仍指向原打开对象。

## 同步资产入口接入

`read/read_bounded` 保留 URI 与根目录隔离检查，使用 libuv 来源读取并在结束时
复查已打开对象长度，避免旧实现从另一条路径查询长度。分配前仍检查调用者字节上限。
同步入口继续具有阻塞语义，canonical 等路径操作尚未迁移；不把此改动称作主线程修复。

核心原生线程构建新增私有 libuv 对象链接，复用锁定的 1.52.1 源码、编译配置和系统库。
静态安装包包含对象，不导出第三方 CMake 目标或头文件；系统链接库保留在 link-only 闭包。
第三方许可证声明同步补齐。无线程/Web 核心不解析此依赖，继续原有文件回退。

接入后的 Windows Release 资产来源、资源服务及平台 I/O 回归 6/6 通过。
核心静态、共享安装包及独立 C11/C++20/示例消费者各 4/4 通过；无线程核心构建通过，
该配置没有引入 libuv 文件后端。检查静态导出未出现 uv_a、gneiss_libuv 或 _deps 路径。
第三方源码保留上游编译告警，未通过抑制改变检查等级。
Linux 与完整大资产性能尚未验证，后续异步迁移完成后仍需按原冻结门槛复测。

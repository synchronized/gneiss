# M-160：Editor 冲突与状态反馈

## 结果

Editor 现在分别监视工程 `sources/` 与作者 `assets/`。前者继续进入防抖、内容校验和自动重新导入；
后者只处理 Scene 与 Prefab，并以文件内容指纹过滤重复通知和 Editor 自身保存产生的事件。

- 保存 Scene 后立即建立新内容基线，并把对应结构修订发布给 Runtime。
- 外部修改当前 Scene 或其引用的 Prefab 时，干净文档会重新打开并清空已经失效的撤销历史，然后发布
  结构修订。
- 当前场景含未保存修改时，相关外部变化进入冲突状态，不覆盖内存文档，也不向 Runtime 发布尚未
  接受的磁盘内容。
- 无关 Scene/Prefab 不影响当前文档状态，但仍作为结构修订发布；Runtime 可按现有规则安全无操作。
- Asset Browser 同时展示作者资产应用或冲突状态，以及 Runtime 的等待、应用、失败和需要重启状态。

删除、不可读或解析失败的结构文件保持原 Editor 场景，并展示失败状态；文件内容不会被错误地记作
已接受基线，后续变化仍可重新尝试。

## 验证

- 作者资产监视测试覆盖自身内容去重、未保存冲突、接受外部变化、无关文件忽略和删除失败。
- Editor、Runtime 进程、文件监听及作者资产监视定向构建与测试通过。

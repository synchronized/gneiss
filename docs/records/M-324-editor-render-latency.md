# M-324：Editor 完整场景持续渲染与排队延迟

2026-10-13，用户反馈 Release 在 Sponza 加载完成后转动相机仍卡顿。本轮使用实际 Editor，
Windows Clang Release、Intel UHD Graphics 630、1280×720、同一 `0.44-full-cooked` 资产根。
原三帧冒烟只能验证有限生命周期，不能代表持续交互流畅。

## 采样与结果

增加 `--smoke-frames 3000`：成功激活后继续运行 3000 个主循环，每 120 轮及首尾读取既有
渲染统计。实际显示帧数与主循环数分开，GPU 统计取异步最近回执。命令见
[Editor 指南](../guides/editor-interaction.md#启动与打开场景)。

| 指标 | 修改前 | 一帧等待上限 |
| --- | ---: | ---: |
| 激活后采样时长 | 35.875 s | 34.216 s |
| 显示帧数 | 495 | 538 |
| 平均显示 FPS | 13.80 | 15.72 |
| 排队等待采样中位数 | 204.594 ms | 61.230 ms |
| 排队等待采样范围 | 183.715～278.679 ms | 41.052～98.581 ms |
| GPU 总耗时采样中位数 | 38.134 ms | 37.088 ms |
| 阴影 GPU 采样中位数 | 16.185 ms | 16.043 ms |

完整计数与采样值以 [JSON 证据](artifacts/0.50-editor-render-latency.json) 为准；表中 GPU 子阶段
不可与总耗时重复相加。两次均接收 553 个节点并退出 0，stderr 为空。固定默认相机，未自动回放
鼠标操作；排队等待不是输入到显示的端到端延迟。每轮只有 25 个周期采样点，表中中位数不代表
所有帧分布。单次顺序对照且没有隔离系统后台负载，不据此承诺稳定的 FPS 提升幅度。

## 修复范围

Granit 渲染适配器的普通交互帧准入从允许三份等待快照改为最多一份，与正在执行的帧重叠。
队列满时继续处理输入，下一次空位出现后捕获最新相机状态；未改变 Required 帧的可靠性契约，
也未修改 Granit、分辨率、阴影质量或资产。保留底层执行器原有队列与替换能力。

渲染执行器、帧包、Scene Load Application、Editor Scene Loader 共 4 项本地回归通过；
最终 Editor Demo 120 轮冒烟退出 0。新参数拒绝零帧（退出 64），最终构建通过。
本次没有重新运行远端矩阵或宣称 0.50 已可发布。

## 剩余问题

15.7 FPS 仍不满足流畅视角操作。GPU 单帧约 37 ms，阴影与不透明绘制占主要 GPU 时间；
实际显示间隔约 64 ms，尚不能只归因于 GPU，下一步应拆分已有的渲染线程资源准备、命令录制、
acquire/present 等计时。主循环基线还记录到约 89.7 ms 的一轮，其中条件等待约 88.0 ms；
这与渲染队列延迟是不同口径，未在本轮解决。既有冻结响应门禁继续以 M-321 为准。

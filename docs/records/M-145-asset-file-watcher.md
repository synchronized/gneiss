# M-145：工程源资产文件监听实施记录

## 结果

Editor 资产模块新增私有 `asset_file_watcher`，递归监视工程 `sources/` 并以线程安全有界队列输出
规范化相对路径。公开头文件不包含 libuv 类型；具体后端通过既有 `uv_loop_executor` 在专用 I/O
线程运行，生命周期由监听对象独占。

事件只表达“候选变化”，保留平台给出的 changed 或 renamed 提示，不承诺一次写入只产生一个事件。
Windows 根监听使用 libuv 递归能力；其他平台为已有目录分别注册监听，并在目录重命名事件后发现
新目录。队列满时丢弃最旧事件并累计计数，后续 M-146 仍须通过防抖与内容校验确认真实变化。

## 验证

- 缺失监听根返回 `not_found`，重复停止返回 `not_ready`。
- 已有嵌套目录中的修改和重命名能够产生相对路径事件。
- 运行中新增目录及其文件能够被发现。
- 有界队列在事件洪峰下累计丢弃数量。
- Windows Clang Shared Debug 专项测试连续运行 20 次通过。
- Windows Clang Static Debug 专项测试通过。

Linux 的实际文件监听行为将在 M-150 跨平台矩阵中统一验收。

## 2026-09-23：缺失源目录的启动处理

Lantern Gallery 等只有运行资产的工程可能没有 `sources/`。Editor 改用可选目录启动模式：
目录缺失时返回 `not_ready`，不创建目录或后台线程；主线程每秒重试一次，目录出现后启动监听并
刷新资产列表。默认严格模式仍返回 `not_found`，作者资产目录的监听行为不变。
路径被普通文件占用或其他真实启动错误仍报告一次并停止重试，需要修正后重新打开编辑器。

新增缺失目录、重复等待、文件占位、稍后创建目录、后续文件事件及停止的回归测试。
Editor Demo 与 Lantern smoke 将资产监听启动失败文本作为失败条件，避免退出码成功掩盖告警。
Windows Clang Debug 编辑器构建、监听/作者监视/导入/重新导入队列/两项 Editor smoke 共 6 项测试
通过；Lantern 单独启动日志为空，未再报告 `-11 / not found`。
clang-tidy 检查仍报告监听器已有代码的告警（包括回调异常边界）；本次不将其描述为静态检查全绿。
未验证 Linux 文件事件或目录启动后删除再重建的恢复行为。

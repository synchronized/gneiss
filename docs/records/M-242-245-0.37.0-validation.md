# M-242～M-245：0.37.0 编辑器交互与发布验收

## 状态与环境

2026-09-25，发布验收通过。Windows 本地 Clang Debug、原生 Win32/Vulkan，Granit 0.30.0。
本机 CPU 为 Intel Core i5-8600K，显卡为 UHD Graphics 630（驱动 31.0.101.2140）。
原生枚举仅发现一个活动显示器：1920×1080，96×96 DPI，无法执行真实跨显示器迁移。

## 交互缺陷与覆盖

- 原 Gizmo 在清空选择时直接清除拖动状态，已应用预览可能没有撤销记录；历史记录失败时还可能
  通过当前选择回滚错误节点。改为保存原目标身份的拖动事务，释放、切换选择或隐藏视图统一收尾。
- 原无参数 `ImGuizmo::IsOver()` 查询上一帧悬停，改用当前操作命中查询，避免当前帧输入占用滞后。
- 发布前新增“拖动→删除→连续撤销/重做”回归发现：非根子树快照保留了外部父 UUID，恢复时
  场景解析返回 invalid_argument。捕获快照现将根 parent 置空，由恢复接口显式参数重新挂接；
  增加引擎公共接口回归，验证包含子节点的非根子树；Delete 前收尾拖动并保存独立历史。
- 提取生产视图/投影构建用于输入回放，近远裁剪面与 Editor Camera 对齐；仿射矩阵分解拒绝非零透视行。
- `transform-gizmo-drag` 覆盖根/子节点 Move、Rotate、Scale，多帧只记录一条命令，正非均匀父缩放，
  切换和清空选择、Prefab 来源节点、Undo/Redo、历史容量为零回滚、非法矩阵和场景关闭。
- `gizmo-input-replay` 在 100%、125%、150%、200% 尺寸下用 ImGui 输入事件驱动真实 ImGuizmo，
  三种操作均命中、捕获、改变合法模型矩阵并释放。这是合成像素尺寸测试，不是物理 DPI 迁移。
- `native-window-interaction` 完成 18 次 resize、3 轮最小化恢复、96/120/144/192/96 DPI 合成消息，
  共 90 帧，检查物理客户区尺寸、输入快照与 ImGui 指针存在性/坐标一致，以及 UI 提交和主循环返回值。
  离屏窗口会产生真实 WM_MOUSELEAVE；允许事件队列两个更新帧收敛后验证，指针在外时必须不参与命中。

## 资产响应性测量

复现命令（输出目录必须不存在）：

```powershell
cmake --build --preset windows-clang-debug --target gneiss_editor_asset_response_benchmark
./build/windows-clang-debug/bin/gneiss_editor_asset_response_benchmark.exe ./build/asset-response-new
```

使用原创静态三角形 glTF，以合法 JSON 空白补足文件体积，64 文件组为每份 1 MiB。
此数据测量文件读取、哈希、解析和现有导入事务路径，**不代表高面数模型或大纹理处理成本**。
哈希/重导入各重复三次取均值；补扫使用默认每次 8 候选/1 导入，去抖与稳定等待为零以排除等待时间。
Debug、缓存可能已热，非 Release 性能承诺。原始结果在本地 `build/0.37-asset-response.log`。

| 输入 | 单文件哈希均值 ms | 单文件重导入均值 ms | 未修改补扫最大 tick ms | 修改一文件后最大 tick ms |
| --- | ---: | ---: | ---: | ---: |
| 1 MiB × 1 | 5.247 | 48.028 | 10.470 | 54.741 |
| 16 MiB × 1 | 80.885 | 548.070 | 81.048 | 615.143 |
| 64 MiB × 1 | 327.192 | 1963.222 | 343.723 | 2258.758 |
| 1 MiB × 64 | 8.471 | 64.018 | 59.344 | 85.926 |

结论：候选数量预算不能保证交互帧时限。后台化优先级是源文件哈希/稳定检查和完整重导入事务，
随后测量并迁移索引解析及作者文件扫描；主线程保留场景冲突判定、UI 状态及 Runtime 修订发布。
需要独立计划定义任务取消、关闭等待、版本过期结果丢弃和资产写入串行化，不能只把 importer 放进
异步线程而继续让补扫哈希阻塞主线程。本版本完成测量和决策，尚未后台化，大文件阻塞仍是已知限制。

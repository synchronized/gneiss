# M-295：平台工具的链接边界

日期：2026-10-05。完成目录迁移前的底层反向链接清理。

## 变更与边界

动态库加载、子进程、libuv 执行器与 IPC 原先仅为复用结果值而公开链接整个 Engine。
四个目标现改为依赖内部头文件目标 `gneiss_core_values`，不新增运行时状态、不安装该目标。
沿用既有结果码和强类型值；仅使用构造、比较与取值，不调用依赖 Engine C ABI 的 `message()`。
静态构建保留相同的 `GNEISS_STATIC_DEFINE` 定义，公共头和导出未改变。

新增原生动态库夹具及独立消费者，覆盖加载、调用、缺失符号、无效参数、重复关闭和重新加载；
该消费者仅链接动态库适配目标。IO、IPC、子进程沿用既有功能、线程和生命周期测试。

## 验证

- Windows Clang Debug 共享与静态配置：相关目标构建通过，各 10/10 测试通过，
  包含 8 个平台测试与 2 个已有边界检查（1.53 秒 / 1.75 秒）。
- 核对两种配置生成的 Ninja 链接规则，8 个平台测试均不包含 Engine 链接依赖。
- 共享配置 Editor 与 Runtime 重新构建通过。
- 共享与静态安装消费者各 1/1 通过（9.98 秒 / 8.69 秒）。
- 新测试格式检查、差异检查通过。

未运行 Linux/macOS、浏览器、远端 Actions 或 GPU 专项；本轮不宣称已完成整个 Platform
语义适配和源码布局迁移。宿主共用协议与其余层间依赖仍需按 DEV-045 审计。

## Platform 目录迁移

后续将原 `src/platform/` 与 IO、IPC、Process 三组集中到 `src/engine/platform/`，对应内部头
统一使用 `.hpp`，同步更新 CMake 与直接消费者。原有 target 名称、资源所有权、线程行为、
IPC 线格式、可执行文件名及安装 SDK 路径不变。根目录 `apps/` 与应用协议保留原位。

Platform 的头包含检查增加 Application、World、Scene、Render、Asset、Apps 六种反向依赖
反例，并保留共享结果值的正例。此检查只覆盖约定的直接包含形式，不替代完整依赖图。
迁移后再次核对两种配置的 8 个平台测试链接规则，均不链接 Engine。

窗口适配仍使用既有 Application 描述与输入值类型，旧 `application_internal` 命名空间也尚未
迁移；本次目录调整不代表这些语义边界已经完成。其余 Core/Asset/Function 与 Editor 的迁移
继续按 DEV-045 实施。

迁移验证：共享与静态全量构建通过；共享全量 CTest 174/174 通过（196.41 秒），静态受影响
回归 19/19 通过（29.00 秒），覆盖窗口交互、IPC、子进程、动态库、宿主启动/关闭和安装消费者。
另补静态帧包回归 1/1 通过（0.05 秒）。新增动态库测试补齐路径转换异常捕获后，共享专项再次通过，静态回归使用
更新后的测试；该测试的 clang-tidy 自有代码告警已清零，未关闭检查。格式、文档链接和差异
检查通过。跨平台与远端发布矩阵仍待版本整体就绪后执行。

# M-331：异步新场景启用固定版本

2026-10-15，接续[宿主版本重载](M-331-host-version-reload.md)，将 scene_load_service
的资产批次显式切到 fixed_version。场景构建继续消费本次请求选定的租约，不回查 URI 缓存。

## 行为与边界

材质仍分别准备其纹理依赖，网格仍按原有批量上限处理。批次内及批次之间的同版本资源
由既有版本缓存复用；绑定收集继续拒绝同 URI 对应不同 RID 的不一致结果。
最终来源复验、候选 World 隔离、显式激活、取消及退役契约不变。

激活后切回原始 VFS 的资产服务，与准备期间的来源复验包装保持同一来源身份。
因此未修改内容的异步重载能复用新场景的固定版本，不再因两条入口使用不同缓存键而重复上传。

本次只切换异步打开场景入口。同步场景实例创建、节点编辑和同步热重载仍可能使用旧 URI
缓存；尚未统一所有资产消费入口。每个场景域仍拥有自己的缓存，不能宣称跨 World 共享。
固定模式需要准备、复验才能确定版本；跨批次复用上传不代表完全省略重复文件读取和解析。

## 验证

Windows Clang Debug 定向 CTest 5/5 通过：scene-load-application、texture-load-application、
asset-pixel、core-boundary、core-boundary-negative。Runtime、Editor 构建通过。

scene-load-application 新增线程池和协作模式测试：

- 两个材质分批准备并引用同一纹理，绑定检查成功，纹理负载预算仅计一次（4 字节夹具）。
- 激活后仅请求该纹理，回执含纹理及两个材质的版本，peak_upload_bytes 为零。
- 第一批材质准备后修改共享纹理，后续加载失败并完成清理，原活动 World 及两个实体保留。

既有测试继续验证取消、来源变更、失败重试、关闭；真实 GPU 像素测试覆盖候选场景
成功切换、取消/失败保留画面，以及宿主异步资产重载。没有执行完整 Sponza、跨平台、
安装消费者或性能对照，不据此声称大场景加载耗时无回归。

scene_load_service 和对应测试执行 clang-tidy；新增初始化/声明告警已修正，原有复杂度、
测试夹具析构等告警仍存在。格式及 diff 检查通过；未执行远端操作。

# CAORS 协作输入接入验收

## 本次变更

输入宿主装配不再要求后台 libuv loop。VFS 不支持异步打开时，输入宿主显式允许
执行器读取最多 1 MiB 的完整文档快照；之后使用原 Loader 与采用流程。
桥默认仍要求异步能力，未显式允许的调用者不会静默改为同步读取。

快照关闭拒绝新读，已接受请求独立保活字节；关闭回执仍等待摘要处理完成。
排队打开被丢弃时产生失败终态，取消及放弃请求不要求等待同步读取完成。
已经执行的同步读取本身不可抢占。

## 验证

Windows Clang Debug 构建成功，两个 CTest 全部通过：

- `gneiss.caors.vfs-bridge`：原 libuv 与快照两种路径，来源身份和摘要、读取上限、
  关闭屏障、取消、队列丢弃、来源变化和失败保留旧版本。
- `gneiss.caors.application`：线程池与协作调度均验证加载、采用、无效重载、取消、
  同步接口取消旧请求、跨线程拒绝、在途退出及复用宿主执行器。

## 未完成范围

本次协作验证使用原生线程启用的构建，并显式选择 cooperative 模式。
无线程构建和 Emscripten 输入路径尚未验收；输入开关及相关构建限制仍保留。
协作队列读取占用推进线程，不构成主循环延迟改善结论。同步加载入口尚未合并。

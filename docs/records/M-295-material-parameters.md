# M-295：材质准备参数与纹理 RID 分离

日期：2026-10-05。继续实现 ADR-054 的资产准备与资源发布边界。

## 实施结果

`src/engine/asset/material_parameters.hpp` 保存颜色、PBR 系数、透明状态及逐槽采样参数，
不包含纹理 RID、资源服务或后端对象。解析结果与批次准备共用该类型；纹理依赖继续单独使用
自有 URI 字符串。删除原解析结果中重复保存参数的 `material_resource state`。

同步获取材质与批次暂存共用发布边界转换函数，然后根据已取得的纹理租约绑定 RID。
缺失依赖仍拒绝暂存；现有缓存事务、资源所有权和错误码保持不变。发布后的 `material_resource`
和公共 C/C++ SDK 布局不变，没有增加第二套资源存储。

准备预算继续使用发布资源的 `sizeof(material_resource)` 加 URI 字节数，避免因为准备结构
删除句柄而放宽候选预算。该估算仍位于 Render 准备代码，不宣称整个准备层已经归入 Asset。

## 验证范围

- 新增编译期检查，准备材质类型不能具有纹理句柄字段或发布描述构造方法。
- 材质 v5 往返覆盖同步获取、CPU 准备、暂存与发布：检查全部 PBR 参数、透明状态、五个纹理槽
  及逐槽采样参数；准备不创建资源，缺失依赖不泄漏资源；预算与原有计算保持一致。
- 新测试使用独立 VFS，避免污染既有缓存命中测试的读取计数。
- 原有纹理加载、场景加载与真实 GPU 像素测试继续验证取消、回滚和渲染行为。

Windows Clang Debug 共享全量构建成功，相关测试 11/11 通过（18.92 秒）；静态相关目标构建成功，

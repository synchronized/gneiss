# M-273～M-278：0.42.0 异步场景加载验收

## 状态

2026-09-25，实施与验收中，尚未发布。范围与固定门槛见
[VER-042](../plans/VER-042-0.42.0-async-scene-loading.md)，资产身份、许可、能力损失与同步基线见
[M-272](M-272-sponza-baseline.md)。本版未修改 Granit 仓库。

## 正确性与生命周期

- 纯 CPU 描述准备覆盖 Scene/Prefab、父节点优先顺序、依赖去重、类型冲突、无效层级、规模和深度限额。
  源文件账本使用长度与 SHA-256，验证等长修改、缩小、增长、缺失与会话隔离。
- 候选使用独立 World、Scene Service 与资源缓存；共享 Render Service 只管理资源，不把候选节点加入
  活动 ECS、检查镜像或渲染提取。测试保留旧帧资源引用，验证旧 World/Scene 在替换回收后失效。
- 混合资产子批次沿用 4 项/8 MiB 上传预算与单项超限规则；输入、解码与累计驻留分别受限。
  子批失败与取消回收整个场景候选，候选完成不等于场景已发布。
- `gneiss.asset-pixel` 在两种执行模式下回读真实 GPU 输出：完整候选 ready 时旧图像逐像素不变，
  激活后颜色改变；ready 取消与依赖损坏保持旧图像和 3 个 CPU RID；修复后可再次激活。
- Editor/Runtime 进程测试覆盖首次激活、缺失目标失败、修复重试、实际 IPC 取消、再次重试、检查会话
  更新与退出。游戏模块记录每次初始化/关闭配对，不在候选准备失败时重新初始化旧模块。
- 初轮 Windows Debug 全量 156/158 通过。生命周期测试并发读取每帧追加的追踪文件偶尔读失败，已将
  该夹具限定为生命周期事件；重复运行进一步暴露关闭终态被失败心跳掩盖，修正后连续 20 次通过。
  Cooked Lantern 损坏纹理仍报告上传失败；异步候选统一归入场景加载错误，测试明确检查退出码 4，
  上传阶段日志及错误级别检查保持。相关 9 项复验通过。

## 大场景测量方法

硬件与资产同 M-272。每个样本独立进程，不清空操作系统文件缓存，可能命中热缓存；没有把结果称为
冷盘性能。日常配置仅缩小贴图，完整配置保留 4096 贴图。每配置两模式各三次，顺序运行，本机暂停编译。

```powershell
python -B tools/performance/measure_scene_loading.py D:/sunday/workspace/asset-cache/intel-sponza --debug build/windows-clang-debug/bin/gneiss_scene_load_baseline.exe --release build/windows-clang-release/bin/gneiss_scene_load_baseline.exe --output build/0.42-scene-matrix
```

测量使用一次连续 `Application::run()`；主线程 update 回调推进候选。主线程事件间隔与渲染呈现计数
分开采样。CSV 保存主线程观测到的最新呈现间隔，观察间可能完成多帧，因此不是完整 GPU 帧事件流。
`render_60_ticks_ms` 包含 60 次主循环及排空，不等于 60 个渲染帧；`presented_frames` 为包括加载期的
累计值。GPU 回读用于正确性，回读成本不作为帧率。独立显存计数不可用，进程工作集包含驱动映射。

正式 24 样本全部完成。原始数值、可执行文件/引擎 DLL 哈希、转换记录和图像摘要归档于
[矩阵 JSON](artifacts/0.42-scene-matrix.json)。采样时版本号尚为 0.41.0，但已使用本分支的完整异步
加载实现；后续版本号更新及宿主修订不改变该加载路径。基准随后补充了连续切换及最小化分桶指标，
不能把新增指标倒填为这 24 个样本已经测得的结果。

24 次激活最大 1.291 ms，均低于预先固定的 5 ms；线程池事件间隔均满足 P95 100 ms/最大 250 ms。
主线程单次推进最大 7.87 ms，包含资产子批收尾与候选构造，不能把实例化的 2 ms 软预算说成整个
推进调用的硬上限。全部样本为 553 节点、458 RID，候选 CPU 资源日常 215,395,096 字节、
完整 1,788,259,096 字节，均在 2 GiB 内。同一配置的 12 张异步回读图逐像素相同。

异步总加载时间高于同步基线：源文件哈希/最终复核、候选准备及分阶段调度增加了工作和等待。
本次改善的是线程池模式加载期间的可操作性，不能宣称总加载更快。Debug 完整协作模式的最终源
验证任务约 50 秒不可抢占，窗口会出现明显停顿；协作模式只验证结果和生命周期一致，不适合作为
此类大场景的流畅交互方案。该限制沿用采样前已声明的边界，没有放宽线程池的验收线。

## 窗口与故障预验收

以下为正式矩阵前的单次 Release 预验收，原始文件位于本地 `build/0.42-baseline/`：

| 场景 | 结果 |
| --- | --- |
| 完整配置切换，移动相机、10 次 resize、最小化恢复 | 成功；事件间隔 P95 16.44 ms、最大 68.32 ms；峰值工作集 7,629,381,632 字节；激活 0.35 ms、旧域回收 0.92 ms |
| 日常配置，子批完成后取消 | 15.51 ms 确认取消 |
| 日常配置，GPU 在途取消 | 252.25 ms 确认取消 |
| 日常配置，ready 后取消 | 16.92 ms 确认取消 |
| 日常配置，部分资产准备后依赖缺失 | 失败，旧图像逐像素不变 |
| 日常配置，加载中关闭窗口 | 析构等待 105.01 ms，调度器遗留任务为零 |

完整切换的旧/新候选 CPU 资源分别约 1.665 GiB；回收后 CPU Service RID 从 458 回到 458。
数量不代表驱动已立即释放所有显存。取消和失败样本均验证旧图像完全相同、RID 数量恢复。
完整配置初始异步加载与交互切换的固定相机 PPM 完全一致，SHA-256 为
`fee18c1b7437242e0f5768b399afb3e9cb3876b5263f032690677f4e91985803`。
同步与异步参考图有 72/786432 个像素不同，平均 RGB 差异小于 0.0007/255；差异位于边界，
不宣称二者逐像素完全相同。材质/透明贴花差异见 M-272，不把这些已知渲染能力缺失归因于调度器。

## 发布门禁与边界

Shared Debug 完整回归 157/158 通过（173.69 秒）；唯一失败为新增协议测试错误地把高于当前的能力
版本当作不兼容。通用协议一直按最高可理解版本协商，修正断言并增加更高版本接受/更低版本拒绝后，
该项复验通过。扩展后的首次失败重试、准备/实例化取消、GPU 像素与共享安装消费者均通过。
最小 Emscripten 5.0.6 宿主在真实 Chrome 报告 `GNEISS_TASK_WEB_PASS`；原创 ZIP 四项 Python 测试通过。
核心新组件已执行 clang-tidy：无编译错误，剩余为状态机复杂度、指定初始化格式和按值传参等建议，
未禁用检查。Static Debug 全量 155/155 通过（94.95 秒）。Shared Release 首轮 156/158 通过，
两个失败均已复现并进入修复验证：

- 纹理事务测试退出时报堆损坏。独立 Windows ASan 探针确认 `mixed()` 的缓存析构访问已销毁的
  `render_resource_service`；修正三个测试夹具的声明顺序，并在内部加载器注明资源服务须晚于缓存与
  租约销毁。修正后 ASan 探针通过；Application 实际成员顺序符合此约束。该探针仅插桩测试及相关
  资产实现，链接既有非插桩库，不替代完整 Linux Sanitizer 门禁。
- Lantern 交互重复测试第 14 次复现 IPC `NOT_READY` 退出。无帧率限制的示例每 30 次 update 打印
  日志，挤满发送队列，暂停确认发送失败。Transport 的日志发送现在为非日志预留四分之一容量
  （最多 16 项）；接收队列满时非日志消息优先替换日志。增加小容量队列回归，确保控制消息不被
  日志淹没；仍保留容量上限，不宣称任意消息洪泛下都可靠。测试失败时输出完整控制台便于追踪。

修复后 Release 的 IPC Transport、Lantern 工作流和纹理事务各连续 40 次通过（合计 146.84 秒）。
最终 Shared Release、手动 Linux/Windows 矩阵及发布仍待完成。Linux Sanitizer 增加纹理事务、
渲染资产加载器与 Prefab 实例生命周期测试，覆盖本次发现的退出顺序问题。
远端 Linux 图形矩阵已增加 Runtime 宿主构建，确保执行新的 Editor/Runtime 场景切换测试；Windows
新增 MSVC Runtime 构建和非 GPU 测试，托管 Runner 的 Vulkan 限制保持由 Linux 和本机覆盖。

公共同步场景 API 保留；内部异步入口不是公开异步 SDK。任意游戏模块回调的副作用不承诺自动回滚。
协作模式不能抢占单个解析、哈希或解码。源文件复读检测变化，不提供跨进程原子快照。
完整引擎 Web、跨屏 DPI 人工验收、全 PBR 材质及独立 GPU 显存测量均未由本次结果推导为已支持。

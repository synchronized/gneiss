# M-288：纹理负载租约与原内容重建

## 实现范围

2026-09-30 为绑定设备且按变体读取的文件纹理分离上传负载与长期资源元数据。
后台准备仍生成自有字节，暂存为候选时将其移动到 `shared_ptr<const vector<byte>>`，
候选和上传命令分别持有强引用。长期资源只持有弱引用、Manifest、设备选择和重建来源。
没有复制整块负载，也没有修改已经共享的资源或帧快照。

全部上传回执及事务结束后，候选释放；上传命令释放其引用。最后一个强租约结束时负载析构。
失败、重试及上传中关闭沿用同一生命周期。GPU 纹理缓存保留资源元数据，不强持有该 CPU 负载。
公共内存纹理和旧同步路径保持原语义。

重建来源保留原读取句柄、选中范围及原摘要。原 Manifest 不变，重读负载必须匹配原摘要；
不从相同 URI 打开新版文件。来源损坏时恢复失败，不用新内容替代旧资源。
Windows 打开来源显式允许共享删除，语义依据
[CreateFileW 说明](https://learn.microsoft.com/zh-cn/windows/win32/api/fileapi/nf-fileapi-createfilew)。
长期句柄允许路径替换，但不保证内容不可变。选择与成本见
[ADR-052](../decisions/ADR-052-texture-residency-and-budgets.md)。

## 本地验证

- 容器重建：非零偏移、预算拒绝且不读取、摘要变化、短读、失败后重试、最后引用释放关闭来源。
- 原生来源：VFS 销毁后继续读取、并发区间读取；句柄存活期间重命名、同路径新建及删除原路径，
  仍读取原内容。原文件截断后报告短读。
- 资产候选：旧帧保留元数据，上传命令仍持有负载时弱引用有效；命令及候选租约释放后弱引用失效，
  可以按原摘要恢复，内容改变会拒绝恢复。
- 纹理服务在 thread_pool / cooperative 两种模式下验证失败回执、成功重试、迟到取消、
  上传中关闭；完成后确认负载租约实际失效，旧帧仍然有效。
- 真实 GPU 像素回归包括异步独立变体加载、同步兼容、Mip 与 PBR 材质通道。

Windows Clang Debug 共享库全量构建通过，相关回归 9/9 通过（15.34 s）；静态库相关目标
构建通过，读取来源、容器、加载器、纹理服务和真实 GPU 像素回归 5/5 通过（16.83 s）。
两轮启用 `VK_LAYER_KHRONOS_validation`，原始 CTest 日志没有 Validation Error / VUID。
修正新增排版及 Win32 BOOL 判断告警后，共享/静态受影响目标重新构建通过，读取来源测试再次通过。

对四个核心实现文件运行变更行 clang-tidy，修复新增 Windows 判断与括号告警；既有的大型加载/
上传函数仍超过复杂度阈值，不将此检查描述为全文件无告警。`git diff --check` 通过。
原始日志位于本地 `build/0.44-texture-residency/residency-*.log`；未触发远端 Actions。

## 未完成的验收与限制

- 当前仅同设备 GPU 投影缺失时同步恢复，可能阻塞渲染线程；设备丢失自动恢复不属于已实现能力。
  尚未用真实 GPU 注入纹理缓存丢失及源损坏组合，CPU 重建测试不冒充此项验收。
- 资源保留打开文件句柄；原文件路径删除后，磁盘空间可能到最后一个句柄关闭才释放。
- 场景预算仍按保守候选字节计数，尚未接入按实际驻留与上传暂存分别计量的 M-289。
- 未测量完整 4K Sponza 峰值内存、恢复延迟或 Linux；不能据此宣称 0.44 已验收或发布。

# 单项资源加载与内容缓存收尾

日期：2026-10-23。范围：[资源简化计划](../plans/PLAN-051-progressive-render-assets.md) R4。
功能与 Release 性能验收均完成；完整加载与早激活采用不同测量口径。

## 实现

- `texture_load_service` 每次读取、解码、上传、更新一个资源。材质依赖追加到独立队列，
  已有成功纹理直接复用。失败继续后续项；取消保留已成功项，只清理未生效数据。
- 删除 `asset_candidate`、`stage_asset`、`publish_assets`。任务只持目标引用、请求序号和临时数据，
  不再创建临时 RID；上传完成后更新一个稳定 RID。GPU 确认与旧帧保活继续保留。
- 同步重载逐项处理：坏材质保旧，其他网格、纹理仍更新。材质重载不强制重读纹理。
- 缓存条目记录挂载来源，拒绝不同来源的同 URI。VFS 副本共享来源；设备准备配置仍校验。
  多加载器共享请求序号空间，防止局部计数使旧任务覆盖新任务。
- 删除材质文档版本索引、历史查询与文档租约包装。资源直接共享只读描述；加载任务保存摘要
  和字节数。CPU 缓存使用弱引用按来源和内容去重，没有版本选择或采用。
- 大场景测量等待活动场景视觉队列完成，再采样最终资源数和图像；吞吐比较使用
  `load_and_drain_ms`。旧的场景提交前 `cancel-gpu` 测量已明确拒绝，该阶段不再存在。

随后新增显式纹理依赖重载失败测试，相关测试 **1/1**，0.95 秒。
包含真实 GPU 像素、协作/线程池、IPC 逐项回执、编辑历史、场景激活/切换、安装 consumer、
C11/C++20 头和分层检查。测试日志保存在本地 `build/asset-migration/`。

首轮全量测试 200/201：输入启动测试使用在第 99 次更新故意失败的模块，早激活后可在
视觉加载期间触发。改用持续正常运行的模块夹具；原模块会话故障传播测试保持原样。
没有关闭测试或提高超时来掩盖失败。

核心三个改动文件运行完整 clang-tidy 配置，无错误诊断；仍有四项可读性建议：静态成员建议、
嵌套条件表达式、推进函数认知复杂度 28（阈值 25）、一个初始化尾逗号。

源码、安装头和测试不再引用上述资产版本/候选协议及材质版本索引。

## 边界

没有修改公共 C ABI 或 Granit，也没有进行远端操作。本机没有验证 Linux、Web 或完整静态构建矩阵。
单资源串行处理降低同时持有的数据量，但吞吐与响应性必须以 Release 实测判断。
场景/Prefab 结构临时域和作者命令提交检查继续存在；它们不属于已删除的资产版本事务。

最差事件间隔 54.35 ms；完整加载中位数不超过基线 1.5 倍，进程峰值不超过基线 1.1 倍。

代价必须保留：日常完整加载中位数分别增加约 31.1% 和 43.5%，不能用约 300 ms 的
早激活掩盖吞吐下降。完整场景本轮中位数下降，但文件缓存未清理、状态未受控，
样本随运行逐渐变快，因此不宣称冷启动加速，也不将差值全部归因于本次实现。
后续吞吐优化可以在现有单资源契约下评估，不恢复版本选择或整批发布。

# M-331：来源身份与固定版本缓存条目

2026-10-15，Windows Clang Debug 本地实现与验证；依据
[共享资产实施设计](../plans/asset-scene-ownership.md)。本批不表示场景共享加载已完成。

## 变更

既有 resource_cache 的唯一索引改为复合键表，新增 version_key 获取与观察接口。
键包含运行期来源身份、URI、资产类型和非空版本标识；相同键复用已发布条目，不同版本并存。
版本标识由调用者提供，缓存不解释编码，也不读取或复验文件；来源、依赖及准备配置的完整版本
构造仍待加载链路接入，不能用缓存 revision 或请求编号代替。

旧 URI 获取、观察和事务重载使用同一表内的保留键：空来源、零键类型、空版本。
条目原有类型校验与热重载行为保留；新接口拒绝空来源、零类型和空版本，不能通过新接口访问
旧保留键。未创建第二套缓存或运行时状态，旧接口仅用于尚未迁移的调用方。

固定版本接口不提供原地重载，失败或异常撤回加载占位，重试不会影响其他版本。
发布后资源不可原地修改是调用方契约；本批沿用 shared_ptr<void> 负载，不宣称已经由类型系统
保证深层不可变。加载器仍限所属线程执行，同键递归返回 INVALID_STATE，尚非异步订阅合并。

## 验证

Engine 及资源缓存、场景加载、渲染资产加载测试构建通过。定向 CTest 5/5 通过：
resource_service、scene-load-application、render_asset_loader、core-boundary、core-boundary-negative。

缓存新增用例验证：同键只加载一次、新版本失败不影响旧版本、异常后可重试、新旧版本并存、
不同来源与类型隔离、释放旧版本不影响新版本、旧 URI 重载不覆盖固定版本、无效键拒绝、
递归获取拒绝及最后使用引用释放后的清理。用例是缓存级验证，没有冒充两个真实场景的端到端测试。
resource_cache.cpp 的 clang-tidy 无诊断，所改 C++ 格式检查及 git diff --check 通过。

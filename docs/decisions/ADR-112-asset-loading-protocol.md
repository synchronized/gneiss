# ADR-112：资产身份、内容与加载协议分离

## 状态

2026-11-08：已接受，实施见 [PLAN-107](../plans/PLAN-107-asset-model-loading-protocol.md)。
承接 ADR-107，统一本次从零设计的目标边界；不表示所有能力已实现。

## 决策

资产管理器统一拥有五类资产的索引与加载生命周期，文件和 Render 保持独立服务。
具体资产类型提供领域内容；薄 asset 基类只提供身份和运行类型，不提供加载或 GPU 方法。
共享身份稳定，内容为不可变快照；重载成功替换当前内容，旧快照可以继续存活。
请求的身份访问不表示加载成功；take 返回该次操作结果，CPU 就绪与 GPU 就绪分离。

加载协议为解码、声明依赖、装配。Loader 不持有管理器或自行推进其他请求，调度由加载操作承担。
异构依赖允许在调度内部类型擦除，对 Loader 保留类型化结果；不将擦除扩散到上层资源 API。
content/reference 分别表达等待内容与只绑定身份。依赖图负责等待环及强拥有环检查，首版拒绝循环。
引用序列化只记录定位与属性路径，不发起 I/O；匿名资产须先保存或明确采用内嵌规则。

场景资产与 World 实例分离，实例化期间解析 Prefab 与覆盖，运行组件只持有有效数据。
CPU 内容不因资源类别统一而强制排队析构；后端有线程要求的操作进入服务队列，GPU 安全释放归后端。

## 取舍

相比分散 Loader 管理依赖，统一协议需要少量内部依赖状态，但消除重复取消、轮询与错误传播。
相比直接覆盖共享内容，不可变快照多一个拥有边界，换取异步解码、历史与热重载的清晰语义。
不选择把所有对象继承通用 RefCounted，也不增加 resource_service 或公开 reserve 接口。

# ADR-088：Prefab 直接实例化与非原子替换

- 状态：已接受。
- 日期：2026-10-26。

## 背景

用户取消“Prefab 完整准备后统一替换、失败保留旧实例”的要求。
此前为在活动 World 内跨帧构建隐藏节点，引入 publication_group、候选实例、
发布与退休状态、批量切换以及分步清理。这些机制不再是当前需求。
本决策覆盖 DEV-051 中关于 Prefab 分帧结构事务的旧选择。

## 决策

- CPU 文件读取和依赖资源准备继续使用异步加载；节点实例化在所属线程同步执行。
- 取消 publication_group 和 prefab_candidate；普通 ECS 与 Scene Tree 对象创建后直接可见。
- Prefab 替换在基本身份和参数形状校验后先删除旧实例，再创建新实例。
  后续失败清理本次创建的节点、实体和资源引用，不恢复旧实例。
- 多个实例依次处理，前面已完成的替换不因后面失败而回滚。
- 编辑器从实际场景重建记录；失败也执行同步并标记文档已修改。
  若重建记录本身失败，清空视图缓存，避免暴露已失效的节点。
- 撤销/重做继续保存描述和资源强引用，不保存隐藏运行实例。
  实例创建期间不可取消；异步来源准备仍可取消。

## 影响与边界

删除运行时发布协议及其跨层可见性规则，降低 World、Scene 和 Editor 耦合。
大型 Prefab 同步创建可能占用一帧；当前接受此代价，不提前设计流送调度。
运行阶段替换失败可能使目标实例消失，批量失败可能留下部分更新；调用者必须显示失败，
不得宣称旧实例仍在或全部未变。基本输入校验失败可以不修改场景，但这不是回滚保证。

本决策不要求删除普通场景的加载隔离，也不取消作者文件写入的失败恢复。
现有按 UUID 协调节点的结构重载入口另有实现；本轮不把它们描述为已全部删除。

实施与验收见 [PLAN-055](../plans/PLAN-055-prefab-direct-instantiation.md)。

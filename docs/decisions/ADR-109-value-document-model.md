# ADR-109：结构化值、不可变文档与操作式 Prefab 覆盖

## 状态

2026-11-07：已接受；同日复审后调整领域边界与实施顺序，待分阶段实施。实施状态以 [PLAN-104](../plans/PLAN-104-value-document-prefab-overrides.md) 为准。

组件身份外置包装及运行存储边界的后续调整已由 [ADR-110](ADR-110-game-object-runtime-model.md) 接受；
迁移状态以 PLAN-105 为准，其余文档版本与历史决策继续有效。

## 背景

复杂属性覆盖依赖 JSON property_snapshot，组件、子树、文档历史维护不同的复制恢复路径。
仅增加 value 对象引用不能固定历史内容；统一深拷贝又会破坏资源共享语义。

## 决策

保留结构化不可变 value 与反射捕获/恢复；组件属性内容统一，场景领域结构保持强类型。
对象、父子关系、组件 UUID 和类型身份由明确记录表达，不要求整个场景成为无类型值树。
普通数学值按值保存，任意运行时对象引用不直接进入文档；资产转换为稳定身份，不隐式深拷贝。

Core/Meta 只处理值与访问；Scene 负责身份、层级和 Prefab 组合；Editor 文档负责编辑版本和历史。
World 适配负责运行时同步，不反向决定编辑内容。不因分层再创建多套 Service 或注册表。
纯文档内容和候选计算不依赖 Application、World、历史执行器。

编辑命令、历史版本、Prefab 持久差异共用值与地址，但语义和生命周期分开。
编辑通过 set_property、add/remove_component、reparent_object、remove_subtree 等领域操作校验。
历史以前后版本为准，操作用于执行和合并；不强制永久重复保存完整版本和完整操作日志。
历史切换要求当前版本与记录基线完全相同，未记录的独立修改使旧历史失效；拒绝操作而非
覆盖其他编辑或尝试猜测合并。整文档历史替代旧的逐属性回调语义。
首版恢复可以重建完整 World 投影；对象 UUID 和组件 UUID 稳定，节点/实体句柄不稳定。
Prefab 保存整理后的持久差异，集合操作保留必要顺序；同路径 set 归并，整体替换以 diff 补充。

组件实例 UUID 独立于类型 GUID，即使每类型只允许一项，删除后重建也不能绑定旧覆盖。
身份由组件集合中的 `component_entry { uuid, description }` 持有；description 仍为多态强引用。
不把实例 UUID 塞进每个具体描述类，不要求 Meta 基类继承字段；文件按同一领域结构保存。
运行时适配只在实体上保留类型到实例 UUID 的关联，随实体释放，不持有文档版本或历史。
无身份列表整体替换；子树复制明确重映射对象/组件及内部引用，不由序列化推测身份。
文档版本逻辑不可变，按需要共享未修改记录，不提前实现通用持久化树框架。

结构非法在接受编辑前拒绝；资源未就绪不否定合法编辑。
World 同步失败保留文档并记录未同步版本与诊断，允许重试，不从半更新运行时覆盖文档。
先允许对象/子树重建，再优化精细增量。嵌套 Prefab、精确历史内存预算另行分阶段设计，
不作为本轮基础边界完成条件。运行时无需持有编辑历史。
对象引用校验与结构合法性分开：已知目标缺失和未知外部文档分别报告，不因删除目标强制删除引用，
不为诊断加载整个项目。来源对象目录由所属文档层提供，Core/Meta 不认识场景。

## 替代方案与代价

保留 JSON 快照实现简单，但把内存历史与文件格式耦合，难以统一差异和容器编辑。
只使用共享对象引用开销低，但无法保持历史内容。每次深拷贝全树较直观，但大文档历史成本高。
采用不可变结构增加路径复制、共享节点及历史预算管理成本；换取统一版本、历史和修改入口。
不实现自动共享对象图或循环图持久化；需要共享身份时领域数据显式定义对象表和引用。

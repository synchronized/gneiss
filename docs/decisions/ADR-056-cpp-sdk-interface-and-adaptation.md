# ADR-056：C++ SDK 的接口组织与调用约定

- 状态：已接受
- 日期：2026-10-07

## 背景

0.47 完成原生值类型与 RAII，但公共模块头中混合了调用接口、C 布局转换和回调寿命实现。
Application/World 样板证明可分离这些职责，同时保持既有运行时与错误协议。

## 决策

继续沿用内部 C++ → C ABI → C++20 包装的分层，不创建独立 C++ 二进制包装库。
模块头维护类型、方法签名、所有权结构与短 constexpr 操作；复杂适配放在同模块的
`detail/*.inl` 中，自动包含并随 SDK 分发。实现文件不是用户入口。
Core、Asset URI、日志等短小模块保留单文件，不以文件数量作为规范。

0.48 保留 result 与输出参数，不建立平行的 expected/异常调用协议。失败输出语义以具体
接口为准，不因整理而静默改变。借用视图的 const 约束句柄自身，场景包装也采用相同约定；
后端状态可变，但线程、安全和寿命要求不因此放宽。所有权动作仍然修改拥有者。

Render 保留已有资源拥有者模板；不扩展成全 SDK 通用框架。Reflection 的稳定回调存储
继续随 Registry 转移；不能因为放进 detail 就省略所有权结构。Game Module 继续使用
编译期回调桥接，因为 C ABI 没有实例 user_data 槽位，不用全局闭包注册表替代。

## 影响

普通调用与 C ABI 不变；显式成员函数指针需适配新增 const，消费者重新编译。
安装分发增加实现片段，须验证干净安装和多编译单元链接。
拆分不消除转换临时数组、传递 include 或回调存储，不承诺零拷贝或编译性能改善。

## 替代方案

不采用全量 `.cpp` 包装库：会引入额外 C++ 导出/二进制约束。
不同时切换结果类型：会扩大迁移面，让接口组织和错误语义变化难以分别评审。
不为所有函数机械拆文件，也不以类型擦除或通用 owner 模板隐藏关闭失败。

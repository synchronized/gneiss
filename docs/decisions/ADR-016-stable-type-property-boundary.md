# ADR-016：稳定类型标识与属性访问边界

- 状态：已接受
- 日期：2026-08-28

## 背景

编辑器属性面板、场景迁移和后续 Undo/Redo 需要跨构建、进程与重命名稳定地识别类型和字段。
若使用名称、注册顺序、编译器 RTTI、EnTT ID、成员地址或内存偏移，持久化数据会绑定具体实现，
属性写入也会绕过组件校验和派生状态失效。首版还需要明确注册、未知字段和多态边界，避免 Type
Registry 在实现过程中自然扩张为通用 C++ 反射系统。

## 决策

- Type ID 使用显式分配的 128 位 UUID；全零值无效。公共 C ABI 使用 16 字节值表达，文本格式使用
  规范 UUID 字符串。名称只用于显示和诊断，重命名不得改变 Type ID。
- Field ID 使用类型内部显式分配的非零 `uint32_t`；零值无效。完整字段身份是 Type ID 与 Field ID
  的组合；已使用的 Field ID 废弃后不得分配给其他语义。
- Type ID 和 Field ID 必须写入源码或受版本控制的 Schema，不根据名称、地址、编译器哈希或注册
  顺序自动生成。重复注册只有在完整描述一致时才可幂等成功，任何冲突都必须明确失败。
- Type Registry 在初始化阶段显式注册，随后冻结。冻结后允许并发只读查询，不允许继续注册、注销
  或替换描述；首版不支持动态模块卸载。
- Registry 复制并拥有类型名、字段名和约束等元数据。调用方查询得到的借用结果只在 Registry
  生命周期内有效；公共接口不返回 C++ 对象、组件指针或第三方反射类型。
- 属性通过类型注册的 getter/setter 适配器访问，不公开成员地址或偏移。setter 必须校验值类型、
  范围、只读性和对象生命周期；失败不得留下部分修改，并负责触发必要的派生状态失效。
- 作者文档在解析、迁移和重新保存时保留当前受支持 Schema 中的未知字段；Runtime 实例化只消费
  已注册字段。高于当前支持版本的文档整体拒绝，未知字段不得绕过已知字段校验。
- ECS 组件继续采用组合，不通过反射继承表达多态。序列化始终记录具体 Type ID；`base_type_id`、
  `is_a`、继承字段枚举和动态构造仅作为未来扩展点，首版不实现。

## 影响

- 类型与字段可以安全重命名，但改变语义时必须分配新标识或提供明确迁移。
- 编辑器和序列化无需依赖 EnTT、C++ RTTI 或组件布局，公共 C11 ABI 可以稳定表达标识和元数据。
- 注册描述必须集中维护，代码评审需要防止 UUID 复制、Field ID 复用和无迁移的语义变化。
- 冻结模型简化查询线程安全，但动态插件和热重载必须在后续真实需求中另行设计。
- 保留未知字段需要作者文档层维护原始扩展数据，不能只把 JSON 直接转换为运行时组件后再保存。

## 替代方案

- **名称作为身份**：可读但重命名会破坏持久化数据，也容易产生模块间冲突。
- **名称哈希或编译器类型哈希**：存储紧凑，但仍继承名称或工具链不稳定性，且碰撞处理复杂。
- **全局递增整数**：C ABI 简单，但依赖中央分配和注册顺序，不适合跨模块长期演进。
- **成员偏移直接访问**：读写快，但绑定对象布局、绕过不变量，无法安全支持计算属性。
- **首版实现反射继承**：能表达对象层次，但当前 Transform、Camera 和 ECS 用例不需要该复杂度。

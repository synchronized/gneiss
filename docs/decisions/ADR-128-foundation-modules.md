# ADR-128：分层目录与完整领域构建目标

## 状态

2026-11-19 接受；实施见 [PLAN-124](../plans/PLAN-124-foundation-modules.md)。
扩展 ADR-121 的阶段方案，目标名 core 改为职责明确的 base，保留总体分层目录。

## 决策

架构层、领域模块、部署产物分别表达职责、编译依赖和链接所有权。目录无需逐个变成库，
但命名模块必须提供完整实现，不能由 Engine 补齐 Math、Meta 或日志主体。
平台能力不反向依赖运行世界和资产；文件挂载与 IPC 消息服务属于 Function。
类型按领域归属，不因结构简单或被多处使用就下沉 Core。

模块目标拥有源码与直接依赖；第三方配置不再注入自有源码。共享构建的状态由唯一动态库
持有，独立导出宏区分提供者和消费者；静态构建维护显式链接闭包。
不为模块化新增服务定位器、注册协调对象、转发接口或运行时初始化流程。

## 取舍

基础工具与测试可以独立链接，依赖方向可验证。代价是共享库导出、安装闭包和 Data/Meta
适配需要真实迁移；不采用仅移动目录或重新编译源码进 Engine 的捷径。
不选择单一大 Core 库，它会让 IO 等基础使用者获得不需要的数学与反射依赖。

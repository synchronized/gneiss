# ADR-065：分帧结构事务使用 World 发布组

状态：已接受，分阶段实现。

## 背景

用户确认 Prefab 构造、取消及大型历史恢复采用分帧事务。不能仅隐藏编辑器层级面板：
ECS 遍历、实体查询、渲染收集和相机选择也必须排除未发布对象。

## 决策

同一 World 的候选结构使用内部发布组，不引入第二个 World 或迁移实体 ID。
组只表达可见性及 World 归属，不拥有资产、场景语义或调度器。
候选对象只能通过持有对应组的内部构造接口写入；普通查询和系统遍历不可见。
所属线程完成验证及所有可失败准备后，以无分配操作发布整个组。
取消保持未发布，逐步释放候选；组不能跨 World 使用，也不能重复发布或发布后继续添加成员。

Scene Tree 必须采用同一发布边界，父子关联及主相机选择须在提交前准备，不能先修改可见状态。
Editor 镜像、作者描述、版本选择和历史提交必须与组发布组成同一无失败提交段。
没有完成这些边界前，不将局部 ECS 隔离接口接入活动场景。

## 影响与限制

发布组增加内部元数据与遍历过滤。已发布对象保留原实体 ID，正常销毁仍使旧 ID 失效。
不提供公共 C ABI 或插件接口；不把数量预算当成严格时间上限。
历史保存快照和资产租约，重建时创建新的候选组，不长期保存整套隐藏实例。

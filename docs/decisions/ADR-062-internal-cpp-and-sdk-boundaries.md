# ADR-062：内部 C++ 与外部 SDK 边界

- 状态：已接受，实施待完成
- 日期：2026-10-15

## 背景

Gneiss 已有 C ABI、C++ RAII SDK 和独立游戏模块。内部职责整理需要避免为了内部调用
重复执行 C 描述与原生类型转换，同时保持独立消费者的明确接口和生命周期约束。
用户确认内部 C++、外部 C ABI 及其 RAII 包装分工，见
[0.51 版本计划](../plans/VER-051-0.51.0-architecture-boundaries.md)。

## 决策

- 引擎内部模块通过明确的 C++ 接口协作，不要求每个内部类或方法提供 C API。
- 同源码构建的 Editor、Runtime 与工具可依赖规定的内部接口，仍禁止访问其他模块私有实现。
- 外部安装 SDK、独立动态游戏模块保留 C ABI；外部 C++ 包装基于该 ABI，完整覆盖已公开能力。
- C ABI 层负责参数校验、转换、句柄解析和异常/错误边界；业务及资源状态只存在于内部实现。
- 包装不创建第二套运行时，不让第三方原生类型进入普通公共接口；RID、线程与所有权约束不变。
- 内部原生 C++ 接口不承诺跨工具链二进制兼容，随同源码编译；公开 C ABI 也不自动等于永久兼容，
  仍须明确结构版本、调用约定、生命周期及支持平台。
- 本版默认保持已发布公共契约，不为消除内部转换直接删除公共 API；变更需独立评估迁移与消费者。

## 2026-10-16 补充决策：原生对象与 SDK 命名分离

用户确认将本项纳入 0.51，先完成 Application 纵向迁移，再推广到 World、Scene 与资产模块。
以下是已接受的目标，尚未实现，不把命名调整视为行为迁移完成。

| 层 | 目标命名示例 | 职责 |
| --- | --- | --- |
| 内部 C++ | `gneiss::engine::Application`、`World`、`SceneInstance` | 拥有实际状态，维护业务规则和生命周期 |
| C ABI | `gneiss_application_*` | 校验、类型转换、句柄解析、异常及错误转换 |
| 外部 C++ SDK | `gneiss::sdk::Application`、`ApplicationRef`、`World` | 基于 C ABI 的强类型与 RAII 包装，不拥有第二套业务状态 |

- 同源码 Editor/Runtime 通过规定的内部 C++ 模块接口调用对象；外部 SDK 经 C ABI 调用同一对象。
  内部业务不再绕回 C ABI 或 SDK 来调用自身。动态模块的真实 ABI 边界仍保留。
- 内部值类型、枚举、配置和结果语义由模块定义，C 布局转换集中在适配层。
  不为同一个内部概念新增意义相同的多套对象；RID 的类型、代次、所属服务及线程校验不取消。
- `.hpp` 是 C++ 头文件，不专属于 SDK。公共和内部可各有 `application.hpp`，依靠完整路径和
  命名空间区分；文件名保持小写下划线，不为避免同名而继续新增 `*_state` 包装。
- 有生命周期、状态转换和不变量的对象使用类及 RAII；解析、哈希、数学计算等无状态算法保留
  自由函数。真实状态快照仍可命名 State，不进行全仓库后缀替换或为了面向对象增加继承层。
- 迁移采用 PascalCase 类型名；仅随对应模块迁移更新，未迁移模块遵循原规则。
  实施时同步更新 coding-style 的适用范围，不开展无关的全仓库风格修改。
- 本次接受公共 C++ 命名空间和类型名的源码不兼容调整；现有头文件路径原则上保留。
  不提供占用旧顶层类型名的长期兼容别名。仓内示例、测试及安装消费者一起迁移并提供旧新对照。
- C ABI 符号、结构布局、RID 表示与动态模块协议不因这次命名调整改变。若实现发现必须改变
  这些契约，或需要新的长期所有权决策，应先列出影响和方案交用户决定。

## 影响

需要审计调用方、明确内部接口与私有头，补构建约束和越界反例。实现可以仍链接到同一个
Engine 库，不能因目录拆分无条件创建新 DLL。公共 SDK 测试必须继续使用安装接口。
详细模块迁移与关闭依赖在实施审计后确定，本 ADR 不表示这些工作已完成。

## 替代方案

- 所有内部调用绕经 C ABI：接口统一，但容易增加重复转换并让内部设计受对外布局牵制。
- 删除所有 C ABI：可简化纯源码消费，但会改变现有 SDK/动态模块边界，本版不采用。
- 内部 C++ 与外部包装分别持有业务状态：增加一致性和生命周期风险，不采用。

## 原生宿主关闭权（2026-10-16 已确认方案 A）

原生宿主负责它创建的 Application 的关闭。兼容 C 句柄只借用同一对象，不授予关闭权；
对借用句柄调用 destroy 返回 invalid_state。撤销桥接只撤销访问，不关闭对象。
外部 C API/SDK 创建的拥有型句柄仍由其拥有者销毁，既有 ABI 符号与布局不变。
桥接不强持有对象；对象关闭后禁止新借用访问，旧 RID 不可用于访问已关闭资源。
运行中或关闭回调重入销毁应拒绝，不能在拒绝后移除拥有句柄。

## 命名风格澄清（2026-10-16 已确认）

用户确认恢复仓库既有小写下划线；本决定覆盖上文 PascalCase 示例及风格迁移条款。
内部为 `gneiss::engine::application`，外部为 `gneiss::sdk::application`；相关类型一致采用
小写下划线。命名空间、真实对象所有权、SDK 与 C ABI 的分工保持不变，不保留大写名称别名。

## Render 快照与矩阵准备（2026-10-16 已确认方案 A）

Render 接收原生 TRS 与相机参数，基础变换值不属于场景对象。通用矩阵算法位于 Render，
不属于 Granit 后端；World 调用通用算法准备相机矩阵，实例 model/normal 仍在渲染线程准备。
本轮不改变线程分工，不把全场景矩阵工作搬回主线程，不引入第二套场景状态。
编辑器相机独立于运行时相机；资源仍由服务拥有，快照只复制值与 RID。C ABI 保持不变。
不采用由 World 预计算全部实例矩阵的方案 B，以避免同时改变主线程负载与接口边界。

## 属性值与内部头可见范围（2026-10-17）

用户确认继续收尾属性/反射 C++ 类型与模块头可见性。复用公共 C++ 类型标识、字段标识及枚举，
将其移到不包含 SDK 所有者的 `core/reflection_types.hpp`；原 SDK 包含路径不变。
内部属性快照使用拥有文本的 variant，外部 SDK 的借用文本协议保持不变；两者的差别是值的
生命周期，不产生第二套 Registry。已有 C 回调契约保留，布局转换集中在 Registry 适配及 IPC 边界。

同源码消费者通过显式 CMake 接口清单获得头文件，不再由 Editor、Runtime、资产工具 SDK 或
任务目标传递整个 `src`。构建树复制获准契约及其依赖头，原文件仍是唯一源码；清单改变后使用
新的目录，避免被移除的头残留可见。接口不安装、不创建新 DLL。场景加载值契约与私有加载器
分开，Runtime 使用借用桥而非注册表头。白盒测试独立声明私有包含目录，不提升生产接口权限。
本项收紧宿主与模块、任务与上层的边界，不宣称 Engine 单库内部已全部拆成独立编译目标。

## Scene / World 类型与实例事务（2026-10-17）

用户确认继续收敛场景值类型、Scene 封装和 Prefab 事务。World 实体/节点操作与 Scene 节点操作
使用现有 `entity_id` / `scene_node_id`；Scene 查询使用原生枚举。Scene 标识与枚举提取为
`core/scene_types.hpp`，SDK 与内部共用，不产生第二套 RID。整数表存储及真正 ABI 输出边界显式
复制标识，保留原操作失败时清零或保持输出的差异；本轮不重定义错误码、场景实例 RID 和反射回调协议。

Scene 实例定义留在私有头，节点、Prefab 容器与作者描述只由实例及所属 Scene 服务维护。
加载构建器通过只读描述和构造操作推进；服务保留跨实例资源切换与提交协调职责，不把这些状态
交给 Application 或宿主。Shared Assets、World、Scene 之间的既有所有权关系保持不变。

Prefab 候选以可移动、不可复制的 `prefab_candidate` 表达唯一运行时及作者描述所有权；Application
只通过构造、预览和分步清理操作使用它，不获得 `prefab_runtime_instance` 或其存储地址。
新增提交成功后候选为空，批量替换成功后候选接收退休对象；失败保留候选供清理或重试。
事务和它返回的借用视图必须早于 World 销毁，操作限所属线程；析构兜底释放，交互路径分步清理。

## 单实例编辑与 Application 依赖（2026-10-18）

普通单实例编辑由 Scene 实例维护 ECS、作者描述与租约的一致性；Scene 服务负责入口线程、
句柄及资产归属校验。跨实例替换和 Prefab 批量发布继续由服务协调，不为拆文件破坏事务原子性。

Application 的签名依赖独立值契约，不因 Mesh/Material 绑定或渲染统计而包含具体 Scene 服务、
World 或渲染执行器。需要使用服务的源码显式包含该服务契约。纹理加载器与内部资产加载器不作为
Application 的公共访问入口；兼容入口使用其状态查询、请求和取消方法，不直接操作加载器。
本项沿用现有对象所有权，不新建 Manager、虚接口、运行时状态或安装 SDK。

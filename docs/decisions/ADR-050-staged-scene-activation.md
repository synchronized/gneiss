# ADR-050：场景加载使用隔离候选与安全点激活

- 状态：已接受；0.42 实施中，独立候选域与宿主已接入，大场景与发布验收进行中。
- 日期：2026-09-25。

## 背景

0.41 渲染资产可以异步准备，但场景实例化仍修改所属线程上的 World、Scene Tree 和资源引用。
把现有同步加载整体移到工作线程会破坏所有权；在活动 World 中逐帧直接增加可见节点则暴露半成品。
真实大场景还可能超过单资产批次容量，仅提高限额无法同时解决停顿、峰值内存和失败回滚。

## 决策

复用宿主执行器与既有资源准备能力，以一个 Scene 加载会话关联纯 CPU 准备、分批 GPU 候选、
主线程分阶段实例化、最终激活及旧场景回收。线程池与协作模式共享请求、取消和终态语义；
提交不是立即执行，主线程拥有 World 和 Scene Tree，渲染线程独占 GPU。

候选必须与活动场景隔离，对渲染、ECS 系统、游戏查询、拾取和检查接口均不可见。仅隐藏渲染对象
不构成隔离。采用 Application 内部独立候选 World 与私有资源缓存；Scene/Prefab 服务随域拥有，
准备完成后交换活动域所有权。复用现有 World、缓存和服务实现，不新增公共 World 状态或查询过滤规则。
候选缓存中的子批次发布只影响候选，资源 Service 仍由 Application 统一拥有。

资产子批次复用 0.41 的纯准备与上传实现，但不能直接循环调用“每批发布旧 RID”的重载入口。
会话持有候选版本租约，子批次 GPU 成功不等于活动资源或场景已经应用；最终激活前不得改变旧场景
可观察的资源版本。相同 URI 的复用以版本身份验证，源变化和迟到结果必须拒绝或按明确定义重试。

会话在只读 VFS 包装层记录每份源文件的长度和 SHA-256；跨批次重复读取校验同一身份，全部资产
准备完成后再次复读验证。该检测不承诺文件系统原子快照；验证后的外部变更属于后续修订。激活后的
资源服务重新使用原始 VFS，不能继承已结束会话的版本约束。摘要实现从 tooling 下移至内部 core，
工具和运行时共享实现，避免运行时反向依赖工具模块；哈希使用固定大小工作区，不复制完整负载。

在途源、解码和上传受背压约束，已准备资源与旧场景驻留分别纳入累计预算。分批完成后仍驻留的
候选不能从预算中消失。容量不足应在可控边界报告并回收，不以无限增大缓存替代容量管理。

最终激活发生在主线程安全点，所有可失败的必要准备尽量提前完成。激活的可见步骤必须整体成功
或保持旧状态，最终步骤本身也要计时，不能以后台阶段结束掩盖一次长时间主线程提交。
旧帧持有旧资源直到消费完毕，旧场景随后按生命周期回收；首次加载失败保持加载界面及错误反馈。

场景激活许可与子批次 GPU 许可分开。激活前取消阻止新场景可见，已经接受的 GPU 命令仍需安全
收尾再回收；最终提交点后的取消明确返回过晚。每个请求仅产生一次终态，携带会话/请求身份，
迟到事件不作用于下一请求。模块激活后的任意游戏副作用不在场景事务自动回滚承诺内。

完整场景切换允许新实体身份；同一 Scene/Prefab 的结构热重载继续遵守
[ADR-037](ADR-037-scene-prefab-structural-hot-reload.md)，不能以整场景替换规避保留实体和实例覆盖。
两类事务对同一活动场景串行协调。异步入口暂留内部，既有公共同步 API 和 Game Module ABI 保持兼容。

Editor/Runtime 在可协商的 `scene` IPC 域承载完整加载、取消和阶段事件，使用独立的会话与修订身份。
资产域继续负责原有热重载，不扩大其批次上限或改变结构修订语义。旧宿主未协商场景域时不发送该域
消息。启动场景同样报告阶段事件；外部切换的终态关联原请求，切换后检查镜像和属性编辑身份失效。

## 影响与替代方案

需要显式的候选所有权和激活生命周期，旧场景与候选共存会增加内存峰值。协作模式的单次解析、
解码和驱动调用仍不可抢占；时间预算只在可暂停工作之间检查，不承诺硬实时。

拒绝工作线程直接构造 World、活动场景逐节点可见发布，以及简单提高单批上限三种方案。
全量同步加载继续作为兼容入口与性能对照，但不能承担新异步流程的主线程准备工作。
实现和验收顺序见 [DEV-042](../plans/DEV-042-async-scene-loading.md)。

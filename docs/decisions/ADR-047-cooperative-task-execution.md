# ADR-047：任务契约共用线程池与协作执行模式

- 状态：已接受架构方向，目标 0.40.0，尚未实现。
- 日期：2026-09-25。

## 背景

[ADR-046](ADR-046-task-scheduling-service-boundary.md) 确立宿主持有调度器、服务持有任务作用域的边界。
0.39 实现目前固定创建线程，尚不支持浏览器无线程宿主。已有消费者持业务锁提交任务，因此
提交时立即执行任务体会改变重入及锁顺序，不能作为透明替代方案。

Emscripten 需要与浏览器事件循环协作；多线程产物另有共享内存、部署和主线程阻塞限制。
Granit 后端支持 Web 并不会自动改变 Gneiss 的调度、主循环和服务销毁规则。

## 决策

保留一套内部任务 API 与状态模型，在创建时显式选择线程池或宿主协作执行模式。
句柄、作用域、依赖、串行顺序、取消、容量和完成回执共用实现；执行驱动与等待机制按模式分离。
不要求以公共虚基类暴露执行后端，不新增第二套业务队列或安装 ABI。

- 两种模式的 submit 均只入队，poll/query 均不执行任务体。
- 协作模式由所属宿主线程显式驱动就绪任务；禁止递归驱动，不在服务持锁提交的调用栈中运行任务。
- 驱动受任务数量与时间预算约束，在任务之间检查；无就绪任务立即返回，未来延迟由后续宿主回调推进。
- 时间预算不抢占任务。耗时解析需由业务拆分或在支持时使用后台执行，不能依靠预算自动变为异步操作。
- 关闭拆成请求停止、确认任务收尾、回收状态；浏览器主线程使用非阻塞路径。
  析构前必须完成必要收尾，仍禁止从自身任务销毁服务或调度器。
- 无线程构建不编入线程创建及等待后端；不通过 workers=0 的隐含含义或创建失败自动选择模式。
- 线程池仍是现有桌面默认模式；协作模式先用于确定性验证、最小 Web 宿主及消费者兼容性验证。

宿主按帧先处理请求，在合适阶段驱动协作任务，再消费结果并应用业务变更。具体顺序应保证
不持有消费者业务锁；跨线程数据同步和 Scene/ECS/GPU 所有权仍由服务负责。
专用渲染执行器及 libuv 事件循环不纳入本次执行模式改造。

Editor、Runtime 和工具复用调度模块，各宿主拥有实例并注入服务；不同进程不会共享同一线程池实例。
Runtime 纹理异步准备纳入 0.40，依赖模式契约稳定后实施；其资源事务边界见
[ADR-048](ADR-048-runtime-asset-preparation.md)。上述能力当前均尚未接入。

## 影响与替代方案

- 选择宿主协作队列，保持提交语义一致并允许浏览器在批次间处理事件；代价是宿主必须主动驱动。
- 不采用提交即执行的 inline 后端：它会引入锁重入、嵌套执行及与线程池不同的完成时序。
- 不要求所有 Web 构建启用 pthreads：无线程宿主是独立目标，多线程需要独立构建与部署验证。
- 不创建独立 Web 调度器：重复维护任务状态、失效与取消语义会扩大平台差异。
- 模式统一不保证吞吐、线程身份或帧时一致；公共契约测试与各执行模式专属测试需要分别维护。

实施阶段、浏览器门禁及待收口接口见
[VER-040](../plans/VER-040-0.40.0-cooperative-scheduling.md)。

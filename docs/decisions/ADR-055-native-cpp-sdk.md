# ADR-055：原生 C++ 公共类型与规范头路径

- 状态：已接受，计划在 0.47 实施；当前 0.46 尚未实现。
- 日期：2026-10-06

## 背景

现有 SDK 的 RAII 与函数覆盖不能解决普通 C++ 调用依赖 C 描述、初始化宏和裸常量的问题。
项目仍处于早期，用户确认不继续维护旧公共头转发兼容，要求两项在下一版统一完成。

## 决策

保留 [ADR-053](ADR-053-cpp-core-and-c-abi.md) 的内部 C++ → C ABI → 外部 C++ SDK 分层。
对外普通 C++ 接口使用自有枚举、标志、描述和值类型；原生值类型不意味着新建运行时或重复资源。
常规方法的输入输出不再直接依赖 C 描述或以 C 结构别名代替原生类型。
既有结果码、RAII、强类型 ID 与借用契约保持，显式原生句柄互操作与动态模块 C 导出允许必要例外。

初始化宏、`struct_size`、保留字段与指针长度留在内部适配；默认值表达对象语义。
导出及条件编译宏仍可用于基础设施，不要求公共 `.hpp` 文本完全不出现 C 类型或宏。
标准库容器和视图不跨 C ABI；转换逐字段进行，枚举与长度显式校验，不通过重解释结构布局省略转换。
借用视图必须有可说明的有效期，无法保持借用寿命时使用拥有型输出。

回调使用原生 C++ 参数，在 ABI trampoline 转换和隔离异常；上下文由明确的所有者或调用方负责。
必要的适配存储只服务于值转换及回调寿命，不建立第二套资源表、元数据注册表或任务调度。
不隐式延长 Application 生命周期，也不承诺底层接口没有提供的注销或取消能力。

公共头仅保留 `gneiss/engine/` 规范模块路径及 `gneiss/gneiss.h`、`gneiss/gneiss.hpp` 总入口。
0.47 起移除旧功能头与 `gneiss/core/` 转发头，不再新增兼容别名或重载来延续旧 C++ 调用。
本决策取代 ADR-054 公共目录补充中“保留旧路径转发”的后续版本策略，0.46 发布事实不变。
源码布局、Editor 私有边界与插件非目标继续遵循 [ADR-054](ADR-054-source-layout-and-host-boundaries.md)。

## 影响与取舍

消费者需要迁移 include 和 C++ 调用后重编译；规范 C API 的导出、布局与运行行为保持。
原生类型转换增加维护、测试和部分临时存储成本，必须通过全量语义清单而非函数名统计验收。
历史文档不重写，当前 Reference 在相应实现落地后更新。

拒绝继续以 C 别名加 RAII 声称完整原生 SDK，也拒绝让 C++ SDK 绕过 C ABI 直接暴露内部实现。
不增加与用户当前需求无关的插件、Editor API 或通用数学框架。
完整范围及验收见 [VER-047](../plans/VER-047-0.47.0-native-cpp-sdk.md)。

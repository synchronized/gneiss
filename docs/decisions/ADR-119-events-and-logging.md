# ADR-119：对象级通知与独立结构化日志

- 状态：已接受方向，适配实现待验证。
- 日期：2026-11-11。
- 实施：[PLAN-116](../plans/PLAN-116-events-and-logging.md)。

## 决策

1. 以对象拥有的强类型 Signal 为基础，发布与订阅权限分离，优先复用 EnTT；不建立全局业务事件总线。
2. 延迟广播和跨线程投递是不同能力，按实际需求使用作用域 dispatcher 与任务/mailbox，日志不依赖它们。
3. 日志业务入口采用频道 Logger，logging runtime 独立于 Application，支持启动前诊断和工具使用。
4. Gneiss 原生记录保留结构化语义；根据依赖核查，使用唯一原生队列和 spdlog 同步输出适配，
   不采用 spdlog 异步队列再叠加自有队列，不通过文本往返编码扩展字段。
5. Logger 不把每次输出成功纳入业务控制流；配置失败返回 result，运行输出失败走专门诊断。
6. fatal/OOM 输出独立于正常日志，不等待后台线程，不改变 ADR-114 的进程异常策略。

## 取舍

直接使用 EnTT 类型最少代码，但其连接借用信号、监听者，不能直接提供源先销毁安全或拥有型 lambda。
因此适配层只承担明确的生命周期与接口边界，不声称任意重入、线程安全或自动目标保活。

spdlog 标准记录不能直接携带 Gneiss 错误码和上下文；因此采用前述方案评估中的第二种接法。
代价是仍维护一份队列，但可复用现有实现，避免分离 UI 与文件各自排队后顺序和关闭不一致。
后端换库不应改变原生记录、IPC 或 Console；spdlog 类型与宏不进入普通模块接口。

Ludens 作为频道式调用参考，不直接复制其未同步频道表、仅哈希身份、持锁回调及永久存活实现。
当前生产接口未因此改变，具体 API、限制和依赖验证项以实施计划为唯一来源。

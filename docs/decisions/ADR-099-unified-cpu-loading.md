# ADR-099：统一 CPU 加载协议与缓存生命周期

- 状态：已接受。
- 日期：2026-10-31。

## 背景

通用描述请求与网格/纹理一次性数据请求分别交付共享引用和移动值，
导致调度分支、取消状态与消费方式重复。直接合并为强缓存会延长大块 CPU 数据寿命。

## 决策

asset_manager 只提供一种 load<T>/asset_request<T> 协议，成功交付共享只读 CPU 数据。
管理器负责文件读取、任务调度、在途合并和缓存；私有 Loader 负责格式步骤。
resource_service 负责创建/更新运行资源，render_service 负责 RID 和后端，二者边界不变。

CPU 缓存身份含来源域、URI、类型和完整加载参数，不用 profile generation 代替完整配置。
reload 是操作而非身份。同键在途请求共享结果，各观察者独立取消。
经后续简化，CPU 与运行资源缓存统一使用弱引用，删除策略选择。
CPU 引用及从缓存取得的类型化运行资源引用共享缓存条目控制块，Render 接收同一只读数据引用，避免为采用结果复制大块负载。
成功重载替换缓存指向；旧引用继续有效，失败不替换旧结果。
重载任务结束后，无使用者持有的旧结果照常释放，不引入版本事务。

## 取舍

弱缓存可在最后一个引用释放时立即失效，下次加载可能重新读取；这是不延长大块数据寿命的代价。
显式参数不同会产生不同缓存条目，包括读取上限，避免跨配置错误合并。
内置网格/纹理 Loader 暂不提供公共多阶段插件注册；新增真实类型时再扩展。
不增加 GPU 就绪语义、流送、同步等待或新的线程池。

历史唯一缓存决策见 [ADR-078](ADR-078-unified-asset-index.md)；当前 CPU 与运行资源各自缓存的接口见
[资产参考](../reference/assets.md)，实施见 [PLAN-094](../plans/PLAN-094-unified-asset-loading.md)。

读取额度已由 [ADR-100](ADR-100-loading-limits.md) 移至文件服务，CPU 缓存键不再包含读取上限。

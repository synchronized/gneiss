# ADR-005：资产 URI 与虚拟文件系统边界

- 状态：已接受
- 日期：2026-08-26

## 背景

场景需要引用可随工程移动的资源，不能保存绝对路径、构建路径或平台路径。相同资源还需要稳定的
缓存键，而目录挂载不能允许路径穿越或符号链接逃逸资产根。

## 决策

- 首版只接受规范形式 `asset://目录/文件`，scheme 区分大小写。
- URI 必须是合法 UTF-8，使用 `/`；拒绝空路径、空段、`.`、`..`、控制字符、反斜杠、冒号、
  查询、片段和百分号编码，不进行隐式修复或大小写折叠。
- 规范 URI 原文就是缓存键；文件系统大小写规则不改变 URI 相等语义。
- VFS 管理 URI 挂载点并按最长前缀选择后端；文件系统后端只接收相对挂载点的路径，不理解资源类型。
- Application 默认把 `asset://` 挂载到只读 `native_file_system`。本地后端对根和目标执行 canonical
  解析，最终目标必须是根内普通文件，因此指向根外的符号链接也会被拒绝。
- 首版只实现同步只读接口。归档、HTTP 或其他网络来源以后作为独立文件系统后端挂载，不改变 Loader。
- 缓存按 URI 保存单一资源类型；命中共享实例，类型冲突失败，外部租约释放后允许回收。
- 同步加载失败不永久缓存；保留该次稳定结果码，然后下一次获取重新执行 Loader。
- URI 校验属于公共 C ABI；VFS、文件系统后端、文件字节和缓存实现保持内部类型。

## 影响

场景和资源描述可跨工程位置及操作系统移动。严格规则避免多个字符串映射到同一缓存项，也避免
加载器在规范化策略上产生分歧。最长前缀挂载允许局部目录由资源包或网络来源覆盖，而资源 Loader
始终只读取逻辑 URI。调用方若接收非规范输入，必须在保存为场景前显式转换或提示错误。

## 替代方案

- 接受相对文件路径：路径与 URI 语义混合，难以替换压缩包或网络 Provider。
- 自动折叠 `.`、`..` 和重复分隔符：使用方便，但会产生别名和审计歧义。
- 百分号编码：扩大规范化和安全表面，当前没有需要编码保留字符的用例。
- 失败永久缓存：减少重复 I/O，但修复文件后无法在不清缓存的情况下重试。
- 由每个 Loader 直接访问本地、归档或网络：重复路由和安全策略，并把来源差异传播到资源层。

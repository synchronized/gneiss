# ADR-081：共享 Engine 分配运行期类型身份

- 状态：已接受；实现已接入，运行验证待统一执行。
- 日期：2026-10-24。

## 决策

移植 CAORS 的类型名集中注册机制，用 `engine::type_id` 标识当前进程内的 C++ 类型。
资源缓存和 Loader 使用这一类型键，替代 `std::type_index`。注册表实现只编入 Engine；
模板只提取规范名称并缓存返回值，不在每个模块独立分配编号。

ID 为非零顺序编号，void 对应无效 ID。名称由注册表持有，首次注册受互斥锁保护。
初始化内存不足或编号耗尽沿用 CAORS 的不可恢复策略，不返回可能造成类型混淆的替代编号。
不引入能力注册表、字段反射、调试快照系统或 CAORS 分配器。

反射稳定身份直接使用 `engine::type_guid`，删除原根命名空间的 `gneiss::type_id`。
原 `runtime_type_id` 更名为 `engine::type_id`，不保留兼容别名；二者无隐式转换。
既有组件 GUID 字节、场景文件中 32 位十六进制编码和 `type_id` 字段名保持不变。
`type_name<T>`、`type_identity<T>` 作为静态定制点移到 `core/traits`，不参与运行期编号分配。

## 边界

运行期 ID 不持久化，不替代已有 16 字节资产/组件身份或 GUID。名称一致依赖相同工具链、ABI
和 ODR 定义，注册表不检测同名不同布局；匿名、局部类型不得作为跨模块资源契约。
共享模块必须链接同一个 Shared Engine，不允许各模块静态嵌入一份 Engine 后声称进程唯一。
静态构建只承诺同一个链接映像中的统一身份。编译器类型名仅作为注册表内部去重键，
不提供按 ID 反查名称的接口；展示名称由显式元数据提供。

## 反射关联

反射定义可显式绑定运行期 `type_id`，但其稳定身份仍是 `type_guid`。
模板注册和查询只适配 C++ 身份，不自动推导名称、GUID、字段或访问器。
Registry 内运行期索引指向已有类型记录，不复制元数据；GUID 与非空运行期 ID 均不允许重复注册。
未绑定 C++ 类型的数据描述只按 GUID 查询，运行期 ID 不暴露到反射查询结果或持久化协议。

## 替代方案

继续使用 RTTI 最简单，但无法显式控制类型键的登记与诊断入口。仅使用名称 hash 会引入碰撞
处理；全局编号加字符串判等避免将 hash 当身份。持久化 GUID 适合保存格式，不应为每个普通
CPU 资源类型增加持久化身份维护要求。

## 验收

编译跨翻译单元、cv/ref 归一、不同类型、数组名称、并发首次注册、重复登记和注册后 ID 稳定性用例；
资源缓存/Loader 的现有功能用例改用新键。按当前授权不执行这些用例，最终运行验证单列待办。

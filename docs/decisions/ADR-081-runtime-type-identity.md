# ADR-081：共享 Engine 分配运行期类型身份

- 状态：已接受；实现已接入，运行验证待统一执行。
- 日期：2026-10-24。

## 决策

移植 CAORS 的类型名集中注册机制，用 `engine::runtime_type_id` 标识当前进程内的 C++ 类型。
资源缓存和 Loader 使用这一类型键，替代 `std::type_index`。注册表实现只编入 Engine；
模板只提取规范名称并缓存返回值，不在每个模块独立分配编号。

ID 为非零顺序编号，void 对应无效 ID。名称由注册表持有，首次注册受互斥锁保护。
初始化内存不足或编号耗尽沿用 CAORS 的不可恢复策略，不返回可能造成类型混淆的替代编号。
不引入能力注册表、字段反射、调试快照系统或 CAORS 分配器。

## 边界

运行期 ID 不持久化，不替代已有 16 字节资产/组件身份或 GUID。名称一致依赖相同工具链、ABI
和 ODR 定义，注册表不检测同名不同布局；匿名、局部类型不得作为跨模块资源契约。
共享模块必须链接同一个 Shared Engine，不允许各模块静态嵌入一份 Engine 后声称进程唯一。
静态构建只承诺同一个链接映像中的统一身份，Engine 卸载后名称视图失效。

## 替代方案

继续使用 RTTI 最简单，但无法显式控制类型键的登记与诊断入口。仅使用名称 hash 会引入碰撞
处理；全局编号加字符串判等避免将 hash 当身份。持久化 GUID 适合保存格式，不应为每个普通
CPU 资源类型增加持久化身份维护要求。

## 验收

编译跨翻译单元、cv/ref 归一、不同类型、数组名称、并发首次注册和名称存储用例；
资源缓存/Loader 的现有功能用例改用新键。按当前授权不执行这些用例，最终运行验证单列待办。

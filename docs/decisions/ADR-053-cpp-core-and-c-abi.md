# ADR-053：内部 C++ 实现与 C ABI、C++ SDK 分层

## 状态与背景

2026-10-05 接受，0.45 实施中。当前 API 入口、内部导出和服务实现的边界需要收紧；
文件名配对不代表公共 C++ 包装完整。实施范围见 [VER-045](../plans/VER-045-0.45.0-cpp-boundaries.md)。

## 决策

外部 C++ SDK 调用公共 C ABI，公共 C ABI 委托内部 C++ 实现。内部模块直接调用所属模块的 C++
契约，不反向依赖外部 RAII 层。Scene Tree、ECS、Service 与后端的现有方向不变。

内部使用 C++20 类型、容器、引用、span 与明确所有权；不为消除所有 `gneiss_` 字样机械复制纯值类型。
ABI 描述中的 `struct_size`、指针长度、保留字段与旧布局处理留在适配入口，内部接收校验后的语义对象。
内部头按 C++ 内容使用 `.hpp`；公共 `.h` 保持 C11。已有内部 `.h` 随模块迁移，不全仓一次改名。

公共 C 入口集中于单独的适配目录（当前 `src/api/c/`，迁移目标见 ADR-054），按功能拆分。入口可以解析句柄、检查 ABI 参数、转换错误和隔离异常，
不得成为场景调度、资源加载或业务规则的第二个实现。句柄注册表必须只有一个所有者，清单明确其
所在模块；C 入口与内部宿主共享内部契约，不重复注册同一对象。

内部实现继续按状态所有权划分；后端只能由对应 Service 依赖。Render 资源的 GPU 生命周期属于
Render，格式解析、解码、缓存与资产任务依据依赖图归入 Asset 或其子模块；离线 Cook 归 Tooling。
不建立职责重叠的 `resource/` 或可被任意模块访问的通用后端目录。
Render 定义只含值与 RID 的提交快照；World 负责提取，Render 不反向包含 World/Scene 的状态或接口。
独立 PNG 解码归 Asset，Cook 与运行时加载复用同一解码实现；GPU 候选、上传和镜像仍归 Render。

公共包装保持轻量、无第二套状态：拥有资源使用不可复制、可移动 RAII；借用使用 ref/view；
实体及资源 ID 是强类型值，不自动意味着拥有。包装通常只保存父句柄与资源句柄，不为安全性
隐式延长整个 Application 生命周期。父资源先失效时借用操作报告失效，析构必须安全且不抛异常；
具体关闭、等待和线程限制逐项写入契约，不能靠忽略错误掩盖未释放资源。
拥有型包装的显式关闭返回结果；关闭失败时保留句柄，父服务或资源已失效视为释放完成。
既有 Application、World、Scene、Registry 的 reset() 从 void 改为 result，直接调用语句兼容；
绑定旧成员函数指针类型的代码需更新。release() 显式转移原始所有权，不改变资源线程约束。
析构或移动覆盖违反线程约束导致关闭失败时终止进程，避免静默泄漏；不隐式跨线程调度销毁。

回调适配拥有明确的上下文寿命与注销规则；异步请求销毁不自动承诺已完成取消。公共 C++ 包装的
“完整”按 C 功能和可用性验收，不要求每个标量或查询都变成 RAII 类。

宿主私有导出先分类：通用外部能力可补入公共 C ABI 与包装，宿主专用能力放入不安装的内部接口，
必要的同版本 C++ 跨库接口明确为私有且不承诺 ABI 稳定。不得直接把内部类导出成第二套公共 SDK。

## 目录与构建约束

目标布局已由 [ADR-054](ADR-054-source-layout-and-host-boundaries.md) 更新：src 下组织 Engine、Editor、
Tooling 实现，根目录 apps 组织程序入口；Engine 内按功能、资产、基础与平台分层。本决策不再维护第二份目录树。
当前物理路径见 [源码目录说明](../concepts/repository-layout.md)，迁移步骤见 DEV-045。

通过 target 私有链接、包含范围和依赖检查约束方向；不强制每个目录成为独立动态库。
最终安装目标保持既有消费方式，第三方头、编译定义与原生句柄不向普通 SDK 传播。

## 取舍

拒绝只搬目录而保留循环调用，也拒绝内部经 C ABI 互调以及对外另建独立 C++ 运行时。
代价是边界转换、包装生命周期和兼容验证增加；收益是核心职责唯一、外部 ABI 清晰且 C++ 使用完整。
迁移逐模块进行，先验证小闭环再推广，不将机械重命名和行为修复混成无法评审的大提交。

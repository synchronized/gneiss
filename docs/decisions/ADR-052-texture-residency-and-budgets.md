# ADR-052：纹理驻留与加载预算

- 状态：已接受设计方向，待实现；数值预算与具体接口在 M-286 审计后确定
- 日期：2026-09-30

## 背景

运行纹理封装已有 BC7 与 RGBA8 变体，但当前加载器保存整个负载，由渲染后端选择上传变体。
完整大场景还会叠加文件、解码、候选和上传副本；只缩小 GPU 格式不能保证 CPU 峰值降低。
现有不可变帧快照和多纹理租约要求保持依赖有效，不能简单在上传调用返回时清空纹理数据。
版本目标见 [VER-044](../plans/VER-044-0.44.0-texture-residency.md)。

## 决策

1. **设备选择留在后端边界。** 在后端允许的线程查询能力并产生不含 Granit 原生类型的不可变描述，
   工作线程依据选择结果读取资产。描述绑定设备代次，失效时重新选择；不使 ECS、Scene Tree 或公共 ABI
   依赖 renderer、Manifest 原生类型或后端句柄。
2. **只准备需要上传的变体。** 封装及 RGBA8 回退保留在持久资产中，CPU 准备对象只拥有所选负载。
   元数据、范围、Mip 与内容完整性仍须验证；全文件哈希可分块进行，不要求全文件驻留。
   现有 VFS 不足时扩展其最小通用能力，不为单一纹理绕开包路径或完整性规则。
3. **释放依赖明确的生命周期。** CPU 负载以租约保持到上传实际完成及所有相关读取结束。
   只对有可靠、版本固定重建来源的资源允许随后释放；无来源的内存纹理保留原有语义。
   不修改仍被旧帧持有的不可变快照。释放策略须覆盖重新上传、回读、后端重建及错误恢复。
4. **预算按实际所有权计量。** 在现有 Application 与 Service 装配边界协调活动资源、候选和上传暂存，
   分配前预留，成功后转为实际占用，所有权结束才退还。共享租约只计一次，转为活动资源时转移归属。
   候选失败不销毁旧场景；不得通过统计归零掩盖仍由帧、缓存或上传任务持有的内存。
5. **预算与系统指标分开。** CPU 候选上限继续为 2 GiB；其他限额根据 M-286 测量确定。
   预留字节、实际服务占用、进程 RSS、GPU 逻辑字节和驱动驻留分别报告，不能互相代替。
   本版不建立全引擎通用内存管理器，也不增加任务池。
6. **身份与提交保持一致。** 准备缓存区分内容版本、颜色/法线等语义、格式/Mip 和设备选择配置。
   发布前复核设备代次及资产版本；取消或失败只清理候选，迟到结果不能修改已切换的场景。
   同一资源的帧、材质和上传依赖沿用现有 RID/租约模型。

## 影响

读取和上传阶段将新增选择与预算协调，缓存命中和设备重建需要显式处理失效。
稳定重建来源可能保留磁盘缓存或文件租约，其成本需要测量；磁盘文件存在本身不足以证明内容不变。
RGBA8 回退保证格式兼容，不保证完整未压缩场景符合当前内存预算。
格式升级、公开 API 扩展或 Granit 新接口仅在审计确认必要后提出，不作为本决策已存在的能力。

## 替代方案

- 直接提高候选上限：保留重复副本，不能解决跨场景峰值与取消期间的占用，不采用。
- 始终保留全部变体或总是展开 RGBA8：简化重试，但削弱压缩带来的内存收益，不作为文件纹理默认方案。
- 上传调用返回即释放：无法证明 GPU、暂存和旧帧不再引用，违反所有权约束，不采用。
- 先引入虚拟纹理或完整流送系统：扩大格式与渲染范围，当前先完成可测量的整纹理加载闭环。

## 待审计事项

Granit 公共选择接口及完成回执、VFS 区间读取与内容固定方式、重建契约、可共享负载身份、
预算数值与画质阈值由 [DEV-044](../plans/DEV-044-texture-residency.md) 的 M-286 收敛。
若发现通用上游能力缺失，先记录可复用需求，由用户负责 Granit 提交。

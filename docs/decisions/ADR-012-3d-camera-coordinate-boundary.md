# ADR-012：3D 坐标、Camera 与后端变换边界

- 状态：已接受
- 日期：2026-08-27

## 背景

`0.4.0` 的场景使用二维正交投影和显式 Z 排序，尚未定义可供 Camera、深度测试、光照、物理和
编辑器共同使用的 3D 坐标约定。若矩阵布局、观察方向或裁剪空间转换分散在组件、资产和后端中，
后续模块会产生相互不兼容的变换。

## 决策

- Gneiss 世界空间采用右手坐标系，`+X` 向右、`+Y` 向上，Camera 局部前方为 `-Z`。
- Transform 保持平移、四元数旋转和缩放的纯数据表达；公共 ABI 不暴露后端矩阵类型。
- 内部矩阵使用列主序存储、列向量和右乘组合；公共 ABI 暂不暴露矩阵。
- Camera 组件只保存投影类型和参数；视图矩阵由其实体的世界 Transform 推导。
- Camera 世界缩放不参与视图矩阵；旋转四元数在构造视图矩阵时归一化，零长度旋转无效。
- 首版只支持透视 Camera，并要求有限的垂直视场角、正数宽高比以及 `0 < near < far`。
- Render Snapshot 保存渲染所需的值副本，不保存 Camera、节点或后端对象指针。
- 引擎空间到 Granit/Vulkan 裁剪空间的 Y 方向和深度范围适配只发生在 Granit Render Service 边界。
- 已知点测试固定 Camera 平移与旋转、近平面深度零、远平面深度一和帧缓冲 Y 方向适配。

## 影响

- 场景、ECS、序列化、编辑器和未来物理服务可以共享同一世界空间定义。
- Granit 之外的后端可以独立适配自身裁剪空间，而不改变资产或公共 Camera 数据。
- 现有 2.5D 资产仍可位于 XY 平面；迁移到 3D 时不需要交换 X/Y，但需使用 Camera 和真实深度。
- 矩阵布局成为长期兼容约束，实施前必须先验证现有 Transform 组合行为。

## 替代方案

- 直接采用 Granit/Vulkan 坐标和矩阵类型：接入简单，但会把后端约定泄漏到公共 API 和资产。
- 使用左手坐标系：与部分工具链一致，但不符合当前四元数和常见跨平台图形约定的预期方向。
- 各后端自行解释 Camera 参数：短期灵活，但会导致场景可见性和深度结果不一致。

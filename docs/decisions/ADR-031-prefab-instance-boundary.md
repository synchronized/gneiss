# ADR-031：Prefab 使用引用实例与复合作者身份

## 状态

已接受，2026-09-03。

## 背景

当前场景可以复制子树，但复制结果与来源完全分离。Lantern Gallery 等工程中的重复灯架需要保存多份
节点；修正原型后必须逐份修改。若直接把 Prefab 展开写回场景，会失去来源关系并让更新传播、撤销和
冲突处理依赖脆弱的结构比较。

## 决策

- Prefab 是独立、版本化的作者资产，保存单棵节点树并复用现有 Transform 与组件值语义。
- 场景保存 Prefab URI、实例 UUID、父级和实例根 Transform，不保存展开后的源节点副本。
- Prefab 内节点以源节点 UUID 标识；场景中的实例节点以“实例 UUID + 源节点 UUID”复合寻址。
- 复合作者身份只用于作者模型、Editor 命令和序列化；Runtime 仍使用当前会话的 Entity ID、Scene
  Node ID 与检查对象 generation，不把作者身份当作 RID。
- Scene Instance 负责解析引用、预取依赖、创建 Runtime 投影和失败回滚，继续作为唯一可写作者边界。
- 首版只允许修改实例根名称与 Transform。源子节点在 Hierarchy 中可见但只读；不建立任意字段覆盖。
- Prefab 更新以显式刷新或重新打开场景传播。刷新需要原子替换实例投影，并尽量恢复选择；失败时保留
  旧实例和作者声明。
- v1 拒绝嵌套 Prefab、引用环、缺失源、多个根和实例 UUID 冲突。

## 影响

- 同一 Prefab 的多个实例共享来源和资源缓存，但各自拥有独立 Runtime 实体、组件与资源租约。
- Editor 命令不能继续假设所有目标只由单个场景节点 UUID 表示，需要支持明确的复合作者地址。
- 场景格式需要新版本表达实例声明；旧场景迁移后语义不变。
- 任意子节点覆盖、Apply/Revert、Unpack、嵌套 Prefab 和 Variant 需要独立需求与后续 ADR。

## 替代方案

- 保存展开副本并附加来源标签：拒绝，来源更新与本地修改难以可靠区分。
- 使用运行时 Entity ID 或 RID 标识实例节点：拒绝，这些标识不能跨重建和保存稳定存在。
- 首版直接实现任意属性覆盖和嵌套：拒绝，在基本引用与生命周期尚未验证前会过早冻结复杂合并语义。

# ADR-085：渲染资产分阶段读取与纯内存解码

状态：已接受。

## 背景

旧准备器在 CPU 任务里推进文件打开、范围读取、摘要和解析，并允许同步回退。
这使异步调度、数据格式和 GPU 就绪语义耦合，也让浏览器接入难以保证不阻塞。

## 决策

文件服务独占异步 I/O；运行时加载服务串联读取和 CPU 解码，渲染服务独占上传和 GPU 生命周期。
复用纹理描述、容器 Manifest 和网格头部，不为相同元数据增加第二套持久描述。
先整读后解码，运行时保留所选纹理变体的 CPU 数据；恢复上传不再依赖同步文件来源。
材质依赖、稳定 RID 和更新失败保留旧资源的规则不变。同步工具接口保持显式同步。

## 影响与替代方案

优点是文件等待不消耗 CPU 任务，后端差异收敛到 file_service，纯解码易于验证。
代价是整读临时输入和选中变体的 CPU 常驻内存；未来流送再引入有界分块和异步恢复。
现在直接实现 mip/LOD 流送会引入尚未需要的调度和 GPU 驻留协议，因此不采用。
直接给每种资源增加 JSON 会重复已有容器信息，也不采用。

实施范围与验收见 [PLAN-052](../plans/PLAN-052-async-render-assets.md)。

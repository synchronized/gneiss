# ADR-095：场景当前状态以编辑 World 为准

状态：已接受，实施见 [PLAN-082](../plans/PLAN-082-scene-data-authority.md)。

## 背景

Scene 同时维护可变描述和 World，编辑操作双写，保存又从 World 覆盖描述字段。
描述数组与节点数组的下标关系隐含了保存成员与 Prefab 展开成员的区别。

## 决策

- 编辑 World 是名称、层级、变换及组件当前值的权威来源。
- Scene 管理保存成员、场景身份；Prefab 实例记录管理来源、映射和显式覆盖。
- description 用作加载输入、保存输出、快照；不作为普通对象的第二份可变状态。
- 游戏运行状态与编辑状态隔离，临时对象不因挂入树中而自动参与保存。
- 资源选择准备成功后才提交；失败保留旧引用及 URI。无持久化身份的组件拒绝保存。
  当前不引入未解析 URI 组件；未来若支持失败占位，须先定义目标身份与解析引用的独立存储。
- Prefab 修改与覆盖更新是一项局部操作；不引入全局发布或事务框架。
- 重载使用当前捕获结果计算差异；若未来需要三方合并，单独定义只读基线。

## 取舍

描述驱动适合离线编辑，但会增加当前 World 交互的同步工作；完整双向同步成本更高。
选择对象驱动可减少双写，但需要组件安装/捕获对称、保存归属和失败资源身份契约。
Prefab 的覆盖意图仍须单独保留，不能只根据运行值推断。

## 编辑资源准备的职责边界

实施见 [PLAN-097](../plans/PLAN-097-editor-resource-preparation.md)。

编辑命令通过 Application 借用既有 `scene_service`，由其检查宿主线程、关闭状态和场景加载互斥。
`resource_load_group` 统一复用就绪引用、筛选缺失资源和汇总异步结果；不另建编辑器加载服务。
Application 保留 I/O 推进和关闭职责，不提供编辑专用缓存查询、清理或资源准备方法。
缓存过期项由正常资源推进清理，编辑命令只释放自己的强引用。

编辑器可包含协调服务的原生头文件；`scene_domain` 和 `resource_load_group` 实现头仍不对宿主开放。
这增加一处显式原生服务依赖，但避免在 Application 中逐项复制编辑操作。资源选择和 Prefab
操作继续负责文档身份检查、撤销及提交，服务不接管编辑器文档。

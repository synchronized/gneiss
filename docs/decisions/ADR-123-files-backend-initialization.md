# ADR-123：Files 后端工厂与服务初始化

- 状态：已接受
- 日期：2026-11-17

## 决策

后端工厂只构造对象和保存配置，不执行异步准备。外层使用类型化配置、create_backend_xxx
及 backend 接口；具体类和非共享辅助定义放入 cpp。Native 借用执行器，生命周期不得早于
后端请求结束；Browser 的共享实现用于异步保活，不为隐藏类而额外增加 PImpl。

宿主先配置 service 的挂载，再调用一次 initialize。服务按后端对象身份去重并冻结挂载；
全部后端成功且完成通知被分发后才接受 I/O。提交初始化成功只表示接受，最终结果只在
所属线程 dispatch_completions 中通知。后端可以内联或跨线程完成，用户通知行为保持一致。

初始化不使用文件请求并发额度或字节预算，但完成通知占用分发预算。没有挂载也延迟通知成功。
失败保留首次完成失败的原因，等待所有已接受初始化收尾后通知一次；不自动重试或回滚配置。
resolve_source 属于挂载元数据查询，不要求 I/O 已就绪。

初始化期间 shutdown 拒绝新工作，等待已接受初始化完成，先通知初始化 cancelled，再通知
关闭成功。析构放弃用户通知，迟到回调只持有独立完成状态与后端，不访问已销毁服务。
每个后端由一个服务负责初始化和驱动，不增加跨服务共享初始化状态。

Application 只接收服务级完成通知；内联完成通过一次分发处理，异步完成由主循环继续分发，
不阻塞等待。环境资产在完成回调后请求；文件初始化未完成时暂不执行业务更新。
当前 Application 配置选择 Native、Fetch 或 existing 浏览器目录，不增加持久化启动配置。

## 取舍

保留统一异步边界和关闭语义，宿主不维护各后端 ready 标志。没有实际消费者前不提供公开状态
枚举、重试入口或通用后端枚举配置。Web 既有实现随路径迁移，完整导出仍按路线图另行推进。

接口事实见 [文件服务参考](../reference/file-service.md)，实施见
[PLAN-119](../plans/PLAN-119-engine-build-test-layout.md)。

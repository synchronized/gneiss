# ADR-105：序列化格式边界

状态：已接受。日期：2026-11-05。

## 决策

Meta 负责类型与属性访问；序列化放入 `engine/core/serialization`。
JSON 入口显式位于 `serialization::json`，文本输出与字节输出分别命名。
资源专用二进制 codec 仍负责自身格式，不由 JSON 入口猜测或选择。
当前注册表的字节 codec 在嵌套值中实际要求 JSON，应明确标注该限制。

字段、容器与引用遍历通过 reader/writer 访问格式后端，不依赖 yyjson。
JSON 节点适配限定在专用接口；不增加第二套反射注册表或通用 DOM。
第二种格式有真实使用需求后再实现，不预先增加 MessagePack 依赖。

## 影响

内部调用显式选择格式，不保留含糊的 Meta 序列化别名。
迁移保持文件布局、诊断及对象引用语义；格式专用回调仍可保留。
不得把接口搬迁描述为已经完成格式无关遍历。

序列化基础设施可以内部取得默认注册表；业务调用继续使用无 registry 重载。
边界检查同时覆盖 Meta 和 Serialization，场景描述值仍不得包含这些执行接口。

## reader/writer 的最小边界

当前采用后端借用节点和游标，不复制一份通用 DOM。JSON 后端直接包装 yyjson 节点；
共享遍历负责字段、容器、引用、校验与路径。后端负责结构节点与标量映射。
与 caors 的事件接口相比，此方案保留现有节点 codec 的零重编码接入方式；
代价是它不是前向流式 writer，未来真正需要流式输出时再扩展。
反射开关与未知字段策略提升为格式无关配置；JSON 节点/字节回调仍为专用扩展。

## 统一调用上下文

通用与 JSON API 采用 context-first，默认便捷入口内部建立 context。
注册表选择与深度限制集中到 context；递归状态私有，格式回调沿用同一个上下文。
显式注册表不再作为序列化入口的独立参数；视图与 context 不匹配时拒绝操作。
配置通过 const 引用借用，运行状态可变，因此禁止并发共用，允许失败后顺序复用。
不增加无实际调用场景的 resolver、factory 或第二套对象身份系统。

## 类型与文件包装分离

类型注册只描述字段、校验和必要的通用 reader/writer 编解码，不注册 JSON 专用回调。
资源 format/version 与文件大小限制属于资源文件入口，不能随着描述对象嵌套而传播。
value 的标签和多态内容通过通用结构操作表达，JSON 后端只负责节点及基础标量。
本次替代之前保留的 JSON 专用注册方案；既有资源文件布局保持不变。

### 类型能力归属补充

类型构造、基类转换和反射对象转换归入 Meta 的 object_ops；序列化绑定仅保留字段遍历、
多态保存策略、编解码和原有校验回调。诊断归入 serialization。两种能力仍由同一 Meta
注册表保存，不新增注册表或运行时状态。内部 JSON 节点适配使用 json::detail 命名空间。

# ADR-029：Runtime 检查使用只读镜像模型

- 状态：已接受
- 日期：2026-09-02

## 背景

0.15.0 已建立 Editor 与独立 Runtime 间的版本化本机 IPC，但 Editor 只能观察宿主状态和日志，不能
查看 Runtime 中真实存在的场景节点、组件属性和更新统计。直接让 Editor 访问 Runtime 内存会破坏
进程隔离；让 IPC 线程访问 Scene Tree 或 ECS 则会违反主线程所有权。

## 决策

- Runtime 主线程从 Scene Tree、ECS 和统计源生成有界、可序列化的检查快照；I/O 线程只负责传输。
- Editor 为每个运行会话维护独立只读镜像，不把运行态对象写入作者场景，也不复用作者对象指针。
- 对象身份由会话 ID、运行时对象 ID 和 generation 共同限定；对象 ID 只在所属会话内有效。
- 首次连接或明确请求时发送完整快照，随后发送带单调序号的增量批次。Editor 检测到序号缺口时丢弃
  增量并请求新的完整快照。
- 属性值使用既有稳定 Type ID、Field ID 和受限值类型表达，不传输 C++ 对象布局、原生指针、RID
  后端内容或第三方类型。
- 0.16.0 的检查能力只读。未来运行态写入必须另行定义权限、事务、冲突、撤销和持久化语义。
- 检查、统计和日志使用独立的有界队列预算；控制消息优先，检查流量不得阻塞 Pause、Resume、Stop
  或心跳。

## 影响

- Editor 可以展示 Runtime 的真实场景树和属性，同时保持作者会话与运行会话隔离。
- Runtime 必须在主线程安全点采样；快照频率、单批大小和每帧预算需要显式限制。
- 断线、重连或新一轮 Play 会创建新镜像，旧会话消息不得污染当前视图。
- 只读模型暂不支持运行时调参，但避免在缺少事务语义时形成不可预测的作者数据回写。

## 替代方案

- 共享内存或进程内嵌 Runtime：吞吐更高，但扩大平台复杂度并削弱崩溃隔离。
- Editor 直接读取场景文件：只能看到作者数据，无法证明 Runtime 的真实状态。
- 首版即支持双向属性编辑：交互更强，但需要同时解决校验、冲突、撤销和持久化，超出本版本闭环。
- 每帧发送完整场景：实现简单，但带宽、解析和 UI 更新成本随场景规模快速增长。

# ADR-110：统一 Game Object 存储与 Prefab 文档边界

## 状态

2026-11-07：已接受，实施见 [PLAN-105](../plans/PLAN-105-game-object-runtime-model.md)。
本决策调整 ADR-109 中组件身份由 component_entry 外壳保存的选择，并将场景树/实体双存储
收敛为同一实体上的运行层级；既有实现不会因决策接受自动视为已迁移。

## 决策与原因

component_description_base 保存组件 UUID，类型 GUID 继续表达类型。
组件领域基类本来就具有实例语义，外置包装造成重复访问和身份传递；不向 meta::object 注入场景身份。
共享描述保持只读，编辑/复制创建独立候选，不能原地修改共享 UUID。

game_object_description 通过 optional prefab 表达来源；Prefab 存在时独立 components 必须为空。
相较 scene_entry variant，通用身份、名称、层级和变换操作更直接，代价是领域校验负责互斥约束。

Prefab 来源和覆盖归文档，组合后产生完整有效对象。运行对象不记录覆盖或在赋值时生成覆盖。
编辑器维护来源地址到实体映射；运行时实例化和编辑器保存不共用一套可变记录。
加载回执向编辑器交接本次实例化的固定内容和实际资源身份；接管不从 World 反推作者描述，
也不再次读取可能已经重载的资产当前内容。失败/取消回执释放这些引用。
需要来源热重载的 Runtime 协调器保留激活时固定内容与地址关联，作为比较基线；
它不是可编辑文档，不维护编辑历史，也不把这些数据放入 World 或组件。

World 唯一拥有实体、组件和场景成员；game_object/scene_instance 为非拥有访问句柄。
World 内部独占场景集合，宿主场景域只拥有 World；场景集合先于 ECS 析构。
资源服务由宿主保证比 World 更晚销毁；场景借用句柄不能延长 World 寿命。
层级是同一实体的数据，删除独立节点到实体的第二套生命周期。
删除具有层级的实体等同于删除其整棵对象子树；不留下脱离实体的节点。
世界变换继续即时派生，本次不增加未经性能需求验证的脏标记缓存。
运行句柄校验 generation 与 World 归属，描述 UUID 由场景实例域限定。
不让 game_object 继承 meta::object 或使用强引用延长已删除实体的寿命。

## 2026-11-08：统一组合与应用边界

以文档 → 纯组合 → 通用运行应用为唯一迁移主线，不继续逐个包装旧运行作者接口。
组合属于 Engine 的无状态能力，接收描述及显式固定来源，不读取文件、不访问 World 或编辑历史。
Editor 只负责从不可变文档恢复输入；Runtime 和 Editor 必须使用相同的展开与地址规则。

文档对象描述允许 Prefab 引用与覆盖，组合对象表示完整有效内容；相似字段不构成长期双份权威状态。
组合结果为临时值，来源关系随实例化回执交给需要它的调用方。World 不保留作者地址、覆盖表或
为保存服务的 persistent 分类。运行资源引用由实际组件持有。

首次实例化视为空集合到目标集合的应用，编辑同步按对象地址增删和更新。共同应用逻辑不得
出现 Prefab 专用更新分支。不引入新的版本发布、通用事务或隐藏旧实例保活机制。

撤销只修改文档：属性保存前后值，组件保存独立描述，删除子树保存文档子树及必要资源引用；
确需整体替换时可使用文档快照。value 中的共享对象引用不得直接充当不可变历史快照。
不增加与 entity_id 同生命周期且同用途的稳定实例 ID；文档地址负责跨重建定位。

## 2026-11-08：Runtime 来源刷新

正式加载路径直接实例化组合后的普通对象。来源刷新由 Runtime 协调器持有固定来源快照与
对象地址关联，再调用共享组合和应用；IPC 消费显式回执，不反查 World 的 Prefab 状态。
Prefab 根节点也是普通成员，其运行 UUID 不借用外层实例 UUID，避免根角色变更导致身份冲突。
来源未修改的变换保留游戏运行值；来源显式修改变换时使用新来源值。
解析或校验失败不更新基线；运行应用不提供回滚，应用失败或存储失配后标记基线失步，
必须重新激活场景，不能继续假定旧基线仍代表 World。
旧手动实例化和捕获路径仍待迁移，不能据此声称 World 已完全删除 Prefab 状态。

## 2026-11-08：子树历史归属

子树快照是 Editor 文档历史的值，不是 Engine 场景实例的能力。
删除运行集合的 capture_subtree/restore_subtree；运行层保留普通创建、组件安装和递归删除，
恢复历史由 Editor 导入冻结描述后调用通用投影完成。快照类型及冻结内容恢复函数归属
Editor 文档模块，Engine 不依赖它们。

## 影响与替代方案

保留节点与 ECS 双存储可以隔离树遍历，但增加身份同步、删除和失效边界。
全部改为 refcount 对象更接近传统对象树，却与现有 ECS 所有权重叠；本次不选择。
采用统一实体存储需要迁移层级、渲染采集、场景卸载和编辑器关联，不能只更名后宣称完成。
原决策允许文档历史保留前后不可变版本及完整重建。2026-11-08 此项由
[ADR-111](ADR-111-document-history-projection.md) 调整为局部变更历史与统一增量投影。

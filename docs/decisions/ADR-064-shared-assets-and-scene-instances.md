# ADR-064：共享资产与场景实例分离

- 状态：已接受设计方向，实施待完成
- 日期：2026-10-15
- 关系：补充 ADR-063；调整其目标命名和资产所有权，不改变协调层归属

## 背景

当前 `application_scene_state` 各自拥有资产缓存和加载器，底层渲染资源服务共享。
跨域共享渲染服务不等于按资产身份复用缓存。仅抽出 `scene_session` 不能解决这个边界。
用户要求将场景视为资产、明确资产依赖与运行实例，并先将讨论方案落地到文档。

## 决策

- 场景资产是可共享、可多次实例化的描述；场景实例是实体、节点映射和运行状态，二者分离。
- World 是 ECS 与 Scene Tree 的运行数据容器；运行上下文拥有一个 World 及其场景实例服务，
  不等同单个场景实例。当前 application_scene_state 按这个职责演进；资产缓存迁出后再评估
  world_context 更名，不新增平行上下文对象。打开场景时替换整个运行环境是当前策略，
  不把场景资产、场景实例与 World 固定为一一对应关系。
- 资产系统管理身份、依赖、加载和缓存。场景实例持有资产使用引用，不独占一套共享资产缓存。
- Application 拥有资产系统实例，显式注入依赖；不是进程全局单例，不引入全局服务定位器。
- 资产管理器负责通用机制，具体资产格式和解析仍归对应模块，经注册的加载接口协作。
  asset 模块不得反向包含 scene、render、application 或 Granit 私有实现。
- 资产依赖与对象组成分别表达：对象包含组件描述，组件引用资产；不把每个组件变成独立资产。
- ECS 组件继续只存纯数据或 RID；资产使用引用由场景实例的资源持有记录管理。
- 同一资产的兼容版本可跨场景复用；使用引用保持版本存活。管理器统一管理不等于永久强持有。
- 候选与已发布资源隔离。新场景加载失败或取消不得改写旧场景正在使用的资产版本。
- 请求与共享任务分离；取消一个请求仅撤销该请求的需要，不能破坏其他请求仍依赖的加载。
- 场景关闭释放自己的使用引用。后端资源仍归对应服务，已提交帧的持有与 GPU 完成约束不变。
- 协调对象目标名称为 `scene_controller`，只协调准备、实例化、激活、取消和退役。
  当前代码仍名为 `scene_session`，后续迁移更名；不将它解释为单个场景实例或通用多世界管理器。

具体对象、建议目录、迁移和验收的唯一计划来源为
[共享资产与场景实例实施设计](../plans/asset-scene-ownership.md)。
这些对象是内部 C++ 设计，不自动增加 C ABI、SDK 或 Editor 公共 API。

## 影响

### 已确认的首批身份与发布规则

用户已确认 [资产身份审计](../records/M-329-asset-identity-audit.md) 的两项建议：

- 首批逻辑身份为运行期来源域、合法 URI 和资产类型；不引入持久 GUID、侧车文件或改名追踪。
  URI 保留大小写，不能跨来源域仅凭路径合并。VFS 副本保留来源身份，新挂载建立新身份；
  后端挂载后不得重新指向另一来源。内容变更属于版本变化，不通过复用路径掩盖。
- 新场景使用固定版本引用；变化的候选资产独立准备，成功后切换使用引用。
  显式热重载是单独事务，后续明确使用者范围，本轮不静默改写已有公开 RID 或热重载契约。

首批准备版本使用带格式域标识的 SHA-256：按固定顺序编码来源 URI、类型、长度、摘要，
纹理追加准备配置和所选变体，材质按固定槽位追加纹理版本，包含空槽。
整数使用固定 64 位小端，字符串带长度，不哈希结构体填充或指针。
版本键另保留直接与传递输入的来源身份，参与相等比较并延长来源标记寿命；
摘要相同但来源不同不得合并。该键仅供运行期使用，不承诺跨进程持久格式。
当前只处理已有材质到纹理的依赖边，不提前实现通用循环依赖图。
确认版本键不等于完成发布隔离；渲染加载器和候选 RID 迁移仍须独立验收。

### 已确认的使用者更新方向

用户确认保留稳定逻辑资产身份和独立资源版本，并由所属系统处理更新通知与引用切换。
新内容及受影响依赖准备、上传成功后，场景系统在安全边界更新实例租约与 ECS RID；
失败保留原版本。在途帧保留旧数据，最后一个引用释放后回收。业务代码不逐个对象修补。
首阶段可限定当前活动 World，长期范围由使用者订阅决定，不把“活动 World”写成永久限制。
这是目标契约，尚未完成热重载通知、使用者更新和 GPU 验收；公共原始 RID 不隐式跟随版本。

必须同时评估资产身份、版本发布、租约寿命与资源关闭顺序，不能只把缓存移到 Application。
优先演进既有 resource_cache、资产租约、准备流程和执行器，禁止保留两套平行状态。
首个闭环验证跨场景复用与失败隔离；预算缓存、LOD、流送和任意多世界管理不是前置任务。
本决策纳入 0.51 架构工作，未完成工作明确保留，不提前安排 0.52。

## 替代方案

- 每个场景域独占缓存：隔离直观，但跨域复用受限；当前实现作为迁移起点，不作为目标。
- 将现有缓存直接改为全局共享：易使候选发布污染旧场景，也混淆项目和来源身份，不采用。
- 场景关闭时强制销毁全部依赖：会破坏其他场景和在途帧持有，不采用。

# ADR-084：统一回调式文件服务

- 状态：已接受，分阶段实施
- 日期：2026-10-25

## 背景

旧 VFS、asset_source 和平台回执共同承担读取编排，上层难以统一回调线程和关闭生命周期。
桌面 libuv、浏览器 Fetch/FS/IDBFS 的执行机制、能力和持久化语义不同。

## 决策

使用 PImpl file_service 作为 Platform 层的统一异步文件入口，负责路由、请求所有权和所属线程完成分发。
2026-10-26 补充决策：通用文件接口、路由和后端统一归 platform/files；资源层只依赖该接口。
此为目标边界，实施进度以文件服务计划为准。
Platform 不依赖资产身份、Meta codec 或旧 VFS；挂载提供通用来源标记，资产身份与缓存仍由 Resource 管理。
后端保持类型明确的异步操作，支持后台完成；旧轮询回执仅在后端内部非阻塞适配。
文件操作与资产加载不保留同步入口或同步回退；工具同样使用异步入口，不提供 wait/get 阻塞包装。
缓存查询、纯内存编解码和数据就绪后的场景实例化可同步执行。
宿主统一驱动完成分发和异步关闭，资产管理器不隐式驱动或关闭共享服务。
读链仅对 not_found 回退；写唯一后端；挂载启动后冻结。不要求各平台实现全部能力。
回调与读取数据都由请求拥有，取消产生唯一终态，关闭必须先收尾请求再结束平台执行器。
文件服务管理字节，asset_manager 管理反序列化和资源引用，不恢复版本/事务协议。
write 与 flush 分开；浏览器 IDBFS 恢复、写入、持久化具有独立时序。
使用现有调度能力，不新增通用 Service 基类或线程池；JS Promise 仅作可选适配。

2026-10-27 补充决策：未知长度 HTTP 流采用后端私有 JS Fetch + ReadableStream BYOB，
由消费者逐块请求；普通整读与范围读继续使用 Emscripten Fetch。JS 位于
`platform/files/browser/fetch_stream.js`，通过 CMake 的 `--js-library` 自动链接，
安装包携带链接依赖，不提供公共 JS API。不支持 BYOB 时返回 unsupported。
服务按 JS 与 Wasm 两份块缓冲预留预算；浏览器自身网络缓存不属于引擎可控预算。

编辑器指纹读取共享 Application 的文件服务，宿主通过 async_files 提供同一实例，
不另建挂载或 I/O 执行器。编辑器只取消自身请求，不分发或关闭共享服务。
文件回调仅交付拥有的字节，CPU 指纹计算交给已有任务调度器。
目录枚举同样使用文件服务分页 list，并复用条目类型信息；编辑器不重复查询原生根目录。

作者编辑不承诺跨文件原子提交：新 Prefab 来源独立保存，父场景只改内存并等待显式保存；
普通撤销/重做不读写磁盘。应用覆盖到共享来源为显式保存且形成历史边界，父场景仍未保存。
允许来源已保存而父场景尚未保存，不为此引入日志回滚协议。单文件写入采用临时文件完成后替换，桌面由 libuv 异步执行，浏览器只操作内存 FS。
write 完成表示可见，IDBFS 持久化另由 flush 承诺；不提供跨文件原子性或跨进程比较交换。

## 影响

能够隐藏平台差异和开放/读取/关闭细节，调用方通过回调组合工作。
需要迁移宿主分发、资产任务状态和同步加载调用点，保留资源缓存的挂载来源身份。
后端能力不足显式失败；IDBFS 无法承担任意大文件低内存持久化承诺。
实施与验收以[异步文件服务计划](../plans/PLAN-051-async-file-service.md)为准。

## 替代方案

- 继续公开旧 VFS 和轮询回执：迁移小，但平台编排持续泄漏到资源层。
- future/get：不解决事件循环调度，容易阻塞主线程；暂不采用。
- 完整 Godot Object/Signal 或通用服务框架：引入无实际需求的依赖和复杂度，不采用。

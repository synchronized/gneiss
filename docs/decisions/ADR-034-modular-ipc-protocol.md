# ADR-034：本机 IPC 使用协议域与统一分发

- 状态：已接受
- 日期：2026-09-03

## 背景

ADR-028 建立了版本化本机 IPC、回环 TCP Transport 和专用 I/O 线程。协议随后扩展到控制、日志、
场景检查、统计和属性写入，但所有消息仍共享一个全局枚举。Editor 与 Runtime 会话需要先按消息编号
特判专用负载，再进入集中式条件分发；新增功能会同时修改通用协议、双方会话和能力判断。

## 决策

- IPC v2 将帧寻址拆为“协议域 + 域内操作”，并统一携带消息语义标志、请求 ID 和负载长度。
- v2 使用固定 24 字节网络字节序帧头和 32 位请求 ID；保留字段必须为零，单帧负载上限为 1 MiB。
- 协议域首批包含 `session`、`control`、`log`、`inspection`、`statistics` 和 `property`；握手与能力协商
  属于 `session` 域，不作为普通业务域扩张。
- 请求 ID 在单次连接内由发起方生成，零值只用于无需响应的事件；响应必须复用请求 ID。通知、请求、
  响应和错误由帧标志明确区分。
- 通用 Dispatcher 只负责版本、方向、能力、负载上限和处理器注册校验，不理解域内 JSON 字段或业务
  状态。每个域独立编码、解码并拥有 Editor/Runtime 两侧处理器。
- I/O 线程继续只操作 Transport、拆装帧和有界队列；Editor UI 与 Runtime 游戏状态只在各自主线程
  消费强类型事件或命令。
- 控制域保持高优先级，不得被日志、检查或统计流量阻塞；各域分别声明队列预算与过载策略。
- 当前项目尚未发布，直接以 v2 替换内部 v1，不维护兼容分支或迁移层。协议仍是私有 C++20 实现，
  不进入公共 C11 SDK。
- 回环 TCP、一次性令牌、独立命令行降级路径和 `child_process` 故障恢复保持 ADR-028 的现有决策。

## 影响

- 新协议域只需增加域内编解码、处理器和能力声明，不再扩大全局消息枚举或双方集中判断。
- 请求关联、方向错误和未知域能够由通用层一致处理，属性写入不再拥有私有的关联约定。
- 帧格式与协议主版本发生不兼容变化；Editor 与 Runtime 必须来自同一 SDK 构建。
- 模块化不会自动提供并发业务执行；需要 Engine 或 UI 状态的命令仍必须排队到主线程安全点。
- 未来可替换为命名管道或 Unix Domain Socket，但该变化仍只属于 Transport 层。

## 替代方案

- 继续扩大全局消息枚举：短期改动少，但协议域、方向和能力边界会继续散落在双方会话中。
- 仅拆分源文件而不引入域：降低文件长度，却无法解决全局编号与集中分发耦合。
- 采用通用 RPC 框架：可获得代码生成和成熟关联模型，但会引入超出本机调试需求的依赖与公开契约。
- 同时建设公共 Network Service：底层 I/O 有复用点，但远程不可信连接与 Editor 本机控制的安全、
  生命周期和流控语义不同，应由独立真实用例驱动。

# ADR-058：场景取消终态与资源清理

- 状态：已接受，实施中
- 日期：2026-10-07

## 背景

完整场景上传阶段的取消测得约 2.04 秒：资产服务获得上传许可后继续整批上传。
允许隔离候选域停止后续批次后，等待当前上传及回滚回执仍测得约 735 毫秒。
业务请求永久取消与后端完成清理是不同事实，不能把取消终态解释成资源已经释放。

## 决策

- 普通资产重载保持原有提交许可语义。仅场景的隔离、未发布资产域允许停止后续上传。
- 上传中的场景取消立即禁止激活并返回唯一取消终态；`cleanup_pending=true` 明确表示仍持有资源。
  不释放在途上传引用，不取消后端必须完成的回执，不清零实际预算。
- 当前上传完成后回滚未发布 GPU 投影，等待回滚回执，再销毁候选和租约。
  完成后进度快照设置 `cleanup_complete=true`、`cleanup_pending=false` 并重新采样账本。
- 已消费终态的调用者通过进度查询取得清理快照，不会取得第二次完成回执。
  清理期间服务仍忙，重试返回 NOT_READY；新请求接受时清除上一请求的清理快照。
- Runtime 对外部切换只发送一次带原 request_id 的终态响应。后续清理快照通过 request_id=0
  的事件发送。Editor 只接受身份、URI、取消阶段一致的清理完成补报，不改变原终态或诊断文本。
- 两个字段均为可选内部 IPC 扩展，缺省 false；禁止同时为 true。未知清理状态不解释为已清理。
  Editor 仅在明确 `cleanup_pending` 时阻止新请求，兼容省略字段的旧消息。

## 验收与影响

保持 M-312 原门槛：从取消到终态不超过 250 毫秒，从取消到实际清理完成不超过 1 秒。
夹具分别记录 `cancel_ms` 和 `cancel_cleanup_ms`，不能用候选析构函数的局部耗时代替总清理等待。
后一指标包含上传、回滚及回执等待。实景是否达标以 M-313～M-316 记录为准。

确定性测试覆盖延迟上传/回滚回执、不继续提交、资源保留、单次终态、清理后重试、
旧身份与迟到消息拒绝，分别运行线程与协作模式。公共 C/C++ SDK 不变，不引入额外执行器。

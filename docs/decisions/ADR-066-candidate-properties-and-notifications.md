# ADR-066：候选属性写入与发布后通知分离

状态：已接受，分阶段实现。

用户确认将属性数据修改、校验与激活/变更通知分离。候选构造不调用访问活动 World 的旧 setter，
不临时发布对象，也不发送普通业务信号。

内部反射字段可注册候选数据写入回调，和现有字段类型共用唯一注册表。回调仅借用候选数据与
注册上下文，负责修改与校验，不访问活动场景、服务或发信号；失败时整份候选可以丢弃。
普通运行时 setter 继续保留以便渐进迁移，未注册候选能力时明确返回 UNSUPPORTED，绝不回退。
这是契约约束，不是针对任意 C++ 回调的副作用沙箱。

发布前完成所有决定成功与否的准备；发布与历史提交之后再通知使用者。初始化期间的多次写入
可以合并为激活通知，普通变更通知描述已提交状态。通知回调不能反向宣告已提交事务失败；
需再次修改场景时交给后续编辑事务处理，不能在无失败提交段重入。

首批先实现内部候选绑定及内置组件接入，再根据真实接收者接入通知；不预建公共插件信号总线。
尚未完成的通知派发、取消与关闭集成仍属于开发计划，不描述为当前行为。

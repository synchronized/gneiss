# ADR-060：可选 CPU 性能采集

## 状态与背景

已接受，0.50 实施中。阶段累计 CSV 缺少连续线程时间线，临时暂停采样也会扰动被测程序。
主线程长间隔排查需要成熟工具记录帧与后台任务，并保留可复查的采集文件。

## 决策

- 采用 Tracy v0.13.1，固定提交 `05cceee0df3b8d7c6fa87e9638af311dbabc63cb`，BSD-3-Clause。
- `GNEISS_ENABLE_PROFILING` 默认关闭；关闭时不获取或链接依赖，标记参数不求值。
- 启用时，所有自有模块链接同一个共享 client，避免引擎 DLL 与宿主各有一份运行时状态。
  即使引擎静态链接，profiling 构建仍携带该共享库；安装时随包携带库与许可证。
- 自有标记集中在内部 diagnostics 头文件，第三方头与编译定义只用于目标私有编译，
  不进入公共 C ABI 或 C++ SDK。任务按调度器 owner 与 task id 成对关联，不使用对象地址。
- 首轮覆盖 CPU 主循环、事件、加载、任务提交/执行/终态/接收。GPU 时间戳与 Granit 内部
  标记另行评估，不把 CPU 上传提交耗时描述为 GPU 执行耗时。
- 按需连接，监听本机，关闭网络广播；不为了采集阻止正常退出。调用栈采样与系统事件
  能力受平台和权限限制；保留优化构建的符号，但不承诺自动取得缺页或等待根因。

## 替代方案与影响

RenderDoc 适合渲染帧状态检查；Perfetto 可以展示结构化时间线，但自行维护完整采集器会
扩大本次范围。Windows 系统级等待继续可用 WPR/WPA 辅助，Tracy 不绕过其权限要求。
保留已有 CSV 作为冻结门槛依据，不用 profiling 构建的通过覆盖此前失败。
启用采集有 CPU、内存和代码布局成本，性能验收使用普通构建；不同时运行两个采集器。

## 验收

验证默认关闭、开启后共享与静态构建、C/C++ 安装消费者、任务生命周期回归，实际保存
并重新读取采集文件，核验主循环及后台任务来自同一 client。未完成项记录在 M-321。

# ADR-036：资产热重载使用修订通知与事务替换

- 状态：已接受
- 日期：2026-09-04

## 背景

Editor 已能将工程 `sources/` 中的 glTF/GLB 重新导入为 Runtime 资产，Runtime 通过 VFS、资源缓存和
RID 消费派生产物。目前运行中的资源不会随作者文件变化更新。直接让 Runtime 监听源目录会复制
导入职责；直接覆盖正在使用的资源又可能在多产物导入失败时暴露混合版本。

## 决策

- Editor 独占作者文件监听、内容确认、自动重新导入和修订发布；Runtime 只消费已提交的派生产物。
- 平台文件事件是提示，不是事实来源。Editor 对规范化路径防抖，等待文件可稳定读取，并以内容校验
  和及导入索引判断是否存在真实变化。
- 一次源资产导入产生一个单调递增的逻辑修订。所有派生产物与索引提交成功后，该修订才可通知
  Runtime；导入失败不发布修订。
- Editor–Runtime 新增私有 Asset IPC 域。通知只包含资产 URI、资源类型和修订；正文仍由 Runtime
  通过工程 VFS 加载。Runtime 返回已应用、失败、忽略旧修订或需要重启。
- Runtime 在主线程安全点构造并验证候选资源。只有候选及必要依赖全部成功后才切换缓存映射，失败
  保留最后成功资源；后端对象销毁遵守帧内引用和 GPU 生命周期。
- 首版支持 Texture、Material 和静态 Mesh。Material 依赖的 Texture 先更新，多产物 glTF 导入作为
  一个修订批次应用。Scene、Prefab 结构和 Game Module 不进入该事务。
- 文件监听器、导入调度和 Asset IPC 都是工具及内部 C++20 实现，不新增 Stable C ABI，也不暴露
  libuv 类型。

## 影响

- 保存源文件后可以在不重启 Runtime 的情况下更新首批渲染资源，失败时仍保持可运行画面。
- Editor 与 Runtime 不共享可变内存，IPC 也不承担大文件传输；双方通过修订识别过期通知和结果。
- 自动导入必须处理重复事件、半写入文件和连续保存，不能把每个文件事件直接映射为一次导入。
- Runtime 资源缓存需要区分逻辑身份与当前后端实例，并为旧实例提供安全退役时机。

## 替代方案

- Runtime 直接监听源文件：实现入口看似简单，但会把导入器和作者目录语义带入发布宿主。
- IPC 传输完整资产字节：可脱离共享目录，却扩大内存、分帧和流控复杂度，当前本机工程没有需求。
- 原地修改现有资源：减少句柄变化，但多资源失败时难以回滚，也容易违反后端并发与 GPU 生命周期。
- 变更后自动重启 Runtime：安全但丢失运行状态，无法验证资源缓存与 Asset 协议域的长期边界。

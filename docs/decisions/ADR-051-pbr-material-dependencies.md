# ADR-051：PBR 材质语义与多纹理依赖

- 状态：已接受，待按 0.43 计划实现
- 日期：2026-09-29

## 背景

Material v3 和当前资源租约仅支持基础颜色纹理；其他标准 PBR 槽绑定默认资源，GPU 切线为固定值。
直接增加 Shader 参数不能解决导入、Cook、缓存和异步发布中的依赖缺失。

## 决策

- Gneiss 保持作者格式与 RID 的所有权，Granit 仅接收标准材质和 GPU 数据；不依赖上游私有布局。
- Material v4 增加 MR、normal、occlusion、emissive 纹理及 normal scale、occlusion strength、
  emissive factor；无贴图使用标准中性资源。旧版本保持既有默认值，不自动变成新材质。
- 内部槽顺序固定为 base color、metallic-roughness、normal、occlusion、emissive。
  资产 URI、RID、缓存租约、CPU 依赖快照及 GPU 绑定使用相同槽映射；不再假定单个纹理依赖。
- 每槽可引用同一资源，但用途、颜色空间、Mip 处理和采样状态不能按源路径误合并。
  base color/emissive 使用 sRGB，MR/normal/AO 使用 linear；颜色因子保持线性。
- 公开 Material 描述只在尾部追加字段并根据 struct_size 读取；保留旧描述大小作为兼容边界。
  新字段必须校验有限值、范围和 Texture 所属服务，公共包装不增加独立状态。
- 材质租约持有所有纹理租约，帧包捕获所有依赖的不可变快照；GPU 候选同样保持依赖所有权。
  候选失败或取消不更新旧材质；发布前复核缓存身份，提交时整批安装，旧帧结束后释放旧依赖。
- 网格切线作为独立可选属性追加，保留旧顶点布局；新二进制格式显式版本化，不重解释旧文件。
  缺失切线的旧资源保留既有无实际法线贴图行为；新导入路径为需要法线贴图的几何准备有效切线。
- 法线纹理的 Mip 按向量语义处理，不能套用颜色伽马。派生资产的处理器版本与配置参与缓存键。
- UV/采样器/Alpha/双面等依赖上游契约的扩展在能力确认后补充本决策；不保存“看似支持但被忽略”的字段。
  不支持的新导入材质必须明确诊断，不静默丢失特征。

## 影响

变更贯穿公共描述、资源服务、帧捕获、Loader、候选事务、导入器和 Cook，不能只修改渲染后端。
接口与文件格式的兼容、失败资源回收及同纹理多用途需要独立测试。
五贴图可能明显提高场景驻留；保留预算与超额拒绝，任何调整必须有测量记录。

## 替代方案

- 只在后端按文件路径加载附加贴图：绕过 VFS、RID 和事务生命周期，拒绝。
- 复用 Granit 示例资产管理器替换 Gneiss 缓存：引入平行运行时状态及错误分层，拒绝。
- 保持单纹理字段再增加四套独立处理流程：易遗漏回滚和依赖更新，采用统一槽遍历。

# ADR-019：Editor 源资产、派生产物与导入索引边界

## 状态

已接受。

## 背景

`gneiss_assetc` 已能把 glTF/GLB 转换为 Runtime 资产，但 Editor 尚不能浏览、导入或重新导入源文件。
直接让 Editor 启动 CLI 会丢失结构化诊断和事务边界；把 fastgltf 或源格式解析放入 Runtime 又会破坏
既有离线导入分层。多个源文件若直接写入同一资产根，也会互相覆盖或产生不明确的所有权。

## 决策

- 工程中的源资产位于 `sources/`，运行时可加载的作者资产仍位于 `assets/`。
- 每个源文件的派生产物写入 `assets/imported/<稳定源键>/`；一次导入只能替换自己拥有的目录。
- `.gneiss/asset-index.json` 记录规范源路径、导入器标识与版本、内容哈希、状态和输出 URI。该索引是
  可重建的派生数据，不是 Runtime 资产格式，也不保存无法从源文件或导入设置恢复的作者信息。
- 首版没有可调导入设置；出现真实设置后另建版本化作者侧设置格式，不把设置只存入可重建索引。
- 现有导入核心整理为 Editor 与 `gneiss_assetc` 共用的内部 C++ 工具 SDK。CLI 保持薄前端，Editor
  直接调用 SDK 并接收结构化结果，不启动子进程。
- 工具 SDK、fastgltf 和资产索引实现只属于工具构建，不进入 `gneiss` Runtime、公共 C ABI 或普通
  安装 Consumer。Editor 通过自身模型把导入结果映射为 UI 状态。
- 导入先写同级暂存目录，成功后替换目标派生目录；索引只在产物提交成功后更新。失败保留上一次
  完整产物和索引记录，并返回可展示诊断。
- 首版文件变化检测使用显式刷新与轮询元数据/内容哈希，不把平台文件监视 API 下沉到 Runtime。

## 影响

- 同名源文件不会争用同一输出目录，派生产物具备明确所有者并可安全重新导入或清理。
- 工程可以删除索引并重建；版本控制策略可按工程选择提交派生产物或在构建阶段重建。
- `asset://` 与现有 Loader 无需理解源文件、导入器或索引。
- 未来增加图片、音频等导入器时复用统一记录与事务协议，但各导入器仍独立声明支持范围。

## 未采用方案

- Editor 启动 `gneiss_assetc` 子进程：拒绝，首版已有可复用核心，进程文本协议会重复定义错误语义。
- Runtime 直接加载 glTF：拒绝，会传播工具依赖并模糊源资产与运行时资产边界。
- 所有导入直接覆盖 `assets/`：拒绝，无法表达产物所有权，也无法安全处理多个来源和删除传播。

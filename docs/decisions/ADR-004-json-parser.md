# ADR-004：使用 yyjson 解析内部 JSON 文档

- 状态：已接受
- 日期：2026-08-26

## 背景

`0.2.0` 需要解析版本化场景和资产源描述。解析器必须支持严格 UTF-8 JSON、精确整数与浮点数、
语法错误字节位置，并以显式结果而非异常表达失败。JSON 库仅是内部实现，不能定义公共 ABI、Schema
或编辑器反射模型。

M-13 使用最小场景文档比较了 yyjson `0.12.0`、nlohmann/json `3.12.0`，并评估 simdjson 与
Glaze 的适用边界。

## 决策

- 使用 yyjson `0.12.0`，以 Git submodule 锁定提交
  `8b4a38dc994a110abaec8a400615567bd996105f`。
- yyjson 固定构建为 Gneiss 内部静态库，不安装、不进入公共头，也不通过 CMake 接口传播给使用者。
- 使用默认严格读取选项，保留 UTF-8 校验，拒绝注释、尾随逗号、`NaN` 和 `Infinity` 等非标准输入。
- 语法解析只生成 Gneiss 内部文档视图；字段要求、未知字段和 Schema 版本由 Gneiss 校验层决定。
- yyjson 的错误码、指针和文档对象只存在于内部实现，公共 API 转换为 Gneiss 结果与自有诊断。

## 影响

- 解析路径无需异常，能直接获得错误字节位置并保留 64 位整数。
- C 实现编译一次，场景解析的 C++ 调用层保持轻量；依赖不增加额外运行时 DLL。
- Gneiss 需要封装文档所有权、字段读取和诊断，不能让业务模块散布 yyjson 调用。
- yyjson 尚未承诺 ABI 稳定，但静态私有链接使升级影响局限于内部适配层。

## 替代方案

- **nlohmann/json 3.12.0**：API 直观且生态成熟，但模板编译成本更高，默认异常模型与项目错误边界
  不一致；保留为工具端候选，不用于运行时解析核心。
- **simdjson 4.6.4**：适合大型文档吞吐，但输入缓冲与视图生命周期约束对当前小型场景没有收益。
- **Glaze**：强类型映射性能优秀，但会在 Schema 尚未稳定时引入模板反射耦合。
- **自研解析器**：Granit 的受限解析器适合固定工具格式，不足以承担通用场景数值、Unicode 和诊断
  契约；Gneiss 不复制维护一套 JSON 标准实现。

# ADR-077：统一资源强引用入口

- 状态：已接受。
- 日期：2026-10-24。

## 决策

内部资源强引用使用 asset_ref<T>，底层复用 std::shared_ptr 的控制块、引用计数和删除器。
支持复制、移动、只读转换、判空、访问和 reset；不接受裸指针建立独立所有权。
别名引用可让调用方访问 CPU 描述并共同保活其缓存条目，不分配第二个控制块。
只有最后一个强引用释放才销毁拥有的对象；每个引用析构不直接执行资源清理。

通用资产请求领取 asset_ref<const T>；Prefab 使用 asset_ref<const prefab_description>。
渲染资产统一引用缓存条目，通过领域辅助函数访问 RID、类型和 URI，不保留每类型 lease 类。
异步请求负责等待和取消观察，强引用负责生命周期，两者不合并。

## 身份、缓存与更新

资源身份由管理器固定的来源域、URI 和类型共同限定。缓存不跨管理器全局复用。
通用管理器按类型和 URI 索引；现有 Prefab/渲染缓存按 URI 索引并校验类型与来源域，
不允许将同一条目解释为另一个类型或挂载来源。
缓存持有强引用，通过 collect_unused/release_unused 显式释放无人使用的条目。
通用管理器回收时必须保留活动任务的索引，不能导致迟到完成访问已删除条目。

CPU 描述重载产生新只读对象，旧引用继续保活旧数据；渲染重载更新稳定 RID 的内容，
在途帧继续保活其已取得的数据。引用非空不等于 GPU 内容就绪。
失败保留既有成功数据，不引入来源二次读取或事务协议。

## 线程与取舍

引用计数安全不等于对象操作线程安全。渲染资源的引用释放仍遵循所属线程约束，
服务须晚于全部资产引用销毁；GPU 安全回收继续由服务和后端完成。
不借本次改动创建尚无调用需求的销毁队列或资源继承体系。
使用标准控制块有少量存储及原子计数成本，换取明确且可复用的所有权语义。

# ADR-037：Scene 与 Prefab 结构热重载使用身份协调事务

- 状态：已接受
- 日期：2026-09-05

## 背景

0.22.0 已支持 Texture、Material 和静态 Mesh 的事务式热重载，但 Scene 与 Prefab 仍被明确排除。
这两类资产不仅替换后端资源，还会改变节点层级、组件集合、实体映射和 Prefab 实例投影。直接销毁
并重建整个运行场景会让未改变对象的实体身份失效，也会丢失 Runtime 临时状态；逐项原地修改则可能
在中途失败时暴露半新半旧的结构。

## 决策

- 继续由 Editor 协调作者文件变化、提交派生资产并发布修订；Runtime 不监视作者目录。Scene 与
  Prefab 复用 Asset IPC 域的修订、请求关联、重同步和结果反馈，不创建平行协议通道。
- Scene 节点 UUID 是同一场景修订间的逻辑身份。Prefab 投影使用“实例 UUID + 来源节点 UUID”作为
  逻辑身份。名称、父节点位置和数组顺序都不能用作身份匹配依据。
- Runtime 先加载并严格验证完整候选描述，再生成确定排序的结构差异。差异至少表达节点与组件的
  新增、删除、保留、重挂接和作者字段更新；未知类型、重复身份、无效层级或资源依赖失败均在提交前
  拒绝。
- 提交发生在 Runtime 主线程安全点。事务预先准备新增实体与资源租约，并记录可回滚状态；全部操作
  成功后一次发布新结构和修订。失败时销毁候选资源并保留旧场景、旧修订及既有对外可见身份。
- 匹配且组件类型兼容的节点保留实体 ID；新增节点获得新实体，删除节点的实体在提交后失效。重挂接、
  重命名和作者字段更新不单独改变实体 ID。首版不承诺组件内部地址稳定。
- 序列化字段由新作者描述覆盖。附着在保留实体上的非作者运行时状态应继续存在；为避免把同类型的
  Runtime 临时组件误判为作者组件，实现必须记录组件来源，不只比较“实体是否拥有该类型”。
- Prefab 来源变化对当前场景内全部同源实例形成一个事务批次。实例局部字段覆盖在新来源值之上重新
  应用；覆盖引用已删除节点或字段时拒绝整个批次，并向 Editor 返回可诊断冲突，不静默丢弃覆盖。
- Editor 有未保存作者修改时，不以外部文件变化覆盖其内存文档；标记冲突并要求用户选择重新载入或
  保留本地修改。Editor 自己成功保存产生的修订可以正常进入 Runtime 热重载。
- Game Module、原生动态库、脚本状态迁移、跨工程场景切换和网络远端设备不属于本事务。

## 影响

- 未改变对象可以在结构更新后保留实体身份和 Runtime 临时状态，游戏代码持有的匹配实体 ID 继续
  有效；被删除对象的旧 ID 明确失效。
- Runtime 需要作者组件来源信息、候选差异和回滚日志，内存峰值会高于直接原地修改。
- Prefab 的一个来源修改可能影响多个实例，因此不能逐实例发布成功，否则会产生同源混合版本。
- IPC 仍只发送 URI、资产类型和修订；候选正文通过工程 VFS 加载，不把场景数据塞入控制消息。

## 替代方案

- 整场景销毁重建：实现简单，但会使全部实体 ID 和运行状态失效，拒绝采用。
- 直接按 JSON 顺序原地修改：缺少稳定身份和原子边界，失败时无法可靠回滚，拒绝采用。
- 通过 IPC 发送逐项编辑命令：适合实时编辑操作，不适合作为磁盘资产修订的事实来源。
- 首版自动删除失效 Prefab 覆盖：表面上提高成功率，但会造成作者数据静默丢失，拒绝采用。

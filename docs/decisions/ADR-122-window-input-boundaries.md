# ADR-122：窗口采集与输入语义边界

- 状态：已接受
- 日期：2026-11-17

## 背景

Window 已负责平台窗口及输入采集，Input 负责键鼠状态和动作映射。原 Application 同时复制
平台键鼠快照并逐条重放事件，存在重复修改入口；固定 256 条事件缓存把输入突发变成应用错误。

## 决策

- 保留两个服务：Window 不依赖 Input 服务，双方只共享 Core 中的输入值类型和窗口身份。
- `window::service::poll_events(on_input)` 一次泵送并同步交付本窗口或无窗口归属的输入；
  返回关闭请求、焦点丢失摘要。回调不保存，不得重入；错误不回滚已交付事件。
- Application 开始输入帧、连接采集回调、处理窗口通知。Input 通过事件更新键鼠及动作状态，
  删除普通键鼠快照写入口；无真实用例前不增加恢复快照 API。
- Granit 的窗口和输入队列分别消费，不宣称跨队列的原始时序。当前任意失焦通知均在本轮
  输入处理后清理保持状态，包括同轮失焦再获焦；这一保守规则沿用原行为。
- Input 保持单输入上下文，由调用者路由归属，不因增加 ID 就宣称支持多窗口状态。
- 事件使用动态缓冲，每帧清空但复用容量；不合并或丢弃按下、释放、文本事件。
  非法输入仍可拒绝，内存分配失败遵循既有异常策略，不伪装成缓存已满。
- `window::id` 是 Core 中的独立值类型。窗口成功创建时分配进程内递增非零 ID，不复用；
  它不保活、不表示存活、不持久化。零表示没有窗口归属；原生地址和 Granit 类型不暴露。
- Window 与 Input 仍由宿主拥有，在所属线程调用；Render 表面先于窗口销毁。

## 调用流程

创建 Window 服务并初始化；每帧 Input.begin_frame 后调用 Window.poll_events，回调将事件
交给 Input.push，检查结果后处理 close_requested 与 focus_lost。关闭时停止采集，释放渲染
表面后销毁窗口。无窗口宿主仍可以直接注入 Input 事件。

## 取舍

保留了输入回放及测试不依赖真实窗口的能力，消除了平台快照与事件双入口；动态缓冲在高峰后
保留容量。暂不扩展多窗口管理、设备级动作路由、统一跨队列时间线或 SDL/Web 后端。

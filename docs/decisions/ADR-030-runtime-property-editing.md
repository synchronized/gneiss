# ADR-030：Runtime 属性写入使用命令与显式回写

- 状态：已接受
- 日期：2026-09-02

## 背景

0.16.0 允许 Editor 通过会话隔离的只读镜像观察 Runtime。实时调参需要反向写入，但直接修改镜像、
共享内存或作者场景都无法证明 Runtime 已接受修改，也无法正确处理对象销毁、游戏逻辑覆盖、断线和
并发变化。运行态试验与持久化创作还具有不同的撤销和所有权语义。

## 决策

- Editor 发送带命令 ID、会话 ID、对象 ID、generation、Type ID、Field ID、期望修订号和类型化值的
  有界属性写入命令。
- Runtime I/O 线程只解析和排队；Runtime 主线程在安全点校验并执行命令。第三方后端对象不得暴露给
  协议或 I/O 线程。
- Runtime 返回明确的成功或拒绝结果，包括命令 ID、结果码、规范化后的值和新修订号。对象失效、
  类型不匹配、字段只读、修订冲突、队列满和会话失效必须可区分。
- Editor 不乐观修改 Runtime 镜像；Inspector 显示待处理状态，只有 Runtime 的权威结果及后续镜像
  更新才能确认运行值。
- 运行态修改默认仅属于当前 Play 会话，Stop、崩溃或新会话后丢弃。
- “应用到作者场景”是独立且显式的 Editor 操作，只支持存在持久化 UUID 映射且可创作的字段，并通过
  既有命令历史进入撤销、重做和保存流程。
- 同一属性只允许一个在途写入；连续拖动由 Editor 合并为有限频率的最新值，控制消息保持更高优先级。

## 影响

- Editor 能区分请求值、Runtime 规范值和作者值，不把 UI 本地状态误认为执行成功。
- 运行中的游戏逻辑可以在下一帧覆盖属性；这属于真实 Runtime 行为，暂停后编辑提供确定性调参路径。
- 显式回写不会复制整个 Runtime 场景，也不会持久化临时对象、RID 或运行时生成节点。
- 协议仍为 Editor 与 Runtime 的私有接口，不进入稳定 C ABI。

## 替代方案

- Editor 直接修改本地镜像：延迟低，但不能修改独立进程中的真实状态。
- 写入后立即回写作者场景：操作简单，但会把试验值和游戏逻辑结果意外持久化。
- 每次修改传输完整组件：协议简单，但扩大冲突范围和带宽，无法提供字段级错误。
- 共享内存对象：吞吐较高，但破坏进程隔离并泄漏对象布局。

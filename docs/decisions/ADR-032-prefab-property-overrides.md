# ADR-032：Prefab 实例使用稀疏字段覆盖

- 状态：已接受
- 日期：2026-09-03

## 背景

引用型 Prefab 让多个实例共享来源，但 0.18.0 的来源节点完全只读。实例需要保留少量局部差异，同时
继续接受来源更新。若保存展开副本会失去来源关系；若按字段名称或内存偏移寻址，则重命名、布局和
编译器差异会破坏作者数据。场景作者层也不能复用 IPC 值类型，否则会形成 Scene 对 I/O 的反向依赖。

## 决策

- 单条覆盖以实例 UUID、源节点 UUID、稳定 Type ID 和稳定 Field ID 作为作者键。
- 覆盖值由 Scene 内部模型拥有，不借用 Type Registry、JSON DOM 或 IPC 内存。
- 值类别与公共属性 ABI 对齐；写入前由冻结的 Type Registry 验证字段存在、类别一致且具备可写能力。
- 覆盖集合只保存与来源不同的值；恢复来源值时删除记录，并按稳定作者键确定性排序。
- 浮点值使用精确比较，但先把正负零规范为正零；NaN 和无穷值始终拒绝。
- 来源刷新时必须重新验证全部覆盖。字段缺失、类型改变或变为只读时刷新失败并保留旧投影，不静默
  删除作者数据。
- Scene、Runtime 投影、Editor 命令和 IPC 各自保留所属层的数据类型，通过显式转换衔接。

## 影响

- 同源实例可以独立覆盖字段，来源内容仍保持唯一权威副本。
- Type ID 和 Field ID 成为 Prefab 覆盖的持久身份，显示名称只用于界面和诊断。
- 稀疏集合可确定性序列化、比较和进入 Undo/Redo，不会保存无效的“等于来源”记录。
- 字段 Schema 演进必须显式处理失效覆盖；1.0 前没有外部兼容承诺时可直接升级仓库内容。
- Apply 回来源、组件结构覆盖、嵌套 Prefab 和 Variant 仍需独立决策。

## 替代方案

- 保存完整展开节点：读取直接，但失去来源关系并使刷新退化为三方合并。
- 按字段名称保存：便于阅读，但名称不是稳定身份，重命名会错误丢失覆盖。
- 复用 IPC 属性值：减少一个结构，却让持久化模型依赖传输层并混淆所有权。
- 对浮点使用任意 epsilon：表面减少微小差异，但无法形成跨字段、跨版本的确定持久化规则。

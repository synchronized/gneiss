# ADR-049：模型依赖准备与整批资源发布

- 状态：接受，0.41.0 实施中。
- 日期：2026-09-25。

## 背景

0.40 只将纯纹理修订异步化；混合修订仍在主线程读取并创建资源。将同步事务直接放到工作线程
会破坏缓存、RID 与 World 所有权，拆开提交则可能显示新材质和旧几何组成的半更新画面。

## 决策

复用宿主调度器和现有加载服务，按 CPU 准备、主线程暂存、GPU 确认、原子发布四阶段推进。
请求和依赖以 URI/类型描述，CPU 候选只包含自有数据；不得包含后端句柄或可变缓存引用。

材质解析所发现的纹理依赖纳入有界准备闭包，重复 URI 只准备一次。准备结束复核源快照；不承诺
跨进程文件系统原子事务。主线程对请求开始时观察的缓存身份执行过期校验，避免卸载后结果复活。

发布时保留已有 RID 与引用，切换不可变资源版本；新资源在全批成功后进入缓存。材质依赖所有权
随版本保持有效，旧帧拥有旧快照。所有可能失败的分配、依赖校验和 GPU 准备应在发布前完成，
发布阶段只执行不会失败的交换。

GPU 暂存允许分批推进；上传进度不等于已应用。任何资源失败都回收全批候选并保留旧画面。
提交许可前取消；取得许可后完成或回滚，IPC 最终只回复一个终态。阶段通知与最终结果分离，
按会话和修订拒绝迟到事件。

## 影响与边界

旧帧和候选可同时占用内存，预算必须覆盖请求、输入和候选，并明确临时内存的额外成本。
渲染线程仍独占 GPU，上传预算只约束推进粒度，不能保证驱动调用硬实时。初始场景同步加载、
Scene/Prefab 结构修订和公共 SDK 保持独立范围。完整 Web 移植不由本决策推导。

回读测试从实际渲染输出检验几何和材质更新，保留失败旧画面；不依赖系统窗口截图的可用性。

## 实施取舍

网格 GPU 镜像各自拥有顶点/索引缓冲，避免单资源更新触发整个几何 arena 重建。代价是更多缓冲
及绑定，不能假定跨网格批处理仍有相同收益；实际负载测量记录此版行为，不承诺所有场景更快。
上传命令采用四资源/预计 8 MiB 预算，超预算单资源独占一批。依赖闭包、输入与候选边界以及
取消协议的当前数值以[调度指南](../guides/task-scheduling.md)为准。

身份校验使用全局缓存映射修订与加载器发布修订，避免卸载复活；会保守拒绝准备期间发生的
不相关缓存变化。将来只有真实并发负载证明必要时才引入逐 URI 修订，当前不建立额外身份表。

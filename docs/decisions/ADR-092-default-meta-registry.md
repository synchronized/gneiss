# ADR-092：共享默认 Meta 注册表

## 状态

已接受。实施与验收见 [PLAN-059](../plans/PLAN-059-default-meta-registry.md)。

## 背景与决策

资源 codec、场景属性和属性检查器原先分别构建注册表，造成类型可见性分裂。
由 engine 编译单元持有进程共享的默认表，Core 仅负责创建和注册表操作，不依赖具体功能类型。
Function 层 `initialize_meta(callback)` 按内置组件、资源 codec、项目回调、冻结的顺序完成启动。
Runtime 应用创建前调用该入口；独立工具和测试显式调用。重复无参初始化返回首次结果。
项目回调可使用无 registry 的 builder；需在首次 application 创建前调用带回调的初始化。
冻结后不能新增类型；重复带回调初始化返回 invalid_state，不静默忽略项目注册。
初始化失败保留诊断至进程结束，不冻结半成品，不尝试回滚已注册类型。修正配置后重新启动。

默认查询和序列化重载只转发，不隐式注册或冻结。默认表不随应用关闭清空，借用元数据仍需
保持 registry 生命周期，不能跨引擎动态库卸载。每个进程正常只装载一个引擎模块；将引擎静态
复制到多个独立动态库不在共享保证范围内。

## 影响与替代方案

减少重复注册，跨模块共享项目类型。代价是启动后不能按应用隔离默认类型，也不支持插件热卸载。
保留显式 registry 参数及独立创建能力，供测试、隔离工具使用；不增加第二套注册机制。
不选择全局静态自动注册，因为初始化顺序及错误无法清晰控制。
不在各模块首次查询时冻结，避免项目类型注册时机依赖调用顺序。
初始化期间由启动线程独占注册流程；冻结后并发查询，业务对象访问仍由调用方同步。

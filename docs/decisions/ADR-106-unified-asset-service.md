# ADR-106：统一资产服务与场景实例化分离

- 状态：已接受，已实施。
- 日期：2026-11-05。
- 实施：[PLAN-100](../plans/PLAN-100-unified-asset-service.md)。

## 背景

asset_manager 管 CPU 产物，resource_service 管渲染运行资源，scene_service 又承担部分资产准备。
调用方需要了解中间产物类别才能选择入口；请求、缓存、推进和停止形成多组协调。
简单增加一个 content_service 外观会保留这些拥有者和状态，不能消除根本复杂度。

## 决策

只保留一个对外资产管理拥有者 asset_manager，接收已注册描述及渲染资产的加载和创建请求。
读取、解码、依赖装配和运行资源衔接成为内部步骤；file_service 继续提供异步字节访问，
render_service 继续管理 RID 与后端执行。无需统一资产继承体系。

场景资产加载和依赖准备归资产服务；World 创建、节点实例化、活动场景切换及退场不归资产服务。
Scene/Prefab 描述可共享给多个实例，实例卸载不等于模板资产卸载。

通用资源批次由宿主复用 resource_load_group 直接请求资产管理器，场景服务不再转发。
场景视觉加载持有独立请求组，两组只保存请求观察者与回执，共享资产管理器的一份弱缓存。
跨场景编辑互斥由宿主保证。实施见 [PLAN-101](../plans/PLAN-101-scene-service-boundary.md)。

最终资产采用统一弱索引与类型化请求。解码中间产物只按实际消费者保活，不默认另建公开缓存。
描述重载交付新的不可变内容，旧引用有效；渲染运行资源保持稳定身份并采用新内容。
加载完成不表示 GPU 上传完成，不引入跨资产版本事务。

混合运行资源引用直接保存类型化强引用，不将 URI 缓存条目作为公开资源对象。
异步配置统一入口且拒绝装配冲突；Render 绑定独立保留，以支持无异步加载的程序化资源创建。
Scene 与 Prefab 使用具名准备入口，避免布尔参数同时表达资产类别与重载策略。

本决策取代 ADR-099 中 CPU 与运行资源由两个独立管理器负责的目标边界；
其弱缓存、完整身份、观察者取消和无 GPU 等待原则继续适用。实现迁移完成前，
当前行为仍以源码和现行 Reference 为准。

## 替代方案与影响

- 保留双管理器并改名：改动小，但调用分裂与重复生命周期继续存在，未采用。
- 增加统一外观：易渐进接入，但最终会变成三层管理器，仅可作为短期内部迁移手段。
- 将场景运行也并入资产管理器：入口少，但会把 World、活动实例与共享资产所有权混在一起，未采用。
- 采用统一资产服务：减少公开概念和状态拥有者，代价是迁移所有调用端并重新验证请求与关闭顺序。

流送仍为后续决策；未来围绕资产身份、范围读取和驻留需求设计，不在本次提前增加调度服务。

# ADR-107：以资源对象为中心的加载与持久化

- 状态：已接受，分阶段实施中；进度见实施计划。
- 日期：2026-11-06。
- 实施：[PLAN-102](../plans/PLAN-102-resource-object-loading.md)。

## 背景

统一管理器之后，描述、装配、场景准备和渲染身份操作仍集中在 asset_manager。
仅移动文件或增加外观不能消除多种完成语义与转换协议。

## 决策

管理器只协调最终资产身份、弱缓存与加载操作；类型加载器负责装配和依赖条件。
以薄 asset 基类支持统一管理，复用既有引用计数，不要求所有反射对象继承。
具体资源承载可持久化逻辑属性，专门负载仅在表示差异有必要时保留。
资源引用按 URI 持久化，内嵌多态对象沿用原规则；通用序列化不执行 I/O。
解码通过窄上下文接口记录资源身份与依赖，由资产层异步解析。
缺失资源保持来源身份和诊断，不能因暂不可用把保存内容变成 null。
Scene/Prefab 是共享资产，World 实例化与结构更新属于场景逻辑。
资产身份与描述快照分开：成功重载在所属线程替换内容，已有快照继续保活旧内容；
工作线程只处理取得的快照，不访问资产当前内容。实例化不会把实例状态写回共享资产。
ActionMap 同样使用资产身份与描述快照：action_map 保存共享内容，action_map_description 用于
反射及文件格式。InputService 显式复制描述并校验，输入状态不随资产重载自动变化。
GPU 就绪不属于 CPU 加载完成条件；释放由受控通道转交后端所属线程。
公开 load/find_loaded/store 仅面向 asset 派生类型；普通值由格式编解码处理，内部 Decoder 可返回描述。
不建立第二个资源管理器、第二套公开解码缓存或跨资产事务。

## 与既有决策关系

部分调整 ADR-106 的目标：引入薄资产基类，移除管理器具名场景准备入口，
将描述与运行资源默认分离改为按实际数据差异决定。
ADR-106 的单一拥有者、弱缓存、观察者取消、实例化分离和无 GPU 等待原则继续有效。
迁移完成前，源码和现行 Reference 仍描述当前行为。

## 代价与替代方案

保留现有多种对象模型改动小，但转换和入口分类继续扩散。
统一成通用 UObject 式系统会扩大到 ECS 和编辑器，超出真实需求。
本方案集中解决引用持久化、依赖循环和线程销毁；代价是调用端及资产格式迁移，
以及必须限制共享资源的直接可变访问。流送和未知内容保留另行设计。

## 2026-11-06：简化场景准备边界

用户确认不再向上层要求独立的“先准备、再实例化”步骤。目标是资产加载取得必要的
Scene/Prefab 结构依赖，场景模块在所属线程同步整理层级并创建 World 实例；视觉资源独立完成。
不为保留旧接口新增准备服务或专用 CPU 任务调度。层级处理保留为内部算法，编辑内存描述
仍可直接进入实例化路径，不登记文件资产身份。
当前迁移先删除独立 CPU 准备任务，公开准备请求及依赖加载归属继续按 PLAN-102 收敛。
同步处理可能增加单次所属线程耗时，流送和大场景分帧暂不属于本次范围。

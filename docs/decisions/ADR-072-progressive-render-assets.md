# ADR-072：普通渲染资产默认逐步就绪

- 状态：已接受，实施收尾验证中。
- 日期：2026-10-22

## 背景

CAORS 替换后仍存在固定版本发布、版本选择、整批采用和历史保活等协议。
用户确认可以接受首次资源暂不显示、更新期间继续显示旧资源，再逐步切换到新内容。
此前为了严格整批一致性增加的协议不再作为普通加载的默认要求。

## 决策

普通视觉资产采用渐进可用策略，更新保留有效旧资源；共享逻辑 RID 默认稳定。
CPU 读取与解码留在 asset_manager，渲染侧负责上传、安全切换、缺省显示及资源退休。
Runtime 负责逻辑场景生命周期，不默认等待所有视觉资源同时完成。
不以“已提交”推断 GPU 已完成；底层同步与寿命按后端契约处理。
首次 Mesh 未就绪时跳过绘制；首次材质采用默认材质参数，纹理使用对应槽位的默认资源。
合法预留 RID 与内容就绪分别查询；帧快照固定当时的数据或缺省状态，不随之后填充而改变。
2026-10-23 明确删除运行时资产固定版本发布、版本选择和采用协议，消费者统一使用稳定资源引用。
多资源请求允许部分成功；失败或取消不回滚已经生效的资源，回执必须表达逐项结果。
临时读取/上传数据属于任务内部，不建立独立候选资产身份；每资源更新序号拒绝过期结果。
编辑历史恢复作者参数、结构和资源引用，不承诺恢复外部文件的确切历史内容。
作者命令提交检查和场景结构构建保护继续保留，不依赖资产版本事务。
游戏模块必需依赖和公共 ABI 在迁移前单独审计；文件历史不在本次实现。

## 影响与替代方案

允许短暂缺省显示及跨资产分帧更新，换取较少的版本和事务状态；仍需任务顺序、失败诊断、
生命周期和资源回收。稳定 RID 不表示不同来源/类型/设备域可以混用，也不取消销毁失效。
外部文件改变后，撤销资源引用仍使用对应资源的当前成功内容；取消加载也不保证画面恢复原状。
场景结构和作者修改的局部提交保护不下沉为通用资产事务；完全不跟踪上传结果则不能
可靠完成失败处理、重复提交控制与资源释放，不采用。

缓存以 URI 查找时同时校验挂载来源；同 URI 的不同来源拒绝混用，独立工程使用独立缓存。
材质只保留作者描述，加载证据由准备任务拥有；CPU 内容去重使用弱索引，不提供历史版本 API。
这也替代 ADR-069 中具体材质版本租约的安排，资源直接持有只读 CPU 文档。

本决策调整 ADR-071 在替换完成后的后续简化方向，不改写既有实现和验收记录。

# ADR-124：平台 IPC 与宿主协议分离

状态：已接受；迁移见 [PLAN-120](../plans/PLAN-120-ipc-protocol-boundaries.md)。

## 背景

平台传输曾识别日志域，并包含 Editor/Runtime 角色、业务域枚举和握手分发规则。
这使协议演进需要修改平台，且不能独立复用传输。

## 决策

平台 gneiss::ipc 保留固定帧、域编号、连接、队列和 libuv 隔离。协议模块拥有域含义与分发规则。
传输通过本地无状态分类器判断可丢弃消息；默认不分类为可丢弃。分类器对发送及接收生效，
不从帧中读取优先级，不持有业务对象。现有会话显式安装日志分类策略。

后续协议负载使用反射 JSON，反射负责结构转换，协议负责握手和方向，业务负责资源与对象校验。
保持帧格式；负载改变通过域版本表达。暂不实现通用二进制序列化。

## 取舍

保留消息信封而非退化成裸字节流，避免每个宿主重复实现帧处理。
允许无状态本地分类函数是为了保持有界队列中的业务优先级，同时阻止平台依赖具体协议。
不引入传输 backend 服务层；当前单一 libuv 实现用 PImpl 隔离即可。

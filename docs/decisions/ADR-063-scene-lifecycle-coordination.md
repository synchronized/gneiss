# ADR-063：场景生命周期协调归属

- 状态：已接受，实施待完成
- 日期：2026-10-15

## 背景

[M-329 审计](../records/M-329-architecture-audit.md) 确认加载事务与活动域切换分散在
`scene_load_service` 和 `application_state` 中。用户确认采用方案 A。

## 决策

在 Engine 的 application 模块内整理独立的场景生命周期协调组件，内部名称采用
`scene_session`。它拥有加载事务、活动域、待退役域，以及绑定活动域的纹理加载服务。
Application 拥有该组件，负责平台、I/O、渲染后端装配与主循环推进；不再直接维护这些场景状态。

协调组件通过显式参数借用 VFS、渲染资源服务和任务执行器，接收既有上传后端接口。
它不创建线程，不直接依赖 Granit 平台，不复制资源表或公共句柄状态。
scene 模块继续负责场景结构与实例构造；asset 负责资源准备；render 负责 GPU 和帧持有。
Editor 保留用户意图、文档状态和进度显示。

组件负责打开、取消、失败保留旧场景、激活及退役的生命周期约束。准备完成与激活仍分离，
宿主在原有安全时机请求激活；不把准备完成回调直接变成场景切换。
关闭必须先停止并清理加载事务，再释放场景域；渲染后端及其借用的 I/O 执行器继续由
Application 按原有依赖顺序关闭。阻塞和线程契约必须显式保留。

0.51 首批实现围绕这条完整链路及相关依赖约束、回归展开。不同时重排所有子系统，不新增
公开 API 或顶层目录，不指定下一版本编号。其余审计与验收要求见
[DEV-051](../plans/DEV-051-architecture-boundaries.md)。

## 替代方案与影响

将完整运行域下移到 scene 会扩大该模块的资产、渲染和宿主策略职责，本次不采用。
继续让 Application 直接拥有全部场景状态不能集中生命周期规则，也不采用。

新增组件是原有状态的迁移，不能只添加转发类而仍由 Application 维护第二份状态。
允许首批保持内部宿主适配接口，但组件私有状态不向 Apps 暴露；公开 SDK 和 RID 契约不变。
本决策不表示代码已经完成迁移，也不承诺解决 0.50 的历史性能问题。

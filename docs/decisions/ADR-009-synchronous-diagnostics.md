# ADR-009：同步诊断回调

- 状态：已接受
- 日期：2026-08-27

## 背景

结果码适合程序分支，但不足以说明失败模块和上下文。诊断又不能改变原操作结果或引入无界日志。

## 决策

- Application 描述结构提供可选同步诊断回调，使用现有 `user_data`。
- 诊断包含严重度、类别、结果码、模块和 UTF-8 消息；字符串只在回调期间有效。
- 回调在触发操作的 Application 创建线程执行，不得抛出异常或重入修改操作；允许只读查询。
- 回调缺失或调用方丢弃消息不改变原结果。P0 不保存诊断历史；临时 UI 若需要历史，另行增加有界缓冲。
- 第三方诊断在后端边界转换，不公开 Granit 原生结构。

## 影响

调用方可以统一记录输入、资产和后端失败，同时仍以返回结果码作为控制流依据。同步回调成本由调用方
负责，不应执行阻塞 I/O。

## 替代方案

- **全局日志器**：难以隔离多个 Application，且所有权与线程规则不清晰。
- **无界消息队列**：便于 UI 消费，但运行时内存上限不可控。

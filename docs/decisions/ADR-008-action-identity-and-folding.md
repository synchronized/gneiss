# ADR-008：动作标识与帧状态折叠

- 状态：已接受
- 日期：2026-08-26

## 背景

输入映射需要支持运行时替换和未来编辑器修改。业务代码应缓存低成本动作标识，但旧标识不能在
映射替换后静默指向另一个动作。同一帧内还可能发生多次按下与释放，单一最终布尔值不足以表达
边沿。

## 决策

- 公共 `gneiss_action` 使用 64 位 Application 局部句柄：高 32 位保存进程内唯一的非零映射代次
  令牌，低 32 位保存 `slot + 1`，零值无效。
- 每次成功替换映射都推进非零代次；旧代次动作查询返回 `GNEISS_ERROR_INVALID_HANDLE`。加载或
  校验失败不改变当前映射、代次和已缓存动作标识。
- 动作名称是区分大小写的 UTF-8 字节串，只用于映射定义和查找，不作为每帧查询键；同一映射内
  不允许重复。
- v1 映射使用严格 JSON，通过 VFS 从逻辑资产 URI 加载。绑定保存 Gneiss 物理键及有限 float
  缩放，不保存平台或 Granit 键码。
- 动作状态同时保存 `pressed`、`held`、`released` 与标量值。同帧多次变化时，`held` 取最终状态，
  `pressed` 和 `released` 分别记录是否出现对应边沿，因此二者可以同时为真。
- 多绑定标量选择绝对值最大的贡献并裁剪到 `[-1, 1]`；绝对值相同时按映射声明顺序选择，保证
  结果确定。数字动作的 `held` 表示最终值非零。

## 影响

- 业务查询无需每帧分配或散列字符串，热重载后的旧缓存会明确失效。
- 动作句柄不可跨 Application、不可序列化，也不能在成功替换映射后继续使用。
- 代次回绕时跳过零；在同一 Application 内发生约 42 亿次成功替换前不会复用代次。
- 首版映射替换是同步事务，异步加载与热重载仍属于后续任务。

## 替代方案

- **每帧字符串查询**：接口简单，但引入重复查找，并弱化调用方缓存与失效语义。
- **编译期或运行时字符串哈希**：查询便宜，但需要公开碰撞策略，且不能独立解决热重载失效。
- **永久单调动作索引**：实现简单，但重载后可能复用旧槽位，或必须维护无界历史。

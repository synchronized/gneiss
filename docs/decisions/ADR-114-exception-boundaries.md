# ADR-114：预期错误、异常边界与进程 OOM

## 状态

2026-11-09：接受目标方向，实施待开始。实施步骤与验收见
[PLAN-109](../plans/PLAN-109-exception-boundaries.md)，本记录不代表代码已迁移。

## 背景

内部函数重复将 bad_alloc 和任意异常转换为错误码，增加样板代码，也缺少真正的 OOM 恢复保障。
大量 noexcept 与分配、回调混用，使删除捕获必须作为完整调用链契约迁移。

## 决策

可预期失败通过 result 返回；进程堆内存耗尽和内部意外异常在明确执行边界终止。
不支持当前阶段在进程 OOM 后继续运行，不以 assert 代替始终生效的致命处理。
第三方已知可恢复异常只在适配层转换；宿主、线程与 C 回调建立异常边界。
内部可能抛出的函数不为返回 result 而机械声明 noexcept，析构等真实不抛出契约保留。
内部兼容 C++ DLL 不自动成为逐函数捕获边界；C ABI 与不兼容插件协议不得泄漏异常。

致命处理不依赖动态分配、业务日志队列或文档保存。全局 terminate 处理器由自有宿主显式设置，
Engine 不在加载时夺取嵌入宿主的全局异常策略。预算不足、GPU 内存和存储配额失败独立分类。

## 替代方案与代价

继续逐函数捕获容易隐藏缺陷且没有完整恢复语义；禁用所有 C++ 异常会扩大第三方适配成本；
实现完整 OOM 恢复需要紧急内存、回滚和持续可用性保证，现阶段没有该需求。
选择边界终止会使未捕获意外异常不再返回 internal，用户回调、测试和文档必须整体迁移。
具体接口、实施清单与验收只在 PLAN-109 维护，历史已发布记录不回写为新行为。

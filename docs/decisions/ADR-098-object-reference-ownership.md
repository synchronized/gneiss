# ADR-098：共享对象引用统一到 Core

状态：已接受，2026-10-31。

## 决策

Core 提供 `ref<T>`，复用原 asset_ref 的 shared_ptr 控制块实现；资源层的
`asset_ref<T>` 为同一类型的语义别名，不产生第二份所有权。
反射解码、组件描述内容和编辑器整对象编辑载荷使用该引用。注册表及内部任务状态的
shared_ptr 不属于反射对象模型，本次不机械替换。

普通数学值、设置和组件描述保持值语义，不要求继承 RefCounted。不得从借用裸指针
重新建立控制块。资源专用工厂的删除器继续管理所属线程销毁；make_ref 只创建普通 CPU 对象。

引用计数不提供数据线程安全、循环回收或动态类型识别；类型身份继续由 Meta 管理。
meta::instance 仍为借用视图，调用方保留拥有者，修改容器后遵守原有失效规则。

## 持久化边界

本次统一拥有者，不自动注册 ref<T> 为可递归展开的属性。值字段继续按已有反射遍历；
资源引用仍按资源标识，场景对象关系按 GUID，组件描述按类型 GUID 与内容编码。
任意共享引用图、弱引用字段和多态指针属性的通用编解码尚未实现。需要新增对象引用属性时，
只适配统一 ref<T> 语义，先定义引用身份与解码解析规则，不泛化所有 STL 指针类型。

## 影响

无需侵入类型继承关系，既有自定义删除器和弱缓存继续有效；代价是保留标准库控制块。
将所有值都改为共享对象会改变复制/撤销语义，因此不采用。未来有共同运行行为的对象再评估基类。

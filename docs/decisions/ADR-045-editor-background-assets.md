# ADR-045：Editor 资产任务的线程与提交边界

## 状态

已接受，目标版本 0.38.0。

## 背景

0.37 测量发现源哈希和导入可阻塞 UI 数百毫秒至数秒。既有导入先替换派生目录再保存索引，
直接异步调用不能保证取消或源变化后的输出一致性。

## 决策

- 一个 Editor 工程使用一个资产工作线程，串行处理自动检查、手动导入及浏览器刷新。
- 主线程通过短临界区交换命令、结果和状态；锁内不执行文件 I/O、解析或提交。
- 工作线程不访问 Scene、ImGui、RID、Application 或 Runtime；主线程消费成功通知。
- 导入先写入独占暂存目录，导入前后复核源哈希，取得提交许可后才替换派生目录和索引。
  索引写入失败时恢复旧派生目录。取消和源通知可撤销尚未取得许可的任务。
- 提交许可是取消的截止点；已进入提交的任务必须完成或回滚。后续源变化再次排队。
- 取消不抢占第三方解析器；关闭请求停止接收任务并等待当前阶段退出，析构最终 join。
- 打包持有暂停状态，等待工作线程空闲后才启动，直到打包结束才恢复资产任务。
- 浏览器传递独立快照，选择状态留在主线程；作者文档冲突和应用仍在主线程。

## Import Service 的归属

此对象承担 Editor 内部 Import Service 的职责，当前实现名为 `asset_background_worker`。
它拥有线程和任务生命周期，底层调用 Tool SDK；不持有 Scene、ECS 或 GPU 资源，也不加入 Runtime
公共 C ABI。浏览器刷新与导入共用此串行执行器，以避免索引读取与导入提交互相穿插。
未来其他工具出现异步服务需求时，再提取可复用的内部工具层接口，不为名称另建一套状态。

对照 Granit 0.30.0 的 model viewer：`threaded_render_task_executor` 串行执行渲染任务，
`scene_prepare_task` 在桌面通过 `std::async` 准备场景并轮询结果。Gneiss 复用这种所有权与消息交接
方式，但保留自己的资产格式、工程索引、版本校验和提交规则；导入任务不占用渲染线程。

## 后果

复用现有重导入队列的去抖和补扫规则，不引入第二套资产数据库。吞吐暂不并行化。
暂存需要额外磁盘空间，关闭可能等待不可抢占的解析调用。哈希复核不能提供外部写入的文件锁；
提交后的新事件通过下一任务收敛。跨进程读隔离及断电事务恢复不属于本决策保证。
